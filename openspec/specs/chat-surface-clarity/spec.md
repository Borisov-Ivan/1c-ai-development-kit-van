# chat-surface-clarity

## Purpose

Требования к текстам оркестратора в чат: Тест понятности, запрет жаргона kit в copy-paste канонах, разделение thin-chat и файла отчёта.

## Requirements

### Requirement: Chat-facing canons pass the readability test

Оркестратор MUST копировать в чат только формулировки, по которым разработчик 1С выбирает вариант, не зная внутренних имён kit (skill, compile/edit, имена гейтов, Schema, имена субагентов).

#### Scenario: Mode Gate question is product language

- **WHEN** на этапе design `/opsx:new` задаётся вопрос режима управляемой формы
- **THEN** в чате три варианта: вручную в Конфигураторе; автоматически — правки Form.xml в репозитории; программно — только модуль формы; и нет упоминаний skill, compile/edit или «уже в поставке»

#### Scenario: Good examples do not teach jargon

- **WHEN** оркестратор сверяется с decision-block или chat-lexicon для ярлыков режима формы
- **THEN** эталон «хорошо» / замена для `assisted` не содержит «через skill» как обязательную формулировку для чата

### Requirement: Process noise is not shown before a choice

Перед вопросом выбора режима формы оркестратор MUST NOT выводить процессные статусы артефактов (запись маркера, «proposal/design набросаны» и аналогичные non-events).

#### Scenario: Mode question has no process preamble

- **WHEN** оркестратор задаёт вопрос режима формы
- **THEN** сообщение содержит канон вопроса (и при необходимости одну строку зачем нужен выбор) без лога внутренних шагов new

### Requirement: Apply pause-wait is a navigator card

Когда разработка останавливается, потому что следующий шаг человека — создать или поправить объекты в Конфигураторе, выгрузить расширение или завести доп.реквизиты в базе, в чате MUST быть карточка-навигатор. Если в списке задач есть заголовки срезов, первой строкой MUST стоять фраза места среза из требования «Карточка приёмки показывает место среза» в виде для среза, который ещё в работе; список того, что создать, MUST NOT сокращаться. Эта строка MUST NOT говорить, что срез готов и что идёт финальный тест. Дальше MUST быть: где мы; нумерованный список того, что создать; якорь файла и имя раздела с рецептом; как вернуться. Одна ссылка на файл паузы MUST NOT заменять этот список. Прогресс «0 из N» и перечень отсутствующих файлов выгрузки MUST NOT быть телом сообщения.

#### Scenario: Apply pause-wait lists objects in chat

- **WHEN** разработка останавливается, потому что в выгрузке расширения нет объектов, без которых нельзя писать код модулей, и в списке задач есть заголовки срезов
- **THEN** первая строка называет место словами, без дроби и без «это финальный тест»; следом сказано, где мы; есть нумерованный список того, что создать; указан файл паузы и раздел «Что создать в Конфигураторе»; нет «0 из N» и списка отсутствующих файлов как тела сообщения

#### Scenario: Pause-wait is not a decision fork

- **WHEN** единственный путь вперёд — создать объекты по рецепту
- **THEN** в чате нет заголовка выбора «сделать чеклист или имена другие»; расхождение имён — одна фраза в конце, не развилка

#### Scenario: Isolated chat rejects a file-only pause

- **WHEN** в новом чате разработку вызывают на задаче без объектов в выгрузке
- **THEN** первое сообщение не состоит из заголовка «сессия приостановлена» и ссылки на файл паузы без списка «что создать»

### Requirement: Pause-wait file leads with the recipe

Файл `reports/handoff-pause-*.md` при pause-wait MUST начинать человеческую часть с раздела «Что создать в Конфигураторе». Перечень отсутствующих путей XML MUST быть приложением, не шапкой. Секция «Что проверить СЕЙЧАС» MUST говорить, что сценарий на ИБ не гонять, пока нет объектов.

#### Scenario: Первый раздел файла — что создать

- **WHEN** разработчик открывает файл паузы по ссылке из чата
- **THEN** первым содержательным разделом идёт «Что создать в Конфигураторе» с именами, типами и шагами; не список «ничего в коде» из идентификаторов выгрузки

### Requirement: Command AskQuestion and handoff stay user-facing

Шаблоны AskQuestion и thin-chat в new, apply, status, review и verify MUST использовать русские ярлыки ролей и решений; имена гейтов, Schema и `onec-code-*` MUST оставаться в debug/reports или agent-контексте. Thin-chat apply MUST NOT вырезать инвентарь pause-wait: список «что создать» остаётся в чате, таблицы прогресса — в файле.

#### Scenario: Slice acceptance prompt without gate names

- **WHEN** apply спрашивает вердикт по приёмке среза
- **THEN** текст для пользователя сформулирован как «Что решить» / приёмка среза без заголовка с именем внутреннего гейта и без голого кода задачи как единственного заголовка

#### Scenario: Apply pause label is product language

- **WHEN** apply показывает варианты продолжения работы после среза или паузы
- **THEN** в тексте для пользователя нет ярлыка «Пошаговая пауза»; варианты сформулированы на языке эффекта (продолжить / остановиться / принять срез)

#### Scenario: Review fix prompt without agent slugs

- **WHEN** review предлагает устранить замечания
- **THEN** варианты говорят «агент» / «упростить код», а не имена субагентов kit

#### Scenario: Status and handoff separate chat from file

- **WHEN** выводится статус change или handoff apply
- **THEN** в чате нет блока Schema и markdown-таблиц срезов; полный структурированный handoff при необходимости лежит в отчёте; при pause-wait в чате есть список объектов, а не только ссылка на отчёт

### Requirement: SSOT documents do not contradict each other on chat bans

Документы opsx-output-style, brief-card и chat-lexicon MUST одинаково запрещать имена агентов в чате и MUST NOT требовать секцию KB в entry-брифе.

#### Scenario: Entry brief excludes KB list

- **WHEN** оркестратор показывает entry-бриф explore или extend
- **THEN** в брифе нет обязательного слота со списком KB-фактов; discovery остаётся во внутреннем контексте агентов

#### Scenario: Agent names banned uniformly

- **WHEN** self-check перед сообщением в чат ссылается на opsx-output-style и lexicon
- **THEN** оба источника запрещают slug субагентов в user-facing тексте (допустимы «агент», «ревьюер», «архитектор»)

### Requirement: Docs for humans match the Mode Gate canon

faq-kit и quick-start MUST описывать вопрос режима формы через `form_mode` и русские ярлыки; MUST NOT утверждать, что Mode Gate в new спрашивает способ поставки макета.

#### Scenario: FAQ matches form-only Mode Gate

- **WHEN** разработчик читает faq-kit про вопрос режима формы
- **THEN** таблица использует `form_mode` и не обещает вопрос про макет на `/opsx:new`

### Requirement: Progress команд /opsx:* только на русском

В сессии команды `/opsx:*` сообщения оркестратора SHALL быть на русском. Строка-разделитель (progress marker) SHALL быть на русском и не длиннее одной короткой строки — это частный случай, не единственный охват. Язык чата команды `/opsx:*` SHALL задаваться runtime-бюджетом чата (пункт самопроверки перед отправкой), даже если системный Communication предлагает английский. Английские каркасы (`I'll`, `Let's`, `Starting`, `Switched to`, `chat model`, `next-best model`) — примеры провала и тогда, когда фраза не является строкой-разделителем; это не нормативный запретный список HALT.

#### Scenario: Progress на русском

- **WHEN** оркестратор пишет промежуточную строку progress или обычную вводную фразу в `/opsx:verify` или `/opsx:explore`
- **THEN** текст на русском; нет английского каркаса вроде «I'll start» / «Switched to chat model»

#### Scenario: Verify без английского progress

- **WHEN** в `/opsx:verify` длинный внутренний ремонт постановки или независимый разбор идёт на Opus 5 из‑за отсутствия слага сильной модели
- **THEN** в чат допустимы только русские каноны: «Дописываю постановку…», «Разбор постановки (Fable)» / «Разбор постановки (Opus 5)», и при лимите — канон про дорогие модели (в том числе до финальной карточки); отдельный английский «сейчас повторю» не появляется

### Requirement: Last-slice acceptance offers prerelease or archive

«Последний срез» для этого вопроса — срез, после принятия которого не остаётся открытых рабочих задач и открытых приёмок. Принять последний по порядку срез, пока у более раннего открыты рабочие задачи, развилку SHALL NOT открывать. «Принять» на финальной карточке раннего среза SHALL открывать ту же развилку в том же ходе. Слова ответов, в том числе `ревью`, `архив`, `стоп` и вопрос «архивировать» без кода расширения, SHALL оставаться прежними.

После приёмки такого среза в ЗНИ, в которой есть код расширения, оркестратор SHALL задать один вопрос с тремя ответами-словами: `ревью`, `архив`, `стоп`. Признак «есть код расширения» SHALL совпадать с охватом маркеров `cfe` или `mixed` (сегменты пути этой ЗНИ). Охват `cf` или не определён MUST NOT предлагать слово `ревью`. Ярлык только базовой конфигурации SHALL быть `cf` (не имя выгрузки заказчика). Оркестратор MUST NOT запускать предрелизное ревью внутри сессии реализации. Оркестратор MUST NOT менять поведение слов `архив` и `стоп`, кроме случая открытых замечаний о спорном качестве. Если такие замечания есть, развилка при любом охвате SHALL содержать одну информационную строку: сколько замечаний открыто, что ответ `архив` оставит их открытыми и как их разобрать через ревью; слова ответа не меняются. Ту же развилку MUST показывать и при возврате в сессию с ответом «принят» на последнем срезе, и в карточке «реализация завершена», когда всё уже принято и есть код расширения. Слот следующего шага проверки постановки после apply MUST NOT меняться этой ЗНИ.

#### Scenario: Последний срез — развилка из трёх слов

- **WHEN** разработчик принимает последний срез ЗНИ с кодом расширения фразой «принято»
- **THEN** в чате подтверждение приёмки с названием среза и один вопрос с тремя словами `ревью`, `архив`, `стоп`; ЗНИ не заархивирована

#### Scenario: Ответ ревью даёт команду предрелиза

- **WHEN** разработчик отвечает `ревью` на развилку после последнего среза
- **THEN** в чате ровно один следующий шаг `/release-review <имя-ЗНИ>`; сессия реализации завершена; каталог ЗНИ на месте; предрелиз в этой сессии не стартовал

#### Scenario: Ответ архив без изменений

- **WHEN** разработчик отвечает `архив` на развилку после последнего среза, и открытых замечаний о спорном качестве нет
- **THEN** архивация проходит в той же сессии и заканчивается тем же тонким итогом, что до этой ЗНИ

#### Scenario: Ответ стоп без изменений

- **WHEN** разработчик отвечает `стоп` на развилку после последнего среза
- **THEN** сессия реализации завершается, ЗНИ не тронута — как до этой ЗНИ

#### Scenario: Без кода расширения слова ревью нет

- **WHEN** разработчик принимает последний срез ЗНИ без кода расширения (только правила kit или только базовая конфигурация)
- **THEN** в чате прежний вопрос «архивировать» с ответами `архив` и `стоп`; слова `ревью` нет

#### Scenario: Возврат в сессию — та же развилка

- **WHEN** разработчик возвращается в сессию реализации и отмечает последний срез принятым
- **THEN** в чате та же развилка из трёх слов, что после фразы «принято», а не отдельная строка только с командой архива

#### Scenario: Карточка завершения — та же развилка

- **WHEN** разработчик открывает реализацию ЗНИ с кодом расширения, у которой все срезы уже приняты
- **THEN** вместо одной строки с командой архива печатается та же развилка из трёх слов

#### Scenario: Проверка постановки после apply не меняется

- **WHEN** проверка постановки после реализации всех задач предлагает следующий шаг
- **THEN** это по-прежнему команда архива; развилка `ревью` / `архив` / `стоп` в этом слоте не появляется

#### Scenario: Детектор смотрит сегмент пути, не имя выгрузки

- **WHEN** в задачах ЗНИ есть модуль в каталоге расширения чужого проекта (сегмент `cfe` в пути), а путей выгрузки ЭДО нет
- **THEN** после приёмки последнего среза в чате три слова, включая `ревью`

#### Scenario: Развилка сообщает об открытых замечаниях качества

- **WHEN** разработчик принимает последний срез, а после реализации осталось два открытых замечания о спорном качестве
- **THEN** в той же развилке есть одна строка: два замечания открыты, ответ `архив` оставит их открытыми, разобрать их можно ревью этой задачи; слова ответа прежние

#### Scenario: Ответ архив при открытых замечаниях

- **WHEN** разработчик отвечает `архив` на развилку, где была строка об открытых замечаниях качества
- **THEN** архивация в той же сессии сначала показывает список этих замечаний и вопрос ревью / архив без ревью / стоп, как при прямом запуске архива

#### Scenario: Принять последний по порядку при открытых доработках развилку не открывает

- **WHEN** разработчик принимает последний из трёх срезов, а у первого рабочие задачи ещё открыты
- **THEN** вопрос архива в этом ходе не задаётся; следующий шаг — доработки первого

#### Scenario: Принять на финале раннего среза открывает развилку в том же ходе

- **WHEN** разработчик принимает сдачу раннего среза, после которой не остаётся открытых рабочих задач и открытых приёмок, и в заявке есть код расширения
- **THEN** в том же ходе один вопрос с тремя словами `ревью`, `архив`, `стоп`; заявка не заархивирована

### Requirement: Карточка приёмки показывает место среза

Фраза места среза живёт в одном абзаце правила чата у передачи на приёмку. Ожидание объектов, пауза с выбором, остановка по просьбе, карточка проверки на границе среза, конечная карточка пакета и снимок состояния MUST ссылаться на этот абзац и MUST NOT держать свою копию.

Фраза MUST входить в первые строки чата. У передачи, ожидания объектов, паузы с выбором, остановки по просьбе и конечной карточки пакета она MUST быть первой. У карточки проверки на границе среза первая строка MUST оставаться итогом проверки, а фраза места MUST стоять сразу следом, до следующего шага.

Фраза MUST называть место словами. Дробь вида «1 из 1» MUST NOT использоваться. Имён срезов с ещё открытой приёмкой MUST быть не больше трёх, дальше «и ещё N».

Пока срез ещё в работе — ожидание объектов, пауза с выбором, остановка по просьбе, снимок до сдачи — фраза MUST NOT говорить «готов» и MUST NOT говорить, что идёт финальный тест. Пример: «Идёт второй срез из трёх. Первый принят.» У единственного среза, который ещё в работе: «В заявке один срез, он ещё в работе.»

Признак финального теста MUST стоять только на передаче, на карточке проверки на границе среза и на конечной карточке пакета. Финальный тест MUST быть сдачей, после которой ни у одного среза заявки не остаётся открытых рабочих задач. Один срез: «В заявке один срез. Это финальный тест.» Не последний из нескольких, если после сдачи работы ещё останутся: место по счёту и «финальный тест впереди». Последний по порядку при открытых доработках более раннего: сказано, что финальный тест после этих доработок, и MUST NOT говориться «это финальный тест». Последний по порядку, когда у ранних задачи закрыты: «это финальный тест». Если доработки раннего среза закрыли последние работы, сдача этого раннего среза MUST говорить, что это финальный тест. Если другой срез ещё не принят, а его работы закрыты, это MUST быть сказано в той же фразе.

Снимок состояния при уже открытой приёмке MUST говорить, что срез ждёт приёмки, и MUST NOT говорить «это финальный тест». Если эта приёмка — финальный тест, снимок MUST добавить, что откладывать дальше некуда, без слов «финальный тест».

Оборот «принять сейчас или позже, следом архив» в фразу места MUST NOT входить. Таблица следующих задач в чат MUST NOT добавляться. Открывать список задач, чтобы понять место среза, MUST NOT требоваться.

На границе среза место MUST относиться к срезу, чья приёмка открыта. На конечной карточке пакета одного номера MUST NOT быть: названы срезы этой сдачи, какие приёмки ещё открыты, и если после пакета открытых рабочих задач не остаётся — что это финальный тест. Фраза MUST писаться, только когда в списке задач есть заголовки срезов. Без заголовков пауза MUST оставаться как сейчас.

Карточку без этой строки MUST NOT отправлять: её собирают заново. Строка внизу файла её MUST NOT заменять. Строка о срезах, принятых без проверки, на карточке финального теста MUST оставаться отдельным предупреждением и MUST NOT вливаться в фразу места. На карточке последнего по порядку среза, пока у более раннего открыты доработки, этой строки MUST NOT быть.

#### Scenario: Передача называет место среза

- **WHEN** разработчик получает передачу первого из двух срезов
- **THEN** в первых строках сказано, что готов первый срез из двух и что финальный тест впереди; назван второй срез; дроби нет; список задач для этого не нужен

#### Scenario: Единственный срез — финальный тест

- **WHEN** разработчик получает передачу единственного среза заявки
- **THEN** в первых строках сказано, что в заявке один срез и что это финальный тест; дроби «1 из 1» нет

#### Scenario: Последний срез — финальный тест

- **WHEN** разработчик получает передачу последнего из трёх срезов, а первый уже принят
- **THEN** в первых строках сказано, что это последний срез и что это финальный тест; обещания «принять позже, потом архив» в этой строке нет

#### Scenario: Фраза места при открытых доработках раннего

- **WHEN** разработчик получает передачу последнего из трёх срезов, а у первого рабочие задачи ещё открыты
- **THEN** в первых строках сказано, что готов последний срез и что финальный тест будет после доработок первого; слов «это финальный тест» нет

#### Scenario: Финальная сдача после доработок называет финал

- **WHEN** доработки первого среза закрыли последние рабочие задачи заявки, последний срез раньше отложен, и разработчик получает передачу первого среза
- **THEN** в первых строках сказано, что это финальный тест, и назван отложенный последний срез

#### Scenario: Проверка не подменяет итог фразой места

- **WHEN** на границе среза приходит карточка проверки
- **THEN** первая строка — итог проверки, фраза места стоит сразу следом, до следующего шага

#### Scenario: Карточка без фразы не уходит

- **WHEN** в списке задач есть заголовки срезов, а черновик паузы не содержит фразу места
- **THEN** такая карточка в чат не отправляется и собирается заново

#### Scenario: Пакет называет сдачу без одного номера

- **WHEN** разработка заканчивается одной карточкой нескольких срезов и после неё открытых рабочих задач не остаётся
- **THEN** в чате названы срезы этой сдачи, какие приёмки ещё открыты, и что это финальный тест; одного номера «N из M» нет

#### Scenario: Последний срез можно принять позже

- **WHEN** разработчик получает передачу последнего по порядку среза
- **THEN** если у более ранних рабочие задачи закрыты, сказано, что это финальный тест, и в фразе места нет обещания принять позже и сразу выбрать архив; если у более раннего рабочие задачи открыты, сказано, что финальный тест после них, слов «это финальный тест» нет, и немедленный вопрос архива не обещается

#### Scenario: Пауза в работе не называет финальный тест

- **WHEN** разработка останавливается, потому что объекты ещё не созданы, и в заявке второй срез из трёх
- **THEN** первая строка говорит, что идёт второй срез из трёх; слов «готов» и «это финальный тест» нет

### Requirement: Приёмка без прогона остаётся видимой

Фраза «принято без проверки» MUST отмечать срез принятым и MUST записывать, что прогона не было. Обычное «принято» такой пометки MUST NOT ставить. Срезы с пометкой MUST перечисляться на карточке финального теста и в сообщении перед архивом. На карточке последнего по порядку среза, пока у более раннего открыты доработки, этой строки MUST NOT быть. Эта строка MUST NOT быть отдельным вопросом и MUST NOT отменять вопрос об открытых замечаниях качества.

#### Scenario: Принято без проверки видно на последнем срезе

- **WHEN** первый срез принят фразой «принято без проверки», а затем передаётся последний по порядку срез
- **THEN** если эта передача — финальный тест, первый назван как принятый без проверки; если у более раннего ещё открыты доработки, этой строки на карточке нет

#### Scenario: Принято без проверки видно на финальном тесте

- **WHEN** первый срез принят фразой «принято без проверки», а затем передаётся сдача, после которой открытых рабочих задач не остаётся
- **THEN** в карточке финального теста назван первый как принятый без проверки

#### Scenario: Перед архивом видны срезы без проверки

- **WHEN** разработчик запускает архив задачи, где один срез принят без проверки, а открытых замечаний качества нет
- **THEN** перед архивом в том же сообщении назван этот срез, отдельного вопроса из-за пометки нет, архив не останавливается

#### Scenario: Обычное принято пометки не ставит

- **WHEN** срез принят фразой «принято»
- **THEN** пометки «без проверки» нет ни на карточке финального теста, ни перед архивом

### Requirement: Сдача называет состав среза и основные тесты

Когда сдача среза предполагается, в том же сообщении после фразы места MUST быть, что вошло в срез, обычными фразами и без номеров задач. Дальше MUST быть основной тест этого среза — шаги основной приёмки из шапки среза. Необязательные шаги приёмки в чат MUST NOT копироваться. Под списком MUST быть одна ссылка на раздел «Что проверить сейчас» файла сдачи. Этот раздел MUST содержать полный чеклист приёмки среза. Ссылка MUST NOT вести на список задач как на единственное место, где лежат сценарии.

На финальном тесте в тот же список MUST входить основной тест каждого другого среза, у которого работы закрыты, а приёмка ещё открыта, раньше он в списке или позже. У каждого такого блока MUST быть имя среза. Если таких срезов нет, пустой блок MUST NOT писаться. Список основных тестов MUST NOT ужиматься потолком короткой сдачи в 4–8 строк.

На финальном тесте последний абзац MUST быть одним предложением без вариантов ответа: открытых работ в заявке нет, выбор архива придёт отдельным сообщением после принятия. Сам вопрос архива в эту карточку MUST NOT входить.

#### Scenario: В чате есть основной тест

- **WHEN** разработчик получает передачу среза, у которого в шапке записан основной тест
- **THEN** в сообщении сказано, что вошло в срез, перечислены шаги этого основного теста, и есть ссылка на раздел «Что проверить сейчас» файла сдачи; необязательные шаги в чат не скопированы

#### Scenario: Финал собирает тесты ещё не принятых срезов

- **WHEN** разработчик получает передачу среза, после которой открытых рабочих задач в заявке не остаётся, а у другого среза работы закрыты и приёмка ещё открыта
- **THEN** в сообщении есть основной тест текущего среза и основной тест того другого среза, с его именем

#### Scenario: Пустой список отложенных не пишется

- **WHEN** разработчик получает передачу единственного среза
- **THEN** в сообщении нет блока «отложенных тестов нет»

#### Scenario: Полный перечень лежит в файле сдачи

- **WHEN** разработчик открывает раздел «Что проверить сейчас» файла сдачи
- **THEN** там полный чеклист приёмки среза, а не отсылка к списку задач как к единственному перечню
