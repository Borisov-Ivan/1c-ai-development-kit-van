## Context

Панель Canvas — поверхность IDE рядом с чатом, не пузырь сообщения. В `.cursor/` кита до этой ЗНИ упоминаний нет; системный скилл Cursor требует канвас для аналитики. Первый макет стал навигатором по модулю: «куда смотреть», а не «что происходит».

Источник постановки: блок `## Постановка ЗНИ` в чате (2026-08-27), имя `scenario-map-canvas`. Отчёты исследования на машине автора (`temp/reports/exploration-2026-08-27-scenario-board-skill.md`, `exploration-2026-08-27-explain-canvas-map.md`) в этом рабочем каталоге не скопированы; факты ниже — из постановки, не выдуманы из кода 1С.

Связанные ADR: ADR-0001 (чат vs агент) — тексты намёка chat-facing; ADR-0002 (handoff explain после review) — не пересекается, карту сценария не подмешивать в бриф Охвата. Архив `explain-after-review-apply-scope` — прецедент propose без новой команды и без автостарта.

Таксономия KB в kit отсутствует (`_taxonomy.template.yaml` только) — Discovery пропущен.

## Goals / Non-Goals

**Goals:**

1. Карта сценария показывает эффект шага и доказательство.
2. Молчание, пока нет прямой просьбы или узких условий намёка.
3. Сессия `/opsx:explain` не рвётся отдельной командой.
4. Имена «карта точек» и «карта сценария» не смешиваются.

**Non-Goals:**

- Плагины Marketplace и PR-канвас.
- Команда `/opsx:board` и аналоги.
- Запись абсолютного пути `.canvas.tsx` в proposal/design/приёмку.
- Распространение системного MUST canvas на сессии `/opsx:*`.
- Пачка эталонов голоса explain.
- Правки прикладного BSL.

## Existing Mechanisms

### Найденные механизмы

| Механизм | Назначение | Контракт | Можно использовать? |
|----------|-----------|----------|---------------------|
| Карта точек explain (`inventory-card.md`) | Список имён эффектов в чате до прохода | ≤12 строк, без кода и классов | Да — **не заменять**; другая поверхность |
| Журнал `explain-*.md` | Запись прохода после выхода | Каркас `explain-report.md` | Да — источник узлов и evidence |
| Выход explain (`exit-card.md`) | Журнал + один «Следующий шаг» | ≤6 строк; вопрос анализа XOR достаточно | Да — намёк встраивается в существующую строку |
| Explore «Дальше» / handoff | Следующая команда после исследования | Один next step | Да — намёк только при числах по стадиям |
| Системный Canvas Cursor | Панель IDE, `openFile` | Вне git, путь машины | Да как носитель; содержимое — контракт кита |
| docs-canvas / pr-review-canvas | Плагины Marketplace | Не в kit | Нет |

### Выбранный уровень Preference Hierarchy

**Уровень:** 2 — обернуть существующую панель IDE контрактом кита, не плодить команду и не подменять карту точек.

**Обоснование:** карта точек уже занята списком имён в чате. Отдельная команда рвёт persistence explain. Пустая панель «по системному MUST» уже дала шум.

## Design Rationale

Ценность узкая: ≥5 шагов **и** замеры или ветвление; пропорция времени; журнал ещё не записан. Поэтому ядро — контракт узлов + запрет самопроизвольного рисования. Намёк дешевле отдельного вопроса и не занимает второй next-step. Эталон узлов живёт **в скилле** (fixture), потому что живой файл панели на машине автора вне репозитория.

## Decisions

### D1. Намёк в «Следующий шаг», не отдельный вопрос

Выбрано: при ≥5 точках **и** (замеры **или** развилка) добавить вариант в существующую строку next-step. Если уже есть вопрос про доп. анализ — намёк не печатать. Explore — только при распределении времени по стадиям с числами.

Отклонено: только прямая просьба (не трогать exit-card) — честнее, если намёк не будут принимать; оставляем как откат по kill-критериям, не как старт. Отклонено: отдельная команда — рвёт сессию explain.

### D2. Два имени

**Карта точек** — чат, список имён до прохода. **Карта сценария** — панель: что происходит на шаге. Классы точек (`решение` / `наблюдение` / `типовое`) на панель не выносятся.

### D3. Контракт узла

Обязательные поля до публикации: `step`, `name` (эффект), `effect` (2–3 предложения), `evidence` (`file:line` или путь отчёта). Шапка карты: фраза сценария, источник (журнал/отчёт), окно замера если есть времена. Порог: <4 узлов с `effect` — не создавать. Содержимое панели = подмножество файла-журнала.

Запрещено на панели: код и fence BSL, look/SQL как primary, статусы прохода, `newComposerChat`, все узлы раскрытыми, пустые состояния, факты вне журнала.

### D4. Нет команды, нет путей машины в артефактах

Скилл читается из explain/explore по согласию или по прямой просьбе. В постановке, design, spec и приёмке не указывать абсолютный путь `.canvas.tsx`.

### D5. Системный MUST canvas

Сессии `/opsx:*` не обязаны рисовать панель «потому что системный скилл сказал». Молчание — штат.

### D6. Третий черновик среза

Черновик постановки «живой макет как эталон» свёрнут в срез S1: эталон — fixture в скилле. Живой файл панели на машине автора вне git и вне задач агента.

## Implementation Options

**Option A (выбран).** Скилл + намёк в next-step с предусловиями. Проще откатить намёк, чем команду.

**Option B.** Только прямая просьба. Меньше шума, карта почти не всплывает.

**Option C.** Команда `/opsx:board`. Отклонено: persistence.

**Option D.** Рисовать панель на каждый разбор. Отклонено: пустышка и навигатор.

## Behavior Contract

1. Без просьбы и без условий намёка панель не создаётся.
2. Узел без `effect` и `evidence` не попадает на панель.
3. На панели нет «сейчас разбираем» и нет кода как основного содержимого.
4. В чате по-прежнему карта точек (имена) и карточки с кодом.
5. Намёк не создаёт второй «Следующий шаг» и не печатается рядом с вопросом про доп. анализ.
6. Прямая просьба работает, даже если намёк не показывали, если узлов с эффектом ≥4.

## Assumptions

- Панель Canvas в IDE доступна (клик по пути открывает панель; `openFile` работает) — подтверждено автором постановки.
- Файл панели лежит вне git; агент не обязан его создавать в репозитории.
- Порог ≥5 точек и «замеры или развилка» — из постановки, не из замера на ИБ.
- Приёмка kit — по тексту скилла и шаблонов (как у explain-scope), не по ИБ 1С.

## Открытые вопросы

1. ~~Намёк vs только просьба~~ — закрыто в D1 (намёк с предусловиями; откат = выключить намёк, скилл остаётся).
2. ~~Имена двух карт~~ — закрыто в D2.
3. Kill-критерии через месяц (намёк не принимают; расхождение с журналом; узел без effect/evidence; триггер вне explain/explore; одноразовость; дороже одного хода; >80% без времён) — не блокируют apply; follow-up после поставки.

## Risks / Trade-offs

- [Намёк игнорируют] → выключить строку в exit-card, скилл по просьбе остаётся (D1).
- [Панель снова навигатор] → HALT скилла: без evidence не публиковать; fixture как эталон.
- [Две «карты» путают] → D2 + глоссарий; в чате не называть панель «картой точек».
- [Системный MUST рисует пустышку] → D5 явным исключением в скилле и диспетчере.

## Migration Plan

1. Скилл + указатели + fixture.
2. Намёк в exit-card и explore.
3. После месяца — смотреть kill-критерии (follow-up).
