## Пробелы

### G1 — согласие в исследовании не из чего строить панель

- **Задача/артефакт:** третья группа задач (проверка в скилле карты, точки разбора, правило «Дальше»); design D1 / Behavior Contract 9 и 13; spec «Согласие на предложение рисует карту» и «Map outside walkthrough uses named source»; действующий скилл карты (абзац «в исследовании слот Дальше не занимать намёком»); скилл исследования, таблица «Интерпретация ответа» («да» → следующий шаг маршрута); шаблон финала `handoff-block.md` (один «Следующий шаг: /opsx:new»).
- **Что отсутствует:** одна фраза, из какого файла картограф рисует после «да» на предложение в «Дальше». Сейчас «согласие = прямая просьба» + «вне разбора без указанного пользователем отчёта — отказ». Журнала разбора нет, путь в чат по правилам кита не печатают — исполнитель либо откажет вопреки Why (исследование должно давать схему), либо выдумает источник. Задача проверки топологии не снимает запрет скилла занимать «Дальше» намёком. Задача «Дальше» не говорит, что строка «Следующий шаг: /opsx:new» в сообщении с постановкой — не слот карты.
- **Рекомендация:** расширить задачу проверки в скилле карты (единственный контракт предложения) и задачу слота «Дальше». Design D1 / Behavior 13 — той же фразой. Спек «вне разбора» на вход **принятого предложения** не применять.

- **Сниппет** (замена пункта про проверку топологии в `tasks.md`):

```markdown
- [ ] S3.1 Описать в `.cursor/skills/scenario-map-canvas/SKILL.md` проверку топологии и вывода как единственный контракт предложения (без предметных предикатов) и заменить ею строку намёка «≥5 точек и замеры времени» в таблице «Молчание и пороги» и в разделе «Намёк на выходе explain»; снять запрет занимать слот «Дальше» исследования намёком (указать на правило приоритета в скилле исследования). Там же зафиксировать: проверка не пройдена — предложения нет и причина в чат не печатается; после ответа «без карты» предложение до выхода сессии не повторяется; согласие строит панель из источника, на котором прошла проверка (текущий отчёт исследования / журнал разбора / уже пройденные точки) — отказ «вне разбора без указанного отчёта» на этот вход не действует (D1, D9)
```

- **Сниппет** (замена пункта про «Дальше»):

```markdown
- [ ] S3.5 Добавить в `.cursor/skills/openspec-explore/SKILL.md` правило приоритета слота «Дальше»: при прошедшей проверке топологии — схема, иначе пошаговый разбор; оба вместе запрещены. Если печатается блок постановки ЗНИ — варианта схемы нет ни в «Дальше», ни в оставшейся строке «Следующий шаг: /opsx:new». В таблице интерпретации ответа: согласие на предложение схемы строит панель из текущего отчёта исследования (путь уже есть у оркестратора) и передаёт его картографу; команда сессии не меняется (D1)

Правило «вне разбора без указанного пользователем отчёта» на этот вход не действует. Строка «Следующий шаг: /opsx:new» в финале с постановкой ЗНИ слотом предложения карты не является.

### G2 — «сразу карту» до первой карточки: два пути без выбора

- **Задача/артефакт:** задача добавления варианта в шаблон подтверждения списка точек; design D1 п.2; открытый вопрос 5 design («либо убрать вариант, либо описать режим прохода»); spec «Карта во время прохода из уже пройденных точек» (на карте только уже разобранные шаги).
- **Что отсутствует:** выбранный режим. Задача добавляет третий вариант в строку «Подтвердить список?». До первой карточки доказанных `file:line` нет. «Согласие = прямая просьба» + «только пройденные точки» + «узел без доказательства не публикуется» даёт отказ по порогу сразу после собственного предложения. Исполнитель не знает, запоминать фокус до четырёх доказанных сущностей или не вводить вариант.
- **Рекомендация:** закрыть вопрос одним выбором. Проще для реализации — **не** добавлять вариант в подтверждение списка (предложение в разборе только на выходе). Если три точки предложения в spec оставлять — описать отложенную постройку. Ниже — сниппет отложенного режима (spec трогать не нужно).

- **Сниппет** (замена пункта про подтверждение списка), если оставляем три точки предложения:

Согласие запоминает фокус; панель публикуется только когда наберётся не меньше четырёх доказанных связанных сущностей; до этого команда сессии не меняется и повторного вопроса «хотите карту?» нет (D1, открытый вопрос 5 — отложенная постройка)
```

- **Сниппет-альтернатива** (если убираем вариант; тогда же вычеркнуть D1 п.2 и убрать «подтверждение списка точек» из spec «Hint only on an existing decision line»):

## Минорные замечания (не блокируют сами по себе)

- Follow-up kill-критериев ссылается на «открытый вопрос 5»; в design kill-критерии — вопрос 4, вопрос 5 — инвентарь. Поправить указатель, чтобы follow-up не закрывал не ту дыру.
- Заголовок первого среза всё ещё говорит «намёк на выходе разбора»; намёк теперь у третьего среза. Косметика, работы первого среза не переписывать.
- Сценарий «Семь линейных шагов не обязаны давать карту» дважды в «Связь со spec» (второй и третий срез). Владелец — третий (предложение/молчание).
- Скобки «источник, кэш, …» в design/spec — примеры ролей, не фильтр охвата (уже сказано в D3 про словарь). Задаче контракта узла достаточно; отдельная задача не нужна, если исполнитель не превратит шесть слов в allow-list. После G1 стоит одна строка в скилле: перечень `kind` не отсекает сущности вне списка.
- Порог «четыре» после отсева без доказательства **и** без инцидентного ребра в задачах не назван явно; «список без рёбер не публиковать» + «ниже порога — одна строка» достаточны, если G1 закроют. Иначе четыре сущности с одной изолированной дадут либо запрещённый список, либо тихий дроп.

## Simplicity Check

- **Viable alternatives:** единственный выбранный путь поставки — скилл как контракт «когда и что», картограф пишет один файл панели, предложение внутри существующих строк решения. Другой носитель (новая команда, оркестратор рисует макет) в этой оценке не пересматривается.
- **Selected simplest viable design:** тот же путь; готовность упирается не в лишние файлы, а в две недописанные фразы согласия.
- **Why not simpler:** без картографа нельзя задать рабочую модель макета параметром вызова; без смены контракта узла панель снова станет списком. Это уже Chosen, не развилка этой оценки.
- **Complexity budget:** правки markdown в `.cursor/` и `openspec/`; новый файл агента и два эталона; хуков 1С нет; продуктовый BSL не трогается.
