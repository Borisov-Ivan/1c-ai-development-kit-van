## Three-Question Challenge

### Q1 — Problem-Solution Fit

- **Why говорит:** панель должна показывать причинность и слои, а не столбик шагов. Три провала текущего контракта: (1) исследование сложной топологии предлагает только текстовый разбор; (2) разбор предлагает схему только при замерах времени; (3) прямая просьба «покажи карту сценария» уходит в плоский текст, потому что панель «доступна» лишь если её уже открыли или назвали файл. Предлагать должны оба контура, когда расположение и стрелки дают вывод, которого нет в списке.
- **Design адресует:**
  - Why (1) → D1: слот «Дальше» при прошедшей проверке топологии предлагает схему, иначе разбор; карта и разбор не в одном сообщении. D9: предикат без предметной области.
  - Why (2) → D1/D3: предложение по топологии, замеры времени сняты; точки — строка подтверждения списка и «Следующий шаг» на выходе.
  - Why (3) → D7: предикат «уже открыта или назван файл» снят; панель с нуля в каталоге среды. D3: публикация — узлы + связи + слои, список без рёбер не карта.
  - Ремонт (источник при согласии, порог после обоих отсевов, скобки ролей как примеры, отложенная постройка «сразу карту», финал с постановкой без слота карты) **в тексте есть**: D1, D3, Behavior 9/13, § «Решения verify», spec Direct request / Offer / Hint / Map outside walkthrough.
- **Покрытие:** частичное. Три заявленных провала по центру закрыты. Крайние пути, без которых провалы (1) и (3) возвращаются, в постановке всё ещё сталкиваются.

  - **Why говорит о «просьба даёт схему» → design адресует Z, X не покрыт на исследовании.** Постановка ЗНИ заменяет синтез «Дальше» (`openspec-explore/templates/handoff-block.md`: один «Следующий шаг» — создать ЗНИ). D1 и spec Hint это принимают: предложения схемы нет. Закрытая ось не требует предлагать в этом слоте. Но прямая просьба в той же сессии исследования по D7 и spec «Map outside walkthrough» — «вне разбора»: только журнал разбора или отчёт, который пользователь **указал**. Текущий отчёт исследования в сессии не назван исключением, в отличие от принятого предложения. Пользователь, у которого слот «Дальше» уже съела постановка, снова получает отказ одной строкой — это тот же класс провала, что Why (3), только источник теперь «нет указанного отчёта», а не «панель недоступна».
  - **Why говорит о предложении в разборе → design адресует предложение в строке подтверждения списка, но Offer запрещает то, что D1 печатает.** Spec Offer: предлагать **только** если после обоих отсевов есть ≥4 публикуемых сущности. Текущий `inventory-card.md` — имена эффектов **до** первой карточки, без `file:line`. D3: узел без доказательства не публикуется. На шаге подтверждения списка после обоих отсевов публикуемых обычно 0 → по Offer варианта «сразу карту» быть не должно. D1 п.2 и spec «Согласие до первой карточки» этот вариант как раз вводят. Два требования взаимоисключающие, пока не сказано, **чем** на этом шаге считается доказательство (якоря отчёта исследования за именами vs только карточки прохода).
  - **Why говорит «панель не появляется сама» (AC1: без просьбы и без принятого предложения) → design/spec Silence и D5 читаются как автосборка при «сработавшем намёке».** D5: рисовать можно при (3) намёке на строке выхода. Goal 2 и Behavior 1 снимают молчание при намёке. Spec Silence: MUST NOT создавать, **пока нет** просьбы, **нет** сработавшего намёка и **нет** принятого предложения — намёк в том же ряду, что просьба. Proposal AC1 и What Changes 4 говорят «предлагают», не «рисуют». Текущий скилл печатает намёк в строке, а сборка идёт по просьбе (`scenario-map-canvas/SKILL.md` «Порядок действий по просьбе»). Если исполнитель прочитает D5 буквально, панель появится в момент печати намёка — это автозапуск, Non-Goal.

### Q2 — Optimality

- **Выбранный путь:** расширить скилл карты (контракт узлов+связей+слоёв, создание с нуля), вынести макет в отдельную роль с `model: inherit`, предлагать схему вариантом внутри уже существующих строк решения по форме связей.
- **Альтернативы (включая не упомянутые в `## Implementation Options`):**
  1. **Макет заполняет оркестратор по фиксированному шаблону панели, без отдельной роли.** Реализация: один `.canvas.tsx`-каркас в скилле, подстановка `nodes`/`edges`. Плюсы: нет нового агента, воспроизводимее, нет параметра модели. Минусы: нет выбора вида схемы (уровни / ветки / цепочка) под топологию; контекст прохода разбора смешивается с вёрсткой; D8 как раз изолирует макет. Хуже выбранного для Why (причинность «взглядом»). Не отменяет закрытую ось просьбы.
  2. **Скилл кита отдаёт только модель графа; рисует глобальный скилл Canvas.** Реализация: kit собирает JSON, запись файла — по `~/.cursor/skills-cursor/canvas/SKILL.md`. Плюсы: не плодить роль. Минусы, verified: глобальный скилл **обязан** рисовать аналитический артефакт как панель (триггер «user intent / standalone analytical output»), а kit D5 / spec Silence **запрещают** считать системное требование канваса основанием. Смешение двух триггеров снова даёт самопроизвольную панель — это провал молчания, не экономия. Хуже выбранного.
  3. **Схема в чате (Mermaid / ASCII), панель не создавать.** Реализация: граф в пузыре сообщения, без `.canvas.tsx`. Плюсы: нет каталога среды, нет резерва, нет роли. Минусы: Why и AC2 требуют панель рядом с чатом со подписанными связями, не список в чате; два имени (карта точек vs карта сценария) снова сливаются; ADR-0001 — в чат только тонкие продуктовые формулировки, не чертёж. Не решает Why.
- **Вердикт по Q2:** выбранный путь оптимален среди жизнеспособных. Ни одна неупомянутая альтернатива не бьёт Why с меньшим ущербом для молчания, эксклюзивного слота и контракта панели. Закрытую ось `direct_request_linear_publish` не переоткрываю: линейная цепочка с подписями на рёбрах согласована с «список без связей — не карта».

### Q3 — Fresh-Eye Approval

- **Согласовал бы (или нет):** с оговорками.
- **Причины:**
  - Да: три провала Why атакуются точечно (предикат доступности, замеры, слот исследования), без новой команды и без подмены карты точек панелью; ADR-0001/0002/0006 не отменяются.
  - Нет, пока не снято противоречие Offer (≥4 после отсевов) vs «сразу карту» до доказательств карточек.
  - Нет, пока прямая просьба в сессии исследования с постановкой (без «Дальше») может получить отказ «нет указанного отчёта» — это воспроизводит провал «просьба не даёт схему».
  - Нет, пока «намёк» в D5/Silence можно прочитать как основание *собрать* панель, а не *предложить* вариант в строке.

## Verdict

**CHALLENGE** — ось верная и имплементируема, ремонт закрыл заявленные дыры в тексте, но четыре стыка ещё позволяют собрать панель не из того источника, предложить то, что нельзя опубликовать, или нарисовать без согласия.

HARD: развилок «apply сейчас / отложить / принять риск» нет. Закрытую ось просьбы не переоткрываю (`reopen-blocked: direct_request_linear_publish` не применялся — нет verified-факта, что линейная публикация по просьбе ломает контракт панели: текущий скилл как раз рисует столбик узлов без рёбер, и D3 это меняет).

## Gaps for design.md

Уточнения инварианта реализации (ось «просьба сильнее предложения» не меняется):

1. **Просьба в активном исследовании — неявный источник.** В D7 и spec «Map outside walkthrough» явно: прямая просьба (не согласие) в сессии `/opsx:explore`, пока есть текущий отчёт исследования, берёт этот отчёт как источник; отказ «укажите отчёт» — только если сессии исследования нет и журнала разбора нет. Иначе финал с постановкой (нет «Дальше») снова глотает просьбу. Proposal AC2 / Why (3). Не отменяет исключение для согласия.

2. **Два источника: проверка топологии vs публикация узлов.** Для отложенного «сразу карту»: проверка топологии может идти по списку имён / отчёту, из которого список собран; публикация — только из накопленных карточек прохода (и/или якорей отчёта, если они уже есть), после обоих отсевов. Behavior 13 сейчас говорит «из источника проверки топологии» — для отложенного согласия это имена без доказательства. Согласовать D1 п.2, Behavior 13, spec Direct request («источник при согласии») и spec Node contract.

3. **Предикат предложения на строке подтверждения списка.** Либо (а) Offer MAY на этой строке при *предсказанной* топологии списка, без требования ≥4 публикуемых *сейчас*, публикация откладывается (как уже сказано в сценарии фокуса); либо (б) на этой строке предлагать только если якоря отчёта исследования уже дают ≥4 публикуемых после обоих отсевов. Сейчас MUST Offer и D1 п.2 несовместимы. Выбрать одно предложение в D1 и в spec Offer; не оставлять оба MUST.

4. **Намёк печатает, не рисует.** D5 пункт (3), Goal 2, Behavior 1 и spec Silence: «сработавший намёк» = вариант уже напечатан в существующей строке; сборка панели — только прямая просьба или принятое предложение. Согласовать с proposal AC1. Текущие `gate-dispatcher.mdc` и Entry Protocol скилла копируют двусмысленность «рисовать по намёку» — design должен снять её одной фразой, иначе диспетчер снова станет автозапуском.

5. **Сценарий spec на отложенную публикацию.** Есть WHEN согласие до порога THEN фокус, панели нет. Нет WHEN позже набралось ≥4 связанных доказанных THEN панель публикуется без повторного вопроса. Добавить в Direct request (или рядом с «Согласие до первой карточки»), иначе приёмка третьего среза не отличает «запомнили и забыли» от «запомнили и нарисовали».

Косметика, не блокер оси: заголовок требования «Causal map has layers or branches» после линейного исключения вводит в заблуждение; тело уже верное.
