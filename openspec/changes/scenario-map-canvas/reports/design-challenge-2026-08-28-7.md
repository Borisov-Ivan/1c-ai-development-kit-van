## Three-Question Challenge

### Q1 — Problem-Solution Fit

- **Why говорит:** «Панель рядом с чатом должна показывать **причинность и слои** механизма — что питает что, где оригинал и производная копия… Столбик шагов и навигатор по модулю этого не дают» (`proposal.md` §Why). Провал №3: «уходит в плоский текст или в строку, по которой панель не открывается, потому что файл „собрали“, а схема рядом с чатом не появилась».
- **Design адресует:** D7/D10 — предикат «уже открыта / назван файл» снят, файл записывает **родитель** собственной записью, гейт — чистая проверка панели; D8 — картограф отдаёт манифест и файл не пишет; D3 — контракт `header`+`nodes`+`edges`+`views`, `follows` не выдаётся за причинность, у связи обязателен `evidence_ref`.
- **Покрытие: частичное.** Половина Why про «не открывается» закрыта и подтверждена контрактом носителя (см. Q2, «Подтверждения»). Половина Why про «причинность и слои» **на выходе канала теряется** — по двум проверенным причинам.

**G1. Шаблон файла публикует ровно тот вид, который ЗНИ запрещает.**

D10: «Шаблон файла — fixture скилла; родитель заполняет его **механически** и регистрирует файл». Что фактически публикует `fixtures/canvas-shell.md`:

- главный вид — одна колонка одинаковых `Card`, по карточке на узел (`canvas-shell.md:93-114`). Это дословно запрет самого скилла: «стена одинаковых карточек» (`SKILL.md:157`) и slop-запрет носителя «Wall of identical cards» (`~/.cursor/skills-cursor/canvas/SKILL.md:87`);
- связи — плоский текстовый список ниже узлов, притом через машинные `id`: `{edge.from} → {edge.to}` (`canvas-shell.md:116-123`). Рёбра формально есть, но как **текст под списком**, а не как расположение и стрелки. «Вывод, который видно из расположения и стрелок» (`SKILL.md:65`, шапка `insight`) из такой раскладки не считывается;
- кнопка «Слои» пишет `view` в `useCanvasState`, но рендер это состояние **не потребляет** — только печатает `Вид: {view}` строкой (`canvas-shell.md:89-92`). Значит MUST spec «раскладка MUST показать либо не меньше двух уровней, либо ветвление со схождением» (`spec.md:149`) через этот шаблон **структурно недостижим**: переключатель мёртвый, группировки по `layer` в разметке нет;
- `computeDAGLayout` упомянут одной фразой MAY **вне** кода (`canvas-shell.md:132`) и в самом шаблоне не используется.

Это не ограничение среды. Проверено: `computeDAGLayout` экспортируется (`sdk/index.d.ts:25`) и возвращает `nodes[].x/.y`, `edges[].sourceX/sourceY/targetX/targetY`, `isBackEdge` и `ranks[]` — «bounding box per rank — useful for drawing layer bands» (`sdk/dag-layout.d.ts:52-101`). Слои и петли рисуемы штатным API; шаблон от него отказался.

**Бизнес-эффект:** первая живая карта, выданная этим каналом, будет вертикальным списком карточек с текстовой сводкой стрелок — то есть «столбиком шагов» из §Why, только под новым именем. Приёмка S2 («схема… со подписанными связями, уровни или ветки — если они есть») на таком шаблоне не проходит, а приёмка сформулирована как сверка текста скилла, где запрет списка есть **словами** — расхождение слов и шаблона не ловится.

**G2. `follows` против «главного причинного вывода» — противоречие внутри дельты.**

- `spec.md:147` (Requirement «Causal map has layers or branches»): карта «MUST отвечать на центральный вопрос в шапке и показывать **главный причинный вывод**».
- `spec.md:118` + D3(a): у цепочки по прямой просьбе рёбра MUST быть `follows` и MUST NOT носить причинный ярлык.

Для случая `direct_request_linear_publish` (закрытое решение, соблюдается) причинных рёбер в наборе **ноль по построению**. Откуда тогда «главный причинный вывод»? Ни design, ни spec не отвечают. Остаётся `header.insight` — и он ничем не ограничен: запрет причинных ярлыков действует на `label` рёбер, но не на текст шапки. Инвариант «порядок прохода не выдаётся за причинность» держится на уровне рёбер и **свободно обходится в шапке** одной фразой вида «видно, что A вызывает B». Это ровно тот риск, против которого дельта и вводила `follows`.

### Q2 — Optimality

- **Выбранный путь:** родитель резолвит каталог панелей, картограф возвращает манифест данных, родитель механически заполняет fixture и сам пишет один `.canvas.tsx`, гейт — чистая проверка панели, в чат одна строка без пути и без ссылки, успех — штатная кнопка среды.

**Подтверждения (то, что атака не смогла опрокинуть).** Ось «регистрирует родитель» независимо подтверждается контрактом носителя, а не только разовым опытом 2026-08-28, на который ссылается D10:

1. «For a new canvas, **always use the write file tool** to create the `.canvas.tsx` file at that exact path; **do not stop after telling the user the path** or showing code in chat» (`~/.cursor/skills-cursor/canvas/SKILL.md:50`) — прямо против «сообщить путь вместо записи»; снятый предикат «пользователь уже открыл панель / назвал файл» согласован с носителем.
2. «Treat that managed `canvases/` directory as pre-provisioned… do **not** spend turns creating the directory with `mkdir`» (там же) — совпадает с D7 «каталог не создавать вручную; путь не угадывать».
3. «Every canvas edit returns a `Canvas TypeScript check` line in the tool result… treat that as the **authoritative diagnostics signal**» (`SKILL.md:112` носителя) — «чистая строка проверки панели» это реальный сигнал среды, а не самодельная церемония. И он доступен **только тому, кто пишет файл**: если бы писал картограф, гейт неизбежно опёрся бы на самооценку субагента, что D8 запрещает. Значит «картограф файл не пишет» держится и без опыта n=1.
4. API дельты не фантомные: `openFile` — «Open an existing workspace file… Optional `selection` follows VS Code editor line/column fields» (`sdk/hooks.d.ts:126-129`), форма `dispatch` в fixture совпадает; `useCanvasState`, `useHostTheme`, `Pill size`, `CardHeader trailing`, `Text tone` — все экспортируются (`sdk/index.d.ts:38,54-56`, `sdk/ui-primitives.d.ts:167-170,386,456-468`). Запрет `newComposerChat` осмыслен: действие существует и «opens a new local agent chat with the dispatching canvas file as an @mention» (`sdk/hooks.d.ts:120-124`), то есть увело бы пользователя из команды сессии — запрет согласован с Persistence.

- **Альтернативы (включая не упомянутые в `## Implementation Options`):**

  1. **Shell как настоящий граф (`computeDAGLayout` + inline SVG)** — не упомянута. Родитель по-прежнему регистрирует файл; меняется только тело fixture: позиции узлов и координаты рёбер из `computeDAGLayout`, полосы уровней из `ranks[]`, обратные рёбра стилем по `isBackEdge`. **Превосходит выбранный путь** по Why: MUST раскладки из `spec.md:149` становится исполнимым, запрет списка — структурным, а не текстовым. Минус: fixture крупнее, автору нужен SVG-рендер.
  2. **Манифест-как-данные при фиксированном рендерере** — не упомянута. Родитель вписывает в шаблон **только** один блок `MANIFEST` (шапка/узлы/связи/виды), вся раскладка живёт в неизменяемом теле шаблона, группировка по `layer` и переключение видов уже реализованы. Плюс: «заполняет механически» становится буквальной правдой, деградация в список невозможна в принципе, шаблон нельзя «немного подправить под эту карту». Минус: меньше свободы под конкретный сюжет — впрочем, текущая однотипная колонка карточек и так провалит требование носителя о визуальной иерархии и вариативности (`SKILL.md:74-97` носителя).
  3. **Критерий и способ открытия разведены** — не упомянута. Критерий успеха остаётся чистая проверка панели (пункт 3 выше); печать пути становится **аварийным** каналом по факту «панели не вижу», а не рутиной. Плюс: закрывает G3, не возвращая ссылку в критерий. Минус: одна дополнительная ветка в скилле.
  4. **Картограф пишет файл, родитель трогает одну строку** — упомянута в D10 и отклонена. Атака подтверждает отклонение: гейт «Canvas TypeScript check» получает только пишущий агент (пункт 3), иначе публикация опирается на самооценку субагента. Отклонение обосновано **сильнее**, чем в тексте design.
  5. **Открытие доказательства через `newComposerChat` вместо `openFile`** — рассмотрена и отклонена: действие открывает новый чат с канвасом как @mention (`sdk/hooks.d.ts:120-124`), то есть рвёт команду сессии. Запрет в D10 и `SKILL.md:231` корректен.

- **Вердикт по Q2:** ось канала (кто пишет, кто отдаёт манифест, что считается успехом) **оптимальна и теперь подтверждена контрактом носителя**. Реализация канала **не оптимальна**: альтернатива 1 или 2 строго лучше текущего fixture по главной цели ЗНИ, альтернатива 3 закрывает невосстановимый отказ.

### Q3 — Fresh-Eye Approval

- **Согласовал бы:** с оговорками — нет, не в текущем виде.
- **Причины:**
  - Ось решения читается убедительно без истории сессии: «файл пишет тот, кто получает авторитетный сигнал проверки» — самодостаточный аргумент, и он совпал с контрактом среды при независимой проверке.
  - Но единственный артефакт, который реально доходит до пользователя (`canvas-shell.md`), противоречит и собственному скиллу (`SKILL.md:157`), и spec (`spec.md:149`), и slop-правилам носителя. Дельта закрыла «панель не открывается» и не закрыла «панель — это список».
  - Критерий успеха сформулирован через affordance, которого нет в контракте носителя (см. G3), при одновременном полном запрете печатать путь. Свежий взгляд читает это как утверждение о среде, которое агент не может ни проверить, ни исправить.

## Verdict

**CHALLENGE** — ось канала публикации верна и независимо подтверждена контрактом носителя, но шаблон панели структурно не может выдать «причинность и слои», а критерий успеха не имеет пути восстановления; всё это закрывается уточнениями design без смены закрытых решений.

## Gaps for design.md

Все пункты — `implementation_invariant`: закрытые решения `direct_request_linear_publish`, `edges_evidenced_or_investigate`, `parent_side_registration` остаются в силе и не переоткрываются.

1. **G1 — шаблон обязан рисовать граф, а не колонку карточек.** В D10 (или D3) закрепить: главный вид fixture MUST опираться на раскладку носителя (ранги/уровни) либо на группировку узлов по `layer`; переключатель видов MUST влиять на разметку, а не только на текст «Вид:». Правки — `fixtures/canvas-shell.md` (`:89-123`). Формулировка приёмки S2 должна проверять **шаблон**, а не только словесный запрет в скилле.
2. **G2 — граница `follows` распространяется на шапку.** Добавить в D3 инвариант: при наборе только из `follows` `header.insight` MUST называть вывод, видимый из **расположения** (уровни, схождение, повторное использование), и MUST NOT формулировать причинное утверждение о переходах. Симметрично — одна фраза в `spec.md` Requirement «Causal map has layers or branches», иначе MUST «показать главный причинный вывод» и запрет причинных ярлыков противоречат друг другу на линейном наборе.
3. **G3 — путь восстановления, когда проверка чистая, а панели пользователь не видит.** Контракт носителя знает два способа открыть канвас: «open it beside the chat» и «Users can click the canvas file path in the response to open it» (`SKILL.md:112` носителя); «штатной кнопки» в контракте нет — это наблюдение 2026-08-28. Нужен четвёртый допустимый повод (или отдельная ветка): по явному сообщению «панели не вижу» разрешить **одну** строку с путём либо перейти в текстовый резерв. Без этого файл вне рабочей области, вне git, путь не печатался никогда — маршрута к результату у пользователя не остаётся. «Ссылка не критерий» при этом сохраняется.
4. **G4 — стык D8 → D10 теряет контрактные поля.** `HEADER` в fixture не содержит `sources`, хотя шапка требует его (`SKILL.md:66`, эталон `map-good-causal.md:11-13`); тип `MapNode` не содержит `state` (контракт — «если есть жизненный цикл», `SKILL.md:79`); `views[].focus` из манифеста в шаблоне не представлен — виды захардкожены двумя кнопками. Либо расширить fixture до полного манифеста, либо явно записать в D10, какие поля манифеста в файл не переносятся и почему.
5. **G5 — `check-failed` у картографа неопределён.** Агент отдаёт `check-failed` = «манифест не прошёл self-check скилла» (`onec-scenario-map-designer.md:46`), но пункты self-check 7–8 (`SKILL.md:243-245`) — про запись файла родителем и про чат, и картограф их проверить не может. Разделить self-check на manifest-side (1–6) и parent-side (7–8).

## Architectural alternatives

Одна реальная развилка по коду — как именно шаблон перестаёт быть списком (G1). Обе ветки сохраняют `parent_side_registration`.

### Как fixture показывает уровни и связи

**A. Граф координатами носителя:** тело `canvas-shell.md` вызывает `computeDAGLayout` и рисует узлы и стрелки по `x/y`, `sourceX/Y`, `targetX/Y`, полосы уровней по `ranks[]`, обратные рёбра по `isBackEdge` (все поля подтверждены в `sdk/dag-layout.d.ts:52-101`). Trade-off: точное соответствие MUST раскладки и петлям ценой SVG-рендера в шаблоне, который родитель заполняет вслепую.

**B. Группировка по `layer` без SVG:** узлы остаются `Card`, но раскладываются `Grid`/`Row` по значению `layer` (два и более видимых уровня), а каждое ребро печатается на карточке источника и приёмника через `name`, не `id`; переключатель видов меняет группировку (`layer` ↔ порядок цепочки). Trade-off: слои и цепочка видны, ветвление со схождением читается хуже, чем на графе, зато шаблон остаётся механически заполняемым и без ручного рендера.
