# Срез S1: Техпроект по файлу задания

**Сценарий:** Сначала согласование часов, после подтверждения в листе — техпроект таблицами и текст постановки для задачи на разработку.
**Primary acceptance:** Открыть `<имя>-вопросы.md` и `<имя>-согласование.md` — лист содержит вопросы с не меньше чем двумя вариантами и местом для ответа или фразу «вопросов нет», и в обоих случаях строку подтверждения; в согласовании сюжет обзора и часы, нет таблицы нормативов.
**Приёмка:** Прогнать `/opsx:techproject` на одном файле задания и открыть лист и согласование.
**Связь со spec:** Requirement «Техпроект по файлу задания» — Scenario «Согласование часов», Scenario «Техпроект для технического задания», Scenario «Постановка для задачи на разработку», Scenario «В задании нет дыр», Scenario «Повторный запуск с ответами», Scenario «Часы собраны из прозы задания», Scenario «Несколько факторов надбавки», Scenario «Нет подходящей строки справочника», Scenario «Папка шаблонов не меняет запуск», Scenario «В конфигурации нет названного объекта»; Requirement «Обзор задачи не меняется» — Scenario «Обзор остаётся компилятором готовой задачи».
**Зависимости:** нет.

- [x] S1.2 В `.cursor/skills/openspec-techproject/SKILL.md` поправить Entry Protocol: первый вывод рядом `<имя>-вопросы.md` и `<имя>-согласование.md`; `<имя>-техпроект.md` и `<имя>-постановка.md` только когда в листе заполнена строка подтверждения и команду запускают снова; строка подтверждения считается заполненной, когда в ней есть непустая пометка, пустая строка второй вывод не открывает; дыры и связь с прошлыми изменениями берутся протоколом исследования, тем же, что перед созданием задачи на разработку, а не отдельным чеклистом; повторный запуск читает ответы из того же листа и обновляет те же пути; чат не источник ответов и не ждёт подтверждения до записи согласования (D1, D4, D5)

## 4. Приёмка

- [x] S1.accept Принять срез S1 «Техпроект по файлу задания» — по файлу задания есть согласование часов, которое можно отдать, и после подтверждения в листе техпроект и постановка:
  - **Primary (обязательно):** открыть `<имя>-вопросы.md` и `<имя>-согласование.md` — лист содержит вопросы с не меньше чем двумя вариантами и местом для ответа или фразу «вопросов нет», и в обоих случаях строку подтверждения; в согласовании сюжет обзора и часы, нет таблицы нормативов; файлов техпроекта и постановки ещё нет
  - Scenario «Техпроект для технического задания» (опционально): при подтверждении согласования в листе и повторном запуске есть `<имя>-техпроект.md` таблицами, без текста процедур; входящий файл задания не заменён; каталог задачи на разработку не создан
  - Scenario «Постановка для задачи на разработку» (опционально): при том же подтверждении есть `<имя>-постановка.md` блоком «Постановка ЗНИ»; он не заменяет техпроект
  - Scenario «В задании нет дыр» (опционально): на задании без критичных пробелов лист состоит из фразы «вопросов нет» и строки подтверждения, в согласовании и техпроекте нет выдуманных объектов и проводок
  - Scenario «Повторный запуск с ответами» (опционально): ответы вписаны в тот же лист; повторный запуск обновляет те же файлы, новые копии не появляются; уже заполненные строки часов не затёрты
  - Scenario «Часы собраны из прозы задания» (опционально): без готовых строк часов и при одной строке справочника часы = (нижняя граница × коэффициент) + сумма нижних границ названных факторов, дробный результат поднят до следующего целого часа; таблицы нормативов нет
  - Scenario «Несколько факторов надбавки» (опционально): два названных фактора дают сумму их нижних границ, без умножения каждого на коэффициент
  - Scenario «Нет подходящей строки справочника» (опционально): если строка не нашлась, в листе вопрос, часы по этой работе не выдуманы и не проставлены, пока нет ответа
  - Scenario «Папка шаблонов не меняет запуск» (опционально): правка только `template/Техпроект` не меняет часы и состав дыр следующего запуска
  - Scenario «В конфигурации нет названного объекта» (опционально): для имени, которого нет в конфигурации, в листе есть дыра, в техпроекте нет выдуманного реквизита или проводки
  - Scenario «Обзор остаётся компилятором готовой задачи» (опционально): файлы `.cursor/skills/openspec-overview/**` без изменений; обзор по-прежнему только из готовой задачи и без часов
