## Gaps (обязательные правки design.md)

### G1. Контракт двух результатов (анти-разъезд)

В `## Decisions` (после D1) или в `## Behavior Contract` зафиксировать:

- **Топология:** один выходной md (лист вопросов + техпроект секциями) **или** два файла в одном каталоге запуска с явными именами; чат не является носителем листа вопросов (иначе возвращается Why).
- **Связка:** дыры в техпроекте ссылаются на те же пункты листа (и наоборот); нет «вопроса только в чате».
- **Повторный запуск с ответами:** обновляются **оба** результата (или единый файл); новый ритуал не начинается.
- Если дыр нет: лист явно «дыр нет» / секция отсутствует по правилу — но команда всё равно одна и техпроект полный.

### G2. Обзор не трогать

В `## Existing Mechanisms` / Non-Goals / Decisions:

- Файлы `.cursor/skills/openspec-overview/**` не изменяются этой ЗНИ.
- Голос и каркас сюжета **копируются/адаптируются** в шаблоны навыка техпроекта; зависимость «читать customer-overview.md на каждый запуск» допустима только read-only, без правок эталона.
- Секции сюжета для заказчика = правила обзора; инвентарь модулей / часы / нормативы в сюжет не попадают.

### G3. HALT нормативов в любом выходе

Усилить D3 / Behavior Contract:

- Справочник `labor_standards` (и формулы/коэффициенты) — только внутри навыка.
- В выходном md запрещены: таблицы нормативов, ссылки на строки справочника, «по нормативу N», сырые коэффициенты.
- В сюжете для людей — без часов; часы только в приложении, строками задания + текстовое обоснование сложности.

### G4. Карта проводок условно

В D2: «карта проводок — **только если** в задании есть проводки/счета; иначе секция не создаётся и не додумывается».

### G5. Лист вопросов в Primary acceptance

В таблице Slices / Acceptance Checklist: появление листа (или явной пометки «дыр нет») — часть Primary/S1.accept, не только Optional. Иначе «два результата» формально необязательны.

### G6. [УТОЧНИТЬ] vs лист

Явно: контекстные `[УТОЧНИТЬ]` из старого техшаблона **не** заменяют лист вопросов; в сюжете для заказчика дыры либо помечены коротко со ссылкой на пункт листа, либо только в приложении — без возврата к вопросам по одному в чат.
