## Context

Фикстура исходного состояния Primary S1. Постановка не менялась после снимка проверки. После снимка в `reports/` лежит отдельный отчёт, опровергающий предпосылку одного закрытого решения.

## Goals / Non-Goals

**Goals:**

1. Дать проверке два закрытых решения с `premise` и одно опровержение из отдельного отчёта.

**Non-Goals:**

1. Не реализовывать поведение в конфигурации 1С.

## Behavior Contract

1. Доказательством выбора не считается строка, где значение только используется.
2. Итог проверки бывает только GO или NO-GO.

## Decisions

Два закрытых решения записаны в `debug.md`. Одно связано с закрытой записью `EC-1`; тема `EC-1` уже один раз переоткрывалась.

## Slices

### Срез S1: Предпосылка выбора

**Сценарий:** заказчик выбирает вариант по утверждению о шаблоне карточки.
**Primary acceptance:** утверждение о месте доказательства сверено с шаблоном.
**Связь со spec:** Requirement «Место доказательства» — Scenario «Выбор опирается на место возникновения».
**Зависимости:** нет.

## Решения verify (зафиксировано)

- Выбор «строка использования достаточна» принят на утверждении, что соседняя строка шаблона доказывает выбор (`usage_line_is_enough`, `EC-1`). Предпосылка: «Соседняя строка шаблона, где значение только используется, достаточна как доказательство выбора» — `.cursor/docs/templates/decision-block.md:110`. После опровержения заказчик ответил «подтверждаю»; предпосылка та же, запись опровержения не переписана.
- Итог проверки остаётся двоичным (`verdict_is_binary`). Предпосылка: «Итог проверки бывает только GO или NO-GO» — `.cursor/skills/openspec-verify-change/templates/report-header.md:77`.
