## Резюме для разработчика

techproject-after-answers — до старта нужен ваш выбор по логике файла постановки и повторного подтверждения часов.

Лист по-прежнему уходит аналитику без вопросов про часы, рядом с ним называется предварительная оценка, уточнённая цифра появляется в техническом проекте. Не закрыто, что делать с файлом постановки, если задача на разработку уже есть, и ждать ли нового согласия, если уточнённые часы больше уже подтверждённых.

**Что решить: ответы на пакет вопросов**

1. **Если команда запущена по уже существующей задаче на разработку, а не по файлу задания, писать ли ещё один файл постановки?**
   - **A. Не писать второй файл постановки** — появятся лист, согласование часов и технический проект, текст задачи останется прежним. Свежего блока «что менять» из этого запуска не будет.
   - **B. Писать файл постановки** — разработчик получит свежий блок «что менять». Рядом с уже существующей задачей ляжет второй такой документ.
2. **Если после ответов в листе уточнённые часы больше уже подтверждённых, ждать ли нового подтверждения?**
   - **A. Писать технический проект сразу** — в нём видны подтверждённая цифра, новая цифра и ответ из листа, который изменил объём. Большая цифра уходит в проект без второго согласия.
   - **B. Не писать технический проект, пока новую цифру не подтвердят** — обе суммы согласованы. Запуск с пометкой придётся повторить.

## Решения до apply

### 1. Файл постановки для уже существующей задачи

**В чём проблема.** Команда умеет принять на вход уже существующую задачу вместо файла задания, но не сказано, писать ли после пометки в листе ещё один файл постановки.

**На что влияет.** Либо разработчик не получит свежий блок «что менять» из этого запуска, либо рядом с уже существующей задачей появится второй такой документ.

**Если выбрать A / B.** A — лист, согласование и технический проект есть, файл постановки не создаётся. B — файл постановки создаётся, документов два.

**Что в тексте сейчас.** Решение 10 в `design.md` говорит: текст задачи читается как задание, дальше та же цепочка. Раздел постановки навыка пишет файл `<имя>-постановка.md` блоком для создания задачи на разработку. Имя и каталог выходных файлов для входа «уже существующая задача» не заданы.

**Что предлагает план.** Та же цепочка, что для файла задания: лист, предварительная оценка, после пометки технический проект.

**Почему это развилка.** Для файла задания второй документ уместен: задачи на разработку ещё нет. Для уже существующей задачи тот же шаг либо дублирует постановку, либо её не пишет. Это наблюдаемый результат, его нельзя выбрать за заказчика.

**Варианты решения.**

- **A. Не писать второй файл постановки** — после пометки появляются лист, согласование и технический проект; постановка задачи не перезаписывается. Для разработчика: править навык так, чтобы шаг постановки пропускался, если задача уже есть. Для пользователя: свежего блока «что менять» из этого запуска нет.
- **B. Писать файл постановки** — после пометки появляется и `<имя>-постановка.md`. Для разработчика: нужно имя и каталог, которые не затирают файлы задачи. Для пользователя: два документа постановки рядом.

**Что изменится после выбора.** В решении 10 и в сценарии «ЗНИ как задание» будет записано, пишется ли файл постановки. Какие файлы задачи читать как задание и куда класть лист, дописывается вместе с ответом.

**Источники** *(техническое):* G1 в `reports/design-challenge-2026-09-24.md`.

### 2. Повторное подтверждение, если уточнённые часы больше

**В чём проблема.** Строка в листе подтверждает предварительную оценку. Уточнённая цифра появляется вместе с техническим проектом и может быть больше, а второго согласия план не требует и не запрещает.

**На что влияет.** Либо в проект уходит большая цифра без нового подтверждения, либо запуск с уже стоящей пометкой не создаёт проект, пока аналитик не подтвердит новую сумму.

**Если выбрать A / B.** A — проект пишется сразу, обе цифры и причина расхождения видны в нём. B — проект ждёт нового подтверждения.

**Что в тексте сейчас.** Решение 7: уточнённая оценка пишется в техническом проекте. Решение 4: если ответ меняет состав работ, пересчёт попадает в проект, предварительная цифра в согласовании не подменяется. Не сказано, останавливать ли запись проекта, когда новая цифра больше подтверждённой.

**Что предлагает план.** Предварительная цифра живёт в согласовании до появления проекта. Уточнённая живёт в проекте.

**Почему это развилка.** Оба пути сохраняют предварительную цифру. Они расходятся в том, можно ли отдать разработчику проект с большей суммой без новой пометки.

**Варианты решения.**

- **A. Писать технический проект сразу** — в проекте и в чате названы подтверждённая цифра, новая цифра и ответ из листа, который изменил объём. Для разработчика: согласование в этом запуске не пересчитывается. Для пользователя: большая цифра уходит в проект без второго согласия.
- **B. Ждать нового подтверждения** — если уточнённая цифра больше, проект не пишется, пометка считается недействительной для этой суммы. Для разработчика: порог пометки срабатывает ещё раз. Для пользователя: обе суммы согласованы, запуск повторяется.

**Что изменится после выбора.** В решениях 4 и 7 будет записано, пишется ли проект при большей уточнённой цифре. Остальное по этой теме дописывается вместе с ответом: в запуске с пометкой часы согласования остаются предварительными; чтение источника, из которого взята цифра, пишется и в согласование.

**Источники** *(техническое):* G2 в `reports/design-challenge-2026-09-24.md`.

### Рекомендации

Эти пункты не требуют выбора. Их допишут в постановку после ответов на два вопроса выше.

- Незакрытая задача `tz-tech-project` всё ещё требует вопрос о строке справочника в листе и техпроект таблицами. В `proposal.md` и в графе зависимостей `design.md` нужно прямо сказать: эта задача заменяет эти четыре места в навыке, а в основной каталог оба требования как есть не попадают.

- В задачах назвать места навыка и текста команды, где ещё написано старое правило: чат не источник ответов вообще, вопрос о часах остаётся в листе, описание команды говорит «таблицами».
- В спецификацию добавить сценарии «нет подходящей строки справочника» и «часы из чата не пересчитываются без пометки». Для пустой строки: сначала пишутся лист и согласование, затем вопрос в чате; новый чат без ответа задаёт тот же вопрос снова; запуск с пометкой при пустой строке пишет эту работу в проект без часов.
- Сценарий «Техпроект после пометки» проверяет пустую пометку. Переименовать, чтобы имя совпало с проверкой.
- Пробел, найденный уже при записи проекта: раздел пишется с фразой «в задании не указано», новый вопрос добавляется в лист, пометка не сбрасывается.
- В текст «зачем» добавить одну фразу, почему разработчику не хватает коротких таблиц и зачем вход из уже существующей задачи. В критерий приёмки добавить разделы технического проекта.
- В решении о разделах проекта одной строкой указать, куда попадают отчёты, печатные формы и права. Папки `template/Техпроект` в репозитории нет; список разделов берётся из задач, не из этой папки.
