## Why

Лист вопросов по заданию уходит аналитику, а в него попадают нюансы, которые не меняют объём работы, вопросы про часы и технические вопросы, которые не про смысл задания. Из-за этого оценка либо пустая, либо ждёт ответов, без которых цифру уже можно назвать. С листом вопросов отдаётся предварительная оценка. Уточнённая оценка появляется в техническом проекте по результатам ответов. Проект нужен, чтобы разработчик работал по этой цифре без повторных вопросов. Коротких таблиц не хватает: в них нет места для алгоритма, интеграций, внедрения и отката. Чего нет в задании, проект показывает прямо, а не додумывает. Если на входе уже существующая задача, её текст не оформляют заново как сырое задание, и файл постановки для неё не пишется.

## What Changes

- Лист вопросов содержит только вопросы по существу задачи и рассчитан на аналитика. Вопросов про часы, вид работы и демонстрацию в листе нет.
- Уточнение часов идёт в чате. Чат не заменяет лист: ответы по существу задачи по-прежнему вписываются в лист. Часы, названные в чате, в том же ходе попадают в согласование и остаются предварительными.
- Предварительная оценка даётся вместе с листом вопросов. Нюанс, который не меняет объём (имя отчёта, с каким существующим отчётом сверять, какое поле считать группой), эту оценку не задерживает.
- Уточнённая оценка пишется в техническом проекте по результатам ответов. Пока технического проекта нет, оценка остаётся предварительной. Если ответы не изменили объём, уточнённая цифра совпадает с предварительной. Если расходится с подтверждённой, проект всё равно пишется: в нём видны обе цифры и ответ из листа, который изменил объём. Второго подтверждения нет. Расчёт по строкам справочника при этом сравнении не показывается.
- Формула часов, перенос уже указанных в задании часов и запрет показывать таблицу нормативов сохраняются. Часы из самого задания переносятся как есть и в технический проект.
- По файлу задания техпроект и постановка появляются только после непустой пометки в листе и повторного запуска. Для уже существующей задачи файл постановки не пишется. Путь к её каталогу или к файлу в нём читается так же, не как сырое задание. Связь с уже сделанными изменениями для этого входа не ищется.
- Техпроект для разработчика собирается разделами: объекты, алгоритм, интеграции, внедрение, откат, часы. Отчёты, печатные формы и права входят в раздел объектов. Пробел по существу остаётся вопросом в листе, а не догадкой в техпроекте. Если пробел виден только при записи проекта, раздел пишется фразой «в задании не указано», вопрос добавляется в лист, пометка не сбрасывается. Это правило не касается внедрения и отката. Если их нет в источнике, раздел пишется фразой «в задании не указано», вопрос в лист не добавляется, пометка не сбрасывается. Для уже существующей задачи источник включает её решения: если внедрение или откат сказано в решении, раздел ссылается на номер. По списку объектов эти разделы не заполняются.
- Задача на входе необязательна. Она указывается именем так же, как в обзоре задачи, в том числе из архива. Как задание читается её текст «зачем» и «что меняется». Её решения закрывают пробел: если ответ уже есть в решении, вопрос в лист не пишется, а раздел проекта заполняется со ссылкой на номер решения. Выходы лежат в корне её каталога под именем каталога. Файла постановки нет.

## Capabilities

### New Capabilities

- `techproject-after-answers`: состав листа для аналитика, предварительная и уточнённая оценка, необязательный вход из уже существующей задачи без файла постановки, техпроект для разработчика после пометки в листе

### Modified Capabilities

- Нет требований в основном каталоге, которые меняются этой задачей. Поведение команды из незакрытой задачи по техпроекту здесь заменяется в четырёх местах: вопрос о выборе из двух строк справочника и вопрос о работе без подходящей строки уходят из листа в чат; запрет «чат не источник ответов» остаётся только для ответов по существу задачи; короткие таблицы техпроекта заменяются разделами для разработчика. В основной каталог оба требования как два добавленных не попадают. Первой архивируется `tz-tech-project`. Эта задача архивируется второй и при архивации оформляет замену как изменение требования «Техпроект по файлу задания». Формула часов, порог пометки, формат вопроса в листе и запрет читать `template/Техпроект` при запуске сохраняются.

## Impact

Меняются текст команды техпроекта и её навык. Обзор задачи не меняется. Формула часов и порог появления технического проекта сохраняются. Незакрытая задача по той же команде описывает прежнее правило «две строки справочника — вопрос в листе»; эта задача его заменяет для листа аналитика. Приёмка той задачи идёт на текущем навыке до исполнения этой.

## Acceptance Criteria

На задании с открытыми вопросами по существу, включая имя отчёта, в листе нет вопросов про часы, а рядом с листом есть предварительная оценка. Технического проекта на этом шаге нет. Когда по результатам ответов и пометки в листе появляется технический проект, в нём есть разделы для разработчика и стоит уточнённая оценка. Если ответ из листа изменил объём, в проекте видны подтверждённая цифра, уточнённая цифра и этот ответ. Если вместо файла задания указана уже существующая задача, в том числе путём к её каталогу или к файлу в нём, лист, согласование и проект лежат в её каталоге под именем каталога, файла постановки нет, файлы задачи не заменены. Если ответ на пробел уже есть в решении этой задачи, вопроса в листе нет, а раздел проекта ссылается на номер решения.
