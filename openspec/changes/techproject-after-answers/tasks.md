# Срез S1: Лист аналитику и оценка в проекте

**Сценарий:** По сырому заданию аналитик получает лист по существу и предварительную оценку; по результатам ответов технический проект содержит уточнённую оценку.

**Primary acceptance:** Передать файл задания с открытым вопросом об имени отчёта и увидеть лист без вопросов про часы и предварительную оценку рядом с листом. Технического проекта на этом шаге нет.

**Приёмка:** Прогнать команду на одном файле задания и повторно после пометки в листе.

**Связь со spec:** `specs/techproject-after-answers/spec.md`. Требования «Лист вопросов только по существу», «Предварительная оценка вместе с листом», «Уточнённая оценка в техническом проекте», «Вход из уже существующей задачи». Scenarios «Лист только по существу», «Часы не в листе», «Предварительная оценка с листом», «Уточнённая оценка в техническом проекте», «Без пометки техпроекта нет», «ЗНИ как задание», «Вход из существующей задачи без постановки», «Нет подходящей строки справочника», «Часы из чата сохраняются», «Расхождение оценки в техническом проекте», «Пробел при записи проекта», «Внедрение и откат без вопроса», «Пробел закрыт решением задачи», «Задача из архива».

**Зависимости:** срезов внутри задачи нет; внешнее предусловие — приёмка `tz-tech-project`

**Предусловие:** в `openspec/changes/tz-tech-project/tasks.md` отмечен `S1.accept`. Пока не отмечен, `SKILL.md` не переписывается. При архивации этой задачи требование «Техпроект по файлу задания» оформляется как изменение, а не как второе добавленное. Первой архивируется `tz-tech-project`.

- [x] S1.1 Переписать раздел «Лист вопросов» в `.cursor/skills/openspec-techproject/SKILL.md`. В лист попадают только вопросы по существу: противоречие задания, пробел, без которого нельзя описать решение, неопознанное имя. Вопросов про часы, вид работы по справочнику, демонстрацию, внедрение и откат в листе нет. У вопроса не меньше двух вариантов и место для ответа, либо фраза «вопросов нет». Строка подтверждения остаётся. Ответы по существу читаются из листа, а для уже существующей задачи также из её решений; чат их не заменяет. Для уже существующей задачи пробел, закрытый её решением, в лист не попадает. Первый запуск не ищет пробелы по разделам технического проекта (решения 1, 2, 10).
- [x] S1.2 Переписать раздел «Часы» в `.cursor/skills/openspec-techproject/SKILL.md`. Предварительная оценка называется в чате и пишется в таблицу часов согласования с пометкой «предварительная» в том же запуске, что и лист. Нюанс без смены состава работ её не задерживает. Для уже существующей задачи объём берётся из What Changes, а решение уточняет состав работ, только если закрывает пробел. Если развилка может сменить состав, одной фразой названо, какое чтение источника легло в цифру: в чате и в согласовании рядом со строкой часов. При двух подходящих строках справочника команда выбирает сама и пишет обоснование словами; молча брать более тяжёлую строку нельзя. Если не подходит ни одна строка, сначала пишутся лист и согласование с пустой строкой, затем в чате один вопрос, в листе его нет, часы пустые до ответа. Новый чат без ответа задаёт тот же вопрос. Демонстрация названа как этот случай: строки для неё в справочнике нет, новую строку не добавлять. Формула прежняя: (нижняя граница строки × коэффициент) + сумма нижних границ факторов, факторы без коэффициента, дробный результат поднимается до следующего целого часа. Уже указанные в задании часы переносятся как есть, в том числе в технический проект, даже если ответ изменил состав работ. Таблица нормативов, коэффициент и формула не показываются. Заменить дословно: абзац над Entry Protocol «Чат не заменяет файлы и не является источником ответов» и шаг 5 «Чат не источник ответов» — чат не источник ответов по существу; строку раздела «Часы» «вопрос о часах … вопрос остаётся в листе» — вопрос остаётся в чате, не в листе (решения 3–6, 8).
- [x] S1.3 Дописать в разделы «Часы» и «Каркас согласования» `.cursor/skills/openspec-techproject/SKILL.md` правило о часах из чата. Названные или поправленные в чате часы в том же ходе записываются в согласование и остаются предварительными. Повторный запуск без пометки эти строки из-за ответов в листе не пересчитывает. В техническом проекте такая строка переносится как есть, если состав этой работы не изменился; если изменился, пересчитывается, а прежняя цифра из чата названа рядом. Строки из самого задания этим пересчётом не затрагиваются. Согласование оценку уточнённой не называет. Подтверждённая цифра — та, которую запуск с пометкой прочитал в согласовании до записи. В запуске с пометкой команда часы согласования не пересчитывает. Часы, названные в чате в этом ходе, записываются в согласование как предварительные, а в проекте названы как цифра из чата. Повторный запуск без пометки не меняет в согласовании цифры, посчитанные командой, из-за ответов в листе; пересчёт этих строк идёт только в техническом проекте. Исключение — пустая строка по работе без строки справочника, которую заполнил ответ в чате. Если состав такой работы не изменился, часы из чата переносятся в проект как есть и входят в итог. Если ответы изменили состав, пересчёта нет: в техническом проекте строка без часов, рядом прежняя цифра из чата и ответ из листа, итог помечен «без работы …», в чате один вопрос о новых часах (решения 7, 8, 11).
- [x] S1.4 Заменить короткие таблицы в разделе «Техпроект» `.cursor/skills/openspec-techproject/SKILL.md` разделами для разработчика: объекты метаданных, алгоритм, интеграции, внедрение, откат, уточнённая оценка. Отчёты, печатные формы и права входят в раздел объектов. Таблица проводки остаётся, только если проводка есть в источнике. Текста процедур нет. Чего нет в источнике, того нет и в проекте. Если раздел объектов, алгоритма или интеграций не из чего заполнить, в нём «в задании не указано», вопрос добавляется в лист, пометка не сбрасывается. Если в источнике нет сведений о внедрении или откате, раздел пишется «в задании не указано», вопрос в лист не добавляется, пометка не сбрасывается, по списку объектов раздел не заполняется. Для уже существующей задачи источник включает её решения: если внедрение или откат сказано в решении, раздел ссылается на номер, а не на фразу «в задании не указано». Работа без строки справочника пишется без часов и итог помечается «без работы …», только если в чате ответа нет или ответы изменили состав. Если часы в чате названы и состав не изменился, они переносятся как есть и входят в итог. Уточнённая оценка пишется только здесь и в чате называется уточнённой. Если она расходится с цифрой, которую запуск прочитал в согласовании до записи, в проекте и в чате видны обе цифры и ответ из листа. Расчёт по строкам справочника при сравнении не показывается. Второго подтверждения нет. По файлу задания технический проект и постановка появляются только при непустой пометке и повторном запуске. Для уже существующей задачи файл постановки не появляется. Входящий файл не заменяется, каталог задачи на разработку не создаётся. Разделы записаны в самом навыке. Папка `template/Техпроект` при запуске не читается и не задаёт разделы. Заменить строки «Работа без ответа по строке справочника пишется без часов» и в разделе «Постановка» «вопрос в листе сохраняется»: вопрос о часах в лист не пишется. Заменить строку «вместе с постановкой»: для уже существующей задачи постановки нет (решения 7, 9, 10, 12).
- [x] S1.5 Заменить и дописать в Entry Protocol `.cursor/skills/openspec-techproject/SKILL.md` и в `.cursor/commands/opsx-techproject.md` необязательный вход из уже существующей задачи. Задача указывается именем. Путь к каталогу внутри `openspec/changes/` или к файлу в нём, в том числе к `proposal.md`, — тот же вход: имя по каталогу первого уровня под `openspec/changes/` или под `openspec/changes/archive/`, не по вложенной папке; файл постановки не пишется. Сначала открытая `openspec/changes/<имя>/` с файлом `proposal.md`. Если она найдена, архив не смотреть. Иначе архивный каталог с `proposal.md`, имя которого равно `<имя>` или оканчивается на `-<имя>`. Каталог без `proposal.md` не найден. Правило записать в навыке своими словами. Навык обзора не читать и не менять. Не найдено или в архиве на имя нашлось больше одного каталога — сообщить и ничего не писать. Связь с уже сделанными изменениями для этого входа не искать: она уже в тексте задачи. Дыры по существу искать по-прежнему и класть в лист. Как задание читаются Why и What Changes её `proposal.md`. Решения (`## Decisions` и `## Решения verify`) читаются только чтобы закрыть пробел, со ссылкой на номер; способ реализации требованием не называется. Если `design.md` нет, источник — только Why и What Changes. Выходы лежат в корне найденного каталога под именем каталога: `<каталог>-вопросы.md`, `<каталог>-согласование.md`, `<каталог>-техпроект.md`. Файла постановки нет. Файлы задачи не заменяются, новый каталог не создаётся. Перенос часов из файла задания к этому входу не относится. Заменить: строку «На вход — файл частного задания» — файл задания или имя задачи; шаг «Взять путь к файлу задания» — путь или имя; шаг «Рядом с заданием четыре пути» — для файла задания четыре пути рядом с ним, для существующей задачи три пути в корне её каталога; шаг «Прочитать входящий файл» — для задачи Why и What Changes плюс решения по правилу; шаг «записать техпроект и постановку» — для существующей задачи без постановки; строки «Не добавлять сведения, которых нет во входящем файле» и «Нет имени или шага — дыра в листе» — источник существующей задачи включает её решения; строку «Результат класть в лист и в файл постановки» — постановка только если вход — файл задания; вводную раздела «Постановка» — исключение для существующей задачи. В тексте команды остаются запрет читать `template/Техпроект` и запрет менять обзор задачи (`.cursor/skills/openspec-overview/**`). В `description` навыка убрать «таблицами»: техпроект разделами для разработчика и уточнённая оценка. В `description` команды убрать обязательную постановку: для уже существующей задачи её нет (решения 10, 12).

  - Scenario «Часы не в листе» (опционально): две подходящие строки справочника не порождают вопрос в листе, предварительная оценка названа.
  - Scenario «Нет подходящей строки справочника» (опционально): в листе нет вопроса по этой работе, строка часов пустая, вопрос один в чате.
  - Scenario «Часы из чата сохраняются» (опционально): названные в чате часы в том же запуске лежат в согласовании как предварительные.
  - Scenario «Без пометки техпроекта нет» (опционально): ответы в листе есть, пометка пустая — технического проекта нет, оценка остаётся предварительной.
  - Scenario «Уточнённая оценка в техническом проекте» (опционально): после непустой пометки и повторного запуска появляется технический проект для разработчика без текста процедур, в нём уточнённая оценка, в чате она названа уточнённой.
  - Scenario «Расхождение оценки в техническом проекте» (опционально): уточнённая цифра не совпала с подтверждённой — проект есть, в нём обе цифры и ответ из листа, второго подтверждения нет.
  - Scenario «Пробел при записи проекта» (опционально): в пустом разделе объектов, алгоритма или интеграций написано «в задании не указано», вопрос добавлен в лист, пометка на месте.
  - Scenario «Внедрение и откат без вопроса» (опционально): в источнике нет сведений — в разделах «в задании не указано», вопроса в листе нет, по списку объектов не заполнено. Если решение существующей задачи это описало, раздел ссылается на номер.
  - Scenario «ЗНИ как задание» (опционально): вместо файла задания указана уже существующая задача — лист и проект строятся по её тексту «зачем» и «что меняется».
  - Scenario «Вход из существующей задачи без постановки» (опционально): файла постановки нет, файлы самой задачи не заменены.
  - Scenario «Пробел закрыт решением задачи» (опционально): вопроса в листе нет, раздел ссылается на номер решения, способ реализации требованием не назван.
  - Scenario «Задача из архива» (опционально): лист и согласование лежат в корне архивного каталога под его именем; неизвестное имя, каталог без `proposal.md` и несколько каталогов на одно имя файлов не создают. Путь к каталогу или к файлу в нём — тот же вход.
