# Срез S1: Режим сессии

**Сценарий:** в чате `-noapi` / `-api` и память после лимита управляют дорогими вызовами; таблица ролей не ломается.
**Primary acceptance:** Написал `-noapi` или `--noapi` — следующий дорогой вызов идёт на модели чата, без попытки платной модели.
**Приёмка:** чтение правил выбора моделей и один контрольный ход в чате apply (написать `-noapi` перед дорогим вызовом); без информационной базы 1С.
**Связь со spec:** Requirement «Ключи в чате задают режим сессии» — Scenario «Ключ без API», Scenario «Ключ с API», Scenario «Оба токена в одном сообщении», Scenario «Ложное слово не включает режим», Scenario «Токен на дешёвой команде», Scenario «Новый чат сбрасывает»; Requirement «Память после лимита без повторных падений» — Scenario «Память после лимита», Scenario «Таймаут не липнет», Scenario «Целостность первого сбоя»; Requirement «Режим без API не отменяет разбор и не зовёт эскалацию» — Scenario «Не путать с пропуском архитектора», Scenario «Эскалация в режиме без API», Scenario «Разовый слаг и токен в одном сообщении».
**Зависимости:** нет.

- [x] S1.5 Записать в `.cursor/rules/model-selection.mdc` отличие `-noapi` от `--skip-architect`: архитектурный разбор постановки остаётся, файл `.gate-override.yaml` не создаётся (D2)

- [x] S1.11 Сверить в `.cursor/rules/model-selection.mdc` таблицу «Роли и Task.model»: строки Primary ролей совпадают с текстом до правок среза, чтобы слой режима не переписывал мэппинг
- [x] S1.12 Верифицировать по тексту `.cursor/rules/model-selection.mdc`: ключ в сообщении `/opsx:status` (и аналогов) переключает режим сессии, даже если команда не меняет свой вывод (Scenario «Токен на дешёвой команде», D2, D5)
- [x] S1.13 Верифицировать по тексту `.cursor/rules/model-selection.mdc`: явный слаг и `-noapi` в одном сообщении — этот вызов со слагом, дальше сессия без API; сброс только `-api` (Scenario «Разовый слаг и токен в одном сообщении», D7)

## 4. Приёмка

- [x] S1.accept Принять срез S1 «Режим сессии» — ключ в чате направляет следующий дорогой вызов на модель чата, таблица ролей на месте:
  - **Primary (обязательно):** Написал `-noapi` или `--noapi` — следующий дорогой вызов идёт на модели чата, без попытки платной модели.
  - Scenario «Ключ с API» (опционально): сессия уже без API → написать `-api` или `--api` → следующий дорогой вызов снова по таблице ролей
  - Scenario «Память после лимита» (опционально): по тексту правил после сбоя лимита этот вызов дорабатывается на модели чата, следующие в этом чате не повторяют то же падение и не повторяют строку про недоступность; если в чате apply случился живой лимит — те же шаги наблюдаемы
  - Scenario «Новый чат сбрасывает» (опционально): новый чат без ключа начинается с таблицы ролей; память прошлого чата не действует
  - Scenario «Таймаут не липнет» (опционально): по тексту правил сетевой таймаут даёт шаг 2 этого вызова и не включает режим на весь чат
  - Scenario «Не путать с пропуском архитектора» (опционально): `-noapi` и `/opsx:new` без `--skip-architect` — разбор постановки остаётся, `.gate-override.yaml` не создаётся
  - Scenario «Эскалация в режиме без API» (опционально): сессия без API и без явной просьбы «на самой дорогой модели» — дорогие роли на модели чата, самая дорогая эскалация не запускается «на всякий случай»
