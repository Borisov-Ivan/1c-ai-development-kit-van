# Design: kit-session-api-mode

## Context

Таблица ролей и двухшаговая цепочка «дорогая модель → при сбое модель чата» уже зафиксированы в `kit-evolution-models-economy-profiles` и живут в `.cursor/rules/model-selection.mdc`. Памяти «лимит исчерпан на этот чат» нет: каждый следующий вызов снова бьётся в платную модель. Отдельного запроса «есть ли квота» у Cursor нет — только сбой вызова. Общего разбора ключей у команд нет: каждый скилл читает свои `--флаги` из текста.

Пользователь выбрал: не ключ в `project.md`, а режим сессии у оркестратора. Явный сигнал — токены `-noapi` / `-api` (и с двумя дефисами) в любом сообщении чата.

Связанные ADR: ADR-0001 (в чат не копировать слаги моделей и имена агентов) — сообщение «дорогие модели недоступны» без слага.

## Goals / Non-Goals

**Goals:**

- Два явных режима в одном чате: жечь лимиты API или нет.
- После сбоя лимита не повторять падение на каждом следующем вызове.
- Ключи в чате однозначны; смысл — в одном правиле выбора моделей, не в десятках команд.
- Не ломать таблицу ролей, inherit через отсутствие параметра, запрет Fable как запаса, самосверку enum.

**Non-Goals:**

- Признак в `openspec/project.md` и вопрос в `/init-project`.
- Проверка квоты до вызова (probe).
- Файл-состояние между чатами (`session-notes` не кэш API).
- Смена таблицы ролей, профилей тона чата, политики Fable.
- Копирование ключей во все `.cursor/commands/*.md`.

## Decisions

**D1. Режим живёт в оркестраторе на время чата.** Не `project.md`, не `temp/session-notes.md`. Новый чат начинается с «с API». Альтернатива «признак проекта» отклонена пользователем 2026-08-17: два режима — «сегодня есть лимит / сегодня нет», это сессия.

**D2. Токены в любом сообщении.** Сообщение разбивается по пробельным символам; каждый фрагмент сравнивается без учёта регистра с литералами `-noapi`, `--noapi`, `-api`, `--api`. Совпадение фрагмента целиком = токен. Вхождение внутри другого фрагмента (`--api-key`) токеном не является. Увидел `-noapi` — режим «без API» до `-api` или нового чата. Увидел `-api` — сброс, снова таблица ролей. Не путать с `--skip-architect`: тот отключает архитектурный разбор как шаг протокола; `-noapi` разбор оставляет, но на модели чата.

**D3. Память после сбоя — только лимит / недоступность / ошибка выбора модели.** Сетевой таймаут не переключает режим на весь чат (иначе короткий сбой навсегда сажает на модель чата). Первый сбой в сессии по-прежнему отрабатывает второй шаг того же вызова; память влияет только на **следующие** вызовы. После первой строки «дорогие модели недоступны — дальше на модели чата» (без слага, ADR-0001) следующие пропуски шага 1 в том же чате — без повторной такой строки.

Два множества (не смешивать со списком «Что считать сбоем» в SSOT):
- Сбой **цепочки этого вызова** — как сейчас: недоступность, таймаут, лимиты/credits, `Invalid model selection`, иные ошибки API → шаг 2 того же типа субагента.
- **Липкая память сессии** — только лимит/credits, недоступность модели, ошибка выбора модели. Таймаут и нераспознанная сеть шаг 2 делают, режим не переключают. При сомнении в классе ошибки — не липнуть.

**D4. SSOT смысла — `model-selection.mdc`.** Перед вызовом с конкретной моделью оркестратор проверяет режим сессии. Cue в `tool-name-guard.mdc`. Follow-up в том же чате — `session-discipline.mdc` (протокол команды не сбрасывает режим). `model-selection.mdc` не always-apply: cue в `session-discipline.mdc` обязан на каждом ходе перед вызовом с конкретной моделью проверить токены текущего сообщения, затем память сессии, затем таблицу ролей. FAQ — как пользователю это сказать. В палитре — одна строка только у команд, которые реально зовут дорогие модели.

**D5. Команды без дорогих вызовов не объявляют ключ своим флагом.** `/opsx:status`, `/session-save` и аналоги не документируют ключ как свой флаг и не меняют поведение вывода (не ошибка, не справка). Токен в том же сообщении всё равно переключает режим сессии (D2: любое сообщение).

**D6. Пропуск шага 1 не отменяет шаг 2 текущего вызова.** Режим «без API» (токен или память) разрешает **не начинать** шаг 1 на **новых** вызовах. Если вызов **уже** ушёл с конкретной моделью и вернул сбой — шаг 2 без параметра модели обязателен. Память выставляется после этого шага 2 и действует только дальше. Не вызывать субагента вовсе и не подменять его отчёт — по-прежнему запрещено. Явный `-noapi` = сразу финальный шаг (без параметра модели), не обход делегирования.

**D7. В режиме «без API» закрытая эскалация и Primary не вызываются.** Пока сессия в «без API», оркестратор не передаёт слаг самой дорогой эскалации и не передаёт Primary ролей: вызовы — без параметра модели. Это расширяет запрет «эскалация не запас после сбоя», а не отменяет список режимов: `-api` или новый чат возвращают прежнюю политику. Явный запрос «на Fable» / конкретный слаг — разовый override на этот вызов, режим сессии не сбрасывает. Если в одном сообщении разовый слаг и `-noapi`: этот вызов идёт с указанным слагом; дальше сессия без API. Сброс режима — только `-api` / `--api`.

**Порядок (слоя project.md нет):** (1) разовый явный слаг пользователя на этот вызов; (2) токены `-noapi`/`-api` в сообщении; (3) память после липкого сбоя; (4) таблица ролей. Если в одном сообщении и `-noapi`, и `-api` — побеждает последний по тексту слева направо. В `session-discipline.mdc` — cue 2–4 строк: перед каждым вызовом с конкретной моделью проверить (2)–(4); follow-up не сбрасывает режим. Таблицу токенов и классификацию сбоев туда не копировать: SSOT — `model-selection.mdc`.

## Existing Mechanisms

Обследовано (kit, не конфигурация 1С):

1. Двухшаговая цепочка в `model-selection.mdc` — использовать как есть, добавить слой «пропустить шаг 1, если режим без API или сессия уже знает про лимит».
2. «Первый раз за сессию» — уже есть для сверки имён моделей; расширить соседним флагом режима, не новым файлом.
3. Разбор `--ключей` в каждом скилле — не подходит как SSOT: ключ про модели не является режимом apply/verify.
4. Overlay `project.md` — сознательно не используем (решение пользователя).
5. `temp/session-notes.md` — handoff между чатами, не кэш квоты; в предыдущей ЗНИ файл-состояние профиля уже отклоняли.

Уровень: расширить существующий механизм выбора модели, не строить параллельный.

## Design Rationale

Точка правки — момент «сейчас звать субагента с конкретной моделью», а не вход каждой команды. Иначе смысл ключа расползётся по сорока файлам и разъедется со `--skip-architect`. Сообщение пользователю при лимите — одна строка без слага (ADR-0001).

## Behavior Contract

- Написал в чате `-noapi` или `--noapi` — следующий вызов роли с конкретной моделью идёт сразу на модели чата, без попытки платной.
- Написал `-api` или `--api` — следующий такой вызов снова по таблице ролей; память про лимит сбрасывается.
- Токен — фрагмент после разбиения сообщения по пробелам, совпадающий целиком с одним из четырёх литералов; `--api-key` режим не включает.
- `/opsx:status -noapi` (и аналоги) не меняют вывод команды и не дают справку про ключ; режим сессии при этом переключается.
- После сбоя «лимит / модель недоступна / ошибка выбора модели» — одна строка «дорогие модели недоступны — дальше на модели чата»; следующие вызовы в этом чате не повторяют падение и не повторяют эту строку.
- Таймаут сети сам по себе режим не включает.
- Новый чат начинается с «с API».
- Перед каждым вызовом с конкретной моделью: токены текущего сообщения, затем память сессии, затем таблица ролей.
- Явный слаг в одном сообщении с `-noapi` действует на этот вызов; дальше сессия без API; сброс — только `-api`.
- `-noapi` не заменяет `--skip-architect` и не пишет `.gate-override.yaml`.
- Таблица ролей, запрет эскалации как запаса и самосверка имён моделей не меняются.

## Implementation Options

1. Признак в проекте + ключи + память сессии — шире, но для «сегодня нет лимита» лишний файл. Отклонён.
2. Только память после сбоя, без ключей — меньше определённости. Отклонён (пользователь оставил `-noapi` / `-api`).
3. Режим оркестратора + токены в чате + память после лимита — выбран: проще и совпадает с UX.

## Simplicity Check

- **Viable alternatives:** (1) признак в project.md; (2) только память без ключей; (3) режим оркестратора + токены + память (выбран); (4) probe квоты; (5) кэш по каждому Primary-слагу; (6) ключ как флаг каждой команды; (7) кэш в session-notes.
- **Selected simplest viable design:** (3) — один признак сессии, SSOT в `model-selection.mdc`.
- **Why not simpler:** (2) не даёт явный режим до первого удара; (1) отвергнут пользователем; без памяти не лечится повторный удар после лимита.
- **Complexity budget:** ~10 файлов kit, 0 метаданных 1С, 0 хуков, 1 проверка перед вызовом с конкретной моделью, 0 репозиторных feature flags.

## Risks / Trade-offs

- [Новый чат снова один раз бьётся в лимит] → принято: без файла между чатами; смягчение — сразу написать `-noapi`.
- [Таймаут приняли за лимит] → липнет только лимит / недоступность / ошибка выбора модели.
- [Путают с пропуском архитектора] → в правиле и FAQ явно: `-noapi` не отменяет разбор постановки.
- [Грубо: все дорогие модели сразу на чат, хотя у одной квота ещё есть] → принято ради простоты; тонкий кэш по каждой модели — вне этой ЗНИ.
- [Разбор постановки и ревью на модели чата хуже] → ожидаемо; пользователь сам выбрал экономию.

## Blast Radius

- **Контракт:** двухшаговая цепочка и таблица ролей остаются; добавляется право пропустить первый шаг по режиму сессии.
- **Архивный источник:** `openspec/changes/kit-evolution-models-economy-profiles` (proposal / design / specs/subagent-model-mapping).
- **Эффект для пользователя:** меньше повторных падений после лимита; явные ключи в чате.
- **Альтернативы:** признак проекта; probe квоты — отклонены.
- **Обоснование:** слой поверх, не отмена.
- **Контракт эскалации:** в режиме без API Primary и самая дорогая эскалация не зовутся, кроме разового явного слага; список режимов эскалации не удаляется. Не снимается сценарий «сбой Primary → шаг 2» и «сбой обычного архитектора не включает самую дорогую эскалацию».
