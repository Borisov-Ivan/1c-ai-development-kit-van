# Design

## Context

См. `proposal.md`. Стык уже описан в `reports/architecture-2026-10-23-handoff-empty-explore.md`: подтверждённое короткое подтверждение на создании заявки не считается постановкой, поэтому после записи решения ход останавливается и предлагает пустой разбор. Пустой разбор тему не читает.

Каталог на `develop` уже требует один порядок артефактов и один следующий шаг для бага в открытой заявке (`openspec/specs/kit-protocol-coherence/spec.md`). Признаки «только модуль» уже завязаны на постановку (`openspec/specs/split-form-layout-modes/spec.md`), но не запрещают взять их из варианта, выбранного в том же ходе.

Связанные ADR: ADR-0007 — вопрос автора по-прежнему пропускается только для доказанной эволюции набора без модулей; ADR-0001 — тексты в чат остаются на языке эффекта. Оба решения не заменяются.

Рядом идут заявки `fix-route-from-analysis` и `slice-check-opus`. Они не меняют передачу постановки и режим формы.

## Goals / Non-Goals

**Goals:**

- Создание с именем без готового блока постановки спрашивает короткое подтверждение до записи описания и решения.
- Ответ на это подтверждение снимает остановку «нет постановки». Если изменение сложное, сразу идёт уже существующий разбор решения.
- Недособранная заявка (описание есть, требований нет) продолжается тем же именем. В тексте остановки одна такая команда.
- Заявка, где уже есть требования и список задач, по-прежнему дописывается.
- Признаки «только модуль» не берутся из варианта поставки, выбранного в том же ходе.
- Из исследования с шагами команда создания новой заявки показывается только вместе с блоком постановки.
- Одна изменённая строка кода несёт одну хвостовую пометку и не обрастает второй служебной строкой.

**Non-Goals:**

- Пустой разбор в новом чате не начинает читать прошлый разговор и отчёты.
- Готовый блок постановки в чате по-прежнему создаёт заявку без повторного подтверждения.
- Короткое подтверждение не заменяет явную пометку пропуска разбора решения.
- Дописывание уже полной заявки не начинает само читать блок постановки из чата.
- Путь свободного текста без имени не выравнивается с созданием с именем: его короткое подтверждение постановкой для снятия остановки не считается.
- Уже записанный режим формы в чужом проекте этой заявкой не переспрашивается и не правится.
- Маршрут «доработка без обследования сразу идёт в создание» не переписывается так, чтобы разбор был обязан печатать блок постановки.
- Уже стоящие пары в модулях не переписываются.
- Новый шаблон генерации под «НАЧАЛО» / «КОНЕЦ» не заводится.
- Фраза «что и зачем» не укорачивается: уходит лишняя строка, текст фразы остаётся.

## Decisions

### Подтверждение считается постановкой

Если имени заявки ещё нет готового блока постановки, создание показывает короткое подтверждение и ждёт ответ. После согласия этот ответ считается постановкой для условия остановки. Описание и решение до ответа не пишутся.

Если каталог уже есть, а требований нет, текст подтверждения берётся из записанного описания. Уже записанные автор и режим формы не переспрашиваются.

Это правило про создание с именем. Подтверждённый ответ считается постановкой только на этом пути. Путь свободного текста без имени не выравнивается: его короткое подтверждение постановкой для снятия остановки не считается, и ветка остановки на нём не переписывается. Исходный обрыв и критерии приёмки — про создание с именем.

Альтернатива: обязать разбор печатать блок до команды с именем. Отклонено для доработки без обследования: она имеет право блока не собирать. Для исследования, которое понимает и чинит, блок до команды создания обязателен.

Альтернатива: убрать остановку целиком. Отклонено: тогда описание пишется без согласия заказчика.

### Одна команда возврата

После того как ответ на пути с именем считается постановкой, а продолжение каталога без требований подтверждается по записанному описанию, остановка «нет постановки» на шаге разбора решения недостижима. Эта ветка снимается. Если отчёта архитектора нет, остаётся уже существующий путь «анализ запускается сейчас» либо явная пометка пропуска со следом в заявке.

Тексты остановок, которые сохраняются (отказ от подтверждения до записи описания и прерванный ход), содержат одну команду: повтор создания с тем же именем. Пустого разбора в них нет. Вторая команда с пропуском разбора решения остаётся только как явная пометка со следом в заявке, не как равный выбор в том же абзаце.

### Куда вести финал разбора

Если заявка той же области открыта и требований ещё нет, следующий шаг — дозавершение тем же именем. Если требования и список задач уже есть, следующий шаг — дописать заявку. Вторая заявка из новой постановки при живом каталоге с тем же именем не создаётся. Продолжение существующего каталога тем же именем не считается командой создания новой заявки и блока постановки не требует.

Альтернатива: всегда только дописывать. Отклонено: дописывание вставляет задачи в уже существующий список и не проходит остановленную цепочку «решение → требования → задачи».

### Команда создания из исследования — только рядом с блоком

Исследование, которое идёт понять и исправить, показывает команду создания новой заявки только в том же сообщении, где уже напечатан блок постановки. Доработка без шагов исследования по-прежнему сразу идёт в создание, и там короткий ответ считается постановкой. Продолжение уже начатой заявки тем же именем блока не требует, только когда каталог виден в списке открытых заявок.

Согласованная в исследовании постановка не должна заново собираться коротким подтверждением на создании. Места правки — слот «Дальше» синтеза, строки финала разбора и секция явной просьбы создать заявку (там сейчас вилка «новая заявка / дополнить существующую»). В этой секции то же правило: без блока команды новой заявки нет; каталог без требований продолжается тем же именем; каталог с требованиями и задачами дописывается.

Исключение «продолжение тем же именем без блока» действует только когда каталог виден в списке открытых заявок в момент сообщения. Иначе команда с именем — создание новой заявки и требует блока.

Альтернатива: не показывать и продолжение уже начатой заявки, пока блока нет. Отклонено: возврат к заявке без требований идёт коротким ответом по записанному описанию.

### Откуда берутся признаки «только модуль»

Положительные признаки читаются из слов заказчика, блока постановки или кода. Код — элементы формы уже выводятся программно в модуле, а в разметке формы их нет. Блок постановки принимается источником, потому что заказчик продолжил работу с этого блока.

Вариант «всё в модуле», выбранный в решении того же хода, признаком не является. Собственное решение хода — разделы решения (принятые решения, варианты реализации, обоснование выбора) и выбранный вариант отчёта архитектора того же хода. Нет признаков — задаётся вопрос. Уже записанный валидный режим по-прежнему не переспрашивается.

### Хвост одной строки

Если весь фрагмент изменения в этом месте — одна физическая строка кода, пометка ставится в конец этой строки. Текст хвоста равен уже собранной открывающей пометке текущего шаблона. Отдельная строка над кодом и закрывающая пометка не пишутся.

Пара остаётся, когда верно любое из условий: изменены две или больше соседних строк одного изменения; фрагмент — новая или целиком переписанная процедура; строка лежит внутри строковой константы или текста запроса; на строке уже есть комментарий о смысле кода. Несколько одиночных хвостов подряд сжимаются в одну пару. Одна строка многострочной сигнатуры, если изменилась только она, считается одной строкой. Хвост ставится на строку, которая остаётся в тексте модуля. Одна добавленная строка внутри блока вставки получает хвост на этой строке, не на директиве. Строка внутри блока удаления хвост не получает. Удаление единственной строки, после которого несущей строки не осталось, остаётся парой и не переносит пометку на удалённый текст.

Тот же критерий записывается в грамматике размещения, в инструкции оформления при разработке, в карточке проверки соседних пометок, в чеклисте проверки комментариев и в обзоре слоёв. Текст открывающей пометки не меняется.

Заказчик 9 ноября 2026 оставил это правило в той же заявке, что и передачу постановки, и назвал заявку двойной. Сверка того же дня советовала не смешивать цели. Риск записан, артефакты ради хвоста всё же меняются.

## Existing Mechanisms

Штатное размещение пометки — пара вокруг фрагмента, сжатие соседних пар одного изменения и хвост закрытия у конца процедуры. Однострочная форма основной конфигурации покрывает целую процедуру, не одну строку внутри метода. Эти правила не дают короткий хвост на единственной изменённой строке. Новый диалект комментариев не заводится: хвост использует уже собранный текст открывающей пометки.

## Design Rationale

Точка правки — уже существующие создание заявки, финал разбора и классификатор режима формы. Новый маршрут не заводится. Короткое подтверждение на создании уже есть для свободного текста; его же получает путь с именем, когда блока постановки нет. Ответ на свободном тексте постановкой для снятия остановки не считается. Разбор решения после согласия остаётся тем, который на создании уже запускается при сложном изменении. См. `reports/architecture-2026-10-23-handoff-empty-explore.md`.

## Behavior Contract

1. Создание с именем без блока постановки не пишет описание, пока заказчик не подтвердил короткое описание изменения. Подтверждённый ответ на этом пути считается постановкой. Путь свободного текста без имени не выравнивается: его короткое подтверждение постановкой для снятия остановки не считается.
2. После подтверждения остановка из-за отсутствия блока не повторяется. Сложное изменение сразу идёт в разбор решения. Ветка остановки «нет постановки» после этого недостижима и снимается. Остаются отказ от подтверждения до записи описания и прерванный ход.
3. Готовый блок постановки в чате по-прежнему проходит без этого подтверждения и без паузы на имени.
4. Если описание уже записано, а требований нет, повтор с тем же именем показывает подтверждение по этому описанию и не открывает второй каталог.
5. Пустой разбор в новом чате просит описать задачу и не подставляет прошлую тему.
6. Если у заявки уже есть требования и задачи, финал разбора предлагает её дописать.
7. Без признаков «только модуль» в словах заказчика, постановке или коде задаётся вопрос. Вариант из собственного решения хода вопрос не отменяет.
8. Явный пропуск разбора решения по-прежнему требует пометку и след в заявке.
9. Из исследования, которое понимает и чинит, команда создать заявку стоит только в том же сообщении, где есть блок постановки. То же правило у явной просьбы создать заявку. Доработка без шагов исследования этим пунктом не отменяется. Продолжение уже начатой заявки без блока действует только когда каталог виден в списке открытых заявок в момент сообщения; иначе команда с именем требует блока.
10. Одна добавленная или изменённая строка кода, которая остаётся в модуле, вне строковой константы и без своего смыслового хвоста заканчивается пометкой изменения. Над ней нет второй служебной строки, под ней нет закрывающей пометки. Строка внутри блока удаления хвост не получает. Удаление единственной строки, после которого несущей строки не осталось, остаётся парой.
11. Две соседние строки одного изменения обрамлены одной парой. Два хвоста подряд на одном изменении не остаются.
12. Новая процедура открывается пометкой перед заголовком и закрывается в строке конца процедуры.
13. Строка внутри текста запроса или другой строковой константы не получает служебный комментарий в конце. Пометка стоит парой вокруг оператора, которому принадлежит текст.
14. Строка, у которой уже есть комментарий о смысле кода, сохраняет этот комментарий. Служебная пометка стоит парой вокруг строки.
15. Уже записанные пары в других местах модуля не переписываются этой заявкой.
16. Пометка без фразы на одной строке кода тоже хвост. На нескольких строках она по-прежнему пара.

## Implementation Options

**Option A (выбран).** Подтверждение на создании с именем считается постановкой. Путь без имени не выравнивается. Возврат к недособранной заявке — то же имя, если каталог виден в списке открытых заявок. Признаки формы не берутся из решения того же хода. Из исследования с шагами команда создания новой заявки показывается только рядом с блоком постановки, в том числе на явную просьбу создать заявку.

Почему: одна точка, где постановка появляется, и одна команда, которая продолжает уже открытый каталог.

**Option B (отклонён).** Любой маршрут, включая доработку без обследования, обязан печатать блок постановки до создания. У доработки без обследования права не собирать блок нет, и возврат из остановки снова уходит в разбор без блока.

**Option C (отклонён).** Остановку убрать и всегда писать описание без подтверждения. Согласие заказчика в заявку не попадает.

**Primary acceptance:**

- S1: создать заявку с именем без блока постановки — до описания видно короткое подтверждение; после согласия нет приглашения начать разбор без задачи.

## Risks / Trade-offs

- [Подтверждение по уже записанному описанию заказчик воспримет как повторный вопрос] → текст опирается на записанное описание, автор и режим формы не спрашиваются снова.
- [Финал разбора для бага в открытой заявке сегодня всегда ведёт дописывать] → различие вводится явно: нет требований — дозавершение, есть требования и задачи — дописывание.
- [Уже записанный «только модуль» без слов заказчика останется в чужой заявке] → эта заявка чужой каталог не правит. Новые ходы вопрос задают, пока признаков нет.
- [Продолжение уже начатой заявки идёт коротким ответом без блока постановки] → это продолжение каталога, не команда создания новой заявки. Блок обязателен только когда из исследования предлагают создать новую. Продолжение без блока только если каталог виден в списке открытых заявок.
- [Путь свободного текста без имени по-прежнему может остановиться из-за отсутствия постановки] → заявка этот путь не выравнивает. Создание с именем спрашивает подтверждение до записи описания.
- [Хвост одной строки — вторая цель рядом с передачей постановки] → заказчик 9 ноября 2026 оставил обе цели в одной заявке. Сверка советовала разделить. Приёмка хвоста отдельная, задачи передачи постановки не подменяют её.
- [Длинная фраза оставляет широкую строку] → уходит вторая служебная строка, текст фразы не режется.
- [Хвост внутри текста запроса ломает запрос] → такая строка исключена, остаётся пара вокруг оператора.

## Решения verify (зафиксировано)

В исследовании, которое идёт понять и исправить, команда создать новую заявку стоит только в том же сообщении, где уже есть блок постановки. Создание сразу без исследования по-прежнему считает постановкой короткий ответ. Продолжение уже начатой заявки без требований идёт коротким ответом по записанному описанию и блока не требует, только когда каталог виден в списке открытых заявок в момент сообщения. Иначе команда с именем — создание новой заявки и требует блока.

Предпосылка: слот следующего шага в финале исследования может назвать создание заявки без блока постановки (`.cursor/skills/openspec-explore/SKILL.md:218`).

## Open Questions

- Дописывание полной заявки по-прежнему не забирает блок постановки из чата, хотя финал разбора это обещает. В эту заявку не входит.
- В заявке диаграммы отсутствий в СППР режим формы записан как «только модуль» без слов заказчика. Дозавершение того каталога режим не переспросит. Отдельный проход там этой заявкой не делается.
