# Срез S1: Возврат решения по опровергнутой предпосылке

**Сценарий:** разработчик прогоняет проверку ЗНИ, где после прошлой проверки появился отдельный отчёт, опровергающий кодом предпосылку закрытого решения, и вместо повтора прошлого итога получает вопрос о подтверждении этого решения с исправленным фактом и ссылкой на код.
**Primary acceptance:** Given фикстура `fixture-premise-reopen`: два закрытых решения с предпосылкой, свежий снимок прошлой проверки, постановка не менялась, после снимка в `reports/` добавлен отчёт с `путь:строка`, опровергающим предпосылку одного решения → When `/opsx:verify fixture-premise-reopen` → Then вместо повтора прошлого итога карточка с пунктом «прежний выбор опирался на X; код показывает Y (`путь:строка`); подтверждаете выбор?».
**Приёмка:** ручной прогон `/opsx:verify` на фикстуре, 5–10 мин.
**Связь со spec:** verify-stop-repeat — Requirement «Вопросы пакетом при создании задачи» — Scenario «Вопросы пакетом при создании задачи», Scenario «Непроверенный факт в пакете»; Requirement «Все решения прогона одной карточкой» — Scenario «Все решения прогона одной карточкой», Scenario «Вторая тема остаётся на карточке», Scenario «Утверждение в варианте с доказательством», Scenario «Утверждение без доказательства», Scenario «Оценка вместо факта»; Requirement «Стоп по теме» — Scenario «Стоп по теме», Scenario «Здоровая конвергенция не стопится», Scenario «Опровержение не подменяется стопом»; Requirement «Опровергнутая предпосылка возвращает решение» — Scenario «Опровержение из отдельного отчёта», Scenario «Повтор опровержения без нового факта», Scenario «Остальные решения не трогаются», Scenario «Подтверждение и смена выбора», Scenario «Опровергнутое решение не довод». value-efficient-verify — Requirement «Уникальный сигнал переоткрывает решение» — Scenario «Второй уникальный сигнал», Scenario «Опровергнута предпосылка закрытого внешнего условия».
**Зависимости:** нет.

# Срез S2: Сигнал упрощения не теряется

**Сценарий:** разработчик прогоняет проверку ЗНИ, где отчёт готовности задач отметил лишнюю защиту, а постановка это не учла; итог проверки прежний, но к концу прогона замечание учтено правкой задач или записанной причиной.
**Primary acceptance:** Given фикстура `fixture-readiness-simplify`: отчёт готовности с критерием 7 `SUBOPTIMAL`, задачи не менялись, постановка правлена вне архитектурной оси (быстрый путь не срабатывает, готовность переиспользуется), замечание не учтено → When `/opsx:verify fixture-readiness-simplify` → Then итог в чате прежний, а в `design.md` фикстуры в `## Risks / Trade-offs` есть причина с источником `отчёт#пункт` либо в `tasks.md` задача без лишней защиты.
**Приёмка:** ручной прогон `/opsx:verify` на фикстуре, 5–10 мин.
**Связь со spec:** value-efficient-verify — Requirement «Сигнал упрощения из проверки готовности не теряется» — Scenario «Замечание об избыточности учтено», Scenario «Переиспользованный отчёт не теряет замечание», Scenario «Учтённое замечание не возвращается»; Requirement «Непроверенная простота архитектурного решения видна» — Scenario «Простой вариант отклонён без доказательства», Scenario «Отчёт готовности не даёт ложной строки», Scenario «Исправленный отчёт снимает строку».
**Зависимости:** нет (порядок реализации — после S1: общие файлы `openspec-verify-change/SKILL.md`, `report-header.md`, `architect.md`, `onec-code-architect.md`).

# Срез S4: Карточка приёмки показывает место среза

**Сценарий:** разработчик получает передачу среза на приёмку и без списка задач видит, какой это срез, последний ли он и что ещё не сделано; на последнем может принять позже и сразу уйти в архив; приёмка без прогона остаётся видимой.
**Primary acceptance:** Given фикстура `fixture-slice-handoff` из двух срезов, рабочие задачи обоих закрыты, приёмка не отмечена → When `/opsx:apply fixture-slice-handoff`, затем «принято без проверки» на первом срезе → Then карточка первого — «1 из 2, не последний» и имя второго; карточка второго — «2 из 2, последний», принять можно сейчас или позже, и первый срез назван принятым без проверки.
**Приёмка:** ручной прогон передачи на фикстуре, 5–10 мин.
**Связь со spec:** chat-surface-clarity — Requirement «Карточка приёмки показывает место среза» — Scenario «Передача называет место среза», Scenario «Последний срез можно принять позже»; Requirement «Приёмка без прогона остаётся видимой» — Scenario «Принято без проверки видно на последнем срезе», Scenario «Перед архивом видны срезы без проверки», Scenario «Обычное принято пометки не ставит».
**Зависимости:** нет (порядок реализации — после S3: общие файлы `openspec-apply-change/SKILL.md`, `openspec-archive-change/SKILL.md`).
