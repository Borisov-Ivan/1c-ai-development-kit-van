## MODIFIED Requirements

### Requirement: Apply-reviewer does not run disposition AskQuestion

Контур apply-reviewer MUST NOT блокировать цикл AskQuestion as-designed/queue-fix. Weak / design-prescribed MUST NOT авто-waive без следа; допускается авто-fix functional MUST_FIX или open-пометка для последующего `/review`. След открытого замечания MUST записываться в одно фиксированное место задачи, общее для реализации, ревью и архива; решение ревью по замечанию MUST отмечаться в том же следе.

#### Scenario: Apply speed preserved

- **WHEN** apply-reviewer находит CODE MUST_FIX без QualityFlag weak
- **THEN** авто-fix работает как прежде

#### Scenario: Weak not silently waived in apply

- **WHEN** apply-reviewer видит QualityFlag weak / design-prescribed
- **THEN** замечание не считается авто-принятым as-designed; в едином списке следов задачи появляется открытая строка для disposition на `/review` или `/release-review`

#### Scenario: Решение ревью видно в следе

- **WHEN** на `/review` по задаче выбрано решение по замечанию из списка следов
- **THEN** строка этого замечания в списке следов показывает принятое решение и больше не считается открытой

## ADDED Requirements

### Requirement: Открытые замечания качества видны до архива

Перед архивом задачи с открытыми замечаниями о спорном качестве MUST показываться их краткий список и вопрос с тремя ответами: пойти на ревью, архивировать без ревью, остановиться. Ответ «архив без ревью» MUST записываться в след каждого замечания с датой и MUST NOT считаться решением по качеству: замечание остаётся открытым. Архив MUST NOT закрывать замечание сам. Принудительный архив без отметки приёмки MUST NOT пропускать этот вопрос. Без открытых замечаний архив MUST идти как прежде.

#### Scenario: Архив со следами

- **WHEN** разработчик запускает архив задачи, где после реализации осталось открытое замечание о спорном качестве
- **THEN** до переноса в архив он видит список открытых замечаний и вопрос ревью / архив без ревью / стоп

#### Scenario: Архив без ревью не закрывает замечание

- **WHEN** разработчик отвечает «архив без ревью»
- **THEN** задача архивируется, а в следе замечания записано «архив без ревью» с датой, и оно не помечено как принятое как задумано или отложенное ревью

#### Scenario: Ответ ревью

- **WHEN** разработчик отвечает «ревью» на вопрос архива
- **THEN** архив не выполняется, в чате один следующий шаг — ревью этой задачи

#### Scenario: Без следов архив прежний

- **WHEN** в задаче нет открытых замечаний о спорном качестве
- **THEN** архив проходит без вопроса о замечаниях, как до этого изменения
