## ADDED Requirements

### Requirement: Skill file is read on session entry

На первом ходе командной сессии оркестратор SHALL сделать единственным вызовом первого батча чтение скилла команды. На последующих ходах той же команды оркестратор MUST NOT повторно читать скилл целиком и SHALL продолжать соблюдать протокол скилла. Если чтение скилла на входе обрезано, оркестратор SHALL во втором батче прочитать шаблоны скилла; служебные карточки проверки постановки (`executive-summary`, `info-section`, `layer-1-hygiene-table`) MUST NOT копироваться в чат.

#### Scenario: Скилл читается на входе

- **WHEN** пользователь запускает команду workflow первым сообщением чата
- **THEN** первым действием читается скилл этой команды, до файлов из запроса

#### Scenario: Follow-up без повторного чтения скилла

- **WHEN** в той же командной сессии приходит следующее сообщение пользователя
- **THEN** оркестратор не читает скилл заново и продолжает по протоколу команды

### Requirement: Map cue in dispatcher is a pointer

Строка диспетчера про карту сценария SHALL оставаться указателем: прямая просьба «покажи карту сценария» / «покажи схему» ведёт к скиллу карты. Тело протокола карты (молчание, намёк, регистрация панели) MUST NOT дублироваться в диспетчере.

#### Scenario: Cue «покажи схему»

- **WHEN** оркестратор выбирает, грузить ли скилл карты
- **THEN** в диспетчере видна короткая строка-указатель с просьбой «покажи схему», без копипасты правил молчания и намёка
