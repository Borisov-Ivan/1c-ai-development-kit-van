## MODIFIED Requirements

### Requirement: Offer by topology not by topic

Оркестратор MUST предлагать карту сценария только если можно назвать конкретный вывод, которого нет в списке, и есть хотя бы один топологический признак (слои, где один питает другой; ветвление со схождением; жизненный цикл состояний; причинная петля или повторное использование устаревшего результата; одно порождает несколько представлений; разные технические пути). На выходе разбора, в «Дальше» исследования и после записи описания ЗНИ предложение MUST требовать не меньше четырёх публикуемых сущностей после отсева **по правилам выбранного средства** (граф: без доказательства и без инцидентной связи; таблица: без доказательства, инцидентная связь не нужна). На строке подтверждения списка точек разбора предложение MAY печататься по предсказанной топологии списка (или отчёта, из которого список собран), **без** требования ≥4 публикуемых сущностей уже сейчас; публикация панели на этом шаге MUST NOT происходить — действует отложенная постройка. Предложение MUST формулироваться через сущности и вывод, а не общим вопросом «хотите карту?». Предикаты предложения MUST NOT ссылаться на предметную область, тип объекта метаданных или конкретный механизм. Замеры времени MUST NOT быть условием предложения; время MAY быть признаком только вида «временная шкала». После описания ЗНИ признак MUST определяться по форме связей **в том же одном отчёте**, который при согласии уйдёт в сборщика, MUST NOT по объединению файлов, MUST NOT по теме ЗНИ и MUST NOT по числу этапов поставки. Согласие MUST вызывать сборщика с **тем же** путём отчёта; правило «несколько отчётов — все пути» MUST NOT применяться к этому входу.

Отказ предложения в исследовании, на выходе разбора и после описания ЗНИ MUST NOT печататься в чат. Если пользователь отказался («без карты»), повторно предлагать до выхода сессии MUST NOT.

#### Scenario: Исследование предлагает схему при топологии без замеров

- **WHEN** отчёт исследования содержит не меньше четырёх связанных сущностей с топологическим признаком и замеров времени нет
- **THEN** в «Дальше» ровно одно действие — показать схему, с фразой, что станет видно; пошаговый разбор в том же сообщении не предлагается

#### Scenario: Разбор предлагает схему на подтверждении списка без порога публикации

- **WHEN** на строке подтверждения списка точек разбор видит предсказанную топологию списка или отчёта, из которого список собран, замеров времени нет, и есть эта строка решения
- **THEN** в этой строке есть вариант «сразу карту» с фразой, что станет видно; порог «уже четыре публикуемые сущности» не требуется; панель на этом шаге не публикуется; слов про замеры времени как условие нет

#### Scenario: Разбор предлагает схему на выходе без замеров времени

- **WHEN** на выходе разбора есть строка «Следующий шаг», после отсева выбранного средства не меньше четырёх публикуемых сущностей, есть топологический признак, замеров времени нет
- **THEN** в этой строке есть вариант получить схему; слов про замеры времени как условие нет

#### Scenario: На линейных двух шагах схему не предлагают

- **WHEN** разбор проходит два линейных шага без слоёв, ветвлений и состояний
- **THEN** предложения схемы нет; в чате нет строки, почему схему не предложили

#### Scenario: Предложение не зависит от темы механизма

- **WHEN** топология есть у механизма любой предметной области
- **THEN** правило предложения то же, что у любого другого механизма; отдельного условия «если это такая-то тема» нет

#### Scenario: Описание предлагает схему при топологии в отчётах

- **WHEN** после записи описания ЗНИ в каталоге этой ЗНИ есть отчёт разбора, **на этом одном отчёте** после отсева выбранного средства не меньше четырёх публикуемых сущностей, есть топологический признак формы связей и можно назвать вывод, которого нет в списке этапов
- **THEN** в уже существующей строке следующего шага есть вариант схемы с фразой, что станет видно; панель на этом шаге не создаётся; в чате нет строки, почему схему предложили

#### Scenario: Описание с таблицей без рёбер

- **WHEN** выбранное средство — таблица, на одном отчёте после отсева без доказательства остаются четыре строки с доказательством, инцидентных связей нет, есть вывод и признак формы связей
- **THEN** в строке следующего шага есть вариант схемы; отсутствие рёбер само по себе намёк не снимает

#### Scenario: Описание без отчётов схему не предлагает

- **WHEN** вызывается описание ЗНИ, где есть только постановка и решения, без отчётов разбора со связями
- **THEN** строка следующего шага напечатана, варианта схемы в ней нет; строки о причине отсутствия предложения нет

#### Scenario: Плоский набор без формы связей в описании не даёт намёка

- **WHEN** после описания ЗНИ отчёты дают не меньше четырёх доказанных связанных сущностей, но нет слоёв, ветвления, жизненного цикла и петли
- **THEN** варианта схемы в строке следующего шага нет; строки о причине нет

#### Scenario: Отказ без карты в описании не повторяется

- **WHEN** после описания ЗНИ пользователь отвечает «без карты», затем в той же сессии описание вызывается снова
- **THEN** варианта схемы до конца сессии нет; строка следующего шага остаётся

#### Scenario: Согласие описания отдаёт тот же один отчёт

- **WHEN** пользователь соглашается на вариант схемы после описания ЗНИ
- **THEN** в сборщика уходит тот же один отчёт, на котором прошла проверка; фраза про поставку соседней ЗНИ и подмешивание «всех путей» в этот вход не появляются
