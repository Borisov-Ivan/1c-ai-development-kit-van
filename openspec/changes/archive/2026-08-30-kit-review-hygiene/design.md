## Context

Ревью kit после поставки карты сценария и развилки последнего среза: архитектура управляема, раздувание локальное. Два дефекта поставки в чужой проект: (1) классификатор охвата маркеров зашит тремя путями одной выгрузки; (2) учебные эталоны и команды несут имена тех же проектов. Рядом — рассинхрон порога схемы после описания с правилами средства карты, повторное чтение скилла на каждом ходе, битая ссылка контролёра срезов и вызовы несуществующих режимов инструментов.

Связанные ADR: ADR-0009 (главный вид граф или таблица) — применяется к порогу описания, не отменяется; ADR-0001 (чат vs агент) — имена служебных карточек не в чат; ADR-0002 не затрагивается. Разбор постановки: `reports/architecture-new-2026-08-30.md`.

## Goals / Non-Goals

**Goals:**

1. Охват маркеров в любом проекте считается по сегментам `cf` / `cfe`, без литералов чужой выгрузки.
2. Развилка после последнего среза сохраняет смысл: расширение — три слова; kit-only и только база — архив без предрелиза. Ярлык `cf-ea` заменяется на `cf`.
3. Предложение схемы после описания считает порог по выбранному средству; согласие отдаёт тот же один отчёт.
4. Скилл команды читается на входе сессии; протокол на каждом ходе сохраняется.
5. В `.cursor/**` нет имён реальных проектов в примерах и фильтрах.

**Non-Goals:**

1. Принимать, архивировать или переписывать соседние ЗНИ про карту и развилку.
2. Потолок сценариев карты, сжатие оболочки панели, вынос `pav_` из allow-list AP-031.
3. Правка архивных отчётов `openspec/changes/archive/**`.
4. Правка `.bsl` / XML. Новые объекты метаданных.

## Existing Mechanisms

1. Классификатор `marker_scope` в скилле реализации (шаг 4) и в статусе — расширяем алгоритм, не заменяем развилку последнего среза.
2. Карточка проекта (`openspec/project.md`, появляется после `/init-project`) — источник путей cf/cfe, когда файл есть; в репозитории kit файла нет — тогда сегменты пути в задачах.
3. Правила публикации карты (граф: без доказательства и без связи; таблица: без доказательства, связь не нужна) — тот же порог «четыре публикуемые» после отсева выбранного средства.
4. Always-apply правило сессии уже держит протокол на каждом ходе; FIRST AND ONLY Read скилла относится только ко входу.
5. Словарь `marker_scope` в глоссарии уже `cf | cfe | mixed | не определён`; статус и apply ещё расходятся — сводим к глоссарию.

Почему не оставляем литералы путей: kit копируется в любой проект 1С; чужие пути как фильтр дают ложный «нет расширения».

## Design Rationale

Точки правки — тексты kit, не прикладной код. Детектор охвата должен совпадать с правилом путей проекта: сегмент `/cfe/` vs `/cf/`. Развилку last-slice не переписываем: меняется только ярлык `cf-ea` → `cf`. Нейтральный словарь примеров один на всю поставку `.cursor/**`, чтобы не плодить вторую легенду. Allow-list префиксов в антипаттерне именования — механизм LIST, не учебный путь: его не трогаем в этой ЗНИ.

## Behavior Contract

1. Grep `tasks.md` и `design.md` на пути `src/**/*.bsl`. Перед сегментами нормализовать `\` → `/`. Есть `/cfe/` и нет `/cf/` как сегмента каталога выгрузки → `cfe`. Только `/cf/` → `cf`. Оба → `mixed`. Нет путей → не определён (для развилки = как `cf`: без слова `ревью`). Карточка `openspec/project.md` **не** источник `marker_scope`: она задаёт, как в репозитории пишутся корни, но наличие строки cfe в таблице не делает kit-only ЗНИ `mixed`.
2. После «принято» на последнем срезе: `cfe` / `mixed` → `ревью` / `архив` / `стоп`. Пусто / `cf` → архив / стоп, слова `ревью` нет. Слова `архив` и `стоп` ведут себя как в архивной ЗНИ развилки.
3. После записи описания: порог «не меньше четырёх публикуемых» считает отсев выбранного средства. Отсев без доказательства — всегда. Отсев без инцидентной связи — только граф; таблица связь не требует. Условия намёка «конкретный вывод» и «топологический признак» не меняются. Согласие вызывает сборщика с тем же одним отчётом; списки путей «всех отчётов» в этот вход не подмешиваются.
4. Первый ход командной сессии: единственный вызов в первом батче — Read скилла. Следующие ходы той же команды скилл повторно не читают; Entry Protocol и ограничения скилла действуют. При обрезке Read — во втором батче шаблоны скилла; карточки `executive-summary`, `info-section`, `layer-1-hygiene-table` в чат не копировать.
5. В поставке `.cursor/**` нет литералов: Павлик, ДО21_Павлик, pavЭтоИБПавлик, ЭДО ПАО, ЭДО и ЭА, ДО3 Демо, КонтурДиадок, do2-pavlik, nastroyka-knopok-processov. Учебный словарь: `src/Конфигурация/cf/`, `src/Конфигурация/cfe/ДемоРасширение/`, ЗНИ `sample-change`, префикс в эталонах `ext_`.
6. Смысл эталонов (хорошо / плохо, голос, control-run) сохраняется при замене имён.

## Implementation Options

**Вариант A.** Параметризовать детектор по сегментам пути; нейтральный словарь примеров; точечные правки протокола сессии и порога описания.

**Вариант B.** Вынести пути заказчика в overlay `project.md` как allow-list фильтра (kit без overlay молчит).

**Вариант C.** Оставить литералы, добавить комментарий «замените под свой проект».

Выбран A: kit без `project.md` должен работать; комментарий не мешает утечке при копировании `.cursor/`. B не закрывает учебные эталоны.

## Decisions

1. **Детектор, не развилка.** Смысл last-slice не меняется; меняется вычисление признака и ярлык `cf`.
2. **Один словарь примеров** на `.cursor/**`. Архив ЗНИ и отчёты `openspec/changes/archive/**` не трогаем.
3. **AP-031 не в этой ЗНИ.** Префиксы `pav_` / `lvv_` / `пр_` в allow-list — механизм.
4. **Связь с архивом:** extends `2026-08-30-last-slice-review-or-archive` и `2026-08-30-overview-map-offer`. Не Supersedes.
5. **ADR не создаём.** Повтор ADR-0009 на пороге описания; нейтральность примеров — гигиена поставки, не архитектурный выбор платформы.
6. **Architect / verify:** `required` (больше одного файла, смена контракта детектора и порога).

## Assumptions

1. В задачах пути к модулям содержат сегмент `/cf/` или `/cfe/` как в выгрузке конфигурации. Перед классификацией пути нормализуют `\` → `/`. Уверенность: высокая.
2. В kit-репозитории `openspec/project.md` нет — детектор обязан работать по путям в tasks/design. Уверенность: высокая.
3. Приёмка примеров — Grep по `.cursor/**`, не прогон чата на чужой ИБ. Уверенность: высокая.

## Slices

Пять срезов. Пользователь принял декомпозицию в плане работ. Отдельный срез «чеклист поставки» без видимого эффекта в командах не выделяется: пункт чеклиста входит в S1.

| Срез | Пользовательский сценарий | Primary acceptance | Scenarios из spec | Файлы | Приёмка |
|---|---|---|---|---|---|
| S1: Охват маркеров без чужих путей | В чужом проекте после последнего среза развилка смотрит на расширение в задачах, а не на имена ЭДО | Kit-only ЗНИ после «принято» — вопрос архива без слова «ревью»; в скилле реализации нет путей ЭДО | kit-project-neutrality «Фильтр без путей заказчика»; chat-surface-clarity last-slice «Без кода расширения» | скилл реализации, статус, глоссарий, чеклист поставки | сверка текста + Grep |

| S4: Ссылки и запасные инструменты | Контролёр срезов находится по рабочей ссылке; смысловой поиск при отсутствии инструмента не стопит | В скилле постановки ЗНИ ссылка контролёра открывается; в плане анализа нет `explore/fast` | delegation-safeguards сценарии ссылки и fallback | new SKILL, context-strategy, агент картографа, CHANGELOG, budget stub | Grep ссылок |

### Граф зависимостей

- S1 → нет
- S2 → нет
- S3 → нет
- S4 → нет
- S5: не foundation; Primary «Grep утечки = 0» — исход копирования `.cursor/` в чужой проект. Литералы в файлах S1–S4 править в той же задаче, что протокол. S5 — дочистка остатка по дереву + доказательство Grep. S1–S4 принимаются без S5; S5 Primary по дереву — после них (порядок apply S1→S2→S3→S4→S5).

Практический порядок apply: S1 → S2 → S3 → S4 → S5.

### Критерии приёмки по срезам

- **S1** SHALL: нет литералов чужой выгрузки как фильтра; словарь `cf`/`cfe`/`mixed`; развилка last-slice с тем же смыслом. Чеклист поставки — пункт про фильтр/сегменты, не список утечки.
- **S2** SHALL: порог описания по средству; нет «соседней ЗНИ»; условия «вывод» и «признак» остаются.
- **S3** SHALL: Read скилла на входе; cue диспетчера без тела протокола. Замер бюджета always-apply — задача агента, не blocking Primary.
- **S4** SHALL: ссылка контролёра `.cursor/skills/1c-agent-patterns/quality-controller.md` открывается; нет `explore/fast`; картограф без полного Read скилла карты.
- **S5** SHALL: 0 совпадений списка утечки в `.cursor/**` (включая дочистку остатка после S1–S4).

## Risks / Trade-offs

1. Правка apply-скилла пересекается с уже поставленной развилкой last-slice → менять только классификатор и ярлык `cf-ea`, не формулировку трёх слов.
2. Дописывание обрезки в always-apply увеличивает бюджет 34 КБ → держать 3–6 строк, не копировать весь on-demand файл.
3. Замена имён в эталонах сломает «голос» → менять только литералы, структуру абзацев не трогать.
4. Grep `Павлик` в CHANGELOG истории версий — предпочтительно убрать из рабочих примеров; исторические записи журнала агентов про модели не обязаны повторять имена заказчиков.

## Migration Plan

1. Заменить классификатор и ярлык `cf-ea` в apply, status, глоссарии, чеклисте.
2. Выровнять порог и фразу согласия в скилле описания.
3. Уточнить D5 и обрезку; ужать cue диспетчера.
4. Починить ссылки и fallback.
5. Заменить литералы по словарю.
6. Откат: вернуть литералы путей и примеров из git; развилку last-slice не откатывать целиком.

Все срезы: **mechanical** (markdown в `.cursor/**`).
