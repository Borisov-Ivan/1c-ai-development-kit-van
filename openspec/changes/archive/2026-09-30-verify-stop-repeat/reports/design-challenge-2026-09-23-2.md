## Three-Question Challenge

### Q1 — Problem-Solution Fit

- **Why говорит:** известные продуктовые развилки сериализуются в одиночные вопросы (каждый = полный прогон); агент вписывает свои ответы в постановку; контроль среза пять раз с нуля при стабильной структуре; разбор трижды держит одну цепочку; стоп петли на пятой правке вместо третьего касания темы.
- **Design адресует:**
  - Why «пакет известных вопросов» → D5 (пакет при создании) + D6 (карточка всех тем при остановке).
  - Why «агент вписал свои ответы» → D5 / Spec: не вписывать ответ на продуктовую развилку; метка по наблюдаемому поведению.
  - Why «контроль среза с нуля» → D3 / Spec: опора при том же наборе сценариев и том же тексте Primary.
  - Why «разбор повторяет цепочку» → D7 / Spec: леджер для перепроверки, классификация новый/повтор/сужение, неподтверждённое закрытие снова открывает тему.
  - Why «стоп на пятой правке» → D8 / Spec: тематический счётчик (второе переоткрытие) + D1 запасной порог правок в начале прохода.
  - Why «каждый ответ = полный прогон» → D9: запись ответа не смена постановки; стык глубины явно снимает «любая дописка → полный разбор» только для уточнения той же темы.
- **Покрытие:** полное — все болевые пункты Why имеют прямой механизм в design/spec/tasks без подмены симптома.

### Q2 — Optimality

- **Выбранный путь:** точечные правки существующих правил (две точки пакетирования + сходимость разбора + узкий отпечаток + тематический стоп + опора на прошлый контроль), без нового контура и без кода 1С.
- **Альтернативы (включая не упомянутые в Implementation Options A/B/C):**
  1. **Фильтр повторов на стороне оркестратора проверки** — skill проверки до запуска разбора отбрасывает темы из леджера со статусом «закрыт текстом», а разбор не обязан сам классифицировать. Плюс: проще принудить сходимость. Минус: якорит леджер как вердикт (прямо против Risks и Non-Goals); право атаковать закрытое с новым фактом слабее, чем при классификации самим разбором. Отклонена: хуже мандата независимого разбора при той же оси.
  2. **Идентичность темы только по номерам контрактов заказчика** (без номеров разрывов разбора). Плюс: проще S5 без зависимости от S4. Минус: темы, найденные разбором до ответа заказчика, не получают идентичность → петля снова ловится только запасным счётом правок (симптом Why «стоп на пятой правке» возвращается для агентских цепочек). Отклонена: не закрывает Why для тем без контракта.
  3. **Жёсткая блокировка первой проверки до записи ответов пакета** (отдельный машинный замок вне текста skill). Плюс: нельзя «проскочить» с открытыми развилками. Минус: новый контур оркестрации / состояния; ось «шесть файлов правил, без нового контура» ломается; resume уже идущих задач усложняется (Non-Goals). Отклонена: избыточна при исполняемом шаге D5 и Behavior Contract «первая проверка без открытых развилок».
- **Вердикт по Q2:** выбранный путь оптимален на заявленной оси: минимальная инвазивность, переиспользование каркаса, закрытие генератора круга и холостых повторов без отмены каскада дешёвого блокера (Option C) и без оставления генератора (Option B).
