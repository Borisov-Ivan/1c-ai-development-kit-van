## MODIFIED Requirements

### Requirement: Apply pause-wait is a navigator card

Когда разработка останавливается, потому что следующий шаг человека — создать или поправить объекты в Конфигураторе, выгрузить расширение или завести доп.реквизиты в базе, в чате MUST быть карточка-навигатор. Если в списке задач есть заголовки срезов, первой строкой MUST стоять фраза места среза из требования «Карточка приёмки показывает место среза»; список того, что создать, MUST NOT сокращаться. Дальше MUST быть: где мы; нумерованный список того, что создать; якорь файла и имя раздела с рецептом; как вернуться. Одна ссылка на файл паузы MUST NOT заменять этот список. Прогресс «0 из N» и перечень отсутствующих файлов выгрузки MUST NOT быть телом сообщения.

#### Scenario: Apply pause-wait lists objects in chat

- **WHEN** разработка останавливается, потому что в выгрузке расширения нет объектов, без которых нельзя писать код модулей, и в списке задач есть заголовки срезов
- **THEN** первая строка чата называет номер среза и оставшиеся открытые приёмки либо что срез последний; следом сказано, где мы; есть нумерованный список того, что создать; указан файл паузы и раздел «Что создать в Конфигураторе»; нет «0 из N» и списка отсутствующих файлов как тела сообщения

#### Scenario: Pause-wait is not a decision fork

- **WHEN** единственный путь вперёд — создать объекты по рецепту
- **THEN** в чате нет заголовка выбора «сделать чеклист или имена другие»; расхождение имён — одна фраза в конце, не развилка

#### Scenario: Isolated chat rejects a file-only pause

- **WHEN** в новом чате разработку вызывают на задаче без объектов в выгрузке
- **THEN** первое сообщение не состоит из заголовка «сессия приостановлена» и ссылки на файл паузы без списка «что создать»

### Requirement: Карточка приёмки показывает место среза

Фраза места среза живёт в одном абзаце правила чата у передачи на приёмку. Ожидание объектов, пауза с выбором, остановка по просьбе, карточка проверки на границе среза, конечная карточка пакета и снимок состояния MUST ссылаться на этот абзац и MUST NOT держать свою копию.

Фраза MUST входить в первые строки чата. У передачи, ожидания объектов, паузы с выбором, остановки по просьбе и конечной карточки пакета она MUST быть первой. У карточки проверки на границе среза первая строка MUST оставаться итогом проверки, а фраза места MUST стоять сразу следом, до следующего шага.

В фразе MUST быть номер среза из общего числа и имена срезов с ещё открытой приёмкой, включая более ранние, либо что этот срез последний. Имён MUST быть не больше трёх, дальше «и ещё N». На последнем срезе в ту же фразу MUST входить, что принять можно сейчас или позже и что следом будет выбор архива. Таблица следующих задач в чат MUST NOT добавляться. Открывать список задач, чтобы понять место среза, MUST NOT требоваться.

На границе среза номер MUST относиться к срезу, чья приёмка открыта. На конечной карточке пакета одного номера MUST NOT быть: названы срезы этой сдачи и какие приёмки ещё открыты. Фраза MUST писаться, только когда в списке задач есть заголовки срезов. Без заголовков пауза MUST оставаться как сейчас.

Карточку без этой строки MUST NOT отправлять: её собирают заново. Строка внизу файла её MUST NOT заменять. Строка о срезах, принятых без проверки, на карточке последнего среза MUST оставаться отдельным предупреждением и MUST NOT вливаться в фразу места.

#### Scenario: Передача называет место среза

- **WHEN** разработчик получает передачу первого из двух срезов
- **THEN** в первых строках чата видно «1 из 2», что срез не последний, и имя второго среза; список задач для этого не нужен

#### Scenario: Последний срез можно принять позже

- **WHEN** разработчик получает передачу последнего среза
- **THEN** в первых строках видно, что это последний срез, невыполненного кроме этой приёмки нет, и что принять его можно сейчас или позже, после чего сразу будет выбор архива

#### Scenario: Проверка не подменяет итог фразой места

- **WHEN** на границе среза приходит карточка проверки
- **THEN** первая строка — итог проверки, фраза места стоит сразу следом, до следующего шага

#### Scenario: Карточка без фразы не уходит

- **WHEN** в списке задач есть заголовки срезов, а черновик паузы не содержит фразу места
- **THEN** такая карточка в чат не отправляется и собирается заново

#### Scenario: Пакет называет сдачу без одного номера

- **WHEN** разработка заканчивается одной карточкой нескольких срезов
- **THEN** в чате названы срезы этой сдачи и какие приёмки ещё открыты, одного номера «N из M» нет
