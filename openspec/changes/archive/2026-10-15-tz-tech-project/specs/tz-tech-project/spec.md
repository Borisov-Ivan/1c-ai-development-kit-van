## ADDED Requirements

### Requirement: Техпроект по файлу задания

Команда MUST по файлу частного задания сначала создать рядом с ним `<имя файла задания без расширения>-вопросы.md` и `<имя файла задания без расширения>-согласование.md`. Файл `<имя>-техпроект.md` и файл `<имя>-постановка.md` MUST появляться только когда в листе вопросов есть подтверждение согласования и команда запускается снова. Команда MUST NOT создавать каталог задачи на разработку и MUST NOT править модули конфигурации. Чат MUST NOT заменять эти файлы и MUST NOT быть источником ответов. Лист MUST содержать вопросы с формулировкой, не меньше чем двумя вариантами и местом для ответа либо одну фразу «вопросов нет», и в обоих случаях MUST содержать строку подтверждения согласования. Дыры в задании и связь с уже сделанными изменениями команда MUST получать тем же протоколом исследования, что используется перед созданием задачи на разработку. Команда MUST NOT держать отдельный чеклист дыр и MUST NOT делать отдельную сверку имён с выгрузкой вторым источником. Команда MUST NOT читать `template/Техпроект` как источник правил и MUST NOT заменять входящий файл задания. Если во входящем файле нет готовых строк часов, строки MUST собираться по описанным работам. Если подходят две строки справочника, лист MUST содержать вопрос, а команда MUST NOT выбирать более тяжёлую строку молча. Если ни одна строка справочника не подходит, лист MUST содержать вопрос по этой работе, а команда MUST NOT выдумывать часы и MUST NOT ставить их, пока ответа нет. Если строка одна, часы MUST быть равны (нижняя граница строки × коэффициент справочника) + сумма нижних границ всех факторов надбавки, названных в задании. Надбавка MUST быть нулём, если ни один фактор не назван, и MUST NOT умножаться на коэффициент. Если результат дробный, часы MUST подниматься до следующего целого; целое значение MUST оставаться без изменения. Середина диапазона и полная формула справочника MUST NOT применяться. Таблица нормативов, диапазон, коэффициент и формула MUST NOT попадать в лист, согласование, техпроект, постановку и чат. При повторном запуске уже вписанный ответ MUST сохраняться у вопроса с той же формулировкой. Согласование MUST быть текстом для согласования часов: как сейчас, зачем, этапы для людей, что появляется, как работает, что сознательно не делаем, как это закрывает задание, что согласовать, строки часов и указание, что подтверждение вносится в лист. Техпроект MUST быть таблицами: объект, реквизит или табличная часть, тип, назначение; проводка только если она есть в задании; внедрение и откат; работа, часы, обоснование. Техпроект MUST NOT содержать текст процедур. Постановка MUST быть блоком «Постановка ЗНИ» для создания задачи на разработку: симптом, корневая причина, что менять, файлы, приёмка и связь с уже сделанными изменениями. Постановка MUST NOT заменять техпроект. Команда MUST NOT додумывать сведения, которых нет в задании. Если названного объекта нет в конфигурации, лист MUST содержать дыру по этому имени, а техпроект MUST NOT содержать выдуманный реквизит или проводку. Пометки пробелов в согласовании MUST NOT заменять лист вопросов и MUST NOT задавать эти вопросы по одному в чат.

#### Scenario: Согласование часов

- **WHEN** пользователь передаёт файл частного задания
- **THEN** рядом с заданием появляются `<имя>-вопросы.md` и `<имя>-согласование.md`: лист вопросов и текст согласования часов с этапами для людей и часами
- **AND** в листе, согласовании и чате нет таблицы нормативов, формулы расчёта и ссылки на справочник нормативов
- **AND** у каждого вопроса не меньше двух вариантов и есть место для ответа, если лист не сведён к фразе «вопросов нет»
- **AND** в листе есть строка подтверждения согласования часов
- **AND** файлов техпроекта и постановки ещё нет

#### Scenario: Техпроект для технического задания

- **WHEN** в листе вопросов есть подтверждение согласования и пользователь снова запускает команду по тому же файлу задания
- **THEN** рядом появляется `<имя>-техпроект.md` таблицами объектов, внедрения, отката и часов
- **AND** в техпроекте нет текста процедур
- **AND** входящий файл задания не заменён
- **AND** каталог задачи на разработку не создан

#### Scenario: Постановка для задачи на разработку

- **WHEN** в листе вопросов есть подтверждение согласования и пользователь снова запускает команду по тому же файлу задания
- **THEN** рядом появляется `<имя>-постановка.md` блоком «Постановка ЗНИ»: симптом, корневая причина, что менять, файлы, приёмка и связь с уже сделанными изменениями
- **AND** этот файл не заменяет техпроект и не заменяет входящее задание

#### Scenario: В задании нет дыр

- **WHEN** в задании нет пробела, без которого нельзя описать решение
- **THEN** лист вопросов состоит из фразы «вопросов нет» и строки подтверждения согласования
- **AND** согласование и техпроект не содержат выдуманных объектов и проводок

#### Scenario: Повторный запуск с ответами

- **WHEN** пользователь вписал ответы в лист вопросов и снова запускает команду по тому же файлу задания
- **THEN** обновляются те же `<имя>-вопросы.md` и `<имя>-согласование.md`, новые копии файлов не появляются
- **AND** уже заполненные в задании строки часов не затираются
- **AND** уже вписанные ответы сохраняются у вопросов с той же формулировкой

#### Scenario: Часы собраны из прозы задания

- **WHEN** во входящем файле нет готовых строк часов, есть только описание работ, и ему соответствует одна строка справочника
- **THEN** в согласовании есть строки с работой, часами и обоснованием вида работы словами
- **AND** часы равны нижней границе строки, умноженной на коэффициент, плюс сумма нижних границ названных факторов надбавки, и при дробном результате подняты до следующего целого часа
- **AND** в листе, согласовании, техпроекте и чате нет таблицы нормативов, диапазона, коэффициента и формулы

#### Scenario: Несколько факторов надбавки

- **WHEN** в задании названо два или больше факторов надбавки и для работы подходит одна строка справочника
- **THEN** к часам прибавляется сумма нижних границ этих факторов
- **AND** каждый фактор на коэффициент не умножается

#### Scenario: Нет подходящей строки справочника

- **WHEN** описанной работе не подходит ни одна строка справочника часов
- **THEN** в листе есть вопрос по этой работе
- **AND** часы по этой работе не выдуманы и не проставлены, пока нет ответа

#### Scenario: Папка шаблонов не меняет запуск

- **WHEN** после переноса правил меняется только папка `template/Техпроект`, а копия в навыке нет
- **THEN** повторный запуск по тому же заданию не меняет из-за этой правки часы и состав дыр в листе

#### Scenario: В конфигурации нет названного объекта

- **WHEN** в задании назван объект или счёт, которого в конфигурации нет
- **THEN** лист вопросов содержит дыру по этому имени
- **AND** техпроект не содержит выдуманного реквизита или проводки

### Requirement: Обзор задачи не меняется

Команда MUST копировать в свой навык каркас сюжета и голос обзора и MUST NOT изменять файлы обзора задачи. Команда MUST NOT копировать протокол входа обзора, который ждёт подтверждения в чате до записи текста. Исследование дыр MUST NOT подменять файлы команды диалогом в чате.

#### Scenario: Обзор остаётся компилятором готовой задачи

- **WHEN** команда готовит согласование часов по сырому заданию
- **THEN** обзор задачи по-прежнему собирает текст только из уже созданной задачи и не считает часы
- **AND** согласование записывается в файл без отдельного подтверждения в чате до старта
