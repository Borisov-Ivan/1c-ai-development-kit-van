**Сценарий:** тяжёлый разбор, сверка с прошлым договором и просьба самой сильной модели описаны старшим Opus 5; строка «Разбор постановки (Fable)» нигде не разрешена.

**Primary acceptance:** открыть правило назначения и увидеть раздел «Таблица шагов архитектора»: в заголовке нет слова Fable, второй таблицы нет, три бывших сильных шага вызывают старшую модель семейства Opus, мажор 5, со строкой «Разбор постановки (Opus 5)». В бюджете реплик проверки постановки строки про Fable нет.

**Приёмка:** чтение правила, бюджета реплик и профиля. Конфигурация 1С не нужна.

**Связь со spec:** Requirement «Бывшие сильные шаги архитектора идут на Opus» — Scenario «Заголовок раздела не называет Fable», «Тяжёлый разбор идёт на Opus, даже если Fable в списке», «Сверка с прошлым договором идёт на Opus», «Просьба самой сильной модели не вызывает Fable», «Написание и ревью не получают слаг Fable», «В списке нет Opus 5 для бывшего сильного шага», «Сбой Opus не включает Fable», «Обычный разбор без тяжёлого признака не отменяется»; Requirement «Progress команд /opsx:* только на русском» — Scenario «Verify без английского progress», «Progress на русском»; Requirement «Видимость режима без API — канон в том же ходе, не токен» — Scenario «Строка про Fable не исключение проверки», «Канон в том же ходе», «Токен не печатается», «Фон не отменяется»; Requirement «Трёхуровневая пирамида профилей» — Scenario «Профиль Fable не идёт в бриф роли», «Профиль активен для известной модели», «Бриф субагента учитывает профиль его модели», «Неизвестная модель».

**Зависимости:** нет.

## 1. Правило назначения

- [x] S1.1 Заменить в `.cursor/rules/model-selection.mdc` выбор семейства Fable на старший Opus 5, чтобы тяжёлый разбор, сверка с договором и просьба самой сильной модели не вызывали Fable (D1, D2, D5).
  - Строки бывших сильных шагов вызывают старшую модель семейства Opus, мажор 5, и строку «Разбор постановки (Opus 5)», даже если Fable есть в списке.
  - Ветки «сначала Fable», «нет Fable — тогда Opus», «один вызов Fable на повод» и «пока слаг есть» снимаются. Сбой Opus ведёт к вызову без отдельной модели. Fable не подставляется.
  - Слаг семейства Fable не передаётся в написание, обследование, трассу, ревью и упрощение, в том числе по прямой просьбе и разовым указанием. Слаг другого семейства по явной просьбе для написания, обследования и трассы остаётся.
  - Раздел называется «Таблица шагов архитектора». Старое имя со словом Fable снимается. Вторая таблица не появляется. Живые отсылки на старое имя заменяются на новое в `.cursor/skills/openspec-verify-change/SKILL.md`, `.cursor/skills/1c-agent-patterns/architect.md`, `.cursor/skills/1c-agent-patterns/SKILL.md`, `.cursor/rules/architect-gate.mdc`, `.cursor/rules/tool-name-guard.mdc` и `.cursor/rules/verified-cause-gate.mdc`. Фраза «заголовок раздела не переименовывать» из этих текстов уходит. Вместе с лестницей уходят и запреты, которые всё ещё называют этот путь: «Fable не запас», «не эскалировать сбой на Fable», «Fable только по таблице шагов». Архив и журнал агентов не переписываются. Слово Fable остаётся в профиле чата, в роутере «чат открыт на Fable» и в примерах разбора версии, которые в вызов не передаются.
  - Пять мест проверки нескольких частей и фразы про профиль GPT-5.6 не меняются. В дельте требования мэппинга эти предложения не копируются.
  - Критерий: в файле нет назначения шага на семейство Fable; раздел называется «Таблица шагов архитектора»; закрыты сценарии «Заголовок раздела не называет Fable», «Тяжёлый разбор идёт на Opus, даже если Fable в списке», «Сверка с прошлым договором идёт на Opus», «Просьба самой сильной модели не вызывает Fable», «Написание и ревью не получают слаг Fable», «В списке нет Opus 5 для бывшего сильного шага», «Сбой Opus не включает Fable», «Обычный разбор без тяжёлого признака не отменяется».

# Срез S2: Один хозяин на шаг

**Сценарий:** на один шаг остаётся один порядок. Обследование любого объёма и короткий текст ошибки идут обследователю. Команда не держит второй список шагов. Пакет продуктовых развилок остаётся одним сообщением.

**Primary acceptance:** открыть перечень агентов и увидеть, что обследование кода не ограничено тремя модулями.

**Приёмка:** чтение правил и команд. Конфигурация 1С не нужна.

**Связь со spec:** Requirement «Запрет built-in Explore для 1С-кода» — Scenario «Один модуль тоже обследование», «Короткий текст ошибки без трассы», «Обследование BSL при недоступном кастомном агенте», «Не-1С файлы»; Requirement «Цепочка вызова читается из строки роли» — Scenario «Сбой написания не повторяет тот же вызов», «Простая готовность задач без отдельной модели», «Пример ревью не теряет модель роли»; Requirement «Пакет продуктовых развилок остаётся одним актом» — Scenario «Две продуктовые развилки уходят одним сообщением», «Маркер и форма не сливаются»; Requirement «Команда не держит второй порядок шагов» — Scenario «Дописывание не зовёт проверку всегда», «Создание не ставит маркер раньше брифа»; Requirement «В подписанный срез задача не дописывается сама» — Scenario «Новая задача после подписи»; Requirement «Указатель раздела бюджета называет файл, где раздел есть» — Scenario «Раздел есть только в полном теле».

**Зависимости:** S1.

## 1. Вызов ролей

- [x] S2.1 Поправить `.cursor/rules/model-selection.mdc`: роль, у которой первый шаг уже без отдельной модели, после сбоя не вызывается второй раз тем же способом, а простая готовность задач остаётся без отдельной модели (D7).
  - В шапке правила оговорка: модель передаётся, только если строка роли её задаёт.
  - Фраза «цепочка каждой роли — два шага» не покрывает написание, обследование и трассу.
  - Критерий: закрыты сценарии «Сбой написания не повторяет тот же вызов» и «Простая готовность задач без отдельной модели». Зависимости: S1.1.

  - Строка обследователя больше не говорит «3+ модулей». В таблице остановок то же.
  - У архитектора модель берётся из строки шага, в том числе когда отдельной модели нет.
  - Шапка шаблона проверки частей заявки не называет файл агента источником модели.

  - Критерий: закрыты сценарии «Один модуль тоже обследование» и «Пример ревью не теряет модель роли». Зависимости: S1.1.
