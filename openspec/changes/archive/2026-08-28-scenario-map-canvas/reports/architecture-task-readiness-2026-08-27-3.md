## Замечания (не блокируют старт)

### Замечание 1 — в шаблоне выхода останется вторая строка про перезапись (критерий 5)

**Задача:** S1.10a.

S1.10a просит отразить оговорку в разделе «Артефакт журнала (обязательно)» шаблона выхода. Но в том же файле есть ещё два места про запись, вне этого раздела:

- шаг B, последняя строка: «Перезаписать тот же `explain-*.md` с секцией **Заметки**»;
- шаг A, пояснение: «На шаге A файл уже записан (карта + журнал точек; секция „Заметки“ — пустая или отсутствует)» — перечисление разделов, где секции узлов карты нет.

Если правка ляжет буквально по тексту задачи, исполнитель, читающий шаг B, увидит прямое указание перезаписать файл. Ловушка не смертельная — оговорка в разделе «Артефакт журнала» стоит выше и покрывает обе записи, — но одну строку стоит закрыть словами.

**Рекомендация.** В S1.10a добавить, что оговорка распространяется на **все** записи журнала на выходе, включая строку шага B шаблона выхода, а перечисление разделов на шаге A упоминает необязательную секцию карты. Полезно и одно слово в проверочном списке выхода в скилле разбора (пункт про записанный журнал): «секция карты, если была, сохранена».

Второй, более мелкий пункт того же порядка: место секции в каркасе журнала не названо. Читаемо будет после «Журнал» и до «Заметки» — стоит назвать прямо в задаче, чтобы два исполнителя не сделали по-разному.

### Замечание 2 — путь журнала при досрочном создании файла не назван (критерии 1, 5)

**Задачи:** S1.1a, S1.6.

Журнал разбора маршрутизируется по контексту: без привязки к ЗНИ — в рабочий каталог отчётов, при названной ЗНИ — в каталог отчётов этой ЗНИ (таблица есть и в шаблоне журнала, и в шаблоне выхода). Когда файл создаётся досрочно (просьба в середине прохода, панель недоступна), путь выбирает скилл карты, а не выход разбора. Задачи говорят «создаётся по шаблону `explain-report.md`» — таблица маршрутизации внутри шаблона есть, поэтому вывод правильный, но не сказанный.

Риск узкий и реальный: если досрочный файл ляжет по одному пути, а выход запишет по другому (например, ЗНИ названа позже, уже после просьбы о карте), узлы формально сохранятся, но не в том файле, который увидит пользователь по строке «Журнал: …».

**Рекомендация.** Одна фраза в S1.1a или S1.6: путь досрочно созданного журнала — по таблице маршрутизации шаблона, тот же файл, который запишет выход; если контекст ЗНИ появился позже, узлы переносятся в файл выхода. Решения, срезы и спецификацию менять не нужно.

### Замечание 3 — просьба вне сессии разбора не описана в спецификации (критерий 4)

Переносится из прошлого отчёта без изменений: поведение задано решением о источнике узлов и задачами S1.5 / S1.8 (узлы только из существующего журнала или указанного пользователем отчёта, иначе отказ одной строкой), а в спецификации требование молчания ограничено сессиями разбора и исследования, требование прямой просьбы — серединой прохода и выходом. Поведение консервативное (по умолчанию отказ), поэтому это не блокер.

Если нужно совпадение проверяемого и описанного, достаточно одного сценария в требовании «Direct request draws the scenario map»:

```markdown
#### Scenario: Просьба вне сессии разбора

- **WHEN** пользователь просит карту сценария вне сессии разбора и журнала разбора или указанного отчёта нет
- **THEN** панель не строится, в чате одна строка — из чего карту можно построить
```

## Наблюдения

Ни одно не блокирует старт; фиксирую, чтобы автор кита решал осознанно.

1. **Два похожих заголовка в журнале.** В каркасе журнала уже есть раздел «Карта» — список имён пройденных точек, то есть ровно та карта точек, которую ЗНИ разводит с картой сценария по имени. После S1.10a рядом появится «Карта сценария». Формально это и есть проверка на различимость имён, но человек, открывший файл, увидит два соседних заголовка с общим словом. Дешёвое лечение — комментарий-подсказка в каркасе у обоих разделов (в каркасе такие комментарии уже приняты, например у «Заметки»).
2. **S1.10a — одна задача на три файла в блоке про точки вызова.** По смыслу это правка артефакта журнала, а не точки вызова карты. Разбить на две (шаблон журнала; скилл разбора и шаблон выхода) или перенести в отдельный блок — вопрос читаемости, не готовности.
3. **Строка в файле диспетчера (S1.8).** Без изменений с прошлого отчёта: строка несёт и запрет («в сессиях `/opsx:*` карту рисовать только по просьбе или сработавшему намёку»), и указание («просьба → прочитать скилл карты»), тогда как таблица, в которую её просят добавить, состоит из пар «триггер → файл правила», а сам файл в назначении объявляет «только триггеры». Практичное размещение — короткий абзац рядом с алгоритмом (запрет) плюс строка-указатель на скилл (дверь).
4. **Эталон узлов (S1.7).** Без изменений: решение называет его fixture, задача просит секцию внутри файла скилла. В ките эталоны голоса разбора лежат отдельными файлами в каталоге `fixtures/` рядом со скиллом (проверено: шесть файлов эталонов голоса), поэтому исполнитель, читающий сначала решение, может создать файл, которого нет в списке файлов среза. Спецификация требует лишь «в нём есть пример узлов» — оба варианта проходят приёмку, стоит выбрать одно слово в обоих артефактах.
