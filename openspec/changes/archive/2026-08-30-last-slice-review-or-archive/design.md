## Context

После ручной приёмки последнего среза скилл реализации спрашивает только про архив (`архив` / `стоп`) и по слову `архив` архивирует ЗНИ в той же сессии. Предрелизное ревью в этот момент не предлагается, хотя имя ЗНИ известно, карта правок накоплена, задачи с путями закрыты.

Второй путь того же события — возврат в сессию и ответ «принят»: ход уходит в карточку «реализация завершена» со строкой команды архива. Два финала одного события уже расходятся.

Штатное дополнение постановки по отчёту предрелиза доступно, только пока каталог ЗНИ не в архиве. Предрелиз уже умеет взять одну ЗНИ без имени расширения и сам вывести границы по артефактам.

Разбор постановки: `reports/architecture-2026-08-30.md`. Связанные ADR: ADR-0002 (предложить следующую команду, пока границы известны; не автостарт) — применяется, не отменяется; ADR-0001 и ADR-0003 не затрагиваются.

## Goals / Non-Goals

**Goals:**

1. После приёмки последнего среза, если в ЗНИ есть код расширения, разработчик видит один вопрос: предрелиз, архив или стоп.
2. Слова `архив` и `стоп` ведут себя как сегодня. Предрелиз не запускается из сессии реализации: в чат уходит готовая команда с именем ЗНИ.
3. Все входы события «последний срез принят» (фраза «принято», ответ «принят» при возврате, ранний выход «все задачи закрыты», карточка завершения) показывают одну и ту же развилку.
4. Без кода расширения вопрос остаётся прежним.

**Non-Goals:**

1. Менять слот «следующий шаг» проверки постановки после apply.
2. Автозапуск предрелиза внутри реализации; новая команда `/opsx:*`.
3. Подставлять имя расширения в команду; дублировать разбор границ в скилле реализации.
4. Жёсткий запрет архива до предрелиза.
5. Соседние ЗНИ про карту сценария.
6. Прямой вызов `/opsx:archive <имя>` из нового чата не предлагает предрелиз: пользователь уже выбрал архив. Напоминание на входе архивации — отдельная ЗНИ, не эта.

## Existing Mechanisms

1. Вопрос архива после последнего среза и автоархив по слову `архив` в той же сессии — расширяется третьим ответом, не заменяется.
2. Карточка «реализация завершена» со строкой архива и ранний выход шага 3 «все задачи закрыты» (`congratulate, suggest archive`) — оба ведут на ту же развилку, а не печатают свой текст.
3. Команда `/release-review <имя-ЗНИ>` — предлагается как есть; разбор файлов остаётся на стороне ревью.
4. Признак «есть ли код расширения в путях задач» уже считается в сессии реализации — условие показа `ревью`, новый детектор не нужен.
5. ADR-0002 — форма: предложить, не запускать.

Почему не оставляем как есть: момент приёмки последнего среза — единственная точка, где границы ЗНИ ещё полные и постановку ещё можно дописать штатно. Новый механизм не вводится.

## Design Rationale

Точка правки — скилл реализации: одна формулировка развилки на событии «последний срез принят», плюс одна строка в памятке ревью. Предрелиз не встраивается в протокол реализации: у него свой вход, свой разбор границ и свой выбор по качеству. Подставлять расширение в команду нельзя: это второй источник границ. Жёсткий гейт «сначала ревью» ломает автоархив и ЗНИ без кода расширения. Разбор: `reports/architecture-2026-08-30.md`.

## Behavior Contract

1. Развилка привязана к событию «приёмка последнего среза произошла в этой сессии», не к одному тексту ответа. Последний срез — нет следующего заголовка среза с большим номером.
2. Ответ `ревью` показывается, только если в путях выполненных задач есть модули расширения. Иначе — прежний вопрос `архив` / `стоп`.
3. Формулировка развилки одна. Её печатают: фраза «принято» на последнем срезе; ответ «принят» при возврате в сессию, если срез последний; карточка «реализация завершена» и ранний выход «все задачи закрыты» на шаге 3, если пришли в реализацию, а всё уже принято, и есть код расширения. Ранний выход не печатает отдельное «предлагаю архив»: после вычисления признака кода расширения ход идёт на ту же карточку.
4. На `ревью` оркестратор печатает ровно один следующий шаг `/release-review <имя-ЗНИ>` и завершает сессию реализации. ЗНИ остаётся активной. Предрелиз в этой сессии не стартует.
5. На `архив` — шаги архивации в этой же сессии, как сегодня. На `стоп` — сессия без архива, как сегодня.
6. В сообщении с развилкой нет второй команды в слоте следующего шага: один вопрос с тремя словами. После `ревью` — одна команда, без повторного вопроса в том же ходе. Развилка — только чат; в файле `reports/handoff-final-*.md` — нейтральный перечень доступных команд без формы вопроса.
7. Проверка постановки после apply не меняется.

## Implementation Options

**Вариант A.** Одна развилка из трёх слов на событии приёмки; оба пути приёмки и карточка «реализация завершена» ссылаются на неё; предрелиз только командой в чат.

**Вариант B.** Жёсткий порядок: архив недоступен, пока нет предрелиза.

**Вариант C.** Автозапуск предрелиза внутри сессии реализации.

**Вариант D.** Дописать в текущий вопрос строку с командой предрелиза, не меняя ответы.

Выбран A: минимальное расширение существующего хука, контракт «один сигнал в сообщении» соблюдён, автоархив сохранён. B ломает ЗНИ без кода расширения и ADR-0002. C смешивает два протокола. D даёт вопрос и команду одновременно.

## Decisions

1. **Порядок — рекомендация, не гейт.** Сначала ревью удобнее, потому что дополнение постановки после архива штатно закрыто. Слово `архив` по-прежнему архивирует сразу.
2. **Аргумент команды — только имя ЗНИ.** Расширение выводит сам предрелиз. Неоднозначность — его вопрос про охват, не скилл реализации.
3. **Условие `ревью` — код расширения в путях задач.** ЗНИ только по правилам kit и ЗНИ только по базовой конфигурации сохраняют бинарный вопрос.
4. **Единая формулировка.** Шорткат «принято», возврат в сессию, ранний выход «все задачи закрыты» и карточка завершения не получают разные тексты.
5. **Связь с архивом:** новый change, класс `extends` к `2026-08-09-explain-after-review-apply-scope` (предложить, пока границы известны). Контракт «последний срез → только архив» жил в скилле, не в main-спеке; отменяемого требования в `openspec/specs/` нет.
6. **ADR не создаём.** Повтор ADR-0002 на соседней точке; обратимо правкой текста.

## Risks / Trade-offs

1. После `ревью` забудут архив → в ответе явно: архив останется доступен обычной командой; не автоархивируем после ревью.
2. ЗНИ без модулей расширения получит пустой предрелиз → слово `ревью` не показываем.
3. Два финала останутся, если поправить только фразу «принято» или только шаблон карточки шага 7 → правим и возврат в сессию, и ранний выход «все задачи закрыты», и карточку «реализация завершена», и строку варианта `final` в памятке оформления.
4. Смешение протоколов, если запустить предрелиз из реализации → только печать команды.
5. Правило оформления финала останется со строкой архива, если править только скилл → правим и памятку оформления.

## Migration Plan

1. Заменить бинарный вопрос после последнего среза на развилку с условием показа `ревью`.
2. Для последнего среза на ответе «принят» при возврате вести на ту же развилку, не в карточку с одной командой архива.
3. Ранний выход «все задачи закрыты» (шаг 3) не печатает свой финал: после признака кода расширения ведёт на ту же карточку завершения.
4. В карточке «реализация завершена» при коде расширения печатать ту же развилку в чат; в файле handoff — перечень команд без вопроса.
5. В памятке оформления строка варианта `final`: при коде расширения — та же развилка (сигнал — ответ в чате), без кода расширения — прежняя строка с командой архива.
6. Добавить строку в памятке ревью.
7. Откат: вернуть бинарный вопрос, ранний выход «предлагаю архив» и строку архива в карточке и в памятке оформления; памятку ревью убрать.

## Assumptions

1. Признак «есть код расширения» доступен к моменту приёмки: он считается до цикла задач. На раннем выходе «все задачи закрыты» тот же проход по списку задач выполняется до печати (шаг 3 сейчас идёт раньше шага 4 — признак нужно посчитать явно). Уверенность: высокая.
2. Предрелиз по одной ЗНИ сам находит расширение по путям. Уверенность: высокая (команда и резолвер уже так работают).
3. Приёмка — ручной прогон реализации на ЗНИ с кодом расширения и на kit-only; автотестов чата нет.

## Открытые вопросы

Нет. Слово `ревью` (а не «предрелиз») — обратимая правка одной строки.
