## Простота решения (оценка плана, без пересмотра подхода)

План минимален для заявленного поведения: одна новая формулировка, одно условие показа, три места ссылки, одна строка в памятке. Ни одна задача не добавляет хранилища, параллельного протокола или нового признака. Единственное расширение, которое рекомендуется ниже, — не усложнение, а перенос уже принятого поведения в два места, где сегодня печатается старый финал.

## Пробелы

### Пробел 1 — вход в полностью принятую ЗНИ печатает старый финал (критерий 4)

**Задача:** отсутствует; ближайшая — задача про карточку завершения.

**Что отсутствует.** В скилле реализации есть две точки, где сессия сообщает «всё принято». Первая — шаг 3, обработка состояния «все задачи закрыты»: «поздравить, предложить архив»; это ранний выход, он срабатывает именно в сценарии «разработчик открывает реализацию ЗНИ, где все срезы уже приняты». Вторая — карточка завершения в шаге 7, её задачи правят. Если поправить только вторую, основной путь входа продолжит печатать одно предложение про архив, и сценарий спецификации про карточку завершения не выполнится — останутся два разных финала одного события, ровно тот риск, ради которого правится ветка возврата в сессию.

Дополнительно есть порядковая деталь, которую постановка сейчас не закрывает: признак «есть код расширения» вычисляется на шаге 4, то есть **после** обработки состояния на шаге 3. Поэтому недостаточно сказать «печатать развилку при коде расширения» — нужно указать, откуда шаг 3 берёт признак.

**Рекомендация.** Добавить задачу, которая делает шаг 3 не самостоятельной точкой печати, а переходом к единственной карточке завершения (тогда формулировка остаётся в одном месте и признак уже вычислен). Разместить перед задачей про карточку завершения; в план миграции постановки добавить соответствующий пункт.

**Сниппет для вставки в раздел «2. Карточка „Реализация завершена“»:**

```markdown
- [ ] S1.4a В `.cursor/skills/openspec-apply-change/SKILL.md`, шаг 3 «Get apply instructions», обработка состояния `state: "all_done"` («congratulate, suggest archive»): не печатать финал прямо в этой ветке, а вести ход к карточке «Реализация завершена» шага 7 после вычисления признака кода расширения на шаге 4, чтобы вход в полностью принятую ЗНИ давал тот же единственный финал, что и остальные пути приёмки последнего среза (Behavior Contract п. 3, Migration Plan п. 3, Scenario «Карточка завершения — та же развилка»)
```

### Пробел 2 — правило оформления финала остаётся с одиночной строкой архива (критерий 5)

**Задача:** отсутствует; ближайшая — задача про карточку завершения.

**Что отсутствует.** Шаг 7 скилла реализации начинается словами «Формат — T-HANDOFF из `.cursor/docs/opsx-output-style.md` §5.2», а в самой памятке по оформлению строка варианта «финал» таблицы тонкого чата предписывает: одна строка «работы завершены» плюс следующий шаг — команда архива. Файл не назван ни в разделе влияния постановки, ни в файлах среза, ни в плане миграции. После правок скилла останется правило, которое прямо запрещает то, что скилл теперь печатает, — а итоговая сверочная задача требует, чтобы формулировка развилки жила в одном месте, и на этом расхождении она даст ложный результат.

Там же стоит закрыть смежную деталь: правило «один сигнал ответственности» разрешает в сообщении либо следующий шаг командой, либо приглашение ответить в чате. Финал с развилкой меняет тип сигнала с первого на второй — это допустимо, но должно быть написано, иначе самопроверка вывода сработает против новой карточки.

**Рекомендация.** Добавить задачу на правку строки варианта «финал» и дописать файл в раздел влияния постановки, в колонку файлов среза и в план миграции.

**Сниппет для вставки в раздел «2. Карточка „Реализация завершена“» (после задачи про карточку):**

```markdown
- [ ] S1.5a В `.cursor/docs/opsx-output-style.md` §5.2, строка `final` таблицы тонкого чата: описать, что при наличии кода расширения вместо одной строки со следующим шагом `/opsx:archive <name>` печатается та же развилка из трёх слов, а без кода расширения строка остаётся прежней; отметить, что в этом случае сигнал сообщения — приглашение ответить в чате, а не команда следующего шага, чтобы правило оформления и текст скилла реализации не расходились (Decisions п. 4, Behavior Contract п. 3, п. 6)
```

**Сниппет для постановки** (раздел «Impact» и колонка «Файлы» таблицы срезов): добавить `.cursor/docs/opsx-output-style.md` к перечню «скилл реализации, памятка ревью».

## Наблюдения (не блокируют)

1. **Формулировка и условие подряд в одном разделе — достаточно as-is.** Задача про развилку заменяет бинарный вопрос, следующая задача добавляет условие показа и возвращает прежний вопрос для ЗНИ без кода расширения. Правки дополняющие, идут подряд по одному файлу, приёмки между ними нет, а итоговая сверка проверяет результат целиком. Переформулировка не требуется.
2. **Признак кода расширения совпадает с живым текстом.** На шаге 4 скилла признак действительно вычисляется поиском путей `src/**/*.bsl` по задачам и постановке, значения — «только базовая конфигурация», «только расширение», «оба». Трактовка задач (показывать при «только расширение» и «оба», не показывать при пустом и «только базовая конфигурация») совпадает с определением. Классификация опирается на конкретные пути каталогов из карточки проекта — это существующее свойство kit, ЗНИ его не ухудшает.
3. **Единая формулировка условия.** Задача про карточку завершения говорит «при наличии кода расширения», задача про условие показа — через значения признака. Смысл один; при правке стоит использовать одну и ту же формулировку условия, чтобы итоговая сверка читалась однозначно.
4. **Команда предрелиза в списке пользовательских команд.** Памятка по оформлению перечисляет пользовательские команды примерами (`/opsx:apply`, `/opsx:archive`, `/opsx:verify`); `/release-review` там не назван, но список открытый, и в памятке ревью команда описана как пользовательская. Действий не требуется.
5. **Снимок состояния ЗНИ** рекомендует архив при всех принятых срезах. Это другая команда и другая поверхность, спецификация её не описывает; при желании — отдельный follow-up, не эта ЗНИ.
