## ADDED Requirements

### Requirement: Лист вопросов только по существу

Команда MUST по файлу задания или по тексту уже существующей задачи, если она указана вместо файла, создать лист вопросов только с вопросами по существу задачи. В листе MUST NOT быть вопросов про часы, вид работы, демонстрацию, внедрение и откат. У каждого вопроса MUST быть не меньше двух вариантов и место для ответа, либо лист MUST состоять из фразы «вопросов нет». В листе MUST быть строка подтверждения. Ответы по существу MUST читаться из листа, а для уже существующей задачи также из её решений; чат MUST NOT быть источником ответов по существу. Если вместо файла задания указана уже существующая задача, команда MUST NOT создавать файл постановки.

#### Scenario: Лист только по существу

- **WHEN** в задании есть пробел по существу, в том числе не выбрано имя отчёта
- **THEN** в листе есть этот вопрос и нет вопросов про часы
- **AND** у вопроса не меньше двух вариантов и есть место для ответа

#### Scenario: Часы не в листе

- **WHEN** описанной работе подходят две строки справочника часов
- **THEN** в листе нет вопроса, какую строку выбрать
- **AND** предварительная оценка при этом названа

### Requirement: Предварительная оценка вместе с листом

В том же запуске, что и лист, команда MUST назвать предварительную оценку в чате и записать её в согласование с явной пометкой, что оценка предварительная. Нюанс, который не меняет состав работ, MUST NOT оставлять эту оценку пустой. Если под работу подходят две строки справочника, команда MUST выбрать одну сама и MUST назвать в чате обоснование словами. Если не подходит ни одна строка, команда MUST сначала записать лист и согласование с пустой строкой по этой работе, затем задать один вопрос в чате и MUST NOT ставить часы по этой работе, пока ответа в чате нет. Повторный запуск в новом чате без этого ответа MUST задать тот же вопрос. Уже указанные в задании часы MUST переноситься как есть. Часы, названные или поправленные в чате, MUST записываться в том же ходе в согласование и MUST оставаться предварительными. Повторный запуск без пометки в листе MUST NOT пересчитывать эти строки из-за ответов в листе. Повторный запуск без пометки MUST NOT менять в согласовании цифры, посчитанные командой, из-за ответов в листе; пересчёт этих строк MUST идти только в техническом проекте. Исключение — пустая строка, которую заполнил ответ в чате. Таблица нормативов, коэффициент и формула MUST NOT попадать в лист, согласование, чат, технический проект и постановку.

#### Scenario: Предварительная оценка с листом

- **WHEN** пользователь передаёт задание, где среди прочего не выбрано имя отчёта, и состав работ из текста задания понятен
- **THEN** рядом с листом есть предварительная оценка
- **AND** технического проекта ещё нет

#### Scenario: Нет подходящей строки справочника

- **WHEN** описанной работе не подходит ни одна строка справочника часов
- **THEN** в листе нет вопроса по этой работе, в согласовании строка часов пустая, и в чате задан один вопрос
- **AND** пока ответа в чате нет, часы по этой работе не проставлены

#### Scenario: Часы из чата сохраняются

- **WHEN** пользователь в чате называет или поправляет часы по работе, и в листе ещё нет пометки
- **THEN** в том же запуске эти часы записаны в согласование и помечены как предварительные
- **AND** повторный запуск без пометки не меняет эти строки из-за ответов в листе

### Requirement: Уточнённая оценка в техническом проекте

Уточнённая оценка MUST появляться в техническом проекте по результатам ответов и только когда проект пишется. Пока технического проекта нет, оценка в согласовании MUST оставаться предварительной, даже если ответы в листе уже есть. В запуске с пометкой команда часы в согласовании MUST NOT пересчитывать. Часы, названные в чате в запуске с пометкой, MUST записываться в согласование как предварительные и MUST быть названы в проекте как цифра из чата. Если ответы не изменили состав работ, уточнённая цифра MUST совпадать с предварительной. Если уточнённая цифра расходится с подтверждённой, технический проект MUST всё равно появиться, и в нём MUST быть видны обе цифры и ответ из листа, который изменил объём. Подтверждённой считается цифра, которую запуск с пометкой прочитал в согласовании до записи. Второго подтверждения MUST NOT быть. Часы, уже указанные в самом задании, MUST переноситься в проект как есть. Часы, названные в чате, MUST переноситься в проект как есть, если состав этой работы не изменился; если изменился, они пересчитываются, а прежняя цифра из чата названа рядом. Технический проект по файлу задания или по уже существующей задаче MUST появляться только при непустой пометке в листе и повторном запуске. Постановка по файлу задания MUST появляться на том же пороге. Для уже существующей задачи файл постановки MUST NOT появляться. В техническом проекте MUST быть разделы для разработчика: объекты, алгоритм, интеграции, внедрение, откат и уточнённая оценка. Отчёты, печатные формы и права MUST входить в раздел объектов. Текст процедур MUST NOT входить в технический проект. Команда MUST NOT додумывать сведения, которых нет в источнике. Если раздел объектов, алгоритма или интеграций не из чего заполнить, в нём MUST быть фраза «в задании не указано», вопрос MUST добавиться в лист, пометка MUST сохраниться. Если в источнике нет сведений о внедрении или откате, раздел MUST содержать «в задании не указано», вопрос MUST NOT добавляться в лист, и раздел MUST NOT заполняться выводом из списка объектов. Для уже существующей задачи источник MUST включать её решения: если внедрение или откат сказано в решении, раздел MUST ссылаться на номер решения, а не на фразу «в задании не указано». Работа без подходящей строки справочника MUST быть записана без часов, а итог MUST быть помечен, что эта работа в сумму не вошла, только если в чате ответа по этой работе нет или ответы изменили её состав. Если часы в чате названы и состав не изменился, они MUST переноситься в проект как есть и MUST входить в итог. Если ответы изменили состав, пересчёта MUST NOT быть: в проекте строка без часов, рядом MUST быть названы прежняя цифра из чата и ответ из листа, который изменил состав, и в чате MUST быть задан один вопрос о новых часах.

#### Scenario: Уточнённая оценка в техническом проекте

- **WHEN** в листе есть ответы и непустая пометка подтверждения, и пользователь снова запускает команду по файлу задания
- **THEN** появляется технический проект, и в нём стоит уточнённая оценка
- **AND** в чате эта оценка названа уточнённой

#### Scenario: Без пометки техпроекта нет

- **WHEN** в листе есть ответы, а пометка подтверждения пустая
- **THEN** технического проекта нет
- **AND** оценка рядом с листом остаётся предварительной
- **AND** цифры, посчитанные командой, в согласовании не изменились

#### Scenario: Расхождение оценки в техническом проекте

- **WHEN** пометка в листе непустая, и уточнённая цифра расходится с цифрой, которую запуск прочитал в согласовании до записи
- **THEN** технический проект появляется, и в нём видны обе цифры и ответ из листа, который изменил объём
- **AND** второго подтверждения для этой цифры нет

#### Scenario: Пробел при записи проекта

- **WHEN** пометка в листе непустая, а для раздела объектов, алгоритма или интеграций в источнике нет сведений
- **THEN** в этом разделе написано «в задании не указано», в лист добавлен вопрос, и пометка на месте
- **AND** технический проект при этом есть

#### Scenario: Внедрение и откат без вопроса

- **WHEN** пометка в листе непустая, а в задании нет сведений о внедрении и откате
- **THEN** оба раздела содержат «в задании не указано», вопроса о них в листе нет, и пометка на месте
- **AND** разделы не заполнены по списку объектов

### Requirement: Вход из уже существующей задачи

Вместо файла задания команда MAY получить имя уже существующей задачи. Путь к каталогу задачи или к файлу в нём, в том числе к `proposal.md`, MUST считаться этим же входом: имя MUST браться по каталогу первого уровня под `openspec/changes/` или под `openspec/changes/archive/`, не по ближайшему каталогу вложенного файла, и файл постановки MUST NOT появляться. Команда MUST сначала искать открытую задачу как каталог `openspec/changes/<имя>/` с файлом `proposal.md`. Если открытая задача найдена, архив MUST NOT просматриваться. Иначе команда MUST искать в архиве каталог с файлом `proposal.md`, имя которого равно `<имя>` или оканчивается на `-<имя>`. Каталог без `proposal.md` MUST NOT считаться найденной задачей. Если открытая задача не найдена и в архиве на одно имя найдено больше одного каталога, по точному имени или по окончанию, команда MUST NOT писать файлы. Если задача не найдена, команда MUST NOT писать файлы. Связь с уже сделанными изменениями для этого входа MUST NOT искаться. Как задание MUST читаться Why и What Changes её `proposal.md`. Её решения MAY закрывать пробел: если ответ уже есть в решении, вопрос MUST NOT попадать в лист, а раздел проекта MUST ссылаться на номер решения. Способ реализации из решения требованием MUST NOT называться. Лист, согласование и проект MUST лежать в корне каталога задачи под именем каталога. Файл постановки MUST NOT появляться. Файлы задачи MUST NOT заменяться.

#### Scenario: ЗНИ как задание

- **WHEN** вместо файла задания указана уже существующая задача
- **THEN** лист, предварительная оценка и последующий технический проект с уточнённой оценкой строятся по тексту этой задачи, где сказано, зачем она и что в ней меняется
- **AND** файла постановки нет

#### Scenario: Вход из существующей задачи без постановки

- **WHEN** вместо файла задания указана уже существующая задача
- **THEN** появляются лист и согласование с предварительной оценкой, а файл постановки не появляется
- **AND** после непустой пометки и повторного запуска появляется технический проект, нового каталога нет, и файлы самой задачи не заменены

#### Scenario: Пробел закрыт решением задачи

- **WHEN** указана существующая задача, и ответ на пробел есть в её решении
- **THEN** вопроса в листе нет, а раздел проекта ссылается на номер решения
- **AND** способ реализации из решения требованием не назван

#### Scenario: Задача из архива

- **WHEN** указано имя архивной задачи
- **THEN** лист и согласование лежат в корне её архивного каталога под именем этого каталога
- **AND** имя, которого нет ни среди открытых, ни в архиве, не создаёт файлов
