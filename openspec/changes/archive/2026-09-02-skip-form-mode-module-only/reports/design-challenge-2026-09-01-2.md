## Three-Question Challenge

### Q1 — Problem-Solution Fit

- **Why говорит:** при ЗНИ, где правят только модуль формы (номера в заголовках колонок, состав полей и кнопок не трогают), чат всё равно спрашивает «вручную / автоматически / программно»; пропуск даёт «вручную», и на реализации ждут выгрузку из Конфигуратора, хотя разметку не меняют (`proposal.md` ## Why). Verified текущее поведение kit: `.cursor/rules/forms-mxl-mode-gate.mdc` — вопрос по каждой форме без режима, включая задачи на модуль формы; пустой ответ → вручную; `bsl-only` = не менять Form.xml, UX в модуле. FAQ: на `/opsx:new` с управляемой формой — отдельный вопрос всегда.
- **Design адресует:**
  - Why «чат всё равно спрашивает» → классификатор; при доказанном «только модуль» выбора из трёх нет, в карточке сразу программно (Goals 1, Behavior Contract п.1; spec ADDED Module-only).
  - Why «пропуск = вручную → ждут Конфигуратор» → вопрос не показывают; default пропуска на **заданном** вопросе не меняют (Non-Goals 2).
  - Форму не исключать из списка, иначе дыра режима (What Changes п.1; spec: форма SHALL остаться в списке, не `n/a`).
  - Ложноположительный skip (запись программно на правку свойств в Конфигураторе) закрыт сужением токенов: «обработчики»/«видимость» без «в модуле» → вопрос.
- **Покрытие:** полное. Симптом и вредный default пропуска закрываются одним механизмом (не спрашивать + записать программно), а не сменой default для всех форм. Операционализация классификатора больше не шире Why.

### Q2 — Optimality

- **Выбранный путь:** классификатор «только модуль / разметка / неясно»; при доказанном «только модуль» записать программно без меню; форму из списка не выкидывать; при разметке/неясности — прежний канон из трёх (`design.md` Implementation Options, выбранный вариант). Варианты «оставить вопрос и сменить default пропуска» и «выкинуть форму из списка» в Implementation Options остаются хуже Why (вопрос не уходит / дыра режима) и **не предлагаются** повторно.
- **Альтернативы, не упомянутые в `## Implementation Options`:**
  1. **Явный маркер в блоке постановки** (например заранее записанная поставка программно в шаблоне «Постановка ЗНИ») вместо классификации по тексту. Как реализуется: skip только при маркере; иначе всегда канон из трёх. Плюс: нет ложноположительного NLP. Минус: Why как раз про естественную формулировку «только модуль, разметку не трогаем» без нового служебного токена; без маркера холостой вопрос остаётся. Отклонена: хуже закрывает Why, плодит церемонию.
  2. **Эвристика по путям в задачах** (skip, если в tasks есть `Module.bsl` и нет `Form.xml`). Как реализуется: классификатор читает список файлов, не токены постановки. Плюс: механично. Минус: на design списка tasks может ещё не быть; «добавить кнопку» без пути `Form.xml` останется ложным skip либо наоборот лишним вопросом. Отклонена: слабее текстового контракта «в модуле» / «разметку не трогаем».
  3. **Двухвариантный вопрос только для «похоже на модуль»** («модуль в репозитории» vs «выгрузка из Конфигуратора», без «автоматически»). Как реализуется: отдельный канон чата. Плюс: не молчит. Минус: Why про саму паузу, когда постановка уже доказала отсутствие разметки; второй канон расходится с ADR-0001 (три варианта, когда вопрос задаётся). Для kit поставка программно = не менять Form.xml (`forms-mxl-mode-gate.mdc`). Отклонена.
  4. **Не трогать вопрос; на реализации не ждать выгрузку разметки, если в задачах только модуль** (даже при записанном «вручную»). Как реализуется: эвристика apply по составу задач. Плюс: архивный MUST-вопрос формально цел. Минус: в карточке ложная поставка «вручную»; Why про шум вопроса не закрыт; риск разъехаться с паузой Конфигуратора для настоящей разметки. Отклонена: лечит следствие на apply, не причину на design. `reopen-blocked:` ось Chosen (запись на new, не на apply) — verified fact из текущего гейта: `manual` → Конфигуратор+WAIT, `bsl-only` → только модуль; лечить apply при «вручную» ломает эту таблицу.
- **Вердикт по Q2:** выбранный путь оптимален. Ни одна из четырёх неупомянутых альтернатив не лучше по совокупности «меньше пауз / меньше ложных skip / обратимость / Blast Radius / ADR-0001». MUST поясняющей строки не лучше MAY: наблюдаемый критерий skip — карточка ЗНИ, которую читают apply/verify; чат-строка не SSOT режима.

### Q3 — Fresh-Eye Approval

- **Согласовал бы (или нет):** да, без оговорок к тексту постановки.
- **Причины:**
  - Why и выбранный путь совпадают: аналог уже принятого skip макета («ответ однозначен — не спрашивать»), форма остаётся в списке с валидным режимом.

  - Три внутренних расхождения предыдущего прогона (токены классификатора, Mixed, MAY строки) сняты одним наблюдаемым протоколом в design и spec.
