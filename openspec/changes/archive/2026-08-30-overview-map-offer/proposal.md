## Why

Команда описания ЗНИ собирает связный текст для согласования: как сейчас, зачем меняем, этапы поставки, что решить. Схему механизма она не предлагает, даже когда по этой ЗНИ уже лежат отчёты разбора со связями и доказательствами. Согласующий видит этапы поставки и не видит ловушку, из‑за которой изменение затеяли.

## What Changes

1. После записи описания ЗНИ команда смотрит отчёты этой ЗНИ (разбор, журнал пошагового прохода, архитектурный отчёт по теме). Если из них собирается связный набор и с полотна будет виден вывод, которого нет в списке этапов, в уже существующей строке следующего шага печатается вариант схемы: что станет видно. Панель не собирается, пока нет согласия.
2. По согласию в сборщик схемы уходит тот же отчёт, на котором прошла проверка: путь, диапазоны доказательств, вопрос шапки «зачем меняем». Постановка, список задач и сам файл описания — не источник схемы.
3. Если отчётов нет или проверка связей не проходит — предложения схемы нет; причина в чат не печатается. Отказ «без карты» до конца сессии не повторяется.
4. Отдельная команда карты не появляется. В открытую ЗНИ про читаемость шаблона карты это не кладётся.

### Modified Capabilities

- `scenario-map-canvas`: сессия описания ЗНИ может предложить схему механизма по отчётам этой ЗНИ (намёк на строке следующего шага, сборка только по согласию); постановка и файл описания не становятся источником панели; порог сущностей, запрет выдуманных рёбер и регистрация родителем не ослабляются.

## Impact

- Kit: скилл описания ЗНИ, контракт чата описания, скилл карты сценария (когда предлагать и какой источник вне разбора).
- Продуктовый код 1С и конфигурация не меняются.
- Вне scope: смена модели сборщика карты; отдельная команда карты; автосборка панели из описания; карта на проверке постановки и на ревью кода; читаемость шаблона панели (открытая соседняя ЗНИ); ослабление словаря связей и запрета выдуманных рёбер.

## Scope

- In scope: намёк схемы после описания ЗНИ, если есть отчёты разбора; сборка по согласию из этих отчётов; строка следующего шага в чате описания как слот намёка; исключение «укажите отчёт» для принятого предложения из описания.
- Out of scope: прикладная конфигурация; открытая ЗНИ `scenario-map-readability-meaning`; `/review` и `/opsx:verify`; новая команда `/opsx:*` для карты.

## Acceptance Criteria

1. На ЗНИ с отчётами разбора, где связи уже видны, после описания в чате есть предложение схемы с конкретным «что станет видно» и без панели.
2. На ЗНИ только с постановкой предложения схемы нет.
3. Согласие строит панель из отчётов, не из этапов поставки. Отказ «без карты» до конца сессии не повторяется.
4. Файл описания ЗНИ не содержит протокола карты и не является источником узлов.
