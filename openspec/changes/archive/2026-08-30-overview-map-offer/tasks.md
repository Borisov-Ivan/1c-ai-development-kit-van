# Срез S1: Намёк схемы после описания ЗНИ

**Сценарий:** разработчик вызывает описание ЗНИ, у которой уже есть отчёты разбора со связями, видит в строке следующего шага, что станет видно на схеме, соглашается — открывается панель из отчётов, не из этапов поставки.
**Primary acceptance:** вызвать описание ЗНИ с отчётами разбора → в чате есть вариант схемы с фразой «что станет видно», панели нет → ответить согласием → открывается панель из того же отчёта, на котором прошла проверка, узлы не повторяют этапы поставки.
**Приёмка:** ручной прогон описания на ЗНИ с отчётами разбора и на ЗНИ только с постановкой; статическая часть — сверка текста скилла описания, макета чата, скилла карты и списка команд задачами среза.
**Связь со spec:** Requirement «Silence unless asked or hinted» — Scenario «Молчание по умолчанию», Scenario «Намёк не рисует панель», Scenario «Системный MUST canvas не действует на opsx», Scenario «Намёк описания не рисует панель»; Requirement «Direct request draws the scenario map» — Scenario «Прямая просьба рисует карту», Scenario «Карта во время прохода из уже пройденных точек», Scenario «Прямая просьба после выхода разбора», Scenario «Просьба при числе сущностей ниже порога», Scenario «Первая просьба в проекте без открытой панели», Scenario «Панель открывается штатной кнопкой среды», Scenario «С узла открывается доказательство, новый чат с панели не запускается», Scenario «Порядок прохода не выдаётся за причинность», Scenario «Просьба при линейной цепочке», Scenario «Согласие на предложение рисует карту», Scenario «Согласие до первой карточки разбора запоминает фокус», Scenario «Отложенное согласие публикует карту без повторного вопроса», Scenario «Согласие было, порог до выхода не набрался», Scenario «Согласие при неподтвердившейся топологии даёт цепочку», Scenario «Согласие на намёк описания рисует карту из отчётов»; Requirement «Offer by topology not by topic» — Scenario «Исследование предлагает схему при топологии без замеров», Scenario «Разбор предлагает схему на подтверждении списка без порога публикации», Scenario «Разбор предлагает схему на выходе без замеров времени», Scenario «На линейных двух шагах схему не предлагают», Scenario «Предложение не зависит от темы механизма», Scenario «Описание предлагает схему при топологии в отчётах», Scenario «Описание без отчётов схему не предлагает», Scenario «Плоский набор без формы связей в описании не даёт намёка», Scenario «Отказ без карты в описании не повторяется»; Requirement «Hint only on an existing decision line» — Scenario «Намёк на выходе разбора при топологии», Scenario «Нет намёка, если уже вопрос анализа», Scenario «Исследование не предлагает карту и разбор сразу», Scenario «Нет предложения в финале исследования с постановкой»; Requirement «Map outside walkthrough uses named source» — Scenario «Вне разбора без источника — отказ», Scenario «Просьба в исследовании берёт текущий отчёт», Scenario «Прямая просьба в описании берёт инвентарь отчётов», Scenario «Этапы поставки не становятся картой».
**Зависимости:** нет.
**Режим apply:** mechanical

## 1. Слот решения в чате описания

- [x] S1.1 В `.cursor/docs/opsx-output-style.md` §5.6 (T-OVERVIEW): добавить третьим элементом тонкого чата строку следующего шага, которая печатается всегда — включая прогоны, где карта не рассматривалась, — и по умолчанию содержит одно действие «Передать файл на согласование» (не заглушку «достаточно»), чтобы у намёка схемы было уже существующее место в сообщении и не появлялся второй вопрос (Decision 1, F2 отчёта архитектора)
- [x] S1.2 В `.cursor/skills/openspec-overview/SKILL.md` шаге «Write + чат» и в Self-check п. 5: описать чат как три элемента — путь к файлу, блок «Что согласовать», одна строка следующего шага, — чтобы прогон описания на ЗНИ без отчётов печатал строку шага и лимит тонкого чата не был превышен (Decision 1, Behavior Contract п. 1)

## 2. Инвентарь отчётов и проверка предложения

- [x] S1.3 В `.cursor/skills/openspec-overview/SKILL.md` секции «Источники (только Read)»: разделить чтение на две ветки — сюжет файла берётся из `proposal.md` и `design.md`, инвентарь карты из отчётов разбора, журналов пошагового прохода и архитектурных отчётов по теме; `tasks.md` и отчёты проверки постановки не входят ни в одну ветку, — чтобы новая ветка не отменяла запрет строить сюжет описания по отчётам (Behavior Contract п. 3, F5 отчёта архитектора)
- [x] S1.4 В `.cursor/skills/openspec-overview/SKILL.md` шаге «Write + чат»: после записи файла собирать инвентарь отчётов названных ЗНИ, резолвя активный и архивный каталог тем же способом, что шаг «Resolve changes»; тип отчёта брать из `reports/_manifest.yaml` при наличии, иначе по префиксу имени (`explain-*`, `exploration-*`, `architecture-*`); сам манифест и отчёты проверки постановки, контроля качества, независимого разбора постановки и приёмки среза не включать; выбирать **один** отчёт по предпочтению (журнал прохода, затем разбор, затем архитектурный отчёт по теме — последний только если после обоих отсевов в нём есть доказанные сущности и видимые связи, а не формулировки «мы планируем»), на этом же файле прогонять три условия предложения и при согласии передавать в сборщика **тот же** путь, чтобы намёк не обещал вывод, которого нет на панели (Decision 2, Behavior Contract п. 2, F6 и F7 отчёта архитектора)
- [x] S1.5 В `.cursor/skills/openspec-overview/SKILL.md` шаге «Write + чат»: пропускать намёк только при одновременном выполнении трёх условий **на выбранном одном отчёте** — называемый вывод, которого нет в списке этапов; топологический признак формы связей в этом файле; не меньше четырёх связанных сущностей после обоих отсевов, — с явной оговоркой, что объединение нескольких отчётов признаком не считается, признак не считается по теме ЗНИ и не по числу этапов, причина отказа в чат не печатается, а для проверки читаются только секции сущностей, связей и доказательств, не полный нарратив (Decision 3, Assumption 5, Scenario «Описание предлагает схему при топологии в отчётах», Scenario «Плоский набор без формы связей в описании не даёт намёка», Scenario «Описание без отчётов схему не предлагает»)
- [x] S1.6 В `.cursor/skills/openspec-overview/SKILL.md` шаге «Write + чат»: описать ответ пользователя — согласие вызывает сборщика манифеста с путём отчёта, на котором прошла проверка (список путей включится сам после поставки соседней ЗНИ про читаемость панели), диапазонами доказательств и вопросом шапки «зачем меняем»; молчание панель не создаёт; ответ «без карты» снимает намёк до конца сессии, а строка шага остаётся, — чтобы панель собиралась из того же отчёта, а не из этапов поставки (Behavior Contract п. 4–6, Scenario «Согласие на намёк описания рисует карту из отчётов», Scenario «Намёк описания не рисует панель», Scenario «Отказ без карты в описании не повторяется»)
- [x] S1.7 В `.cursor/skills/openspec-overview/SKILL.md` секции «Guardrails»: вывести вызов сборщика манифеста карты из-под запрета делегирования явно, сохранив запрет на обследование `.bsl` и правки кода из этой команды, чтобы ветка согласия была исполнима и не открывала команде описания доступ к правкам модулей (F4 отчёта архитектора)

## 3. Сессия описания в скилле карты

- [x] S1.8 В `.cursor/skills/scenario-map-canvas/SKILL.md` разделах «Порядок действий по просьбе» п. 1 и «Источник узлов»: добавить сессию описания ЗНИ как источник — инвентарь отчётов этой сессии, из которого в сборщика уходит один отчёт, выбранный правилом предпочтения Decision 2 (он же тот, на котором прошла проверка, если проверка проходила); правило «несколько отчётов — все пути» к этому входу не применять; записать третьим исключением из отказа «укажите отчёт» прямую просьбу при уже собранном инвентаре и запретить постановке, списку задач и файлу описания быть источником узлов, а этапам поставки — публиковаться цепочкой узлов (Behavior Contract п. 3–4, Decision 2, Scenario «Прямая просьба в описании берёт инвентарь отчётов», Scenario «Этапы поставки не становятся картой»)
- [x] S1.9 В `.cursor/skills/scenario-map-canvas/SKILL.md` разделах «Проверка топологии и вывода» и «Молчание и пороги»: добавить сессию описания ЗНИ к местам, где действуют все три условия предложения и порог четырёх публикуемых сущностей, с оговоркой, что признак определяется по форме связей в выбранном одном отчёте названной ЗНИ (объединение файлов не считается), отказ проверки в чат не печатается, а ответ «без карты» до выхода сессии снимает предложение (Decision 3, Scenario «Описание предлагает схему при топологии в отчётах», Scenario «Плоский набор без формы связей в описании не даёт намёка»)
- [x] S1.10 В `.cursor/skills/scenario-map-canvas/SKILL.md` разделе «Намёк на выходе explain» (и заголовке раздела): добавить строку следующего шага чата описания ЗНИ четвёртым слотом намёка, отметив, что эта строка печатается всегда, намёк панель не собирает, а запрет считать слотом строку финала исследования с постановкой ЗНИ сохраняется; в абзаце входного протокола о системном требовании среды добавить `/opsx:overview` к перечню сессий, где это требование не является основанием рисовать панель (Behavior Contract п. 1, F2 отчёта архитектора, Scenario «Намёк описания не рисует панель», Scenario «Системный MUST canvas не действует на opsx»)
- [x] S1.11 В `.cursor/commands/opsx-overview.md`: привести описание результата к трём элементам чата — путь к файлу, пункты согласования и одна строка следующего шага, — чтобы вызывающий видел тот же контракт чата, что записан в скилле и в макете §5.6 (Decision 1)

## 5. Приёмка

- [x] S1.accept Принять срез S1 «Намёк схемы после описания ЗНИ» — описание ЗНИ предлагает схему механизма по своим отчётам и по согласию открывает панель:
  - **Primary (обязательно):** вызвать описание ЗНИ с отчётами разбора → в чате есть вариант схемы с фразой «что станет видно», панели нет → ответить согласием → открывается панель из того же отчёта, на котором прошла проверка, узлы не повторяют этапы поставки (Scenario «Описание предлагает схему при топологии в отчётах», Scenario «Намёк описания не рисует панель», Scenario «Согласие на намёк описания рисует карту из отчётов»)
  - Scenario «Описание без отчётов схему не предлагает» (опционально): вызвать описание ЗНИ, где есть только постановка и решения — строка следующего шага напечатана, варианта схемы в ней нет, строки о причине нет
  - Scenario «Плоский набор без формы связей в описании не даёт намёка» (опционально): вызвать описание ЗНИ, где отчёты дают четыре и более доказанных связанных сущности без слоёв, ветвления, жизненного цикла и петли — варианта схемы в строке шага нет, причины в чате нет
  - Scenario «Отказ без карты в описании не повторяется» (опционально): ответить «без карты», затем вызвать описание в той же сессии снова — варианта схемы нет, строка следующего шага осталась
  - Scenario «Прямая просьба в описании берёт инвентарь отчётов» (опционально): после описания попросить показать карту сценария, путь к отчёту не называя — панель построена из отчёта, выбранного из инвентаря правилом предпочтения, отказа «укажите отчёт» нет
  - Scenario «Этапы поставки не становятся картой» (опционально): на открытой панели ни один узел не повторяет этап поставки из файла описания, связи взяты из отчётов разбора
