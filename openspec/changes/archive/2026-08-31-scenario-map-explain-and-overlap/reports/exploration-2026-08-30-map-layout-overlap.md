# Разбор: почему живые схемы карты наезжают подписями и коробками

**Дата:** 2026-08-30  
**Профиль:** bug (kit / scenario-map-canvas)  
**Источник:** скилл, оболочка, эталоны, spec, ADR-0008/0009; снимки трёх живых панелей  
**KB:** discovery без совпадений (`openspec/knowledge/_index.yaml` отсутствует) — фактов KB нет

---

## Для заказчика

1. **Что наблюдаешь.** На трёх открытых схемах рядом с чатом стрелки, подписи связей и синие карточки доказательств лежат друг на друге и на коробках узлов. Схему нельзя прочитать «на пальцах»: не видно, кто кого питает и где ловушка.

2. **Почему так устроено.** Сборщик отдаёт только список сущностей и связей без координат. Положение коробок и подписей считает шаблон панели: раскладка DAG среды плюс простая геометрия. Подпись связи всегда в середине отрезка; карточка доказательства — чуть правее якоря. Разведения подписей от коробок и друг от друга в шаблоне нет.

3. **Связано ли с симптомом.** Объясняет **полностью**: наложение на снимках — прямое следствие того, как шаблон ставит подписи и карточки. Содержание манифеста (как в хорошем эталоне) само по себе не разводит текст.

4. **Что чинить и где.** Чинить **шаблон панели** (разведение подписей связей и карточек доказательств, чтобы текст не ложился на коробки и соседние подписи) и **проверку после записи** (не объявлять схему готовой, пока текст на полотне не читается). Сборщик манифеста координаты не задаёт — там править укладку бессмысленно; при правиле-условии без топологии выбирать таблицу вместо плотного графа.

## Свод

### Вердикт одной фразой

**Укладка сломана в оболочке; у инструкций есть общее «текст читается», но нет алгоритма разведения подписей/карточек — оболочка это не исполняет; сборщик координат не ставит.**

Классификация по вопросу «правило / дыра / не исполняет»:

| Тема | Статус |
|------|--------|
| Текст полотна / сущностей читается в ширине панели | **Правило есть** (скилл, spec, ADR-0009) — **на снимках нарушено**; чек-лист после записи обязан был не допустить публикацию |
| Пересечение рёбер (edge crossing) | **Правила нет** (дыра) |
| Наложение подписей связей на узлы / друг на друга | **Отдельного MUST нет** (дыра); закрывается только общим «текст читается» |
| Callout / карточка доказательства не перекрывает узлы | **Отдельного MUST нет** (дыра); есть только «у якоря, координаты из манифеста не читать» |
| Collision-avoidance в оболочке для edge labels / аннотаций | **Нет реализации** — правило читаемости оболочка **не исполняет** |
| Переключение Связи/Слои, лимит узлов, полосы слоёв | Правила есть и в оболочке частично исполнены (направление DAG, wrap ≤5, полосы, легенда) |

### 1. MUST по темам вопроса

#### Пересечение рёбер

- В скилле, spec и `canvas-shell.md` **нет** MUST «рёбра не пересекаются» / «не проходят через узлы».
- Есть только направление и легенда: скилл чек-лист после записи — «направление каждой связи и легенда использованных типов» (`.cursor/skills/scenario-map-canvas/SKILL.md:64-65`); spec — «у каждой связи видно направление; … легенда» (`openspec/specs/scenario-map-canvas/spec.md:219-222`).
- Обратное ребро — изгибом, не пунктиром (`fixtures/canvas-shell.md:19`, `208-221`).

**Итог:** правило против пересечений **отсутствует** (дыра). На снимках пересечения — ожидаемый побочный эффект прямой геометрии.

#### Наложение подписей связей на узлы

- Подпись ребра ≤4 слов (`SKILL.md:109`; `canvas-shell.md:17`).
- Общее: «Текст полотна MUST читаться…» (`spec.md:203`); «Текст сущностей MUST читаться…» (`ADR-0009:28`); чек-лист: «текст сущностей читается в фактической ширине панели» (`SKILL.md:64`, self-check `8a` на `SKILL.md:309`).
- **Нет** MUST «подпись связи не пересекает коробку узла» и **нет** алгоритма разведения подписей.

**Итог:** узкое правило **дыры**; широкое «текст читается» **есть и на снимках нарушено**.

#### Callout / tooltip / карточки доказательства

- Аннотации ≤2; якорь на узел или ребро; координаты в манифест **не** входят — размещение считает шаблон (`SKILL.md:118-128`; `canvas-shell.md:20`).
- «аннотации рисовать у якорного узла или ребра… не в правой полосе… координаты аннотации из манифеста не читать» (`canvas-shell.md:20`).
- **Нет** MUST «карточка не перекрывает узлы/рёбра/другие карточки».

**Итог:** якорь есть, антиналожение **дыры**. На снимках синие плашки поверх узлов — следствие `annotationBox` без обхода коробок.

#### Переключение граф / таблица и видов

- Средство `header.medium`: `graph` \| `table` (`SKILL.md:54-56`, `84-86`; `spec.md:197`).
- Для графа переключатель видов меняет **раскладку**, не состав рёбер (`SKILL.md:116`; `spec.md:254-257`; `canvas-shell.md:14`).
- В оболочке кнопки «Связи» / «Слои» = `causal-flow` (горизонтальный DAG) / `layers` (вертикальный DAG) (`canvas-shell.md:41`, `312`, `432-445`).

#### Лимит узлов / плотность ряда

- Порог публикации ≥4 сущностей (`SKILL.md:57`; `spec.md:35`).
- Цепочка >5 в одном ряду — перенос (`SKILL.md:64`; `spec.md:203`; `canvas-shell.md:21`, `MAX_ROW = 5` на `:104`, `wrapLayout` `:231-257`).
- >12 узлов — запасная раскладка без подписей полос, **не** бюджет читаемости (`canvas-shell.md:12`; `spec.md:201`; `ADR-0009:28`).
- Если средство бюджет не удерживает — сменить средство или сузить вопрос (`spec.md:203`; `ADR-0009:28`).

#### Слои / полосы

- Координаты считает панель; полосы по полю `layer`, не по рангу (`SKILL.md:65`; `spec.md:201`; `canvas-shell.md:10-13`).
- Если рамки полос пересекаются — заливку не рисовать (`canvas-shell.md:13`, код `bandsOverlap` `:199-206`, отрисовка `:489`).

### 2. Оболочка `canvas-shell.md`: укладка

| Вопрос | Ответ |
|--------|--------|
| ELK / dagre? | **Нет по имени.** Используется `computeDAGLayout` из `cursor/canvas` (`:34`, `:309-318`) + самописный `wrapLayout` (перенос ряда >5) |
| Collision-avoidance для edge labels? | **Нет.** Подпись: `x=midX`, `y=midY-8` (`:544-565`) |
| Collision / z-index для карточек аннотаций? | **Нет.** `annotationBox`: `x = point.x+16`, `y = point.y-h-10+index*2`, при `y<4` — ниже якоря (`:280-290`). Карточки рисуются **после** узлов (`:629-670`) → перекрывают коробки. Сдвиг между двумя аннотациями — 2px (`index*2`) |
| `boxesOverlap` | Только для **полос слоёв** (`:135-145`, `:199-206`) — отключает заливку; **не** для узлов, подписей, аннотаций |
| «Связи» vs «Слои» | Один набор рёбер; `direction: "horizontal"` vs `"vertical"` (`:312`) |

Координаты аннотаций из манифеста не читаются — соответствует контракту (`SKILL.md:128`, `canvas-shell.md:20`).

### 3. Снимки vs эталоны

| Эталон | О чём | Отношение к снимкам |
|--------|--------|---------------------|
| `map-good-causal.md` | Слои, подписанные связи, стартовый исход, аннотация ловушки | **Тот же сюжет** (штамп / копия / подписи) и тот же класс манифеста; на снимках тот же смысл **испорчен раскладкой** |
| `map-good-table.md` | Таблица колонок без графа | На снимках активен **граф** («Связи»/«Слои»), не таблица |
| `map-bad-accordion.md` | Список без рёбер | На снимках рёбра **есть** — не этот антипаттерн |
| `map-bad-no-insight.md` | Полотно есть — смысла нет (вывод только в шапке) | На снимках смысл/ловушки на полотне заявлены; проблема **читаемости геометрии**, не пустого смысла |

**Антипаттерн снимков:** плотная DAG-раскладка без разведения подписей и карточек → наложение текста (близко к запрещённой «стене карточек» по эффекту для читателя, но структурно это граф со связями).

**Сборщик vs оболочка:** манифест хорошего эталона **не содержит координат** (`map-good-causal.md` — только `nodes`/`edges`/`annotations` с якорями). Координаты и отрисовка — зона оболочки (`spec.md:201`: «Координаты узлов MUST считать панель»). Значит симптом наложения — **провал оболочки (рендер)**; сборщик мог отдать корректный манифест. Дополнительно: чек-лист читаемости после записи — обязанность родителя (`SKILL.md:64-65`, `309`; картограф пункты 7–8 **не** проверяет — `.cursor/agents/onec-scenario-map-designer.md:52`). Если панели всё же показали — проверка `8a` не отсекла нечитаемое полотно (процесс), но **геометрия** ломается в оболочке.

## Recommended next steps

1. **Оболочка:** развести подписи рёбер от коробок и друг от друга (смещение вдоль нормали / скрытие при коллизии / вынос в панель деталей при пересечении); для `annotationBox` — поиск свободного места вокруг якоря, не фиксированный `+16/−h`.
2. **Контракт:** явный MUST «подпись связи и карточка доказательства не перекрывают коробки узлов и другие подписи» — сейчас это только общее «текст читается».
3. **Регистрация:** чек-лист `8a` после записи — не объявлять готовность при наложении; при плотном графе MAY сменить средство на таблицу (`spec.md:203`).
4. **Не чинить укладку в сборщике:** координат в манифесте нет по дизайну; чинить рендер и приёмку читаемости.

## Anomalies / concerns

1. Единственная «collision» в оболочке — `bandsOverlap` для заливки полос; читатель видит наложение **текста**, которое этот код не ловит.
2. Проверка смысла **до** записи явно **не** смотрит раскладку (`SKILL.md:62`, `spec.md:196`) — правильно для смысла, но оставляет читаемость только на пост-записи `8a`, которую легко свести к «typecheck чистый».
3. Две аннотации с `index * 2` почти совпадают по месту — на снимках со штампом это воспроизводится как стопка синих плашек.
4. Снимки «штампа» визуально близки к `map-good-causal`: хороший манифест + плохой рендер маскирует успех семантики провалом геометрии.
5. Переключатель «Слои» не раскладывает узлы по полосам слоя как отдельный layout engine — только `direction: vertical`; полосы — обводки поверх той же DAG. Ожидание «Слои = развести» на снимках не выполняется.
6. Архивные гипотезы соседнего агента по readability **не** подтверждались: выводы только из скилла/оболочки/spec/ADR/эталонов.
