# Design: kit-session-noapi-visibility-and-ru-progress

## Context

Режим «с API / без API» уже есть (архив `kit-session-api-mode`, ADR-0004): токен в чате или память после лимита, вызовы без параметра модели, канон одной строки без имени модели. Текст канона уже нормативен (`model-selection.mdc`, Scenario «Память после лимита»). На инциденте PavDO цепочка после лимита сработала, а канон в чат не ушёл: правило on-demand, его читают **до** вызова, обязанность наступает **после** сбоя. Человек ждал токен `-noapi` или явный переключатель и решил, что режим «не включился». Progress `/opsx:*` ушёл английскими каркасами: бюджет чата требует одну короткую строку, но не русский; профиль Grok MAY прямой речи читается как разрешение английского; Communication Cursor на английском перебивает kit. Runtime-норма языка — always-apply бюджет чата, не гайд стиля.

Отдельно: `/opsx:new` всегда спрашивает маркер автора. Для ЗНИ без BSL (эволюция kit, только правила) вопрос лишний. Заказчик 2026-08-19: маркер не нужен; спрашивать только если ЗНИ предполагает написание BSL.

Связанные ADR: ADR-0004 (режим сессии, Load-Bearing); ADR-0001 (строка после лимита без слага и имён агентов).

Отчёт: `openspec/changes/kit-session-noapi-visibility-and-ru-progress/reports/architecture-2026-08-19-kit-session-noapi-visibility.md` (S1–S2). Срез про маркер добавлен заказчиком на `/opsx:new` после отчёта — тот же принцип «не плодить механизм, дописать правило».

## Goals / Non-Goals

**Goals:**

- После лимита человек по одной русской строке понимает: дальше субагенты на модели чата.
- Progress команд `/opsx:*` не уходит по-английски из‑за Communication или профиля модели.
- Вопрос маркера автора на `/opsx:new` — не пропускать, пока не доказан kit-only; спрашивать, когда в ЗНИ будет BSL.

**Non-Goals:**

- Таблица ролей, двухшаговая цепочка, классификация липких vs нелипких сбоев.
- Файл-состояние режима, запись в `openspec/project.md`, третий режим.
- Печать `-noapi` оркестратором.
- Расширение top-20 запрещённых подстрок английскими глаголами как основная защита.
- Отмена независимого разбора постановки; путаница с `--skip-architect`.
- Палитра команд (уже закрыта архивом).
- Смена формата маркеров в BSL, когда маркер всё-таки нужен.

## Decisions

**D1. Видимость = канон, не токен.** Два входа в один режим «без API» (токен пользователя или память после лимита). Оркестратор не пишет `-noapi` в чат и не говорит «включился noapi». Единственный сигнал липкого сбоя — канон: «дорогие модели недоступны — дальше на модели чата».

**D2. Канон в том же ходе, триггер и фраза в always-apply.** Строку сказать **первой** в ходе, где зафиксирован первый липкий сбой, в том числе если другой вызов ещё в фоне. Не откладывать до финала verify. Текст канона не менять: always-apply бюджет чата §5 содержит фразу дословно и триггер «`Task` вернул лимит / недоступность / ошибку выбора». `model-selection.mdc` — когда сказать и что запрещено, не единственный дом текста. В `session-discipline.mdc` — cue. Текст платформы про fallback модели — не протокол kit. В `/opsx:verify` канон лимита и «Модель архитектора: Opus 5» — разрешённые исключения из «одно финальное сообщение» и «ноль промежуточных»; они не ждут карточки вердикта. Точка возникновения обязанности — §5; точка принуждения перед отправкой — §1b (пункт «канон», владелец — срез сигнала). Полное тело бюджета: строка verify в §1 и §5a называют то же исключение.

**D3. In-flight не отменять.** Уже ушедший вызов с параметром модели шаг 2 делает сам. Отдельный абзац «фоновый вызов ещё летит» не нужен. После завершения фона с тем же лимитом канон не повторяется.

**D4. Токен не подменяется каноном лимита.** Явный `-noapi` включает режим как сейчас. Канон лимита не дублируется, если памяти ещё не было: токен сам по себе не требует строки про «дорогие модели».

**D5. Progress `/opsx:*` только русский.** Одна короткая строка. Каркасы `I'll`, `Let's`, `Starting`, `Switched to`, `chat model`, `next-best model` — примеры провала и для обычной вводной речи, не только для строки-разделителя; не нормативный запретный список и не новые пункты top-20. В verify допустимы только канон лимита, «Модель архитектора: Opus 5», «Дописываю постановку…» — и они могут уйти до финальной карточки. При лимите достаточно **только канона лимита**, отдельный «сейчас повторю» не нужен.

**D6. Язык команды важнее Communication и профиля.** Приоритет — в always-apply `chat-output-budget.mdc` §6 (progress) и §1b пункт «язык» (вся исходящая речь `/opsx:*`, не только разделитель). В `opsx-output-style.md` §2 — отсылка, не единственный дом нормы. MAY длины/тона профиля **не** меняет язык `/opsx:*` и **не** отменяет канон. Узкий MUST NOT в `model-grok4.mdc` и cue в `model-adaptation.mdc`.

**D7. Два разных сигнала.** Канон лимита «дорогие модели недоступны — дальше на модели чата» (без имени модели) и канон разбора «Модель архитектора: Opus 5» не смешивать. Вторая строка — когда для независимого разбора постановки или для явной просьбы о самой сильной модели в enum нет слага: факт, какая модель идёт в работу; без «недоступна», «эскалация», «сборка». Семейство Opus 5 в этой строке разрешено; слаг `claude-opus-5-thinking-high` и имя субагента — нет. Канон лимита эту фразу не заменяет и наоборот. Анонс перед вызовом самой сильной модели, когда слаг в enum есть, не менять.

**D8. Маркер автора — только если будет BSL.** Спрашивать Metadata Gate на шаге 1.5 `/opsx:new`, когда в постановке / блоке «Постановка ЗНИ» / тексте запроса (поля «Что менять», «Файлы») есть `.bsl` или модули в `src/` / `cfe/`. **Пропуск только при доказанном kit-only:** scope исключительно `.cursor/**`, `openspec/**` и документы kit. Не опираться на `## Impact` proposal: его ещё нет. Деловая постановка без литерала `.bsl` и без доказанного kit-only — сомнение, **спросить** (не «нет `.bsl` → молча n/a»). Пропуск kit-only: записать `developer: n/a`, пустой `comment_suffix`, `marker_style: minimal` без карточки выбора; это **закрывает** гейт, `n/a` не плейсхолдер «пропущен молча». Resume с уже заполненным `developer` (включая `n/a`) не переспрашивать. Если позже появится BSL — вопрос на `/opsx:apply` при непустом `marker_scope`; если в карточке проекта задан разработчик по умолчанию — взять его без вопроса; иначе один вопрос про ФИО; `n/a` в маркер кода не писать.

**D9. FAQ в срезе сигнала, не отдельный срез.** Два абзаца: чем токен отличается от памяти; почему после лимита в чате нет `-noapi`.

**D10. Cue persistence не дублировать.** `command-session-persistence.mdc` не трогать. Cue «память = без API, сигнал = канон» — в `session-discipline.mdc`.

**D11. Spec ADDED только для новой наблюдаемости.** Не REMOVED и не переписывать Scenario архива «Память после лимита». Не дублировать в дельте уже действующие фразы «без имени модели» / «не повторять строку» / «следующие вызовы без платной модели». Дельта S1 — момент (первая строка того же хода), дословная фраза в always-apply, исключение verify, запрет печати токена и цитаты платформы. Новой capability нет. Дельта `subagent-model-mapping` — MODIFIED чатовой строки при отсутствии слага, не смена таблицы ролей.

## Existing Mechanisms

1. Канон одной строки в `model-selection.mdc` и Scenario «Память после лимита» — дописать **когда** сказать и **что запрещено**; текст канона не менять. Always-apply `chat-output-budget.mdc` §5 — **дом фразы и триггера**; §1b пункт «канон» — принуждение перед отправкой (первая строка).
2. Два входа в режим «без API» — не добавлять третий.
3. Cue токены → память → таблица — усилить: память после лимита = тот же режим без явного `-noapi`.
4. Русский по умолчанию в `opsx-output-style` §2 — отсылка; runtime-приоритет над Communication — в бюджете чата §6 (progress) и §1b пункт «язык».
5. Progress marker §6 — MUST русский; вводная английская речь — тот же провал, что и английский progress.
6. Metadata Gate и «один вопрос за ход» (`sequential-gate-questions`) — пропуск только при доказанном kit-only; деловой язык без `.bsl` — спросить. Поздний BSL — существующий `marker_scope` на apply (сначала разработчик по умолчанию из карточки проекта).
7. FAQ про ключ — ADDED про память, не удалять старый текст.
8. «Одно финальное сообщение» verify — существующий контракт; канон лимита и «Модель архитектора: Opus 5» вписываются как явное исключение в §1/§5a полного тела и в скилл verify, не отменяя карточку вердикта.

Уровень: расширить существующие правила, не строить параллельный «режим видимости» и не вводить третий вопрос на входе new.

## Design Rationale

Точка правки видимости — момент «только что случился липкий сбой» в always-apply разборе `Task failed`: и фраза, и триггер живут там, иначе оркестратор снова открывает on-demand правило. Принуждение перед отправкой — §1b пункт «канон» (первая строка). В verify «одно сообщение» сохраняется для карточки вердикта; канон и строка про Opus 5 — явное исключение, иначе инцидент повторяется на самом вероятном месте. Точка правки языка — §6 (progress) плюс §1b пункт «язык» (вводная речь). Точка правки маркера — пропуск только при доказанном kit-only; деловой язык без `.bsl` — спросить.

Самописный Rationale не закрывает архитектурный разбор: S1–S2 закрыты отчётом `openspec/changes/kit-session-noapi-visibility-and-ru-progress/reports/architecture-2026-08-19-kit-session-noapi-visibility.md`; D8 подтверждён заказчиком в этом чате.

## Behavior Contract

- После первого липкого сбоя первая строка чата в этом ходе — канон без имени модели; фраза дословно в бюджете чата §5; следующие пропуски шага 1 в том же чате без повторной строки.
- В `/opsx:verify` канон лимита и «Модель архитектора: Opus 5» уходят до финальной карточки (исключение из «одно сообщение»); карточка вердикта по-прежнему одна.
- Оркестратор не печатает `-noapi` и не говорит, что «включился noapi».
- Платформенный текст про смену модели не цитируется и не заменяет канон.
- Явный `-noapi` включает режим; канон лимита при этом не обязателен.
- Progress `/opsx:*` на русском; вводная английская речь — тот же провал; приоритет языка — §6 и §1b пункт «язык»; профиль модели язык не отменяет.
- Канон «Модель архитектора: Opus 5» — отдельная русская строка при отсутствии слага сильной модели; не канон лимита.
- `/opsx:new` без доказанного kit-only спрашивает маркер (в том числе деловой язык без `.bsl`); kit-only (только `.cursor/**` / `openspec/**` / документы kit) — не спрашивает; в proposal сразу minimal / n/a; пропуск закрывает гейт.
- `/opsx:new` с `.bsl` / модулями в `src/` в постановке спрашивает маркер как сейчас (один вопрос за ход).
- Если `developer: n/a`, а на apply `marker_scope` не пуст — сначала разработчик по умолчанию из карточки проекта, иначе вопрос автора до правки BSL; в маркер не писать `n/a`.
- Таблица ролей и ADR-0004 не меняются.

## Implementation Options

1. Дописать правила (видимость + язык + условие маркера) — выбран: 0 нового механизма. Уточнение: §5 — дом фразы и триггера; §1b — принуждение перед отправкой (канон — срез сигнала, язык — срез progress); исключение verify для канона явно в §1/§5a.
2. Печатать `-noapi` после лимита — ломает ADR-0004 (токен — слово пользователя). Отклонён.
3. Файл-состояние / `project.md` — отклонено архивом и ADR-0004.
4. Третий режим «видимость» — дубль признака. Отклонён.
5. HALT top-20 английскими глаголами как основная защита — запрещено постановкой. Отклонён.
6. Только FAQ без обязанности канона в том же ходе — английский абзац платформы остаётся первым. Отклонён.
7. Всегда спрашивать маркер (как сейчас) — лишний вопрос на kit-ЗНИ. Отклонён заказчиком.
8. Всегда спрашивать маркер только на apply, никогда на new — проще эвристики, но стиль маркера нужен уже при промпте исполнителю; заказчик просил сузить вопрос, не перенести. Отклонён.
9. Язык только во входном протоколе каждого скилла `/opsx:*` — хуже always-apply: скилл вытесняется из контекста. Отклонён.

Выбранный вариант в задачах: дописать существующие файлы; рецепт «куда вставить абзац» — в задачах через результат, не через микрошаги оркестратора.

## Simplicity Check

- **Viable alternatives:** см. Implementation Options 1–7.
- **Selected simplest viable design:** вариант 1.
- **Why not simpler:** без обязанности канона в том же ходе и без фразы в always-apply инцидент повторяется. Без исключения в verify «одно сообщение» перекрывает канон. Без S2 английский progress и вводная речь остаются до лимита. Без доказанного kit-only kit-ЗНИ снова спрашивает маркер, а деловая постановка 1С наоборот молча пропускает вопрос.
- **Complexity budget:** ~14 файлов kit, 0 метаданных 1С, 0 хуков, 0 новых режимов сессии, 1 условие на входе new + 1 перехват `n/a` на apply.

## Risks / Trade-offs

- [Канон + progress verify в одном ходе] → при лимите только канон; канон и «Модель архитектора: Opus 5» — исключение из «одно сообщение».
- [Эвристика «будет BSL» ошибётся] → пропуск только при доказанном kit-only; деловой язык без `.bsl` — спросить; если BSL появится позже — вопрос на apply по `marker_scope`.
- [Профиль Grok] → MUST NOT узкий (язык + канон), не отмена MAY плотности.
- [Не занести `-noapi` в запрет чата так, чтобы нельзя было объяснить токен в FAQ] → в чате при сбое токен не произносить; в FAQ — можно.
- [S1 и S2 правят один файл бюджета] → S1 владеет §5 и §1b пунктом «канон»; S2 — §6 и §1b пунктом «язык»; на apply не смешивать абзацы.

## Assumptions

- Отдельного API «есть ли квота» по-прежнему нет: сигнал лимита — сбой вызова.
- Communication Cursor может предлагать английский progress; контракт kit его перекрывает текстом правила.
- Kit-репозиторий без `openspec/project.md` — норма; `defaultDeveloper` не из чего взять, для ЗНИ без BSL это не блокер.
