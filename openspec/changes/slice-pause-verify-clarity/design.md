# Design

## Context

См. `proposal.md` — зачем. Сейчас место среза обязано быть в передаче на приёмку, но слот не стоит в первых строках чата и не входит в паузу ожидания объектов и в карточку проверки. Следующий шаг «до реализации» включается от любой пустой отметки, включая открытую приёмку. Тихий повтор смотрит сырой список задач, поэтому смена одних отметок пишет новую карточку. Пустая предпосылка сверку пропускает. Уже названная тема остаётся в пакете без проверки, меняют ли ответы результат. Внутреннего совпадения без парной записи заказчика недостаточно, и это открывает вопрос даже когда правило уже записано в плане.

Связанные ADR: ADR-0001 (в чат — короткая карточка, таблицы задач остаются в файле), ADR-0012 (повтор по дельте и внешний контракт), ADR-0013 (закрытая тема не возвращается без нового факта).

## Goals / Non-Goals

**Goals:**

- Человек на любой паузе среза видит номер и оставшиеся срезы с открытой приёмкой, не открывая список задач.
- Вопрос человеку и полный разбор тратятся только на смену результата или на ещё не охваченный результат.
- Отсутствие проверки и устаревание проверки после дополнения видны в шаге для человека.

**Non-Goals:**

- Не менять ручную приёмку в базе и не заменять её проверкой постановки.
- Не отменять запрет подписывать приёмку молча, пока задачи среза не делают результат достижимым.
- Не отменять запрет закрывать прямое указание заказчика внутренним согласованием.
- Не добавлять новую карточку, новый реестр и новый вид отчёта.

## Existing Mechanisms

Уже есть короткая передача на приёмку со строкой места среза, пауза-навигатор на объекты, пакет вопросов одного прогона, снимок входов и порог повтора темы. Новый параллельный формат паузы не вводится: строка места добавляется в существующие карточки, критерии вопроса сужают уже существующие правила.

## Decisions

### D1. Строка места — обязательный слот каждой паузы

Хозяин фразы — абзац правила чата у передачи на приёмку. Ожидание объектов, пауза с выбором, остановка по просьбе человека, карточка проверки на границе среза, конечная карточка пакета и снимок состояния на этот абзац ссылаются и свою копию не держат.

Фраза входит в первые строки чата. У передачи, ожидания объектов, паузы с выбором, остановки по просьбе и конечной карточки пакета она первая. У карточки проверки на границе среза первая строка остаётся итогом проверки; фраза места стоит сразу следом, до следующего шага.

В фразе — номер среза из общего числа и имена срезов с ещё открытой приёмкой, включая более ранние, либо что этот срез последний. Имён не больше трёх, дальше «и ещё N». На последнем срезе в ту же фразу остаётся: принять можно сейчас или позже, следом выбор архива. Таблица следующих задач в чат не добавляется.

На границе среза номер — у среза, чья приёмка открыта. На конечной карточке пакета одного номера нет: названы срезы этой сдачи и какие приёмки ещё открыты. Один ответ «принято» принимает эти срезы вместе, один возврат возвращает их вместе. Срез, которому нужен уже прогнанный в этом пакете, стартует, не дожидаясь его приёмки. Без пакета следующий срез не стартует. Фраза пишется, только когда в списке задач есть заголовки срезов. Без заголовков пауза остаётся как сейчас.

Карточку без этой строки не отправлять: собрать заново. Строка внизу файла её не заменяет. Строка о срезах, принятых без проверки, на карточке последнего среза остаётся отдельным предупреждением и в фразу места не вливается. У ожидания объектов список «что создать» не сокращается: фраза — одна строка перед «где мы».

Альтернатива — оставить строку только в файле передачи. Отклонена: человек читает чат.

### D2. Открытая приёмка — это шаг принять срез

Пока у среза рабочие задачи закрыты, его приёмка открыта, а у более поздних срезов рабочие задачи не начаты, шаг для человека — принять этот срез. Так же подписывается снимок состояния. Задачи следующего среза в этом шаге не начинаются. Подпись шага не говорит «до реализации».

Пустые отметки более поздних срезов этот шаг не отменяют. Если открыты приёмки нескольких срезов и это не конечная карточка пакета — одно уточнение, какой срез.

На карточке проверки в этой границе первая строка — что срез ждёт приёмки, а не что можно начинать задачи. Это четвёртая формулировка первой строки только для этой границы. Пока у текущего среза ещё есть пустые рабочие задачи, прежняя первая строка «можно начинать разработку» остаётся.

Внутреннюю фазу проверки не переключать на «после реализации», пока есть хоть одна пустая отметка. Архив из-за открытой приёмки не предлагать.

Повтор, в котором изменились только отметки рабочих задач, нового вопроса не открывает и паузу приёмки не снимает. «Текст не менялся» читается по уже существующей маске отметок в снимке; сырой список из-за одних флажков новую карточку вопроса не пишет. Смена текста задачи по-прежнему меняет снимок. Отметка самой приёмки паузу закрывает: это не тот повтор.

Альтернатива — молчать и не показывать паузу. Отклонена: место среза человек читает именно на паузе.

### D3. Пустая предпосылка не выключает сверку результата

Решение, которое меняет поведение или результат, хранит утверждение и место, где значение возникает, по тому же правилу, которое уже отличает варианты. Пустая предпосылка допустима только для решения, которое результат не меняет. Если у решения со сменой результата предпосылка пустая, сверка его не пропускает: в карточке нумерованный вопрос о факте, а вариант на пустом утверждении не подан как доказанный.

Опровержение заполненной предпосылки по-прежнему возвращает это решение. Порог раундов его не гасит и не подменяет вопросом «оставить текст или переписать срез». После ответа тот же факт не спрашивают снова, даже если строки в файле съехали. Пока выбор не подтверждён, его не ставят доводом против других вариантов. «Оставляю» — следующая проверка только по затронутому. «Меняю» — читается весь план.

Альтернатива — запретить пустую предпосылку всегда. Отклонена: учёт шага без смены результата остаётся процессным.

### D4. Уже записанное правило не спрашивается из-за пустой строки журнала

Если план уже содержит правило и это правило не является прямым указанием заказчика и не является принятой осью референса, отсутствие парной записи в журнале вопрос человеку не открывает.

Прямое указание заказчика и принятая ось референса при отсутствии ответа человека остаются открытым вопросом, даже если те же слова уже стоят в плане. Внутреннее совпадение их не закрывает. Парная запись здесь — ответ человека, не второй список указаний.

Сохранение уже данного ответа — отдельный случай. Это не пустая строка журнала и не указание без ответа. Если ответ человека уже записан, абзац только его сохраняет и наблюдаемое правило совпадает с ответом, вопроса про отдельную запись нет, и разбор задач не останавливается. Отдельный список указаний для этого не требуется.

Альтернатива — спрашивать при любой дыре журнала. Отклонена: это и есть остановка «подтвердите уже написанное».

### D5. В пакете только вопросы, которые меняют результат

Тема остаётся в пакете, если ответы меняют результат. Если оба ответа оставляют тот же результат, тема в пакет не входит. Если с уже данного ответа результат изменился, в той же карточке видно, что было в ответе и что стало, и вопрос только про это изменение. Прежний вопрос не повторяется. База «было» — правило из ответа, не текст плана до записи этого ответа. Отдельный вопрос не задаётся и тогда, когда оба ответа оставляют тот же видимый результат, а различие только в том, записывать ли шаг отдельно: этот шаг сливается в приёмку уже выбранного результата. Формулировка «дописать вместе с ответом» тему со сменой результата не снимает. В требование «все открытые темы одной карточкой» входит эта оговорка, чтобы два правила не спорили.

Запрет остаётся: нельзя снять недостижимую приёмку фразой «просто не подписывать», не правя задачи. Вопрос «оставляю или меняю» после несовпадения с модулем в пакете остаётся: смена выбора меняет план.

Альтернатива — выкидывать любую тему, которая не про экран. Отклонена: смена документа или отчёта без новой картинки всё ещё меняет результат.

### D6. Доказательство — место возникновения или явная оговорка

Утверждение, которое различает варианты, опирается на место, где значение возникает. «Места ещё нет» допустимо только когда объекта, где значение должно возникнуть, ещё нет: тогда карточка прямо говорит, что вопрос о тексте плана, и вариант не подан как доказанный. Если объект есть, а место возникновения в карточке не показано, это вопрос о факте. Место, где значение только используется, доказательством не считается. Короткий прогон, который утверждает сверку, пишет место возникновения в тексте карточки, не только во внутренней пометке. Вычисленное значение в карточке помечено как оценка. Дыра в доказательстве — вопрос в той же карточке; отдельная проверка из-за неё не стартует. Такая дыра новым результатом не считается.

Альтернатива — разрешить пробел плана как доказательство без оговорки. Отклонена: человек не отличает дыру текста от факта.

### D7. Полный разбор не пересказывает закрытое

Объём полного разбора не включает уже закрытые пункты без нового факта. Второй полный разбор в том же прогоне допустим только для результата, который первый разбор не охватывал. Дыра доказательства таким результатом не является и этот разбор не открывает. Порог раундов тратится на повтор той же темы. Новый результат — другая тема: этот порог он не тратит и как повтор не отбрасывается.

Если в этом проходе уже задан вопрос «оставить текст или переписать срез» и ответа ещё нет, в этом проходе он один. Новый результат в эту карточку не ставится и не теряется: он остаётся на следующий проход после ответа.

Альтернатива — после порога не задавать ничего. Отклонена: новый результат тогда теряется.

### D8. Предупреждение не выглядит вопросом

Неблокирующее предупреждение — одно предложение после строки следующего шага, не нумерованный пункт пакета. Строка следующего шага от него не меняется и не становится приглашением ответить. Строка о срезах, принятых без проверки, остаётся таким предупреждением.

Альтернатива — вложить предупреждение в пакет вопросов. Отклонена: человек читает его как выбор, которого нет.

### D9. Признак «проверка не выполнялась» живёт в шаге для человека

Признак виден в шаге на входе в разработку и в снимке состояния. Он не подменяет команду этого шага. Список задач и чужие отчёты для признака не открываются. Отчёт архитектора, контроль среза и разбор постановки признак не закрывают и разрешением начинать не считаются.

Если отчёта проверки нет — в том же шаге сказано, что проверка не выполнялась. Выбор сначала проверить или продолжить остаётся.

Если постановку дополнили после последней проверки — старый итог проверки не повторяется. Команда шага берётся из дополнения. Рядом видно, что проверка устарела. Если дополнения нет, а текст постановки новее отчёта — шаг ведёт на проверку, а не на старый итог.

## Behavior Contract

- На паузе среза в первых строках чата виден номер и оставшиеся открытые приёмки либо что срез последний. На конечной карточке пакета названы срезы этой сдачи. Один ответ принимает эти срезы вместе или возвращает их вместе. Срез, которому нужен уже прогнанный в пакете, стартует, не дожидаясь приёмки. У карточки проверки первой строкой остаётся итог, фраза места — сразу следом. Карточка без фразы не отправляется.
- Пока рабочие задачи среза закрыты, а его приёмка открыта, шаг — принять этот срез, даже если у следующих срезов отметки пустые. Архив из-за этого не предлагается. Подпись «до реализации» в этом шаге не используется. Без пакета следующий срез не стартует.
- Вопрос задаётся, когда ответы меняют результат. Если с уже данного ответа результат изменился, в той же карточке видно, что было в ответе и что стало, и вопрос только про это изменение. Рядом место, где значение возникает, либо оговорка, что объекта ещё нет. Пустое утверждение у такого вопроса не выглядит доказанным. Расчёт в карточке помечен как оценка. Дыра в доказательстве остаётся вопросом в той же карточке и отдельную проверку не запускает. Прямое указание без ответа человека остаётся вопросом.
- Уже закрытое и правило плана, которое прямым указанием не является, новым вопросом не становятся. Абзац, который только сохраняет уже данный ответ, вопрос не открывает, и пустой список указаний разбор задач не останавливает. После ответа на несовпадение с модулем тот же факт не спрашивают. «Оставляю» — дальше только затронутое. «Меняю» — весь план. Пока выбор не подтверждён, он не довод против других вариантов. Пока не отвечен вопрос «оставить текст или переписать срез», другого вопроса в этом проходе нет.
- Предупреждение стоит после шага и шаг не меняет.
- Нет отчёта проверки — это сказано в шаге, выбор сначала проверить или продолжить остаётся. Проверка старше дополнения — команда берётся из дополнения, и рядом видно, что проверка устарела.

## Design Rationale

Одна строка места и сужение уже существующих критериев дешевле новой карточки и нового реестра. Повтор того же ответа не возвращается. Если результат с ответа изменился, в той же карточке видно, что было и что стало. ADR-0001 сохраняется: в чат добавляется фраза, таблица задач остаётся в файле. ADR-0012 сохраняется: тихий повтор остаётся, но смена отметок больше не считается сменой текста. ADR-0013 сохраняется: закрытая тема не возвращается; сужается только случай, когда оба ответа не меняют результат и когда план уже содержит правило.

## Implementation Options

- Вариант A. Одна формулировка строки места в правиле чата; пауза на объекты, передача, карточка проверки и конечная карточка пакета на неё ссылаются.
- Вариант B. Четыре независимых абзаца в четырёх скиллах.

Выбран A: одна фраза не разъедется. B отклонён, потому что расхождение текстов — как раз текущая дыра.

Молчаливый отказ подписывать без правки задач запрещён | Спрашивать учёт шага при том же результате | Вопрос не меняет то, что человек увидит |
| Короткая карточка чата без таблицы задач | ADR-0001, Load-Bearing | В чат добавляется одна фраза места среза. Таблица задач остаётся в файле | Вывести список задач в чат | Список задач человек и так открывает, когда фразы нет |

## Slices

Три среза. У каждого свой результат, который можно принять отдельно. Приёмка — карточка в чате, без прогона в базе. Зависимостей между срезами нет. Общие файлы правятся разными абзацами.

| Срез | Пользовательский сценарий | Primary acceptance | Зависимости |
|---|---|---|---|
| S1: Место среза и шаг принять | На паузе в первых строках чата видно, какой это срез и какие приёмки ещё открыты. Если рабочие задачи закрыты, а приёмка открыта, шаг — принять этот срез. | Рабочие задачи среза закрыты, приёмка открыта, у более поздних срезов задачи не начаты и пакета нет → в чат приходит передача → в первых строках номер среза и какие приёмки ещё открыты, либо что срез последний; шаг — принять этот срез, без подписи «до реализации» и без вопроса «принято» в этом ходе. | нет |
| S2: Вопрос только при смене результата | Вопрос человеку есть только когда ответы меняют результат. Пустая предпосылка, пустая строка журнала и место, где значение лишь используется, такой вопрос не подменяют. | К концу прогона одна тема меняет результат, а вторая при любом ответе оставляет тот же → в чате одна карточка и в ней только первая тема. | нет |
| S3: Свежесть проверки и цена прогона | В шаге, который читает человек, видно, что проверки не было или она устарела после дополнения. Тот же прогон не пересказывает уже закрытое. | Отчёта проверки нет, другие отчёты по заявке есть → в шаге сказано, что проверка не выполнялась, и остаётся выбор сначала проверить или продолжить. | нет |

### Покрытие сценариев

| Сценарий | Срез |
|---|---|
| Пауза называет место, передача без вопроса, граница ведёт на приёмку, одни отметки не открывают вопрос, карточка без фразы не уходит, пакет называет сдачу и закрывается одним ответом | S1 |
| Тема без смены результата не входит в пакет, уже записанное правило не спрашивается, сохранение ответа не открывает вопрос, с ответа изменился результат, пустая предпосылка у решения со сменой результата, место доказательства, оценка помечена, дыра доказательства в той же карточке, после ответа тот же факт не спрашивают, стоп на третьей правке оставляет новый результат на следующий проход | S2 |
| Проверки не было, дополнение новее проверки, предупреждение не становится вопросом, разбор не пересказывает закрытое, новый результат не съедает порог повтора | S3 |

Непокрытых сценариев из дельт требований нет.

## Risks / Trade-offs

- [Подпись «до реализации» сохранится из-за пустых задач следующих срезов] → шаг смотрит границу среза: рабочие задачи текущего закрыты, приёмка открыта, поздние срезы не начаты.
- [Строка места разъедется по четырём текстам] → один источник фразы, остальные ссылаются.
- [Сужение пакета спрячет настоящий выбор] → критерий — смена результата, не «есть ли новая картинка».
- [Автослияние учёта шага подпишет недостижимый результат] → запрет «просто не подписывать» остаётся, пока задачи не делают результат достижимым.
- [Порог раундов перестанет ловить петлю] → порог тратится только на повтор той же темы.

## Решения verify (зафиксировано)

Три уже работающих правила остаются рядом с новыми фразами паузы. Пакет срезов по-прежнему закрывается одним ответом, и срез, которому нужен предыдущий, стартует сразу. После ответа на несовпадение с модулем тот же факт не спрашивают; «оставляю» смотрит только затронутое, «меняю» читает весь план. Расчёт в карточке помечен как оценка, дыра в доказательстве не запускает вторую проверку. После ответа тот же вопрос не возвращается. Запись, которая только сохраняет этот ответ, вопрос не открывает. Если с того ответа результат изменился, в той же карточке видно, что было и что стало, и вопрос только про это изменение. Новое указание без ответа по-прежнему спрашивается.

Опора: в действующих требованиях один ответ принимает срезы пакета вместе (`openspec/specs/kit-protocol-coherence/spec.md:10`); после ответа тот же факт не эскалируется, подтверждение сужает следующую проверку, смена читает план целиком (`openspec/specs/verify-stop-repeat/spec.md:113`); расчёт помечен как оценка, дыра доказательства не запускает отдельный разбор (`openspec/specs/verify-stop-repeat/spec.md:37`).
