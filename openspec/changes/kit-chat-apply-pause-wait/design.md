# Design: kit-chat-apply-pause-wait

## Context

На паузе apply при отсутствии метаданных в выгрузке оркестратор писал в чат прогресс среза и ссылку на файл, а полный чеклист Конфигуратора оставлял внизу `handoff-pause-*.md`. Правила «чат самодостаточен» и «тонкий handoff 4–8 строк» противоречили друг другу; тест понятности бил лимит только для развилок A/B.

## Goals / Non-Goals

**Goals:**

- Человек по чату понимает, где он и что создать в Конфигураторе.
- Файл паузы остаётся местом рецепта (типы, FillValue, флаги модуля, пути XML).
- pause-wait не маскируется под decision-block.

**Non-Goals:**

- Переписывать verify, explore, acceptance-handoff целиком.
- Менять запрет создавать XML метаданных агентом.
- Править PavDO: после правки кита повторный apply сам даст новый текст.

## Decisions

**D1. Два вида паузы.** `pause-wait` — следующий шаг человека: Конфигуратор / выгрузка / доп.реквизиты в ИБ. `pause-decision` — выбор A/B (неясное требование, scope). Пользовательский «стоп» — короткий pause, не wait.

**D2. Чат = инвентарь, файл = рецепт.** До 7 пунктов «что создать» в чате (вне лимита 4–8). Якорь файла обязан содержать имя раздела «Что создать в Конфигураторе». Открытие файла — за рецептом, не чтобы узнать задачу.

**D3. Ясность wait важнее лимита строк.** Как уже для развилок: иерархия «лимит > шаблон» не вырезает список объектов. Профили модели по-прежнему не ослабляют HALT; исключение записано в самом бюджете чата.

**D4. Имена в живой ИБ — сноска, не A/B.** «Если имена другие — напишите фактические» в конце карточки, не заголовок «Что решить».

Отклонено: оставить тонкий чат и «смотрите файл» — провал теста читателя на PavDO. Отклонено: копировать весь рецепт в чат — дубль файла и шум.

## Behavior Contract

1. Первая строка pause-wait — где мы, не slug change.
2. В чате нет «0/N задач» и списка отсутствующих XML как тела.
3. Файл паузы начинается человеческим разделом «Что создать в Конфигураторе».
