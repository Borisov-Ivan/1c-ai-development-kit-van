# Slice decomposition — universal-visual-explanation

Kit-only замена продукта: панель визуального объяснения вместо карты сценария. Нет `.bsl`, нет ИБ, нет Конфигуратора. Порог **Standard**, **1 срез по умолчанию**.

## KB references

- Во входе: taxonomy отсутствует; Discovery выполнен, совпадений нет. KB-ID для `used` / `conflict` нет.
- Пустой набор фактов: not relevant — на границу срезов и Primary не влияет.

## Почему один срез

**Пользовательский исход один:** попросить схему (или увидеть автопанель, когда без картинки ответ хуже) → рядом с чатом открывается понятное объяснение того же вопроса → старого комбайна карты нет.

Это не два исхода. Удаление скилла/агента/фикстур без нового скилла оставляет пустоту. Новый скилл без удаления оставляет указатели на комбайн: приёмка «это не старая карта» недостижима. Автопанель, указатель диспетчера, ADR-0010 и пометка соседней ЗНИ — слои той же замены, не отдельные продукты.

### Отклонённые нарезки

| Кандидат S2 | Почему не срез |
|-------------|----------------|
| Удаление `scenario-map-canvas` / агента-сборщика | Нет самостоятельного UX; без удаления S1 не принимается (указатели зовут комбайн). `foundation-slice-with-gate`. |
| Сначала скилл, потом указатели | Указатели без скилла ломают «покажи схему»; скилл без указателей оставляет старый протокол. Один стек. |
| Прямая просьба vs автопанель | Два правила одного продукта; автопанель отдельно не принимается (нет своего носителя). Не 1:1 Requirement → Slice. |
| «Схема компоновки» как kit-панель не открывается | Охранный сценарий того же скилла, не второй продукт. |
| Пометка `scenario-map-explain-and-overlap` | Служебная строка в журнале соседней ЗНИ, не user-journey. |

**Self-check 4a / QC 8b:** Primary достижим задачами S1 (скилл, шаблон, указатели, удаление, ADR). Следующего среза нет. Дубля Primary нет.

**Simplicity Check (граница срезов, не выбор стека):** единственный жизнеспособный вариант — один срез-замена. Более мелкая нарезка либо foundation-с-gate, либо не 1:1 Requirement → Slice.

**Оценка объёма задач (для порога, не для tasks.md):** примерно 8–14 `S1.<M>` (скилл + шаблон, пачка указателей, удаление, ADR, пометка соседней ЗНИ, static-покрытие spec) + `S1.accept`. Это Standard, не повод дробить.

**User Task Contract:** в `S1.<M>` нет «на ИБ», «стенд», «вызвать API». Приёмка — панель рядом с чатом; исчезновение старого конвейера — сверка по файлам kit (агент, optional для пользователя).

**REMOVED без `#### Scenario:`:** `specs/scenario-map-canvas/spec.md` и `specs/delegation-safeguards/spec.md` — только снятие требований. Покрытие QC Scenario Coverage к ним не применяется; закрытие — задачи удаления в S1 (D6).
