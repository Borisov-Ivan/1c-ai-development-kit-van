# Срез S1: Назначение модели по цене ошибки

**Сценарий:** на первой проверке без тяжёлого признака независимый разбор идёт на тяжёлой модели, при тяжёлом признаке — на самой сильной.

**Primary acceptance:** открыть правило назначения и увидеть, что независимый разбор без тяжёлого признака описан тяжёлой моделью и строкой «Разбор постановки (Opus 5)», а с тяжёлым признаком — самой сильной моделью и строкой «Разбор постановки (Fable)», если она есть в списке вызова.

**Приёмка:** чтение правила назначения и чеклиста вызова. Конфигурация 1С не нужна.

**Связь со spec:** Requirement «Мэппинг ролей на актуальные модели» — Scenario «Ревью кода на модели Gemini из списка», Scenario «В списке нет семейства Gemini», Scenario «Сверка одного среза на модели чата», Scenario «Сверка нескольких срезов на профиле GPT-5.6», Scenario «В списке нет профиля GPT-5.6», Scenario «Готовность задач на модели чата», Scenario «Готовность при неизвестном перехвате или вызове платформы»; Requirement «Fable только как закрытая эскалация архитектора» — Scenario «Независимый разбор без тяжёлого признака идёт на тяжёлую модель», Scenario «Независимый разбор с тяжёлым признаком идёт на Fable», Scenario «Сбой Opus не включает Fable».

**Зависимости:** нет.

## 1. Правило назначения

- [x] S1.1 В `.cursor/rules/model-selection.mdc`: оставить простую проверку на тяжёлой модели, независимый разбор берёт самую сильную только при тяжёлом признаке (D1). В единственной таблице шагов раздела «Закрытая эскалация Fable» заголовок не переименовывать и вторую таблицу не заводить. Строка независимого разбора (`mode=design-challenge`) делится условием, не новым разделом. Самая сильная модель, если она есть в списке вызова, и строка «Разбор постановки (Fable)» — при хотя бы одном признаке строки глубокого разбора или триггера повторного разбора: новый объект метаданных, перехват базовой процедуры, Identity Filter, конфликт с архивным контрактом, петля приёмки среза, две жизнеспособные альтернативы, риск безопасности, ресурсов или прецедента. «Фильтр по имени объекта» записать как Identity Filter. Третьего списка признаков не заводить. Без этих признаков вызов идёт на старшую модель семейства Opus, мажор 5, и в чат — «Разбор постановки (Opus 5)», даже когда сильная модель в списке есть. Малый объём заявки запуск на первой проверке и при смене решения не отменяет. Сбой тяжёлой модели переходит к вызову без явной модели и самую сильную не включает. Соседние фразы, которые подставляют слаг из формулировки «на этой сборке семейства нет» или включают самую сильную на любой независимый разбор, как только она есть в списке, переписать так, чтобы модель бралась из списка вызова по уже записанному старшинству. Строки сверки с прошлым договором и явной просьбы о самой сильной модели остаются на прежней лестнице: сильная, если она есть, иначе тяжёлая, с той же одной строкой. Признаки глубокого разбора из строки сильнейшей модели не выпадают. Критерий: по тексту закрыты Scenario «Независимый разбор без тяжёлого признака идёт на тяжёлую модель», «Независимый разбор с тяжёлым признаком идёт на Fable», «Нет слага сильной модели — строка про Opus 5», «Сбой Opus не включает Fable», «Сверка с прошлым договором идёт по лестнице независимого разбора с тяжёлым признаком», «Декомпозиция срезов не идёт на Fable».

- [x] S1.2 В `.cursor/rules/model-selection.mdc` и в пунктах 2 и 3 `openspec/adrs/ADR-0011-architect-step-model-table.md`: поднять готовность на тяжёлую модель при трёх поводах, ревью на Gemini, сверку заявки из нескольких срезов на GPT-5.6 (D2, D3, D4). Новый ADR не заводить. Пункт 3 оставляет сверку с прошлым договором на лестнице самой сильной модели и отдельно говорит, что независимый разбор берёт эту лестницу только при тяжёлом признаке. Абзац последствий перестаёт утверждать прежнюю модель ревью и прежнюю модель согласованности срезов. Вторую таблицу не заводить. Строка роли ревью: убрать точное имя, которого нет в списке вызова; вызов — старшая модель семейства Gemini по тому же старшинству, что у Opus, Fable и Grok. Семейство `gemini` добавить в правило старшинства. Упрощение остаётся на точном имени `composer-2.5-fast`. Если семейства Gemini в списке нет — вызов без явной модели, одна строка предупреждения, другое семейство не подставляется и запас через Opus здесь не используется. Строка роли контроля согласованности срезов (`openspec-quality-controller`): в заявке один срез — без явной модели; в заявке срезов больше одного — старшая модель, которая по роутеру профилей нормализуется в профиль GPT-5.6, даже когда в этот запуск попал один срез; такой модели нет — без явной модели, другое семейство не подставляется. Исключение живёт в этой строке роли, второй таблицы нет. Цепочка, которая сейчас всегда вызывает эту роль без модели, исключение не затирает. Строка готовности задач и пункт 2 ADR-0011: без неизвестного состава перехвата, без неподтверждённого вызова платформы и без неизвестной сигнатуры или контракта данных — без явной модели; ручная настройка и новая связь модулей остаются на модели чата. Три повода — неизвестный состав перехвата, неподтверждённый вызов платформы, неизвестная сигнатура или контракт данных — старшая модель семейства Opus, мажор 5; самая сильная не подставляется. У вызова без явной модели первого платного шага нет. У вызова на тяжёлой цепочка обычная: сбой переходит к вызову без явной модели. Сбой единственного вызова без явной модели по-прежнему не считает шаг пройденным и не подставляет прошлый отчёт как результат этого запуска. Строка роли архитектора модель шага не называет. Написание кода, обследование, трасса, упрощение и рекомендация чата не меняются. Самосверка перед вызовом берёт для ревьюера старшую Gemini, для заявки, в которой срезов больше одного, — старшую модель профиля GPT-5.6. Критерий: по тексту закрыты Scenario «Ревью кода на модели Gemini из списка», «В списке нет семейства Gemini», «Сверка одного среза на модели чата», «Сверка нескольких срезов на профиле GPT-5.6», «В списке нет профиля GPT-5.6», «Готовность задач на модели чата», «Готовность при неизвестном перехвате или вызове платформы», «Сбой единственного вызова готовности задач», «Вызов архитектора без ошибки enum», «Команда на Grok 4 без смены чата», «Рантайм свободен от мёртвых слагов», «Слаг таблицы отсутствует в enum сборки». Зависимости: S1.1.

## 2. Чеклист вызова

- [x] S1.3 В `.cursor/rules/tool-name-guard.mdc`: убрать второй перечень моделей, чеклист ссылается на строку роли контроля срезов (D3, D4). Места, где контроль согласованности срезов назван всегда «без модели», заменить отсылкой на строку роли в `.cursor/rules/model-selection.mdc` и свой перечень моделей не разворачивать. Места, где готовность задач названа всегда вызовом без явной модели или где сбой этой роли безусловно запрещает тяжёлую модель, заменить отсылкой на строку готовности задач той же таблицы, без второго списка поводов. Токены режима сессии и классификацию сбоев в чеклист не копировать. Критерий: в чеклисте нет второго перечня моделей ревью, контроля срезов и готовности задач; одно срезовое исключение и три повода готовности читаются только из строк правила назначения. Зависимости: S1.2.
