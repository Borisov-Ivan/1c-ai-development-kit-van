## MODIFIED Requirements

### Requirement: Per-form delivery modes for managed forms

Proposal ЗНИ с управляемыми формами SHALL хранить режим поставки формы: `form_mode` со значениями `manual`, `assisted`, `bsl-only` или `n/a` (при нескольких формах — YAML-map `forms:` с каноническим ключом метаданных формы → mode; при одной форме допустим скаляр).

После стабилизации списка форм в scope оркестратор SHALL классифицировать **каждую** форму без записанного валидного режима:

- **module-only** — в постановке есть работа в модуле формы и нет разметки этой формы: оркестратор MUST NOT задавать вопрос поставки; SHALL записать поставку программно (`bsl-only`) до приёмки design.
- **layout** или **ambiguous** — есть разметка (файл формы, реквизиты/элементы в Конфигураторе) либо способ не доказан: оркестратор SHALL задать один вопрос про поставку **этой** формы и записать ответ до приёмки design.
- Вопрос SHALL NOT задаваться для табличного макета (Template/MXL) в `/opsx:new`. Макет по умолчанию поставляется вручную; иной путь для макета — только по явному разрешению пользователя во время apply (чат apply / одноразовый вопрос / маркер `[mxl:…]` в tasks), с фиксацией в `debug.md`.

Оркестратор MUST NOT записывать «автоматически» (`assisted`) без явного ответа. Оркестратор MUST NOT записывать `n/a` при задаче на модуль формы. Голого отсутствия файла разметки недостаточно для module-only: нужны положительные признаки модуля и отсутствие токенов разметки.

#### Scenario: Form Mode question on design for in-scope form

- **WHEN** на этапе design у формы без записанного режима в постановке есть разметка (поля, кнопки, Конфигуратор, файл разметки) **или** форма в списке, но не доказано, что правят только модуль
- **THEN** оркестратор задаёт один вопрос про поставку **этой** формы (вручную / автоматически / программно) и до приёмки design записывает ответ в карточку ЗНИ

#### Scenario: Multiple forms get sequential Mode questions

- **WHEN** в scope две или более управляемых формы без режимов, и среди них есть формы с разметкой или неясным способом
- **THEN** оркестратор задаёт вопросы только по этим формам, по одной за сообщение (с паузой до ответа); формы «только модуль» в том же списке уже записаны как программно; разные формы могут иметь разные режимы; режим соседней формы не копируется

#### Scenario: No layout Mode question in new

- **WHEN** постановка затрагивает табличный макет
- **THEN** в `/opsx:new` оркестратор не задаёт вопрос про способ поставки макета

#### Scenario: Layout stays manual unless apply permission

- **WHEN** apply выполняет задачи по табличному макету и пользователь не дал явного разрешения на иной путь
- **THEN** apply следует ручной поставке макета (инструкция / ожидание выгрузки), без молчаливой правки макета в репозитории

#### Scenario: Legacy single artifact_mode maps to form_mode

- **WHEN** в proposal есть только устаревшее поле `artifact_mode` с валидным значением и нет скаляра `form_mode` / map `forms:`
- **THEN** apply и verify трактуют это значение как одинаковый режим для всех форм, уже входящих в scope на момент чтения (включая несколько форм), без переспроса

#### Scenario: Kit evolution without form modes

- **WHEN** ЗНИ — эволюция kit без правки разметки прикладной формы
- **THEN** в proposal режим форм «не применимо», вопрос поставки формы не задаётся

#### Scenario: Empty form mode blocks apply for in-scope form

- **WHEN** в постановке есть задача на управляемую форму (разметка или модуль), а режим этой формы пуст либо «не применимо» (и нет валидного lone legacy `artifact_mode`)
- **THEN** apply и verify останавливаются с требованием дозаполнить режим формы, не подставляя режим другой формы и не выбирая default молча

#### Scenario: Layout non-manual requires recorded apply permission

- **WHEN** apply собирается выполнить неручной путь для табличного макета
- **THEN** путь допускается только при уже зафиксированном разрешении (ответ в чате apply, одноразовый вопрос или маркер `[mxl:…]` / явная запись в tasks) и записи в `debug.md`; иначе apply остаётся на ручной поставке

## ADDED Requirements

### Requirement: Module-only form records programmatic delivery without a question

Если после стабилизации списка форм доказано, что для управляемой формы в ЗНИ меняется только модуль (разметку не трогают), оркестратор SHALL записать поставку программно и MUST NOT показывать выбор вручную / автоматически / программно. Форма SHALL остаться в списке форм (не `n/a`). Поясняющая строка в чат MAY быть; она MUST NOT считаться вопросом выбора. Записанный ранее валидный режим MUST NOT перезаписываться этой логикой.

#### Scenario: Module-only records programmatic without question

- **WHEN** постановка на этапе design: для названной формы правят только модуль (например номера в заголовках существующих колонок), разметку не трогают, режима этой формы ещё нет
- **THEN** выбора «вручную / автоматически / программно» нет; в карточке ЗНИ для этой формы стоит поставка программно

#### Scenario: Mixed forms sequential

- **WHEN** в одной ЗНИ форма A — только модуль без записанного режима, форма B — разметка без записанного режима
- **THEN** для A выбора нет и в карточке сразу программно; отдельным сообщением задаётся вопрос про B; режимы A и B разные

#### Scenario: Resume does not overwrite recorded mode

- **WHEN** в карточке ЗНИ у формы уже записан валидный режим, а задачи выглядят как «только модуль»
- **THEN** оркестратор не переспрашивает и не меняет записанный режим на программно

#### Scenario: Informing line is not a selection question

- **WHEN** оркестратор записывает программно без вопроса и при желании пишет одну строку «записываю поставку программно»
- **THEN** в том же сообщении нет второго взаимоисключающего выбора; строка не требует ответа, чтобы продолжить цикл форм
