# Design

## Context

См. `proposal.md`, раздел Why. Сейчас вопрос «правка задевает два среза?» в `.cursor/rules/vertical-slices.mdc` сам открывает новый срез со своей приёмкой. Проверка считает такую приёмку дефектом и по `.cursor/skills/openspec-verify-change/SKILL.md` спрашивает, объединить срезы или переписать приёмку, даже когда оба ответа оставляют тот же видимый результат. Дополнение затем читает таблицу глубины и уводит это в полную проверку как новый сценарий.

Уже записано и этой правкой не отменяется: если оба ответа оставляют тот же видимый результат, а различие только в том, записывать ли шаг отдельно, вопрос не задаётся и шаг сливается в приёмку уже выбранного результата (`openspec/specs/verify-stop-repeat/spec.md`, требование «Все решения прогона одной карточкой»). Класс «замена значения» и три исхода дополнения живут в одной таблице глубины, второго классификатора нет (ADR-0014, load-bearing). Повтор закрытой темы и смена подхода остаются как в ADR-0013. Проверка по дельте остаётся как в ADR-0012.

Связанные ADR: ADR-0014 (лёгкий маршрут замены значения — одна таблица глубины), ADR-0013 (закрытый вопрос не возвращается; смена подхода даёт полный разбор), ADR-0012 (проверка по дельте).

## Goals / Non-Goals

**Goals:**

- Маршрут починки берётся из вывода разбора дефекта.
- Прежний результат для пользователя дописывается в открытую приёмку и идёт на реализацию.
- Вопрос человеку остаётся, когда от выбора меняется результат или момент, когда его уже можно принять.

**Non-Goals:**

- Не менять правило уже подписанной приёмки.
- Не ослаблять полную проверку при смене формулы, момента, порядка шагов или при новом сценарии.
- Не заводить второй классификатор рядом с таблицей глубины.
- Не отменять остановку «оставить текст или переписать срез» на втором переоткрытии одной темы.

## Decisions

### 1. Вход маршрута — вывод разбора, не новый вопрос

Маршрут читает уже сделанный разбор: что сломалось, остаётся ли обещанный результат, насколько широко та же поломка повторяется на этом пути, что в правку не входит.

Отклонён ярлык «результат тот же — значит простой путь». Он снова подменяет разбор одним вопросом, на который можно ответить, не читая, почему запрос незаконен и меняется ли сумма.

### 2. Число срезов не открывает новый срез

Условие «правка задевает два среза по файлам» перестаёт быть достаточной причиной нового среза и отдельной приёмки. Новый срез остаётся, когда вывод разбора называет результат, которого в текущих срезах нет, или другой момент, когда результат уже можно принять.

Починка текста, которая делает уже записанный результат выполнимым, кладёт задачи в открытый неподписанный срез, чья приёмка уже описывает этот результат. Отдельная приёмка из текста ошибки не пишется. Сумма, справка и закрытый месяц остаются примером такого результата в сценарии починки запроса; в текст общего правила их не вписывать.

Если открытых срезов с этой приёмкой несколько, задачи встают в тот, который другие открытые срезы с той же приёмкой указали в зависимостях. Если такой ссылки нет — в срез с наименьшим номером. Вопрос «если срез однозначно не выбран» при том же видимом результате и том же моменте приёмки не задаётся.

Общий модуль у двух открытых срезов сам по себе новый срез не создаёт. Один уже записанный результат — задачи в его открытый срез, вопрос не задаётся. Два разных уже записанных результата, которые одна правка меняет оба, — это расхождение результата: вопрос человеку остаётся. Результат, которого в текущих срезах нет, или другой момент приёмки — новый срез.

Если уже есть открытый срез, чья приёмка повторяет результат другого открытого среза или взята из текста ошибки, и видимый результат с моментом приёмки совпадают: карточку не показывать, задачи перенести в срез этого результата, снять лишний заголовок среза и его приёмку, затем пройти уже существующий перечень после слияния (перенумерация, одна приёмка, зависимости). Пока лишняя приёмка есть, строка глубины не срабатывает: снятие идёт до чтения таблицы. Ограничение «слияние двух срезов только через вопрос» на этот случай не действует. На расхождение результата или момента приёмки оно действует по-прежнему. Подписанная приёмка этим снятием не трогается: её признак читается раньше.

### 3. Вопрос про раскладку не задаётся

Карточка «объединить срезы или переписать приёмку» не показывается и не считается развилкой, когда видимый результат и момент приёмки совпадают. Раскладку делает решение 2, приёмка из текста ошибки не остаётся. Уже открытый шаг с такой приёмкой тоже не ждёт ответа: карточка не показывается, лишняя приёмка снимается правилом размещения. Ограничение «слияние двух срезов только через вопрос» на этот случай не действует. Это исполнение уже записанного требования «Все решения прогона одной карточкой». Новый смысл в то требование не добавляется.

Если варианты расходятся в результате или в моменте приёмки, карточка остаётся. Ответ на неё не отменяет полную проверку, если выбранный текст меняет формулу, момент правила, порядок шагов или добавляет сценарий.

Вопрос «оставить текст или переписать срез» на втором переоткрытии темы — не эта карточка. Он по-прежнему один в своём проходе и этой заявкой не отменяется, даже если раскладка задач результата не меняет.

### 4. Исход дополнения — та же таблица глубины

Вывод разбора решает, куда положить задачи (решения 2–3). Глубину и исход дополнения он не выбирает. Отдельного прохода «сначала разбор, потом таблица» нет. Ярлык «результат тот же» по-прежнему не заменяет разбор: без разбора не видно, делает ли правка записанный результат выполнимым.

В таблицу глубины, которую уже читают и проверка, и итог дополнения, добавляется одна строка. Она срабатывает только когда одновременно:

1. Уже была первая полная проверка.
2. Формула, момент правила, порядок шагов и условия сценария не изменились, новый сценарий не добавлен.
3. Момент приёмки не изменился: приёмка остаётся той, что уже записана для этого результата.
4. Новая строка приёмки не добавлена.
5. Задачи стоят в срезе, чья приёмка ещё не подписана.

Если разбор написал, что сумма прежняя, а текст формулы, момента правила, порядка или сценария изменился, строка не срабатывает и остаётся полная проверка.

Когда все пять условий истинны, эта строка читается раньше первой строки таблицы, включая «неизвестная граница дельты», раньше строки про правку контракта поведения и раньше фразы, что полный проход остаётся. Смена текста формулы, момента правила, порядка или сценария по-прежнему даёт полную проверку.

Строка не перехватывает дополнение, которое только фиксирует ответ заказчика внутри выбранного подхода: для него остаётся короткая сверка изменённого, не пропуск проверки. Условие «задачи стоят в срезе» выполнено, только если эта дельта дописала задачи починки в открытую приёмку, а не потому что в заявке вообще есть неподписанный срез.

Это соседняя строка той же таблицы, не расширение класса «замена значения» и не второй классификатор. Пункт исхода «проверка не требуется» называет две причины одной таблицы: класс «замена значения» и эту строку. Третьего исхода нет. Короткая сверка ответа внутри выбранного подхода остаётся прежним исходом и в эти две причины не входит.

Добавление текста задачи по-прежнему изменение постановки. Отметка приёмки по-прежнему не делает проверку устаревшей. Если проверку на такой дельте всё же запустили, полный независимый разбор постановки не назначается.

### 5. Подписанная приёмка

Признак подписанной приёмки проверяется первым. Пока он стоит, решения 2–4 не читаются. Остаётся прежнее правило подписанного среза: в подписанный срез не дописывать и приёмку не снимать. На класс «замена значения» в уже принятом срезе это решение не распространяется.

## Behavior Contract

- Починка, после которой проведение, сумма и справка те же, не получает отдельный шаг и не спрашивает, куда её положить. Если такая приёмка уже открыта и результат с моментом приёмки совпадают, она снимается до чтения таблицы глубины, задачи стоят перед приёмкой этого результата. Дальше реализация, если уже была первая полная проверка, лишняя строка приёмки не осталась и эта дельта дописала задачи починки.
- Если открытых срезов с этой приёмкой несколько, задачи встают в срез, который другие открытые срезы с той же приёмкой указали в зависимостях; если ссылки нет — в срез с наименьшим номером.
- Если меняются формула, момент правила, порядок шагов или добавляется сценарий, дополнение предлагает полную проверку постановки. Сумма в примере проведения — случай смены формулы, не отдельное правило. Момент правила (когда наступает результат) и момент приёмки (когда результат уже можно принять) не смешивать: смена момента правила ведёт к полной проверке; расхождение момента приёмки между вариантами оставляет вопрос человеку.
- Одна правка двух разных уже записанных результатов оставляет вопрос человеку. Общий модуль у двух срезов сам по себе вопрос не открывает.
- Человека спрашивают только когда варианты расходятся в результате или в моменте приёмки.
- Дополнение, которое только фиксирует ответ заказчика внутри выбранного подхода и не дописывает задачи починки, этой строкой не перехватывается: остаётся короткая сверка изменённого.
- Уже подписанная приёмка не снимается и не дописывается молча.

## Implementation Options

Выбран вывод разбора как вход маршрута (решение 1). Отклонены: вопрос «результат тот же?» без разбора; карточка «в какой срез» при том же результате; отдельный классификатор помимо таблицы глубины.

## Slices

Один срез. Объём — правка трёх существующих правил и уже записанное требование. Отдельный срез на «проводится» не заводится: это как раз то, что заявка запрещает.

| Срез | Сценарий | Что меняется для пользователя | Приёмка | Зависимости |
|---|---|---|---|---|
| Маршрут починки с прежним результатом | Починка запроса после первой проверки; уже открытая приёмка из текста ошибки снимается; до первой полной проверки строка не срабатывает; смена формулы ведёт к проверке; разный момент приёмки оставляют вопросом; два разных результата оставляют вопросом; подписанная приёмка не дописывается; ответ внутри выбранного подхода остаётся короткой сверкой; повторный запуск проверки не становится полным разбором | Починка с прежним проведением, суммой и справкой не спрашивает, куда её положить, и идёт в реализацию. Уже открытая приёмка из текста ошибки при том же результате снимается. Смена формулы по-прежнему идёт в проверку постановки | Первая полная проверка уже была, приёмка проведения открыта, разбор оставил ту же сумму и справку → карточки «в какой срез» нет, приёмки «проводится» нет, следующий шаг — реализация | нет |

### Матрица приёмки

| Сценарий требования | Покрыт |
|---|---|
| Починка запроса после первой проверки | да, основной путь |
| Уже открытая приёмка из текста ошибки снимается | да, тот же путь, если шаг уже открыт |
| До первой полной проверки строка не срабатывает | да, граница того же пути |
| Смена формулы ведёт к проверке | да |
| Разный момент приёмки оставляют вопросом | да |
| Два разных результата оставляют вопросом | да |
| Подписанная приёмка не дописывается | да |
| Ответ внутри выбранного подхода остаётся короткой сверкой | да, эта строка его не перехватывает |
| Повторный запуск проверки не становится полным разбором | да, проверка внутри того же пути |

## Risks / Trade-offs

- [Разбор ошибочно скажет, что сумма не меняется, и полная проверка не запустится] → строка таблицы не срабатывает, если меняются формула, момент, порядок или условия сценария. Сценарий «смена сути правила ведёт к проверке» остаётся.
- [Остановку по повторной теме примут за отменённую] → вопрос «оставить текст или переписать срез» на втором переоткрытии темы остаётся. Эта заявка его не трогает.
- [Починку после подписанной приёмки по-прежнему оформят новым срезом] → это вне цели. Прежнее правило подписанного среза сохраняется.

## Migration Plan

Переноса данных нет. Откат — вернуть три правила к прежнему тексту: размещение срезов, глубина проверки, итог дополнения.

## Design Rationale

Точка правки — уже существующие развилка размещения и таблица глубины. Новый контур не заводится: ADR-0014 держит исход дополнения в одной таблице. Карточка на скрине противоречит уже принятому требованию не спрашивать о раскладке при том же результате; правка заставляет правило размещения этому требованию подчиниться, а не заводит второе.
