# Срез S1: Маршрут починки с прежним результатом

**Сценарий:** починка запроса после первой проверки оставляет проведение, сумму и справку прежними и не спрашивает, куда положить задачи.
**Primary acceptance:** первая полная проверка уже была, приёмка проведения открыта, разбор оставил ту же сумму и справку → карточки «в какой срез» нет, приёмки «проводится» нет, следующий шаг — реализация.
**Приёмка:** проход в чате по заявке, у которой первая полная проверка уже была, а приёмка проведения ещё открыта.
**Связь со spec:** Requirement «Починка с прежним результатом идёт на реализацию» — Scenario «Починка запроса после первой проверки», Scenario «Уже открытая приёмка из текста ошибки снимается», Scenario «До первой полной проверки строка не срабатывает», Scenario «Смена формулы ведёт к проверке», Scenario «Разный момент приёмки оставляют вопросом», Scenario «Два разных результата оставляют вопросом», Scenario «Подписанная приёмка не дописывается», Scenario «Ответ внутри выбранного подхода остаётся короткой сверкой», Scenario «Повторный запуск проверки не становится полным разбором». Requirement «В пару не ставится ветвь, которая не выполняет уже сказанное» — Scenario «Мёртвая ветвь карточки проверки не спрашивается», Scenario «Карточка дополнения не предлагает не делать уже названное», Scenario «Вход проверки не прячет уже сказанную фразу», Scenario «Следующий шаг после ответа берётся из таблицы глубины», Scenario «Вопрос показывается словами уже записанного результата».
**Зависимости:** нет

Если таких срезов несколько — в тот, который другие открытые срезы с той же приёмкой указали в зависимостях; если ссылки нет — в срез с наименьшим номером. Сумма, справка, закрытый месяц и фразы «проводится» и «без ошибок» остаются примером сценария; в текст общего правила их не вписывать.

  Если уже есть открытый срез, чья приёмка повторяет результат другого открытого среза или взята из текста ошибки, и видимый результат с моментом приёмки совпадают: карточку не показывать, задачи перенести в срез этого результата, снять лишний заголовок и его приёмку, затем пройти перечень после слияния (перенумерация, одна приёмка, зависимости). Это снятие идёт до чтения таблицы глубины. Один уже записанный результат вопроса не задаёт. Два разных уже записанных результата, которые одна правка меняет оба, оставляют вопрос человеку. Результат, которого в текущих срезах нет, или другой момент приёмки — новый срез.

  Признак подписанной приёмки читается первым: пока подпись стоит, эта раскладка не читается, в подписанный срез задачи не дописываются и подпись не снимается. Прочий текст правила подписанного среза и путь класса «замена значения» в уже принятом срезе оставить как есть.

  Проверка: при той же сумме, справке и моменте приёмки в тексте нет развилки «в какой срез» и нет отдельной приёмки из текста ошибки; уже открытая такая приёмка снимается до ветки таблицы глубины; подпись стоит раньше ветки «два среза по файлам»; общее правило не обязывает вписать «закрытый месяц» и «проводится».

Если текст формулы, момента правила, порядка или сценария изменился, строка не срабатывает и остаётся полная проверка, даже когда разбор написал, что сумма прежняя. Для итога дополнения строка даёт уже существующий исход «проверка не требуется». Если проверку на такой дельте всё же запустили, полный независимый разбор постановки не назначается. Добавление текста задачи по-прежнему изменение постановки; отметка приёмки по-прежнему не делает проверку устаревшей. Новое имя глубины не вводить: в ячейке указать, что независимый разбор не назначается, по образцу уже существующей строки «не полный независимый разбор». Условия класса «замена значения» не менять. Шаг «оставить текст или переписать срез» не менять.

## 6. Приёмка

- [x] S1.accept Принять срез S1 «Маршрут починки с прежним результатом» — починка с прежним проведением, суммой и справкой не спрашивает, куда её положить, и идёт в реализацию:

  - Scenario «Уже открытая приёмка из текста ошибки снимается» (опционально): отдельный шаг с приёмкой из текста ошибки уже открыт, проведение, сумма и справка прежние → карточки нет, лишняя приёмка снята, следующий шаг — реализация
  - Scenario «До первой полной проверки строка не срабатывает» (опционально): той же починке ещё не предшествовала первая полная проверка → полная проверка постановки не отменяется
  - Scenario «Смена формулы ведёт к проверке» (опционально): текст формулы, момента правила, порядка шагов или сценарий меняются, даже если сумма прежняя → итог дополнения предлагает полную проверку постановки
  - Scenario «Разный момент приёмки оставляют вопросом» (опционально): один вариант отдаёт результат к приёмке раньше, другой держит его до конца → человек видит вопрос
  - Scenario «Два разных результата оставляют вопросом» (опционально): одна правка меняет два разных уже записанных результата → человек видит вопрос
  - Scenario «Подписанная приёмка не дописывается» (опционально): приёмка среза уже подписана → задачи в этот срез не дописываются и подпись не снимается
  - Scenario «Ответ внутри выбранного подхода остаётся короткой сверкой» (опционально): дополнение только фиксирует ответ внутри выбранного подхода и не дописывает задачи починки → итог предлагает проверку затронутого, не пропуск проверки
  - Scenario «Повторный запуск проверки не становится полным разбором» (опционально): на такой починке проверку постановки всё же запустили → полный независимый разбор постановки не назначается
  - Scenario «Мёртвая ветвь карточки проверки не спрашивается» (опционально): приёмка уже называет суммы, а одна ветвь их не выполняет → вопроса «исправлять или оставить» нет, разбор изменённого плана продолжается в том же запуске
  - Scenario «Карточка дополнения не предлагает не делать уже названное» (опционально): команда уже назвала заявку и правило → пары «дописать или не делать» нет
  - Scenario «Вход проверки не прячет уже сказанную фразу» (опционально): новое требование сказано в той же команде, что и проверка → не предлагается проверить так, будто фразы не было, и не предлагается отложить её в заметки
  - Scenario «Следующий шаг после ответа берётся из таблицы глубины» (опционально): человек дал настоящий новый ответ, и обе ветви до ответа выполняли уже сказанное → следующий шаг называется по таблице глубины, а не фразой «снова вся проверка»
  - Scenario «Вопрос показывается словами уже записанного результата» (опционально): черновик вопроса содержит внутреннее имя или путь к заметке, уже записанный результат — проведение, сумма и справка → человек видит, что будет с проведением, суммой и справкой, вопрос показан, путь к заметке есть в отчёте и не нужен, чтобы понять выбор
