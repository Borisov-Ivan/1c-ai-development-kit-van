# Эффект правила «живые ветви» на остальные процессы цикла

**Дата:** 2026-11-05  
**Контекст:** дефект — пара выбора, где одна ветвь не выполняет уже сказанное или уже записанную приёмку, но её всё равно спрашивают; рядом — остановка «подтвердите?» на команду, которую человек уже дал.  
**Предлагаемое правило:** в пару только ветвь, которая выполняет уже сказанное; одна живая ветвь — вопроса нет; две живые — вопрос есть; догадка ветвь не выбрасывает; остановка без второй ветви — не этот дефект (в правило не втягивать).  
**Источники:** точечные цитаты из перечисленных SKILL и `brief-card.md` (код 1С не читался).

---

## 1. Разбор задачи (`/opsx:explore`)

**Пара с «мёртвой» ветвью относительно уже сказанного:** да, в связке **Варианты** + **Подтвердить?**. После того как пользователь уже назвал номер/ветку («2», «вариант 2»), эталон всё равно предлагает «да» (= вариант **1**) как равноправный ответ — это ветвь, не выполняющая уже сказанное, в одной карточке с подтверждением.

- `openspec-explore/SKILL.md:114` — «в **Подтвердить?** — номер или «да» (= вариант 1)».
- `brief-card.md:164` — «Подтвердить? — … «да» (= вариант 1) или уточните».

**Отдельно (в scope правила не входит):** обязательный слот **Подтвердить?** при одном **Маршрут** без **Варианты** (`SKILL.md:111`, `brief-card.md:119`) — одна живая ветвь «да = идём по маршруту»; это остановка без второй ветви выбора, не пара с мёртвой альтернативой.

**Финальная развилка после Task:** `SKILL.md:225-227` — карточка только при ≥2 взаимоисключающих путях; с предлагаемым правилом согласовано. **Change Creation Gate** (`SKILL.md:295-297`) — две команды всегда в тексте; при уже названной одной команде (`/opsx:new …` / `/opsx:extend …`) возможна та же ошибка, если в чат кладут обе — правило должно сужать до одной живой.

**Правило чинит процесс:** да (сужение **Подтвердить?** / финальной вилки при одной исполнимой ветви; не отменять END TURN, пока в **Варианты** реально 2+ живых маршрута).

**Вердикт:** **включать в ту же правку** (`openspec-explore/SKILL.md` §3, §Change Creation Gate; `brief-card.md` B3 и таблица «Разбор ответа»).

## 2. Создание заявки (`/opsx:new`)

**Пара с мёртвой ветвью:** да на пути **Metadata Gate** после того, как пользователь уже принял черновик текстом; AskQuestion всё равно даёт три опции, из которых «Без описания» / Other не исполняют уже сказанное «принять черновик».

- `openspec-new-change/SKILL.md:92-93` — опции «Принять черновик» / «Без описания — только ФИО и дата» / Other.
- `SKILL.md:117-118` — END TURN после вопроса Metadata Gate.

**Уже согласовано с правилом (не дефект):** **B0** при свежей `## Постановка ЗНИ` — одна строка без согласования (`SKILL.md:18-29`); **B1** только на свободном тексте (`SKILL.md:38-40`, `brief-card.md:59-65`).

**Другие карточки:** Design Gate `SKILL.md:378` ([Принять]/[Скорректировать]/[Пересобрать]) — три живые ветви, пока пользователь не выбрал одну; пакет продуктовых развилок `SKILL.md:401` — по два-три живых варианта на вопрос. **Такой пары «мёртвая + живая» в тексте нет**, если не смешивать с уже данным ответом.

**Правило чинит процесс:** да (пропуск AskQuestion Metadata / B1 при одной исполнимой ветви); **вредно**, если снять обязательный **B1** на пути без постановки или убрать «Без описания», когда пользователь молчал.

**Вердикт:** **включать в ту же правку** (Metadata Gate + трактовка B1 в `brief-card.md`); Design Gate / пакет 5.e.2 — только общий фильтр «сколько живых ветвей», без удаления живых A/B.

## 3. Пошаговый разбор кода (`/opsx:explain`)

**Пара с мёртвой ветвью:** да, когда рамка уже названа в вызове (например, «Tier1», «только файлы с замечаниями»), а бриф всё равно держит **Варианты** с «да» = вариант 1 или повторный **Подтвердить?** после prefill **Охват**.

- `openspec-explain/SKILL.md:68-70,89` — XOR **Варианты** / **Охват**, END TURN на **Подтвердить?**; для huge `/release-review` **обязательно** **Варианты** (`SKILL.md:87`).
- `brief-card.md:177-179` — **Варианты** *или* **Охват** обязательны; **Подтвердить?** обязателен.

**Такой пары нет:** карта точек после «да» (`SKILL.md:99`) — второй шаг согласования списка, обе ветви (правки списка / «дальше») живые; выход «Можно:» (`SKILL.md:149`) — живые альтернативы фиксации.

**Правило чинит процесс:** да, если после prefill остаётся одна исполнимая рамка; **вредно**, если правило заставит убрать **обязательные Варианты** для huge scope (`SKILL.md:87`) или выбор рамки, когда пользователь не назвал её.

**Вердикт:** **включать в ту же правку точечно** (`openspec-explain/SKILL.md` §1, §1a; `brief-card.md` B-explain + таблица ответов); не трогать walk loop / inventory, кроме общей ссылки на правило.

## 4. Реализация (`/opsx:apply`)

**Пара с мёртвой ветвью:** частично закрыто для приёмки; остаётся развилка после полного принятия, если пользователь уже дал команду архива.

- **Уже исполняет правило:** `openspec-apply-change/SKILL.md:150-151` — при ответе в том же сообщении («принято», «отложить», замечание) форму не показывать; `SKILL.md:410-413` — manual shortcut по «принято».
- **Дефект:** `SKILL.md:417-419` — после принятия вопрос `ревью` / `архив` / `стоп` (или «Архивировать ЗНИ? …»); при сообщении вида `/opsx:archive <name>` или «архив» в том же ходе в пару попадают ветви, не выполняющие уже сказанное.
- **Не дефект (две живые):** форма `[1]` принятие / `[2]` замечание / `[3]` отложить (`SKILL.md:154-157`) — «отложить» не дублирует уже записанную приёмку, это вторая живая ветвь; правило их не снимает.

**Правило чинит процесс:** да (доработать разбор команды/слова на шаге 6 Manual acceptance shortcut; сохранить `[3]` и пакетную логику `2b`).

**Вердикт:** **включать в ту же правку** (apply §5 шаг 3-6, Manual acceptance shortcut); не ослаблять skip формы по `150-151`.

---

## 5. Архив (`/opsx:archive`)

**Пара с мёртвой ветвью:** да на шаге 3.5, если пользователь уже сказал «отложить архив» / «стоп», а AskQuestion всё равно предлагает **A** (подписать accept и идти дальше) вместе с **C**.

- `openspec-archive-change/SKILL.md:132-136` — **A** … **B** … **C.** Отложить архив → **STOP**; **D** / `--force-legacy`.
- **Такой пары нет**, когда все accept уже `[x]`: `SKILL.md:109` — переход к 3.6 без карточки 3.5.

**Auto-yes** (`SKILL.md:16`) и пропуск AskQuestion для sync/ADR — не пара с мёртвой ветвью относительно приёмки пользователя.

**Правило чинит процесс:** да (оставить в AskQuestion только живые опции после разбора реплики; **C** не выкидывать, когда пользователь не говорил «отложить»); **вредно**, если правило уберёт **C** «отложить архив» при непринятых срезах без prior intent — это живая вторая ветвь.

**Вердикт:** **включать в ту же правку** (archive §3.5 фильтрация опций); шаг 3.7 (следы качества) — только если в одном сообщении уже дан ответ «ревью»/«стоп» (аналогичный фильтр).

---

## 6. Шаблон `brief-card.md` (сквозной)

**Где варианты обязательны:** B2 **Варианты** (`brief-card.md:87-88`); B3 **Маршрут** XOR **Варианты** (`115-116`); B-explain XOR (`177`); post-extend карточки (`200-209`).

**Пара с мёртвой ветвью:** таблица «Разбор ответа» (`187-195`) — для B3/B-explain с **Варианты** закрепляет «да» = вариант **1**, что усиливает дефект explore/explain при уже выбранном номере ≠ 1.

**Правило чинит:** да — дополнить таблицу: при одной исполнимой ветви из реплики пользователя **Подтвердить?** / AskQuestion не показывать; «да»=1 не применять, если уже назван другой номер.

**Вердикт:** **включать в ту же правку** (центральная SSOT для B1/B2/B3/B-explain).

### В правку входят

- `openspec-explore/SKILL.md` (бриф B3, Change Creation Gate)
- `openspec-new-change/SKILL.md` (Metadata Gate, трактовка B0/B1)
- `openspec-explain/SKILL.md` (entry-бриф, prefill review/apply)
- `openspec-apply-change/SKILL.md` (приёмка 150-151 сохранить; fork archive 417-419)
- `openspec-archive-change/SKILL.md` (AskQuestion 3.5, при необходимости 3.7)
- `.cursor/docs/templates/brief-card.md` (таблица ответов, B3/B-explain)

### Не трогать / не расширять правилом

- Explore/new: обязательный **Подтвердить?** при **одном Маршрут** / B1 без предварительного «да» в реплике (остановка без второй ветви — вне дефекта).
- Apply: пункт **[3] отложить** и форма accept/remark/defer при отсутствии ответа в сообщении (две+ живые ветви).
- New: Design Gate и пакет продуктовых развилок — только фильтр по уже данному ответу, не удаление опций.
- Archive: auto-yes для sync/KB/ADR; bypass при всех accept `[x]` (`SKILL.md:109`).

### Трогать вредно

- Убирать обязательные **Варианты** рамки explain для huge `/release-review` (`explain/SKILL.md:87`).
- Убирать **C. Отложить архив** из archive 3.5 без prior intent пользователя.
- Снимать END TURN explore, пока в **Варианты** реально 2–3 альтернативных маршрута и пользователь их не выбрал.
