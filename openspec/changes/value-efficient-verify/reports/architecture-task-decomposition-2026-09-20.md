# Task decomposition — value-efficient-verify

## Task

Сформировать полный `tasks.md` kit-only ЗНИ по двум утверждённым вертикальным срезам, не изменяя сам `tasks.md` и не перенося предметные детали исходного исследовательского кейса.

## Complexity

Complex: 20 задач в двух последовательно принимаемых срезах, 13 существующих файлов kit, без новых обязательных файлов, сервисов, хранилищ и полных агентских прогонов.

## Chosen Approach

**Approach:** сначала добавить обратно совместимый внешний контракт и раннюю остановку в существующий полный прогон, затем поверх принятого результата ввести снимок, точечную инвалидацию и профильные триггеры.

**Rationale:**

- S1 даёт самостоятельный наблюдаемый результат без кэша и дельта-режима.
- S2 использует внешний дайджест S1 как один из входов существующего отчёта проверки.
- Ответственность распределена через существующие правила, навыки и промпты ролей; новый обязательный участник не появляется.

## Simplicity Check

- **Viable alternatives:**
  1. Сосредоточить всё поведение только в `openspec-verify-change/SKILL.md` — меньше файлов, но контракты apply, review и профильных ролей останутся несогласованными.
  2. Ввести отдельную schema/библиотеку реестра и сервис кэша — технически централизованно, но нарушает запрет на новый обязательный файл или сервис.
  3. Расширить существующие артефакты и узкие контракты ролей — выбранный вариант.
- **Selected simplest viable design:** существующий `debug.md` хранит реестр, существующий `verification-*.md` хранит снимок; остальные файлы только регистрируют события или потребляют профильный контекст.
- **Why not simpler:** один оркестратор без обновления потребителей не гарантирует регистрацию возвратов, проверку кода против затронутого контракта и отсутствие повторных матриц у ролей.
- **Complexity budget:** 13 существующих файлов; 18 рабочих задач; 2 приёмочные задачи; 0 новых обязательных файлов; 0 новых обязательных полных агентских вызовов.
