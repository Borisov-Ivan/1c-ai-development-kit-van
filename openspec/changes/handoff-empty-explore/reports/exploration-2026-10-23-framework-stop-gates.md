## Для заказчика

Остановка после описания и решения отправляет в разбор командой без текста задачи. Такой разбор начинает новую тему и не подхватывает уже записанную заявку.

Если в разборе речь о новой возможности («нужно сделать»), правила разбора не собирают постановку, ради которой была остановка, и снова отправляют создавать заявку. Получается круг: заявка ждёт постановку из разбора, разбор фичи постановку не отдаёт.

Продолжить тот же каталог умеет повтор создания с тем же именем. Текст остановки этого пути не называет. Финал разбора при уже открытой заявке велит только дописывать её, а дописывание рассчитано на список задач, которого остановка как раз не создала. Повтор создания без того же имени выводит имя из новой постановки и может открыть вторую заявку.

Деловой язык без фразы, что меняется только модуль, не разрешает записать поставку формы «только модуль» без вопроса. Это отдельное правило, оно с остановкой не спорит.

Разбор код не пишет. Создание заявки код не пишет. Недособранная заявка не подменяется правкой поставки: к разработке пускает только команда реализации, а при нехватке файлов заявки она возвращает к дозавершению той же заявки.

### 6. Согласованность правил — разрыв

На разборе архитектор запускается без вопроса. Если его не было, поле постановки хранит не отказ, а «нужен разбор». На создании пропуск в диалоге не предлагается: выйти можно только флагом со следом в файле заявки. Без флага проверка срабатывает снова. Закрывает её отчёт архитектора с пересечением области, тот же флаг или несработавшие критерии.

```113:114:.cursor/rules/architect-gate.mdc
| **explore** (Structured Investigation, шаг Decide) | blocking | Архитектор запускается без вопроса. Отказ — только флаг пропуска при создании заявки (`--skip-architect`). Поле постановки отказ не хранит. Если архитектор не запущен — статус `required` |
| **new** (Design Gate) | blocking | Без опции пропуска. Escape только через флаг `--skip-architect <причина>`, оставляющий явный аудит-след `.gate-override.yaml`. |
```

```149:149:.cursor/rules/architect-gate.mdc
1. Файл `architecture-*.md` существует в `reports/` change или `temp/reports/`, и его `scope.files` или `scope.modules` в YAML front-matter пересекаются с текущей задачей. (Одиночный старый отчёт без пересечения scope — Gate НЕ закрыт).
```

```151:151:.cursor/rules/architect-gate.mdc
3. Пользователь явно отклонил архитектора флагом `--skip-architect` при создании заявки (задокументировано в `.gate-override.yaml`). Поле постановки отказ не хранит. Без флага Design Gate снова срабатывает.
```

Скилл создания при отсутствии постановки не запускает этот разбор, а отправляет человека в разбор (строки 330–334). Карта действий архитектурного правила такого шага не содержит: для создания там только блокировка и флаг. Простой запуск без постановки сам по себе не запрещён — жёсткая остановка только при структурных критериях (больше одного файла, больше десяти строк, смена контракта):

```56:56:.cursor/skills/openspec-new-change/SKILL.md
   - Если `exploreContext` отсутствует, это не блокирует простой запуск new. Design Gate ниже выполнит hard-gate только при структурных триггерах.
```

Возврат в разбор для фичи постановку не производит. Маркеры «нужно сделать», «добавить», «изменить поведение» уводят сразу в создание. Блок постановки при таком переходе не собирается. Он собирается, только если по фиче уже были шаги исследования. Вопросный разбор по умолчанию тоже ограничивается сводом в чате и заявку не предлагает.

```80:80:.cursor/skills/openspec-explore/SKILL.md

```

Противоречие перехода: создание останавливается, потому что нет блока постановки; предложенный разбор фичи этот блок не создаёт и возвращает в создание. Поле «нужен разбор» при таком переходе тоже не появляется, потому что блок не печатается. Отчёт архитектора, которым архитектурное правило закрыло бы проверку, на этом переходе не требуется.

Если постановка уже есть, соседний текст того же шага разбор не откладывает, а запускает сразу (строки 337–343). Расхождение только у ветки «постановки нет».

## Разрывы

### 1. Пустой разбор в тексте остановки — ломает сценарий

- `.cursor/skills/openspec-new-change/SKILL.md:333` — «сначала выполните `/opsx:explore`» без текста задачи и без имени уже созданной заявки.
- `.cursor/skills/openspec-explore/SKILL.md:23` — команда без текста задачи считается пустым вводом и просит описать задачу заново; строка 29 запрещает самой найти тему по отчётам.

Противоречие: остановка предлагает команду, которую адресат принимает только как новую тему. Продолжение прежней темы у адресата включается другими словами («продолжи разбор»), и стоп эти слова не называет.

Заказчик выполняет предложенную команду и видит просьбу рассказать, с чем работать. Описание и решение уже лежащей заявки к разбору не подтягиваются.

### 2. Отложение разбора закрывает чат и вызывает создание без имени — путает

- `.cursor/skills/openspec-new-change/SKILL.md:341` — «завершите сессию и запустите `/opsx:new` повторно» с флагом пропуска; имени заявки в команде нет.
- `.cursor/skills/openspec-new-change/SKILL.md:37` — без аргумента и без блока постановки в этом чате единственная открытая заявка не продолжается сама: задаётся вопрос «продолжить с ним или новый?». Строка 38, если такой заявки нет, просит описать change заново.

Противоречие: текст велит уничтожить сессию, в которой тема ещё известна, и вызвать команду, которая тему с собой не несёт. Вопрос про единственную заявку — запасной ход, не приём уже известной темы вместе с командой.

Заказчик в новом чате не продолжает то же решение. Он заново описывает работу или выбирает, старая это заявка или новая.

### 3. Возврат в разбор без текста задачи — путает

- `.cursor/skills/openspec-explain/templates/exit-card.md:55` — следующий шаг «вернуться в `/opsx:explore`» без текста задачи. То же в `.cursor/skills/openspec-explain/SKILL.md:150`.
- `.cursor/skills/openspec-knowledge-add/SKILL.md:125` — для кода и трассы подсказка «сначала `/opsx:explore`», тоже без темы и без пути к файлу.
- Адресат тот же: `.cursor/skills/openspec-explore/SKILL.md:23`.

Противоречие: предлагается команда, которую разбор считает пустым входом, а не продолжением текущего разбора или разбором приложенного файла.

Заказчик, уже разбирающий код или принёсший файл в базу знаний, по этой фразе попадает в приглашение «опишите, с чем работаем», а не остаётся на той же теме.

### 4. Разбор фичи не отдаёт постановку, которую ждёт остановка — ломает сценарий

- `.cursor/skills/openspec-new-change/SKILL.md:332` — остановка, потому что нет блока «Постановка ЗНИ» или файла передачи за 48 часов. Строка 333 отправляет в разбор.
- `.cursor/skills/openspec-explore/SKILL.md:322` — для фичи без шагов исследования создание вызывается напрямую, блок постановки не собирается. Строка 80 того же файла уводит маркеры «нужно сделать / добавить / изменить поведение» в создание.

Противоречие: создание не идёт дальше без постановки из разбора, а разбор новой возможности эту постановку не собирает и возвращает в создание. Архитектурное правило на создании (`.cursor/rules/architect-gate.mdc:114`) такого обхода через разбор не описывает: там только блокировка и флаг пропуска. Отчёт, которым то правило закрывает проверку (строка 149), этот переход не требует.

Заказчик, повторив деловую формулировку в разборе, снова оказывается в создании и снова без постановки. Требования и список задач так и не появляются.

### 5. Уже открытую заявку нельзя дозавершить той командой, которую называет разбор — ломает сценарий

- `.cursor/rules/sdd-workflow.mdc:61` — дозавершение недостающих файлов заявки делает повтор создания. Дописывание — добавление задач к существующей заявке.
- `.cursor/skills/openspec-explore/SKILL.md:250` — если заявка той же области уже открыта, следующий шаг только дописать её; новое создание разрешено лишь когда такой заявки нет.

Противоречие: команда, которая по рабочему процессу дописывает требования и задачи в тот же каталог, финалом разбора запрещена именно потому, что каталог уже есть. Команда дописывания (`.cursor/skills/openspec-extend-change/SKILL.md:324`) вставляет задачи в уже нарезанный список, а не проходит остановленную цепочку «проверка решения → требования → задачи».

Заказчик с недособранной заявкой получает «допишите её» и не получает требований. Либо, если пойдёт создавать заново, упирается в разрыв 6.

### 6. Создание без того же имени открывает другую заявку — ломает сценарий

- `.cursor/skills/openspec-new-change/SKILL.md:30` — без аргумента имя выводится из темы блока постановки, и ход сразу идёт дальше, не сверяясь с уже открытым каталогом.
- `.cursor/skills/openspec-new-change/SKILL.md:153` — продолжается только каталог с тем же именем. Вопрос про единственную незакрытую заявку (строка 37) до этого шага не доходит, если блок постановки уже найден.

Противоречие: дозавершение привязано к старому имени, а вход без имени при новой постановке выбирает новое имя раньше, чем смотрит на уже созданный каталог.

Заказчик получает вторую заявку. Первая остаётся с описанием и решением, без требований и без списка задач.
