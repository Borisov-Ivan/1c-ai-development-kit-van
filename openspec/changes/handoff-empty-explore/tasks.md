# Срез S1: Постановка не теряется

**Сценарий:** Создание заявки с именем без готового блока постановки сначала спрашивает короткое подтверждение, и ответ считается постановкой. Недособранная заявка (описание есть, требований нет) продолжается тем же именем; в тексте остановки одна такая команда, без пустого разбора.
**Primary acceptance:** Создать заявку с именем без блока постановки → до записи описания видно короткое подтверждение; после согласия нет приглашения начать разбор без задачи.
**Приёмка:** сообщения в чате на правилах набора, без прогона в базе.
**Связь со spec:** `specs/kit-protocol-coherence/spec.md` — Requirement «Создание заявки читает один источник»: Scenario «Создание с именем без блока», Scenario «Подтверждение снимает остановку», Scenario «В остановке одна команда», Scenario «Недособранная заявка продолжается тем же именем», Scenario «Пустой разбор ждёт описание», Scenario «Команда создания только рядом с блоком», Scenario «Готовый блок без повторного подтверждения», Scenario «Баг в открытой заявке».
**Зависимости:** нет

- [ ] S1.1 Добавить в `.cursor/skills/openspec-new-change/SKILL.md` шаг 1 (имя аргументом, постановки нет) короткое подтверждение до записи описания. Слот «Изменение» и «Подтвердить?», ход ждёт ответа, описание и решение до ответа не пишутся. Путь с готовым блоком (одна информирующая строка без паузы) не переписывать (Decision «Подтверждение считается постановкой»; Behavior Contract 1, 3). Scenario «Создание с именем без блока», Scenario «Готовый блок без повторного подтверждения».
- [ ] S1.2 Записать в `.cursor/skills/openspec-new-change/SKILL.md` шаг 1 источником постановки подтверждённый ответ на это подтверждение, чтобы остановка «нет постановки» не повторялась. Поле архитектора этот источник не заполняет и флаг пропуска разбора решения не заменяет (Behavior Contract 2, 8). Зависимости: S1.1.
- [ ] S1.3 Поправить в `.cursor/skills/openspec-new-change/SKILL.md` сводку подтверждений (строка про короткую карточку и строка «подтверждение нужно только на пути свободного текста»), чтобы она называла и путь с именем без блока. Путь с готовым блоком остаётся без подтверждения (Behavior Contract 3). Зависимости: S1.1.
- [ ] S1.4 Дописать в `.cursor/skills/openspec-new-change/SKILL.md` шаг 2 (продолжение существующего каталога): если описание есть, а требований нет и постановки в чате нет, подтверждение строится из записанного описания. Второй каталог не создаётся, уже записанные разработчик и режим формы не переспрашиваются (Decision «Подтверждение считается постановкой»; Behavior Contract 4). Scenario «Недособранная заявка продолжается тем же именем». Зависимости: S1.2.
- [ ] S1.5 Снять в `.cursor/skills/openspec-new-change/SKILL.md` ветку остановки «нет постановки» на шаге разбора решения: подтверждённый ответ уже считается постановкой, поэтому эта остановка недостижима. Сложное изменение идёт в уже существующую ветку «анализ запускается сейчас». Новой ветки не заводить. Если отчёта архитектора нет, этот путь остаётся единственным, кроме явной пометки пропуска со следом в заявке (Behavior Contract 2, 8). Scenario «Подтверждение снимает остановку». Зависимости: S1.2.
- [ ] S1.6 Заменить в `.cursor/skills/openspec-new-change/SKILL.md` тексты остановок, которые сохраняются (отказ от подтверждения до записи описания и прерванный ход): без пустого разбора; одна команда повтора создания с тем же именем — только там, где остановка ещё возможна. Пропуск разбора решения — отдельной строкой как явная пометка со следом в заявке, не равным выбором в том же абзаце; строка ветки «анализ запускается сейчас» тоже несёт имя (Decision «Одна команда возврата»; Behavior Contract 8). Scenario «В остановке одна команда». Зависимости: S1.5.
- [ ] S1.7 Развести в `.cursor/skills/openspec-explore/SKILL.md` правило «один следующий шаг» финала разбора: заявка той же области открыта без требований — продолжение тем же именем; есть требования и список задач — дописывание. Вторая заявка при живом каталоге не создаётся. Обещание, что дописывание само забирает блок из чата, не повторять (Decision «Куда вести финал разбора»; Behavior Contract 6). Scenario «Баг в открытой заявке», Scenario «Недособранная заявка продолжается тем же именем».
- [ ] S1.8 Привести в `.cursor/skills/openspec-explore/SKILL.md` строку таблицы финала для бага и абзац «дефект в открытой заявке» к тому же различию: без требований — продолжение тем же именем, с требованиями и задачами — дописывание. Строку маршрута доработки без обследования не переписывать (Decision «Куда вести финал разбора»). Зависимости: S1.7.
- [ ] S1.9 Сверить в `.cursor/skills/openspec-explore/SKILL.md` вход при пустом вводе с требованием: разбор в новом чате ждёт описание и сам не читает прошлый разговор и отчёты. Правка только при расхождении (Behavior Contract 5). Scenario «Пустой разбор ждёт описание».
- [ ] S1.11 Ограничить в `.cursor/skills/openspec-explore/SKILL.md` показ команды создания новой заявки в исследовании с шагами: слот «Дальше» синтеза и строка таблицы для доработки с шагами исследования дают команду создания только в сообщении с блоком постановки. Продолжение существующей заявки тем же именем без блока — только когда каталог виден в списке открытых заявок в момент сообщения; иначе команда с именем требует блока. Строку перенаправления доработки без обследования не переписывать (Decision «Команда создания из исследования — только рядом с блоком»; Behavior Contract 9). Scenario «Команда создания только рядом с блоком». Зависимости: S1.8.
- [ ] S1.12 Подчинить в `.cursor/skills/openspec-explore/SKILL.md` секцию явной просьбы создать заявку тому же правилу: без блока команды новой заявки нет; каталог без требований продолжается тем же именем; с требованиями и задачами — дописывание. Слот «Дальше» и строку таблицы вторым текстом правила не дублировать (Decision «Команда создания из исследования — только рядом с блоком»; Behavior Contract 9). Scenario «Команда создания только рядом с блоком», Scenario «Недособранная заявка продолжается тем же именем», Scenario «Баг в открытой заявке». Зависимости: S1.7, S1.11.
- [ ] S1.10 Сверить формулировки шагов 1–2 и остановок, которые сохраняются, в `.cursor/skills/openspec-new-change/SKILL.md`, финала, слота «Дальше» и секции явной просьбы создать заявку в `.cursor/skills/openspec-explore/SKILL.md` с требованием «Создание заявки читает один источник». Цикл форм не сверять: он в срезе про признаки модуля. Расхождение правится в скилле, не в требовании. Scenario «Поле архитектора», Scenario «Порядок артефактов», Scenario «Нарезка до задач» — сверка без правки: эти формулировки не переписываются. Зависимости: S1.3, S1.4, S1.6, S1.8, S1.9, S1.11, S1.12.

- [ ] S1.accept Принять срез S1 «Постановка не теряется» — согласованная доработка доходит до требований и задач, а недособранная заявка продолжается одной командой с тем же именем:
  - **Primary (обязательно):** Создать заявку с именем без блока постановки → до записи описания видно короткое подтверждение; после согласия нет приглашения начать разбор без задачи.
  - Scenario «Недособранная заявка продолжается тем же именем» (опционально): у заявки есть описание, а требований нет — следующий шаг продолжает её тем же именем, вторая заявка не создаётся, разработчик и режим формы не переспрашиваются.
  - Scenario «В остановке одна команда» (опционально): если создание всё же остановилось до требований, в тексте одна команда с именем начатой заявки и нет пустого разбора.
  - Scenario «Пустой разбор ждёт описание» (опционально): в новом чате разбор без текста просит описать задачу и прошлую тему не подставляет.
  - Scenario «Готовый блок без повторного подтверждения» (опционально): блок постановки в чате есть — короткое подтверждение не спрашивается, ход на нём не останавливается.
  - Scenario «Команда создания только рядом с блоком» (опционально): исследование с шагами предлагает новую заявку, а блока постановки в сообщении нет — команды создания нет, сначала печатается блок.
  - Scenario «Баг в открытой заявке» (опционально): у заявки уже есть требования и задачи — следующий шаг дописать её, а не завести вторую.

# Срез S2: Признаки только модуля

**Сценарий:** Вопрос о поставке формы задаётся, если «только модуль» не сказано заказчиком, не видно в постановке и в коде. Вариант «всё в модуле», выбранный в решении того же хода, признаком не считается.
**Primary acceptance:** В словах заказчика и в постановке нет признаков «только модуль», а в решении того же хода выбран вариант «всё в модуле» → задаётся вопрос о поставке формы, программная поставка до ответа не записывается.
**Приёмка:** сообщения в чате на правилах набора, без прогона в базе.
**Связь со spec:** `specs/split-form-layout-modes/spec.md` — Requirement «Module-only form records programmatic delivery without a question»: Scenario «Собственное решение не доказывает только модуль», Scenario «Module-only records programmatic without question», Scenario «Resume does not overwrite recorded mode».
**Зависимости:** нет

- [ ] S2.1 Дописать в `.cursor/rules/forms-mxl-mode-gate.mdc` абзац «Достаточные признаки «только модуль»» источником признаков: слова заказчика, блок постановки или код. Код — элементы формы уже выводятся программно в модуле, а в разметке формы их нет. Блок постановки принимается, потому что заказчик продолжил работу с него. Вариант поставки из разделов решения того же хода (принятые решения, варианты реализации, обоснование выбора) и выбранный вариант отчёта архитектора того же хода признаком не являются (Decision «Откуда берутся признаки «только модуль»»; Behavior Contract 7). Scenario «Собственное решение не доказывает только модуль».
- [ ] S2.2 Дописать в `.cursor/rules/forms-mxl-mode-gate.mdc` строку «Не skip»: «всё в модуле» только из собственного решения хода — класс «неясно», вопрос этой формы, программная поставка до ответа не записывается. Запрет resume и перечень значений режима не переписывать (Behavior Contract 7). Зависимости: S2.1.
- [ ] S2.3 Поставить в `.cursor/skills/openspec-new-change/SKILL.md` шаг цикла форм (ветка «только модуль») ссылку на источник признаков из правила режима формы, без своей копии. Запрет перезаписи уже записанного режима не трогать (Behavior Contract 7). Scenario «Resume does not overwrite recorded mode». Зависимости: S2.1.
- [ ] S2.4 Сверить `.cursor/rules/forms-mxl-mode-gate.mdc` и цикл форм в `.cursor/skills/openspec-new-change/SKILL.md` с уже записанным требованием в `specs/split-form-layout-modes/spec.md`. Расхождение правится в правиле или скилле, не в требовании; запись программно без вопроса при доказанном «только модуль» сохраняется. Scenario «Mixed forms sequential», Scenario «Informing line is not a selection question» сверяются без правки. Зависимости: S2.2, S2.3.

- [ ] S2.accept Принять срез S2 «Признаки только модуля» — программная поставка формы записывается без вопроса только по словам заказчика, постановке или коду:
  - **Primary (обязательно):** В словах заказчика и в постановке нет признаков «только модуль», а в решении того же хода выбран вариант «всё в модуле» → задаётся вопрос о поставке формы, программная поставка до ответа не записывается.
  - Scenario «Module-only records programmatic without question» (опционально): заказчик сказал, что правят только модуль формы — выбора нет, в карточке заявки поставка программно.
  - Scenario «Resume does not overwrite recorded mode» (опционально): у формы уже записан валидный режим — он не переспрашивается и не меняется.
