## Why

Исследование кладёт полный отчёт в `temp`, а при создании ЗНИ файл остаётся снаружи каталога задачи — `temp` не хранится в git. Открыв отчёт позже, нельзя вспомнить, с каким объектом была проблема: в файле есть разбор найденного кода, нет исходных вводных.

## What Changes

1. После исследования с отчётом и `/opsx:new` по этой теме отчёты обследования, разбора трассы, архитектурного разбора и журнала пошагового разбора переезжают в каталог ЗНИ (`reports/`). В `temp` этих файлов больше нет.
2. В начале отчёта обследования, трассы и архитектурного разбора — шапка вводных: **понятная формулировка** исходного запроса (не дословная цитата чата), названный объект или область (или явное «не назван»), симптом, вопрос исследования.
3. Если ЗНИ уже есть и отчёт ещё в `temp` — при дополнении задачи из этого отчёта файл тоже переезжает в каталог ЗНИ. Опциональный файл передачи ищется в корне `temp/` (`explore-handoff-*.md`), не только в `temp/reports/`.
4. Список файлов в чат-постановку не входит. Опциональный файл передачи постановки по-прежнему только по словесной просьбе. Бриф отдельным файлом не сохраняется. Каталог сессий исследования не возвращается.
5. Если исследования с отчётом не было — ЗНИ создаётся как сейчас, без требования приложить отчёт. Два параллельных разбора в `temp` не смешиваются: в задачу попадают только файлы этой темы.

## Capabilities

### New Capabilities

- `explore-report-promote`: переезд отчётов исследования в каталог ЗНИ при создании и при дополнении из отчёта в `temp`.
- `explore-report-intake`: шапка вводных в отчёте — объект и понятная формулировка запроса без дословной цитаты чата.

### Modified Capabilities

- нет (в `openspec/specs/` нет capability про перенос отчётов исследования)

## Impact

- Kit: правило сохранения отчётов, создание и дополнение ЗНИ, промпт и шаблоны вывода аналитических агентов, журнал пошагового разбора (поправка ссылок при переезде), справка стиля чата про путь отчётов.
- Продуктовый код 1С и конфигурация не меняются.
- Apply: правки markdown правил и скиллов kit (mechanical).

## Scope

- In scope: переезд отчётов типов exploration / trace-analysis / architecture / explain и опционального файла передачи постановки; шапка вводных; зеркало при дополнении ЗНИ из `temp`; поиск «продолжи вчерашний разбор» в каталогах ЗНИ после переезда.
- Out of scope: возврат каталога сессий; обязательный файл передачи постановки; сохранение полного брифа отдельным файлом; перенос всего `temp/reports` без фильтра темы; перенос трасс пользователя (`.pff`, `*_TRACE_*`) и отчётов приёмки/ревью; переписывание архивной ЗНИ `kit-evolution-models-economy-profiles`.

## Acceptance Criteria

1. После исследования с отчётом и создания ЗНИ файл из превью лежит в каталоге задачи, в `temp` его нет.
2. В шапке отчёта видны объект из постановки (или пометка, что объект не назвали) и **понятная** формулировка исходного запроса — не дословный текст сообщения чата.
3. Если исследования не было — ЗНИ создаётся без требования приложить отчёт.
4. Два параллельных разбора в `temp` не смешиваются: в задачу попадают только файлы этой темы.
5. Финальное сообщение создания ЗНИ не печатает перечень перенесённых путей.

## Decisions

1. Связь с архивом: **новый change**. Архив `chat-surface-clarity` / ADR-0001 — чат остаётся без служебного списка файлов, шапка только в отчёте (extends, не отмена). Архив `kit-evolution-models-economy-profiles` — в Why остались пути в `temp`; ту ЗНИ не переписываем (adjacent).
2. Маркеры BSL не применяются (`developer: n/a`).
3. Apply mechanical: правки markdown правил и скиллов kit.
4. Architect / verify: `report: reports/architecture-2026-09-02-explore-artifacts-into-change.md`.
