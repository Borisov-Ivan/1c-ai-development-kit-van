## ADDED Requirements

### Requirement: Intake header names the object

Отчёт обследования, разбора трассы и архитектурного разбора MUST содержать шапку «Вводные» сразу после заголовка. В шапке MUST быть названный объект или область из постановки либо явное «не назван» / «не указаны» — не список модулей, которые агент нашёл в коде.

#### Scenario: Intake header names the object

- **WHEN** исследование шло по постановке с названным объектом или путями в контексте и сохранён отчёт обследования
- **THEN** после заголовка отчёта есть шапка «Вводные» с этим объектом или путями, а секция «Для заказчика» остаётся в конце

### Requirement: Original request is a clear restatement

Поле «Исходный запрос» в шапке MUST быть понятной формулировкой смысла постановки (1–2 предложения). Оно MUST NOT быть дословной цитатой сообщения чата и MUST NOT быть пересказом находок агента.

#### Scenario: Original request is a clear restatement

- **WHEN** открывают отчёт обследования после исследования по свободному тексту пользователя
- **THEN** в шапке «Исходный запрос» читается как сжатый смысл задачи (что разобрать и зачем), без дословного копирования реплики чата и без выводов из кода

### Requirement: Missing header is filled on save

Если агент сохранил отчёт без шапки «Вводные», оркестратор при записи файла MUST вставить шапку из слотов промпта. Объект MUST NOT выдумываться: нет в постановке — «не назван».

#### Scenario: Missing header is filled on save

- **WHEN** тело отчёта пришло без секции «Вводные», а в промпте были симптом, вопрос и контекст
- **THEN** в сохранённом файле после заголовка есть шапка из этих слотов; если контекст пуст — в поле объекта стоит «не назван» или «не указаны»

### Requirement: Trace customer section stays distinct

Четырёхстрочный блок «Для заказчика» в отчёте разбора трассы MUST остаться про симптом пользователя. Он MUST NOT подменять поле «Объекты / пути из постановки» в шапке.

#### Scenario: Trace customer section stays distinct

- **WHEN** сохранён отчёт разбора трассы по дефекту
- **THEN** шапка «Вводные» содержит объект или пути из постановки (или «не указаны»), а «Что наблюдаешь у себя» по-прежнему формулирует симптом, а не список объектов

### Requirement: Explain meta is not duplicated

Журнал пошагового разбора MUST NOT требовать вторую шапку «Вводные», если секция «Мета» уже заполнена сценарием и вопросом.

#### Scenario: Explain meta is not duplicated

- **WHEN** сохранён журнал пошагового разбора с заполненной «Мета»
- **THEN** отдельной секции «Вводные» нет, либо в «Мета» добавлена только строка объектов, если её не было

### Requirement: Brief is not saved as a file

Бриф исследования MUST NOT сохраняться как `temp/briefs/*.md`. Шапка вводных MUST NOT быть полной копией всех слотов брифа (маршрут, варианты, ожидание).

#### Scenario: Brief is not saved as a file

- **WHEN** исследование подтверждено и записан отчёт с шапкой
- **THEN** файла `temp/briefs/*.md` нет, а в шапке нет слотов маршрута и вариантов

### Requirement: Chat постановка has no reports list

Блок постановки ЗНИ в чате MUST NOT содержать обязательное поле со списком файлов отчётов.

#### Scenario: Chat постановка has no reports list

- **WHEN** исследование завершается блоком постановки в чате
- **THEN** в блоке нет обязательного перечня отчётов; фактура доступна в файлах `reports/` после создания ЗНИ
