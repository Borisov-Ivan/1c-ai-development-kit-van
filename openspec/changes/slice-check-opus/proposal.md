## Результат

Проверка плана заявки из нескольких частей идёт на старшей модели семейства Opus. Заявка из одной части по-прежнему проверяется моделью текущего чата. Ревью кода остаётся на семействе Gemini. Назначение этой проверки на GPT в правилах больше не встречается.

## Why

Семейство GPT скоро пропадёт из списка моделей, а проверка заявки из нескольких срезов назначена только на него. Пока модель есть, проверка зовёт её даже если в конкретный запуск попал один срез. Когда модели не будет, правило само уводит проверку на модель чата и запрещает поставить другое семейство.

## What Changes

1. Проверка заявки из нескольких срезов назначается на старшую модель семейства Opus, мажор 5, даже если в этот запуск попал один срез.
2. Заявка из одного среза по-прежнему проверяется без отдельной модели, на модели чата.
3. Если старшей модели Opus 5 в списке нет, проверка идёт без отдельной модели. Другое семейство, включая Gemini, не подставляется.
4. Ревью кода, разбор постановки, написание кода, обследование, трасса, упрощение и рекомендация чата не меняются.
5. Файл профиля чата GPT остаётся, пока семейство ещё можно выбрать в чате. Этот профиль больше не назначает проверку срезов.

## Acceptance Criteria

1. В заявке из нескольких срезов проверка вызывает старшую модель семейства Opus, мажор 5, даже если в этот запуск попал один срез.
2. В заявке из одного среза отдельная модель не задаётся.
3. Ревью кода по-прежнему вызывает старшую модель семейства Gemini.
4. В правиле назначения и в сценариях контракта нет назначения этой проверки на GPT.
5. Если Opus 5 нет в списке, вызов идёт без отдельной модели, и Gemini на эту проверку не подставляется.
6. В правиле назначения у проверки срезов нет фразы «Opus не подставляется», а в таблице старшинства есть строка «Контроль нескольких срезов» с семейством Opus, мажор 5.
7. Для проверки срезов ни Fable, ни строка «Разбор постановки (Opus 5)» не предусмотрены.
