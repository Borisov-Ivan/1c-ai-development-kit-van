### Причина назначения контроля нескольких срезов на GPT (дословные опоры)

1. **Профиль уже был, роли не было.**  
   `…/2026-10-15-verify-model-bands/proposal.md` § Why: «Семейство GPT в назначении ролей не используется, хотя профиль этого семейства уже есть.»  
   `design.md` Context: «Профиль GPT-5.6 уже описан, роли у него нет.»

2. **Одно место в таблице — сверка нескольких срезов.**  
   `design.md` Goals: «Дать профилю GPT-5.6 одно место: сверка нескольких срезов.»  
   Design Rationale: «Место семейства GPT — решение этой заявки: одна роль, сверка заявки, в которой срезов больше одного.»

3. **Не ставить GPT шире.**  
   `design.md` Non-Goals: «Не ставить GPT на каждую проверку и не ставить его на независимый разбор.»  
   Rationale: «Ставить GPT на каждый проход значило бы добавить платный вызов там, где сейчас хватает модели чата.»

4. **Один срез — модель чата; счётчик — вся заявка.**  
   `design.md` «Решения verify»: «Модель семейства GPT берётся, если в заявке больше одного среза, даже когда в этот запуск сверки попал один срез. Заявка из одного среза остаётся на модели чата.»

5. **Обоснование — решение заявки и запрет чужого семейства, не MAY профиля.**  
   `reports/verification-2026-10-14.md`: «Абзац, почему сверка нескольких срезов садится на профиль GPT, опереть на решение заявки и запрет чужого семейства. Цитату MAY профиля убрать.»

**Чего в архиве нет:** сравнительного «GPT лучше Opus / Fable / Gemini / Grok для контроля срезов». Сравнение с другими семействами для **ревьюера** есть раньше: `2026-08-18-…/design.md` D1 — «Альтернатива «reviewer → `gpt-5.6-sol-medium`» отклонена: нет свидетельств преимущества, дороже.» Для QC такой альтернативы с выбором Opus/Fable/Gemini в текстах 2026-10-15 нет — зафиксировано «место профиля» и запрет подстановки.

## Фактическое поведение, если слага GPT в списке вызова нет (без правки правил)

Записанный запасной путь (не дыра):

1. Отбор слагов, нормализуемых роутером в профиль GPT-5.6, пуст → **сразу** `Task` **без** `model=` (модель чата).
2. **Другое семейство не подставляется**; в т.ч. Opus как запас для этой роли **не** используется (в отличие от пустого Fable у шагов сильнейшей модели).
3. Одна строка предупреждения пользователю + предложение обновить таблицу (раздел «Самосверка enum»).
4. При сбое уже ушедшего вызова с `model=` — шаг 2 цепочки: снова без `model=` (общая двухшаговая цепочка).
5. Режим «без API» / липкий лимит: Primary ролей (включая GPT для multi-slice QC) не вызываются → сразу без `model=`.

Источники: `model-selection.mdc` строки роли, цепочка QC, самосверка п.1; spec scenario «В списке нет профиля GPT-5.6».

## Чего архив не разрешает подставлять молча

Из `2026-10-15-verify-model-bands` (и закреплённого в `model-selection.mdc` / spec):

- **Любое другое семейство** вместо отсутствующего профиля GPT-5.6 (Opus, Fable, Gemini, Grok и т.д.).
- **«Второе семейство вместо отсутствующей модели»** — явно out of scope proposal.
- **GPT на каждый проход / на независимый разбор** — Non-Goals design.
- **Подстановка «похожей» модели** — общий запрет kit (с 2026-08-18 D3 no family guessing); для QC дополнительно: Opus не запас при пустом отборе GPT.
- **GPT-5.5 как профиль GPT-5.6** — роутер: «GPT-5.5 к профилю GPT-5.6 не относится.»

Молчаливая замена Primary QC на другое семейство = нарушение зафиксированного контракта архива 2026-10-15, а не «дыра до новой заявки».

## Краткая структура ответа (для чата)

### Роли на GPT (список)

- `openspec-quality-controller`, только если в заявке **больше одного** среза → старшая модель профиля GPT-5.6.
- Один срез / пустой отбор GPT → без `model=`, не GPT.

### Запрет подстановки (дословная цитата)

> такой модели нет — без `model=`, другое семейство не подставлять  
> (`model-selection.mdc`, строка роли QC)

### Почему так решили в архиве

1. Профиль GPT-5.6 был без роли — `…/2026-10-15-verify-model-bands/proposal.md` Why / `design.md` Context.  
2. Одно место: сверка нескольких срезов — `design.md` Goals / Design Rationale.  
3. Не на каждую проверку и не на независимый разбор — `design.md` Non-Goals.  
4. Пустой отбор → модель чата, чужое семейство не подставлять — `proposal.md` п.5, Out of scope.  
5. Обоснование — решение заявки, не MAY профиля — `reports/verification-2026-10-14.md`.

### Фактический запасной путь (слага GPT нет)

Сразу `Task` без `model=` (модель чата); другое семейство и Opus не подставляются; одна строка предупреждения.

### Файлы при снятии GPT с Primary

См. таблицу выше; минимум — `model-selection.mdc` + `openspec/specs/subagent-model-mapping/spec.md`.

### Чего архив не разрешает подставлять молча

Другое семейство вместо GPT; «второе семейство вместо отсутствующей модели»; расширение GPT на независимый разбор / каждый проход без новой заявки.
