# ADR-0004: Сессионный режим с API / без API по ключу в чате

**Статус:** Load-Bearing
**Дата:** 2026-08-18
**Область:** kit / выбор моделей субагентов
**Источник:** openspec/changes/archive/2026-08-18-kit-session-api-mode/reports/architecture-new-2026-08-17.md
**Load-bearing:** yes
**Protects-invariants:**
  - "Режим живёт в оркестраторе на время чата; признак в project.md и файл между чатами не требуются"
  - "Токен — целое слово после разбиения по пробелам: -noapi/--noapi/-api/--api; --api-key токеном не является"
  - "Пропуск шага 1 только на новых вызовах; уже ушедший вызов с платной моделью обязан сделать шаг 2"
  - "Липкая память — только лимит/credits, недоступность модели, ошибка выбора модели; таймаут не липнет"
  - "-noapi не заменяет --skip-architect и не создаёт .gate-override.yaml"
  - "Таблица ролей и запрет эскалации как запаса не переписываются"

## Контекст

После исчерпания лимита API каждый следующий дорогой вызов снова бился в платную модель и только потом уходил на модель чата. Нужны два явных режима в том же чате без настройки репозитория. Таблица ролей и двухшаговая цепочка уже зафиксированы в `kit-evolution-models-economy-profiles`.

## Решение

1. Оркестратор держит режим сессии: `-noapi` / `--noapi` → без API до `-api` / `--api` или нового чата.
2. Перед вызовом с конкретной моделью порядок: разовый слаг → токены сообщения → память после липкого сбоя → таблица ролей.
3. В режиме без API Primary и самая дорогая эскалация не вызываются, кроме разового явного слага на этот вызов.
4. Смысл ключей — в `.cursor/rules/model-selection.mdc`. В палитре дорогих команд — одна строка, что ключ пишется в чате. Команды без дорогих вызовов ключ своим флагом не объявляют.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему отклонён |
|---------|-------|--------|-----------------|
| Признак в project.md | Виден в репо | «Сегодня нет лимита» — не свойство проекта | Пользователь отклонил |
| Только память после сбоя | Меньше ключей | Пока первый вызов не упал, квота жжётся | Нет явного режима заранее |
| Probe квоты до вызова | Точнее | Нет API usage; конфликт с первым Read скилла | Нет средства |
| Ключ как флаг каждой команды | Привычный парсер | Копипаста, путаница со --skip-architect | Смысл разъедется |

## Последствия

- Положительные: можно заранее уйти на модель чата; после лимита нет повторных ударов.
- Отрицательные: новый чат снова начинается с API; грубая политика на все дорогие модели сразу.
- Нейтральные: таблица ролей, inherit через отсутствие параметра, самосверка enum не меняются.
