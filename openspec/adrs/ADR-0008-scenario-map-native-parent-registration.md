# ADR-0008: Карта сценария — нативная регистрация панели родителем

**Статус:** Superseded by ADR-0010
**Дата:** 2026-08-28
**Область:** kit / scenario map canvas
**Источник:** openspec/changes/archive/2026-08-28-scenario-map-canvas/reports/architecture-extend-coherence-2026-08-28-2.md
**Load-bearing:** no
**Protects-invariants:**
  - "Без прямой просьбы и без принятого предложения панель не создаётся; намёк на существующей строке — только вариант, не сборка"
  - "Успех публикации — штатная кнопка среды рядом с чатом после чистой проверки панели у родителя; ссылка в чате критерием успеха не является"
  - "Картограф возвращает проверенный манифест и не пишет файл панели; регистрирует родитель собственной записью"
  - "У узла есть имя и доказательство; у ребра — отношение, подпись и ссылка на источник; порядок прохода — следование, не причинность"
  - "Предложение схемы считается по форме связей, не по теме механизма и не по числу шагов"

## Контекст

Первая поставка карты сценария доводила цепочку до «файл записан, в чат ушла ссылка». Живая проверка показала: запись файла исполнителем макета панель не открывает, markdown-ссылка на Windows ненадёжна, а самооценка исполнителя не заменяет проверку панели среды. Параллельно плоский контракт узла и причинная подпись на порядке прохода давали список вместо схемы.

Capability одна; отдельная команда карты не вводится. Нужен устойчивый контракт публикации и доказательности, который следующие ЗНИ не должны молча откатить к ссылке или к списку.

## Решение

1. Файл панели регистрирует родительский агент сессии полной записью в каталог панелей среды. Исполнитель макета отдаёт манифест (шапка, узлы, связи, виды) и файл не пишет.
2. Гейт публикации — чистая проверка панели у родителя. Схема открывается штатной кнопкой среды. Путь файла в чат штатно не печатается. Аварийная строка с путём — только если проверка уже чистая, а пользователь явно пишет, что схемы нет.
3. Узел: идентификатор, имя, тип, слой, эффект, доказательство. Связь: закрытое отношение, человекочитаемая подпись, ссылка на источник. Порядок уже разобранных шагов отображается следованием и не подписывается причинным ярлыком.
4. ~~Главный вид — граф. Список, аккордеон и стена одинаковых карточек без связей не публикуются как карта.~~ *(Заменено ADR-0009.)* Главный вид отвечает на вопрос шапки выбранным средством. Список, аккордеон и стена одинаковых карточек без связей и без вывода не публикуются как карта.
5. Рисовать можно только по прямой просьбе или по принятому предложению. Предложение — вариант в уже существующей строке решения и только при топологическом признаке.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему отклонён |
|---------|-------|--------|-----------------|
| Ссылка в чате как критерий успеха | Проще проверить в тексте | На Windows не открывается; пользователь путь не просил | Провал публикации |
| Файл пишет исполнитель макета, родитель только трогает строку | Меньше работы родителя | Запись субагента панель не регистрирует; handshake как единственный путь не доказан | Доказан полный `Write` родителя |
| Оставить плоский контракт узла, рёбра необязательны | Меньше схемы данных | Снова список / аккордеон | Не показывает связи |
| Отдельная команда карты | Явный вход | Рвёт исследование и разбор | Non-goal этой capability |

## Последствия

- Положительные: первая просьба даёт схему рядом с чатом; будущие ЗНИ не могут вернуть ссылку или список как «готовую карту» без явной замены этого ADR.
- Отрицательные: публикация зависит от записи родителя и проверки среды; исполнитель макета не самодостаточен.
- Нейтральные: ADR-0001, ADR-0002 и ADR-0006 не отменяются; глобальный скилл Canvas в kit не копируется; живые файлы панели в git не входят.
