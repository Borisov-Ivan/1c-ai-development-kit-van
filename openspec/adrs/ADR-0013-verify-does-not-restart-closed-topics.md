# ADR-0013: Повторная проверка не переоткрывает закрытое

**Статус:** Accepted
**Дата:** 2026-09-30
**Область:** kit / проверка постановки
**Источник:** openspec/changes/archive/2026-09-30-verify-stop-repeat/reports/architecture-new-2026-09-23.md
**Load-bearing:** no

## Контекст

После ответа заказчика и после уточнения уже названной темы проверка снова запускала полный разбор и задавала те же вопросы. Остановка зацикленных правок срабатывала по числу правок текста, а не по повторному касанию одной темы.

## Решение

Известные продуктовые вопросы задаются одним пакетом. Ответ внутри уже выбранного подхода даёт точечный следующий прогон, а не полный разбор. Повтор закрытой темы без нового факта и без смены наблюдаемого правила не удерживает замечание. Второе переоткрытие одной и той же темы останавливает правки вопросом «оставить текст или переписать срез»; порог в три правки остаётся запасным правилом для тем без идентичности. Темы не сливаются по похожести формулировок.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему отклонён |
|---------|-------|--------|-----------------|
| Полный разбор после каждого ответа | Не пропустить смену подхода | Ответ внутри подхода не меняет ось, а прогон повторяется | Смена подхода и так остаётся поводом для полного разбора |
| Стоп только по числу правок | Просто считать | Пять разных тем выглядят как петля, а одна тема растягивается | Тематический стоп ловит реальную петлю раньше |

## Последствия

- Положительные: закрытый вопрос не возвращается следующим прогоном; петля ловится по теме.
- Отрицательные: идентичность темы нужно присваивать при первом упоминании и не угадывать по тексту.
- Нейтральные: правка выбранного подхода или контракта поведения по-прежнему даёт полный разбор.
