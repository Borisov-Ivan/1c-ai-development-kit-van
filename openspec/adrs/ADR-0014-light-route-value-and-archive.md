# ADR-0014: Лёгкий маршрут замены значения и архива

**Статус:** Accepted
**Дата:** 2026-09-30
**Область:** kit / проверка постановки
**Источник:** openspec/changes/archive/2026-09-30-pipeline-light-route/reports/architecture-new-2026-09-30.md
**Load-bearing:** yes
**Protects-invariants:**
  - "Замена утверждённого значения после первой полной проверки не запускает полный разбор"
  - "Отметка приёмки не делает финальную проверку устаревшей"
  - "Повторный прогон не копирует список задач и журнал решений"

## Контекст

После первой полной проверки заказчик менял уже утверждённое значение, например цвет, и конвейер снова разбирал всю постановку. Архив после отметки приёмки считал проверку устаревшей и запускал её заново. Повторный отчёт копировал журналы и пересказывал постановку.

Разбор постановки подтвердил одну точку: таблица глубины проверки и рецепт хэша снимка. Отдельный классификатор и второй снимок отклонены.

## Решение

Класс «замена значения» живёт в одном месте — таблице глубины. Дополнение только называет исход: проверка не требуется, короткая сверка или нужна проверка. У `tasks.md` два ключа хэша: сырой для кэша и выбора режима, нормализованный (флажки замаскированы) — только для свежести архива и границы среза. Запись о приёмке в журнале не входит в ключ, по которому архив решает, вызывать ли проверку. Повторный прогон неполной глубины ссылается на предыдущий отчёт и не копирует список принятых задач и журнал решений.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему отклонён |
|---------|-------|--------|-----------------|
| Один нормализованный ключ для всех читателей | Проще | Ломает кэш контролей, которые зависят от флажков | Сырой ключ сохранён для прежних читателей |
| Убрать внутреннюю проверку архива | Нет повторного прогона | Смена постановки после приёмки пройдёт молча | Третья ветка архива по-прежнему вызывает проверку |
| Отчёт хранит только дельту снимка | Меньше текста | Все читатели снимка собирают цепочку | Читатели не менялись: из снимка убраны только копии журналов |

## Последствия

- Положительные: замена цвета и архив после приёмки не повторяют полный разбор.
- Отрицательные: числовой порог и смена сути правила по-прежнему требуют проверку; это легко принять за «ту же» замену значения.
- Нейтральные: ответ внутри выбранного подхода остаётся точечным прогоном, как в ADR-0013.
