# ADR-0005: Видимость режима без API — канон в том же ходе

**Статус:** Accepted
**Дата:** 2026-08-20
**Область:** kit / chat surface · выбор моделей
**Источник:** openspec/changes/archive/2026-08-20-kit-session-noapi-visibility-and-ru-progress/reports/architecture-2026-08-19-kit-session-noapi-visibility.md
**Load-bearing:** no
**Protects-invariants:**
  - "После липкого сбоя первая строка того же хода — канон без имени модели"
  - "Оркестратор не печатает -noapi и не говорит, что режим «включился»"
  - "Канон лимита и строка модели разбора постановки в verify не ждут карточки вердикта"

## Контекст

Режим без API после лимита уже работал (ADR-0004), но человек этого не видел: канон жил в on-demand правиле, платформа писала про смену модели, токен `-noapi` оркестратор не печатал.

## Решение

Канон «дорогие модели недоступны — дальше на модели чата» — always-apply бюджет чата, первая строка того же хода. Не печатать `-noapi`. Не цитировать платформу. Не отменять ушедший вызов. Второй сигнал — строка модели разбора постановки: «Разбор постановки (Fable)» или «Разбор постановки (Opus 5)», если слага сильной модели нет в enum. ADR-0004 не отменяется.

## Альтернативы

| Вариант | Почему отклонён |
|---------|-----------------|
| Печать `-noapi` оркестратором | Ломает ADR-0004: токен — слово пользователя |
| Файл-состояние / третий режим | Уже отклонено ADR-0004 |
| Только FAQ без обязанности в том же ходе | Инцидент повторяется |

## Последствия

- Положительные: человек видит смену режима в том же ходе.
- Отрицательные: исключение из «одно сообщение» в verify нужно держать явно.
- Нейтральные: таблица ролей и цепочка вызова не меняются.
