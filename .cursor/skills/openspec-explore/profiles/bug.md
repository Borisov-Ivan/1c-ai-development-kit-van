# Профиль `explore-bug` (дефект)

Отчёт — анализ и рецепт исправления. Канва для маршрута в брифе; синтез составных секций — композитор (`openspec-composer`).

## Подсказки для брифа (Цель / Решено, когда)

| Типичная цель заказчика | Критерий «решено» |
|-------------------------|-------------------|
| Убедиться, что не баг / не регресс | Знаю: чинить или не чинить |
| Починить verify / поведение | Воспроизведён сценарий и есть рецепт |
| Ускорить (PERF) | Знаю: оптимизировать или оставить как есть |

## Обязательные секции отчёта

| `target-section` | Содержание | Опциональность |
|---|---|---|
| `Для заказчика` | Вердикт; чинить/не чинить; одно действие сейчас; FAQ «что видите в отладчике» (1 абзац). **Первая секция** после шапки; ≈ T-EXPLORE-DECISION в чате. | обязательно |
| `Свод` | Симптом → причина → фикс; навигация (технический слой) | обязательно |
| `Цепочка причин` | От симптома вглубь; начинается с `### Объекты` | обязательно |
| `Корневая причина` | Одно место: `` `модуль:процедура` `` — что не так | обязательно |
| `Рецепт исправления` | Таблица «Было / Станет» с цитатами | обязательно |
| `Регрессы и проверка` | Что прогнать, какие данные | обязательно |
| `Воспроизведение` | Шаги + входные данные | опционально (трасса/PERF/явное воспроизведение) |
| `Варианты исправления` | Точечный vs структурный | опционально (2+ путей) |
| `Открытые вопросы` | блокирующий / уточняющий | опционально |

## Типичные предметы исследования

- Трасса / стек / PERF — шаг через `onec-trace-analyst` → `temp/trace-analysis.md` (секция `## Для заказчика`).
- Симптом и воспроизведение.
- Цепочка вызовов до точки отказа.
- Точка отказа (корневая причина).
- Рецепт правки.
- Регрессы смежных сценариев.

## Пример маршрута (с трассой)

1. Разбор трассы → `trace-analyst` (не step-файл) → контрольная точка «достаточно?».
2. Воспроизведение → `Воспроизведение` (опционально).
3. Цепочка причин → `Цепочка причин`.
4. Корневая причина → `Корневая причина`.
5. Рецепт → `Рецепт исправления`.
6. Регрессы → `Регрессы и проверка`.
7. Собрать отчёт → T-EXPLORE-DECISION в чате, затем `analysis.md`.

`step-id`: `B1`, `B2`, …

## Handoff после отчёта

- Новая ЗНИ: `/opsx:ff <name>` (по `analysis.md`) — только если финальный DECISION указал «Позже».
- Существующая ЗНИ: `/opsx:extend <change> --from-report openspec/sessions/<slug>/analysis.md`.
