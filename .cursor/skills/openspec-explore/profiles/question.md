# Профиль `explore-question` (вопрос / справка)

Отчёт — ответ на вопрос без проектирования правок. `/opsx:new` не предлагается по умолчанию.

## Подсказки для брифа (Цель / Решено, когда)

| Типичная цель заказчика | Критерий «решено» |
|-------------------------|-------------------|
| Получить ответ да/нет | Есть прямой ответ |
| Понять механизм для своего решения | Могу применить к своему случаю |

## Обязательные секции отчёта

| `target-section` | Содержание | Опциональность |
|---|---|---|
| `Для заказчика` | Прямой ответ на вопрос; применимо ли к вашему случаю. **Первая секция** после шапки. | обязательно |
| `Свод` | Ответ на вопрос; навигация | обязательно |
| `Как это устроено` | Механизм; `### Объекты` | обязательно |
| `Применимо ли к вашему случаю` | Разбор сценария из вопроса | опционально |
| `Рекомендации` | Что делать / чего избегать | опционально |
| `Соответствие стандартам` | ИТС / БСП | опционально |

## Типичные предметы

- Точка входа механизма.
- Внутренняя реализация (модули, регистры).
- Параметры и настройки.
- Связанные сценарии.
- Применимость к кейсу пользователя.

## Пример маршрута

1. Описание механизма → `Как это устроено`.
2. (Опционально) Применимость → `Применимо ли к вашему случаю`.
3. Собрать отчёт → T-EXPLORE-DECISION в чате, затем `analysis.md`.

`step-id`: `Q1`, `Q2`, …

## Fast-path

Если маршрут — **один** пункт и профиль `explore-question`: композитор может быть пропущен; `analysis.md` = содержимое единственного step-файла + шапка + `## Для заказчика` (см. `compose.md` §Fast-path).

## Handoff после отчёта

- Свод в чате — основной результат; файл — по запросу.
