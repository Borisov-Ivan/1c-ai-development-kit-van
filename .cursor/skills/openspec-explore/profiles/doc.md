# Профиль `explore-doc` (доработка)

Отчёт — заготовка ЗНИ: поведение, правки, проверка. Канва для маршрута в брифе.

## Подсказки для брифа (Цель / Решено, когда)

| Типичная цель заказчика | Критерий «решено» |
|-------------------------|-------------------|
| Понять, что менять | Есть целевое поведение и список правок |
| Оценить риски перед ЗНИ | Знаю: заводить ЗНИ или отложить |

## Обязательные секции отчёта

| `target-section` | Содержание | Опциональность |
|---|---|---|
| `Для заказчика` | Что меняется для пользователя; готовность к ЗНИ; одно действие сейчас. **Первая секция** после шапки. | обязательно |
| `Свод` | Итог, границы, ключевые выводы | обязательно |
| `Как сейчас работает` | Текущая логика; `### Объекты` | обязательно |
| `Целевое поведение` | Матрица вход → результат | обязательно |
| `Что и как меняем` | Таблица «Было / Станет» | обязательно |
| `Влияние и проверка` | Сценарии теста и регрессы | обязательно |
| `Соответствие стандартам` | ИТС / БСП / платформа | опционально |
| `Варианты решения` | Альтернативы с обоснованием | опционально |
| `Открытые вопросы` | блокирующий / уточняющий | опционально |

## Типичные предметы

- Точка входа (форма, команда, документ).
- Настройки и флаги.
- Ограничения (организация, RLS, права).
- Смежные механизмы БСП.
- Целевая матрица поведения.
- Конкретные правки с цитатами.
- Сценарии проверки.

## Пример маршрута (простая задача)

1. Текущая логика → `Как сейчас работает`.
2. Целевое поведение → `Целевое поведение`.
3. Правки → `Что и как меняем`.
4. Проверка → `Влияние и проверка`.
5. Собрать отчёт → T-EXPLORE-DECISION в чате, затем `analysis.md`.

`step-id`: `D1`, `D2`, …

## Handoff после отчёта

- `/opsx:ff <name>` — если DECISION указал готовность к ЗНИ.
