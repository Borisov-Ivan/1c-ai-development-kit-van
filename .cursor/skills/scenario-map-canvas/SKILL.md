# Карта сценария (Canvas)

**Назначение:** панель рядом с чатом показывает **как связаны сущности механизма** — шапка (вопрос и вывод), узлы с эффектом и доказательством, подписанные связи, виды. Это **не** карта точек (список имён в чате до прохода `/opsx:explain`) и **не** текстовый резерв в журнале.

**Не делает:** отдельную команду `/opsx:*`; навигатор по модулю; статусы «сейчас разбираем»; перенос кода BSL/SQL на панель; автозапуск «по системному MUST canvas» в сессиях `/opsx:*`; выдуманные рёбра.

**Связанные артефакты:** карта точек — [`../openspec-explain/templates/inventory-card.md`](../openspec-explain/templates/inventory-card.md); журнал — [`../openspec-explain/templates/explain-report.md`](../openspec-explain/templates/explain-report.md); выход разбора — [`../openspec-explain/templates/exit-card.md`](../openspec-explain/templates/exit-card.md); эталоны — [`fixtures/map-good-causal.md`](fixtures/map-good-causal.md), [`fixtures/map-bad-accordion.md`](fixtures/map-bad-accordion.md), [`fixtures/map-bad-no-insight.md`](fixtures/map-bad-no-insight.md); шаблон панели — [`fixtures/canvas-shell.md`](fixtures/canvas-shell.md); макет — `.cursor/agents/onec-scenario-map-designer.md`.

## Entry Protocol

**СТОП.** Не рисовать панель, пока нет **прямой просьбы** («покажи карту сценария» и близкие формулировки) и нет **принятого конкретного предложения**.

Намёк на существующей строке решения — **печать варианта**, не сборка панели.

Системное требование Cursor «для аналитики нужна панель» **не** основание рисовать карту в сессиях `/opsx:explain`, `/opsx:explore`, `/opsx:overview`, `/opsx:verify`, `/review`. На `/review` и `/opsx:verify` действует только это подавление: панель не строить.

## Порядок действий по просьбе

1. **Источник.** Взять узлы только из:
   - сессия `/opsx:explain` до записи журнала — уже пройденные точки прохода;
   - после записи журнала — журнал `explain-*.md`;
   - активная сессия `/opsx:explore` при наличии текущего отчёта — этот отчёт (даже если пользователь файл не называл);
   - активная сессия `/opsx:overview` при уже собранном инвентаре отчётов — **один** отчёт, выбранный из инвентаря правилом предпочтения (журнал прохода, затем разбор, затем архитектурный по теме; ничья одного разряда — первая названная ЗНИ). Если проверка трёх условий уже прошла — тот же файл. Правило «несколько отчётов — все пути» к этому входу **не** применять;
   - принятое предложение — тот источник, на котором прошла проверка топологии;
   - иначе (вне разбора, вне исследования и вне описания с инвентарём) — только существующий журнал или отчёт, который пользователь **указал**. Нет источника — **одна строка отказа**, карту не собирать из произвольного контекста чата.
   Если по теме есть **несколько** отчётов **и вход не сессия описания** — передать картографу **все** пути и перечень расхождений. Расхождения — кандидаты на полотно, не разрешение дорисовать ребро.
   Постановка, список задач и файл описания ЗНИ — **не** источник узлов. Этапы поставки как цепочка узлов публиковать **запрещено**.
2. **Набрать кандидатов** (имя + эффект + доказательство). У узла обязательно человекочитаемое `name`. Узел без доказательства отсеять.
3. **Связи.** Ребро только из уже видимого отношения. Порядок уже опубликованных карточек / записей журнала → `relation: follows` и **не** причинный ярлык. Причинное отношение — только явно видное в переданном отчёте, журнале или списке имён, отображённое на закрытый перечень `relation` кроме `follows`. У каждой связи — `evidence_ref` (порядок прохода, якорь отчёта или журнала). Выдумывать рёбра **запрещено**. Узел без инцидентной связи отсеять. Публикуется **связный набор**.
4. **Порог.** Считать **публикуемые сущности механизма** после обоих отсевов (без доказательства **и** без связи), не число шагов рассказа и не число узлов «как в карточке». Скобки ролей в постановке («источник, кэш, …») — **примеры**, не фильтр охвата и не закрытый список типов. Аннотации в этот счёт **не** входят. Если после обоих отсевов меньше **четырёх** — панель **не** публиковать; в чат **одна строка**, чего не хватает; можно продолжить разбор или исследование. Не добивать порог выдуманными стрелками и **не** добивать его аннотациями.
   - Исключение отложенного согласия **во время прохода:** ниже порога фокус запоминается, строки нехватки нет (см. «Отложенная постройка»).
5. **Носитель.** Каталог панелей резолвит **родительский агент сессии** по правилам глобального скилла Canvas (пути окружения сессии; каталог не создавать вручную; путь не угадывать; глобальный скилл в kit не копировать). Предикат «уже открыта или назван файл» **не действует**: файл создаётся с нуля. Не определился каталог или среды без панели нет — текстовый резерв (ниже). Абсолютный путь файла панели в артефакты ЗНИ и в чат **не** писать. Файл **не** коммитить в репозиторий.
6. **Макет.** Извлечение связей и выбор вида отдаёт роль `onec-scenario-map-designer` вызовом `Task` **без** параметра модели. Передать: пути источников (сессия описания — **тот же один** выбранный отчёт, не «все пути»; иначе — все пути по теме, как в п. 1), диапазоны доказательств, перечень расхождений (для описания — пусто, один файл). Обратно: **манифест данных** (шапка, узлы, связи, виды; необязательные `header.focus_node`, `modes`, `annotations`), исход проверки манифеста, номер круга ремонта (не больше двух). Картограф файл панели **не** пишет. Обход кода шире переданных диапазонов запрещён. Если доказанных рёбер не хватает — исход «публиковать нельзя»; оркестратор **не** подставляет стрелки.

   **Проверка смысла (по манифесту, до записи файла).** Ответ на вопрос шапки складывается из расположения, связей и аннотаций с якорем и доказательством, а не только из текста шапки. Находка, которая меняет действие читателя, присутствует узлом, подписанной связью или аннотацией. Аннотация без якоря, без доказательства или пересказ шапки — отсев. Провал — повтор сборки в уже существующих двух кругах. Исчерпание — «публиковать нельзя», **одна строка** в чат, чего не хватает. Провал проверки смысла **не** причина текстового резерва: панель не публикуется.
7. **Регистрация.** Родитель заполняет [`fixtures/canvas-shell.md`](fixtures/canvas-shell.md) манифестом и **сам записывает** один `.canvas.tsx` напрямую в каталог панелей текущей области — той же записью, по которой среда возвращает проверку типов файла. Дамп скриптом оболочки не регистрирует кнопку рядом с чатом. Гейт — **чистая** проверка типов этой записи (ноль ошибок в результате, не самооценка картографа). Шаблон рисует граф (раскладка носителя, стрелки, полосы по слою узлов); переключатель видов меняет раскладку. Выбор узла показывает эффект и доказательство в панели деталей; файл открывается кнопкой этой панели; запуск нового чата с панели **запрещён**. Исход «публиковать нельзя» — панель не публиковать, одна строка чего не хватает, можно продолжить разбор или исследование. Исчерпанный ремонт манифеста (два круга) — текстовый резерв, наравне со средой без панели и неопределившимся каталогом — **кроме** провала проверки смысла (см. шаг 6). Если проверка чистая, а пользователь явно пишет, что схемы не видит — одна аварийная строка с путём **или** текстовый резерв (восстановление, не критерий успеха).

   **Чек-лист читаемости (по записанному файлу, после чистой проверки панели и до строки о готовности):** направление каждой связи и легенда использованных типов; полосы подписаны слоем своих узлов, а не рангом; нет стены одинаковых карточек; стартовый узел выбран. Провал — одна перезапись родителя. Исчерпание — уже существующая причина резерва «запись или проверка исчерпала ремонт».
8. В чат — **одна строка** о готовности схемы / отказе / резерве **без** пути к файлу и **без** markdown-ссылки. Успех — штатная кнопка среды рядом с чатом. Команда сессии **не** меняется. Вернуться к текущей точке прохода или к исследованию.

**Прямая просьба при ≥4 публикуемых сущностях всегда строит панель.** Топология (уровни, ветки) для просьбы **не** требуется: если признака нет — главный вид = цепочка с подписями `follows` из порядка прохода. Список или аккордеон без рёбер — не карта.

**После выхода разбора** прямая просьба строится из журнала так же, как в середине прохода; отдельного подтверждения нет.

## Контракт карты

Публикация: `header` + `nodes` + `edges` + `views`. Свести обратно к списку `step/name/effect/evidence` без связей **запрещено**. Существующие поля не удалять и не переименовывать.

### Шапка (`header`)

| Поле | Содержание |
|------|------------|
| `question` | Центральный вопрос карты; не длиннее **двенадцати** слов |
| `insight` | Главный вывод, который видно из расположения, стрелок и аннотаций с доказательством (не пересказ темы) |
| `sources` | Журнал / отчёт / пройденные точки |
| `view_primary` | Главный `view.type` |
| `focus_node` | Необязательный id стартового узла. Обязателен, если в наборе есть причинные связи (`relation` кроме `follows`); иначе по умолчанию первый узел |

### Узел (`nodes`)

| Поле | Содержание |
|------|------------|
| `id` | Стабильный идентификатор |
| `name` | Человекочитаемое имя (**обязательно**) |
| `kind` | Значение из словаря ниже |
| `layer` | Имя слоя (человекочитаемое) |
| `effect` | Короткое «что происходит» — **2–3 предложения** |
| `evidence` | Путь и диапазон строк **или** путь журнала/отчёта |
| `state` | Только если есть жизненный цикл |

Узел без `evidence` **не** публикуется. Каждый опубликованный узел инцидентен ≥1 связи. Литеральные кавычки кода в `name` / `effect` запрещены.

### Связь (`edges`)

| Поле | Содержание |
|------|------------|
| `from` / `to` | `id` узлов |
| `relation` | Значение из словаря ниже |
| `label` | Человекочитаемая подпись; не длиннее **четырёх** слов (длинное — в панели деталей) |
| `evidence_ref` | Источник отношения: порядок прохода, якорь отчёта или журнала (**обязательно**) |

Идентификатор у связи **не** вводится: пара `from`/`to` однозначна в опубликованном наборе.

### Виды (`views`)

Ровно один главный вид; вспомогательных ≤2. Если на наборе есть топологический признак — раскладка: не меньше двух уровней **или** ветвление со схождением. Если сущностей хватает, а признака нет (просьба / согласие) — цепочка с подписанными рёбрами. Виды меняют **раскладку** панели, не состав рёбер.

### Режимы (`modes`)

Необязательный список не длиннее **трёх**. У режима обязательны:

| Поле | Содержание |
|------|------------|
| `id` | Стабильный идентификатор режима |
| `label` | Подпись кнопки |
| `highlight_nodes` | Идентификаторы уже опубликованных узлов |
| `highlight_edges` | Пары `{ from, to }` уже опубликованных связей |
| `answer` | Один короткий ответ; не длиннее **двенадцати** слов |

Режим меняет подсветку того же набора узлов и рёбер и этот ответ. Состав узлов и рёбер не меняет, рёбра **не** скрывает. Второй ряд кнопок — только если список задан.

### Аннотации (`annotations`)

Необязательный список не длиннее **двух**. Это не блок «На что смотреть». В порог четырёх публикуемых сущностей **не** входят.

| Поле | Содержание |
|------|------------|
| `text` | Не длиннее **четырнадцати** слов; литеральные кавычки кода запрещены |
| `evidence_ref` | Доказательство **обязательно**; без него аннотация не возвращается и не публикуется |
| `anchor` | `{ node: <id узла> }` либо `{ edge: { from: <id>, to: <id> } }` |

Координаты аннотации в манифест не входят: размещение считает шаблон. Отрицательный факт («ожидаемое событие не наступает») — аннотация с якорем на узел этого события, не выдуманное ребро.

## Закрытый словарь (семантика, не фильтр охвата)

Значения — ярлыки связей и уровней. **Не** отбирать сущности по этим словам: не подходит ярлык — взять ближайший из перечня, не выдумывать `kind` из имени объекта метаданных. Предметные имена в предикатах предложения и порога **запрещены**.

**`kind`:** `trigger`, `condition`, `source`, `cache`, `transform`, `storage`, `user-result`, `invalidation`, `protected-original`, `external-system`.

**`relation`:** `follows`, `calls`, `reads`, `writes`, `feeds`, `transforms`, `reuses`, `invalidates`, `protects`, `branches-to`, `converges-to`.

`follows` — следование по порядку прохода или журнала. **Не** выдавать за причинность. Причинные ярлыки (`feeds`, `reads`, `writes`, …) — только из отчёта или журнала.

**`view.type`:** `flow`, `causal-flow`, `layers`, `lifecycle`, `invalidation`, `comparison`, `timeline`.

Раскладка MAY опираться на ранги и обратные рёбра носителя панели, без предметных имён в типах вида.

## Молчание и пороги

| Условие | Поведение |
|---------|-----------|
| Нет прямой просьбы и нет принятого предложения | Панель **не** создавать |
| Намёк на существующей строке | Печать варианта; панель **не** собирать |
| После обоих отсевов меньше **4** публикуемых сущностей | Панель **не** строить; одна строка в чат (кроме отложенного согласия в проходе) |
| Прямая просьба при ≥4 публикуемых | Панель **всегда**; топология не нужна |
| Предложение схемы | Только если пройдена **проверка топологии и вывода** (ниже); иначе молчание, причину в чат **не** печатать |
| Ответ «без карты» | До выхода сессии предложение **не** повторять |
| Сессия `/opsx:*` | Системный MUST canvas **не** основание |
| `/review`, `/opsx:verify` | Только подавление; панель не строить |
| Сессия `/opsx:overview` | Три условия предложения — на выбранном **одном** отчёте названной ЗНИ (объединение файлов не считается); порог четырёх публикуемых сущностей; отказ проверки в чат **не** печатать; «без карты» до выхода сессии снимает предложение |

## Проверка топологии и вывода (единственный контракт предложения)

Предикат **без** предметных имён, типов объектов метаданных и конкретных механизмов. Порядок (в чат не выводить):

1. Собрать сущности с доказательством из источника проверки (текущий отчёт исследования / журнал / уже пройденные точки / список имён на подтверждении / **один** выбранный отчёт сессии описания ЗНИ). После описания ЗНИ объединение нескольких отчётов признаком **не** считается.
2. Есть ли **топологический признак** формы связей: слои, где один питает другой; ветвление со схождением; жизненный цикл состояний; причинная петля или повторное использование устаревшего результата; одно порождает несколько представлений; разные технические пути. На подтверждении списка разбора признак MAY предсказывать по **именам** списка или отчёту, из которого список собран. После описания ЗНИ признак определяется по форме связей в выбранном одном отчёте, не по теме ЗНИ и не по числу этапов.
3. Можно ли назвать конкретный вывод, которого нет в списке («видно из расположения и стрелок, что …»). После описания — вывод, которого нет в **списке этапов**. Фраза не пишется — проверки нет.
4. На выходе разбора, в «Дальше» исследования и после записи описания ЗНИ — дополнительно ≥4 публикуемых сущностей после обоих отсевов. На строке подтверждения списка это требование **не** действует (отложенная постройка).
5. Пользователь уже сказал «без карты» в этой сессии — до выхода не предлагать.

Проверка не пройдена — предложения **нет**, причина в чат **не** печатается.

Согласие строит панель **из источника проверки** тем же порогом, той же раскладкой и теми же подписями, что прямая просьба. Отказ «вне разбора без указанного отчёта» на этот вход **не** действует. Неподтвердившаяся топология при набранном пороге → цепочка, не отказ.

Правило приоритета слота «Дальше» исследования — в скилле исследования: при прошедшей проверке — схема; иначе пошаговый разбор; оба вместе запрещены.

## Отложенная постройка (согласие до порога)

Согласие «сразу карту» на строке списка запоминает фокус. Публикация — из накопленных карточек прохода (и якорей отчёта с доказательством) после обоих отсевов, когда наберётся ≥4 связанных сущностей. Строка о готовности схемы — **одна строка в том же сообщении**, где карточка прохода впервые дала порог, **без** пути к файлу. Шаблон карточки точки **не** менять; повторного «хотите карту?» нет; команду сессии не менять. Если к выходу порог не набрался — в уже существующей строке «Следующий шаг» одна честная фраза, чего не хватило, без повторного вопроса.

---

## Запреты содержимого панели

На панели **запрещено** как главное содержимое и как главный вид:

- вертикальный список, аккордеон, стена одинаковых карточек, таблица шагов **без связей**;
- код и fence BSL/SQL;
- блок «На что смотреть»;
- статусы прохода («сейчас разбираем», «текущая точка»);
- классы точек разбора (`решение` / `наблюдение` / `типовое`);
- пустые состояния и заглушки «карта появится позже»;
- все узлы принудительно раскрытыми без структуры;
- запуск нового чата с панели.

Код, «на что смотреть» и фрагменты модулей остаются в **чате** и **журнале** разбора.

## Источник узлов

### В сессии `/opsx:explain`

**До записи журнала:** уже пройденные точки. Из карточки: эффект ← «Что берётся» / «Как берётся»; доказательство ← «Где в коде»; связь следования ← порядок прохода (`follows`); причинная связь ← уже видимое в отчёте отношение.

**После записи журнала:** журнал `explain-*.md` (включая секцию текстового резерва, если она уже есть).

### В сессии `/opsx:explore`

Прямая просьба при наличии текущего отчёта — этот отчёт. Согласие на предложение — тот же отчёт (путь уже есть у оркестратора). Несколько отчётов по теме — все пути плюс расхождения.

### В сессии `/opsx:overview`

Инвентарь отчётов этой сессии. В сборщика уходит **один** отчёт по правилу предпочтения (журнал прохода, затем разбор, затем архитектурный по теме; ничья — первая названная ЗНИ). Если проверка трёх условий уже прошла — тот же файл. Правило «несколько отчётов — все пути» к этому входу **не** применять. Постановка, список задач и файл описания — не источник. Этапы поставки цепочкой узлов не публиковать.

### Вне разбора, вне исследования и вне описания с инвентарём

Только существующий журнал или **указанный** отчёт. Иначе одна строка отказа. Отказ «укажите отчёт» **не** применять к: (1) принятому предложению — источник проверки; (2) прямой просьбе в исследовании при текущем отчёте; (3) прямой просьбе в сессии описания при уже собранном инвентаре — один отчёт по предпочтению.

## Текстовый резерв (только технический отказ)

Резерв **не** называется картой. Допустимые причины — только:

1. среда без панели;
2. каталог панелей не определился;
3. запись или проверка исчерпала два круга ремонта.

«Панель ещё не открывали» и «пользователь не назвал файл» — **не** причины резерва.

Провал проверки смысла **не** причина резерва: панель не публикуется, в чат идёт одна строка, чего не хватает.

1. Записать узлы **и связи** в журнал `explain-*.md` в секцию **«Схема (текстовый резерв)»**.
2. Если файла журнала ещё нет — создать по шаблону [`explain-report.md`](../openspec-explain/templates/explain-report.md) с этой секцией.
3. Штатная запись журнала на выходе **сохраняет** секцию «Схема (текстовый резерв)», а не затирает её.
4. В чат — честно, что **интерактивная схема не создана** (с путём к журналу).
5. Третьего адресата нет. Отдельного «чат-файл разбора» не заводить.

## Намёк на существующей строке решения

Намёк — **вариант** в уже существующей строке, если пройдена проверка топологии и вывода. Панель не собирает. Слоты:

1. «Дальше» исследования.
2. Подтверждение списка точек разбора.
3. «Следующий шаг» на выходе разбора — не печатать, если на выходе задан вопрос про доп. анализ (строки нет).
4. Строка следующего шага чата описания ЗНИ — печатается **всегда**, включая прогоны, где карта не рассматривалась; канон «Передать файл на согласование».

**Не слот:** строка «Следующий шаг» финала исследования с постановкой ЗНИ (команда создать ЗНИ).

## Guardrails

- Нет отдельной команды `/opsx:*` для карты.
- Не путать **карту точек** (имена в чате), **карту сценария** (панель со связями) и **текстовый резерв** (журнал при техническом отказе).
- Persistence: просьба в `/opsx:explain` / согласие в `/opsx:explore` / согласие или прямая просьба в `/opsx:overview` не прерывает команду сессии.
- Chat Surface: одна строка итога без пути к файлу и без markdown-ссылки; без дампа узлов в чат. Глобальный скилл Canvas требует ссылку — в сессиях `/opsx:*` это требование **не** действует: успех — штатная кнопка среды.
- Отказ строить карту из-за модели запрещён: вызов картографа без `model=`.
- Выбор узла показывает эффект и доказательство в панели деталей. Файл открывается кнопкой этой панели. Запуск нового чата с панели запрещён.

## Self-check манифеста (картограф, пункты 1–6)

1. После обоих отсевов ≥4 узлов с `name`, `effect` и `evidence`? Аннотации в этот счёт не входят?
2. Каждый узел инцидентен ≥1 связи? У каждой связи `relation` из словаря, `label` и `evidence_ref`?
3. Порядок прохода подписан `follows`, а не причинным ярлыком?
4. Если в наборе только `follows`, `header.insight` не формулирует причинное утверждение о переходах?
5. Главный вид — не список/аккордеон без рёбер? Цепочка с подписями `follows` при отсутствии топологии — допустима.
6. Источник — только разрешённый (пройденные точки / журнал / текущий или указанный отчёт / один выбранный отчёт сессии описания)? Нет кода/SQL/«на что смотреть» / статусов «сейчас разбираем» в манифесте панели? Нет узлов-этапов поставки?
6a. Ответ на вопрос шапки складывается с полотна (расположение, связи, выбранный узел, аннотации с якорем и доказательством), а не только из текста шапки?
6b. Находка, которая меняет действие читателя, присутствует узлом, подписанной связью или аннотацией?
6c. Отрицательный факт, который меняет действие, поднят аннотацией с якорем и доказательством (не выдуманным ребром)?
6d. Аннотация не пересказывает шапку, не добирает порог, имеет якорь и доказательство? Аннотаций не больше двух?

## Self-check регистрации (родитель, пункты 7–8)

7. Путь файла панели не записан в артефакты ЗНИ и не напечатан в чат штатно? Файл вне git? Шаблон рисует граф, переключатель видов меняет раскладку, выбор узла показывает эффект и доказательство в панели деталей, файл открывается кнопкой этой панели, новый чат с панели не запускается?
8. Файл записал родитель напрямую (не дамп оболочки)? Проверка типов записи чистая, ноль ошибок (круг ремонта ≤2)? В чат — одна строка о готовности схемы, не ссылка и не телеграмма узлов?
8a. По записанному файлу читаются направление связей, легенда использованных типов, честные полосы (подпись = слой узлов, не ранг), выбран стартовый узел, нет стены карточек?
