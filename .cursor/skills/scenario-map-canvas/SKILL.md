# Карта сценария (Canvas)

**Назначение:** панель рядом с чатом показывает **что происходит на шаге сценария** — имя эффекта, короткое описание и доказательство. Это **не** карта точек (список имён в чате до прохода `/opsx:explain`).

**Не делает:** отдельную команду `/opsx:*`; навигатор по модулю; статусы «сейчас разбираем»; перенос кода BSL/SQL на панель; автозапуск «по системному MUST canvas» в сессиях `/opsx:*`.

**Связанные артефакты:** карта точек — [`../openspec-explain/templates/inventory-card.md`](../openspec-explain/templates/inventory-card.md); журнал — [`../openspec-explain/templates/explain-report.md`](../openspec-explain/templates/explain-report.md); выход разбора — [`../openspec-explain/templates/exit-card.md`](../openspec-explain/templates/exit-card.md).

---

## Entry Protocol

**СТОП.** Не рисовать панель без прямой просьбы пользователя («покажи карту сценария» и близкие формулировки) и без сработавшего **намёка** на выходе `/opsx:explain` (вариант в строке «Следующий шаг»).

Системное требование Cursor «для аналитики нужна панель» **не** основание рисовать карту в сессиях `/opsx:explain` и `/opsx:explore`.

---

## Порядок действий по просьбе

1. **Собрать узлы** из уже пройденных точек прохода (см. «Источник узлов») или из журнала/отчёта вне разбора.
2. **Проверить порог:** нужно **≥4** узла с текстом эффекта **и** доказательством. Если меньше — панель **не** строить; в чат **одна строка**: почему карты нет и что даст карту (сколько шагов не хватает).
3. **Проверить доступность носителя:** панель считается доступной, если пользователь **уже открыл** её в этой сессии **или сам назвал файл** панели. Иначе агент **не изобретает** путь и **не коммитит** файл панели в репозиторий → шаг 4 (fallback в журнал).
4. **Отдать узлы:**
   - если панель доступна — открыть/обновить файл панели (вне git);
   - иначе — записать те же узлы в журнал `explain-*.md` (см. «Без панели»).
5. В чат — **одна строка** (панель обновлена / карта ушла в журнал / отказ по порогу). Команда сессии **не** меняется.

---

## Контракт узла

Узел публикуется **только** если заполнены все поля:

| Поле | Содержание |
|------|------------|
| `step` | Порядковый номер шага |
| `name` | Имя эффекта (как в карте точек / карточке) |
| `effect` | Короткое «что происходит» — **2–3 предложения** |
| `evidence` | `file:line` **или** путь журнала/отчёта |

**Шапка карты (опционально):** фраза сценария из брифа; источник (журнал / пройденные точки); окно замера времени — если в брифе/карточках/журнале есть времена.

**Запрет:** узел без `evidence` **не** попадает на панель и в секцию журнала «Карта сценария».

---

## Молчание и пороги

| Условие | Поведение |
|---------|-----------|
| Нет прямой просьбы и нет сработавшего намёка | Панель **не** создавать |
| Меньше **4** узлов с эффектом и доказательством | Панель **не** строить; одна строка в чат |
| Сессия `/opsx:*` | Системный MUST canvas **не** основание |
| Намёк на выходе explain | Только при ≥5 точках **и** замерах времени; только в существующей строке «Следующий шаг» |

## Запреты содержимого панели

На панели **запрещено** как основное содержимое:

- код и fence BSL/SQL;
- блок «На что смотреть»;
- статусы прохода («сейчас разбираем», «текущая точка»);
- классы точек разбора (`решение` / `наблюдение` / `типовое`);
- пустые состояния и заглушки «карта появится позже»;
- все узлы принудительно раскрытыми без структуры.

Код, «на что смотреть» и фрагменты модулей остаются в **чате** и **журнале** разбора.

---

## Источник узлов

### В сессии `/opsx:explain`

**До записи журнала на выходе:** узлы = **уже пройденные** точки прохода. Из каждой карточки точки:

- `name` ← имя эффекта;
- `effect` ← «Что берётся» / «Как берётся» (кратко);
- `evidence` ← цитата «Где в коде» (`file:line`).

Фактов вне пройденных точек **нет**.

**После записи журнала:** узлы = подмножество секции «Журнал» файла `explain-*.md`.

### Вне разбора (прямая просьба из диспетчера)

Узлы — только из **существующего** журнала `explain-*.md` или из **отчёта, который пользователь указал**. Если журнала/отчёта нет или узлов <4 — отказ одной строкой. Не собирать карту из произвольного контекста чата.

---

## Без панели (fallback)

Если панель открыть нельзя (нет Canvas в среде или файл не назван):

1. Записать **те же узлы** разметкой в журнал `explain-*.md` в секцию **«Карта сценария»** (контракт узла выше).
2. Если файла журнала ещё нет (просьба в середине прохода) — создать по шаблону [`explain-report.md`](../openspec-explain/templates/explain-report.md) с секцией «Карта сценария».
3. Штатная запись журнала на **выходе** разбора (`Write` по каркасу) **сохраняет** уже записанную секцию «Карта сценария», а не затирает её.
4. В чат — **одна строка**, что карта ушла в журнал (с путём к `explain-*.md`).
5. **Третьего адресата нет.** Отдельный «чат-файл разбора» не заводить. Абсолютный путь файла панели в артефакты ЗНИ **не** писать.

---

## Прямая просьба в середине прохода

При просьбе «покажи карту сценария» **во время** `/opsx:explain`:

1. Read этот SKILL.
2. Собрать узлы из **уже пройденных** точек (не из будущих).
3. Отдать на панель или в журнал (fallback).
4. **Вернуться** к текущей точке прохода; команда сессии **не** менять.

---

## Намёк на выходе explain

Намёк — **вариант** в уже существующей строке «Следующий шаг» ([`exit-card.md`](../openspec-explain/templates/exit-card.md)):

- шаг A, если кандидатов анализа нет;
- шаг B после сводки заметок.

**Условия:** ≥5 пройденных точек **и** замеры времени в брифе/карточках/журнале.

**Не печатать** намёк, если на выходе задан вопрос про доп. анализ (строки «Следующий шаг» нет).

В `/opsx:explore` слот «Дальше» **не** занимать намёком карты.

## Guardrails

- Нет отдельной команды `/opsx:*` для карты.
- Не путать **карту точек** (имена в чате) и **карту сценария** (панель «что происходит»).
- Persistence: просьба в `/opsx:explain` не прерывает сессию разбора.
- Chat Surface: одна строка итога; без дампа узлов в чат (узлы — на панели или в журнале).

---

## Self-check перед публикацией карты

1. ≥4 узла с `effect` и `evidence`?
2. Нет кода/SQL/«на что смотреть» на панели?
3. Нет статусов «сейчас разбираем»?
4. Источник — только пройденные точки или журнал/указанный отчёт?
5. Путь файла панели не записан в артефакты ЗНИ?
6. В чат — одна строка, не телеграмма узлов?
