Миграция `tasks.md` в вертикальные срезы. Инструкция — **явное действие**, не авто-трансформация. Любое применение требует подтверждения пользователя по предложенному diff.

**Output style:** финальное сообщение после применения diff — шаблон **T-CONFIRM** из `.cursor/docs/opsx-output-style.md` §5.5: действие (что реструктурировано) → изменённые файлы (`tasks.md`, секция `## Slices` в `design.md`, `reports/migrate-to-slices-*.md`) → следующий шаг (`/opsx:verify <name>`). Diff-предпросмотр перед подтверждением — нумерованные списки по срезам (см. §4). Перед выводом — self-check-5 (§7).

## Входные данные

- `<change-name>` — активный change (`openspec/changes/<name>/`).
- Артефакты: `proposal.md`, `design.md`, `specs/**/spec.md`, `tasks.md`.

## Шаги

1. **Проверка применимости.**
   - Change активный (не в `openspec/changes/archive/`). Архивные — STOP: `vertical-slices.mdc` требует read-only для архивов.
   - `tasks.md` существует и содержит задачи (`- [ ]` или `- [x]`).
   - Если в `tasks.md` уже есть `# Срез S<N>` — WARN: «ЗНИ уже в slice-режиме. Миграция не требуется. Для корректировки структуры — `/opsx:extend` или ручная правка design.md `## Slices`.»

2. **Сбор контекста для архитектора.**
   - Прочитать `proposal.md`, `design.md` (особенно секцию `## Slices`, если есть), все `specs/**/spec.md` (Requirement / Scenario), `tasks.md`.
   - Собрать список уже выполненных задач (`[x]`).

3. **Вызов архитектора** (`Task(subagent_type="onec-code-architect", model=..., ...)`) по шаблону «Architect — slice restructuring» из `.cursor/skills/1c-agent-patterns/architect.md`:

   > Перед вызовом Task — **Task Pre-call Checklist** из `.cursor/rules/tool-name-guard.mdc` и таблица **`Task.model`** в `.cursor/rules/model-selection.mdc` (Primary и fallback на одном агенте).
   - Цель: перестроить задачи в `# Срез S<N>` структуру с метаданными и `S<N>.T<M>` приёмочными тестами.
   - Уже выполненные задачи попадают в первый срез S1 (или распределяются с пометкой `(уже реализовано)`).
   - Маркер `<!-- slice-gate -->` проставляется автоматически в конце каждого среза.
   - Обновить `## Slices` в design.md параллельно.

4. **Предъявление diff пользователю.**
   - Таблица «старая задача → новый срез».
   - Список новых `S<N>.T<M>` приёмочных тестов (acceptance) с краткой формулировкой.
   - Предупреждение при непривязанных задачах (архитектор не смог отнести к сценарию) — с рекомендацией пересборки или ручного распределения.
   - AskQuestion: [Применить] / [Отклонить] / [Пересобрать с уточнением].

5. **Применение (только после явного «Применить»).**
   - `Write`/`StrReplace` для `tasks.md` — полная замена.
   - `StrReplace` для секции `## Slices` в `design.md`.
   - **Не трогать** `specs/` в ходе миграции — это структурирование tasks, не изменение спецификации.

6. **Сохранение отчёта миграции.**
   - Путь: `openspec/changes/<name>/reports/migrate-to-slices-YYYY-MM-DD.md`.
   - Секции: исходное состояние (счётчики, структура), предложенная структура срезов, применённые правки, оставшиеся вопросы.

7. **Финальное действие.**
   - Вывести пользователю: «Миграция применена. Рекомендовано: `/opsx:verify <name>` — прогон нового tasks.md через QC (Slice Coherence) и Architect readiness.»

## Отказ / повтор

- Отклонение диffа — не применять правки, сохранить отчёт со статусом `aborted` и причиной.
- Повторный вызов допустим без ограничений (идемпотентно: если `# Срез` уже есть, шаг 1 остановит).
