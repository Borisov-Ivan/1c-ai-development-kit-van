# Антиэталон: жаргон и служебная таксономия (плохо)

Мотив: фидбек «класс пункта лишний», «гейт», «отсекается сообщением», «каша».

---

## Плохо — карта (не слать)

```markdown
**Карта разбора:** клик «Направить на подписание» → старт

1. Отказ для ДИ / СЗ — решение
2. Вызов сервера направления — наблюдение
…
8. Запись и старт БП — типовое (пропуск)

Типовые по умолчанию не разбираем полной карточкой (кроме явной просьбы или если критичны для соседних решений).

Подтвердить охват? — «да» / что убрать или добавить / сменить класс пункта.
```

**Почему плохо:** классы в каждой строке; заголовок про «клик → старт»; аббревиатуры без расшифровки; служебный абзац про протокол skill; просьба «сменить класс».

## Как надо — карта

```markdown
**Карта:** направление на подписание — что происходит после нажатия кнопки

1. Отказ для должностной инструкции и части служебных записок
2. Вызов сервера направления
…
8. Запись и старт бизнес-процесса (можно не разбирать)

Подтвердить список? — «да» / что убрать или добавить.
```

---

## Плохо — карточка (не слать)

```markdown
**Точка 1/9: отказ для ДИ / СЗ** · решение

**Зачем смотрим** — это первый гейт на клиенте: до сервера и создания БП часть предметов отсекается сообщением. Не путать с серверными проверками реквизитов/файлов — здесь только «этот вид документа сюда не пускаем».

**Указатель** — смысл в литералах «Должностная инструкция» / «Служебная записка» и в имени «Ким…» внутри ЭтоСЗ(); без совпадения подписанта СЗ через этот гейт не блокируется.

**Значимость** — смена вида или подписанта = правка конфигурации; для новой ветки копировать эти отказы as-is или выносить.
```

**Почему плохо:** класс в заголовке; `гейт` / `литерал` / `as-is` / «правка конфигурации»; «сообщением» без текста отказа; «не путать» без имени соседней точки по делу; голые ДИ/СЗ/БП.

## Как надо — фрагмент карточки

```markdown
**1/9. Почему для должностной инструкции и части служебных записок кнопка сразу отказывает**

**Зачем смотрим** — сразу после нажатия, ещё до сервера, код смотрит на предмет задачи. Для части документов пользователь видит отказ и дальше сценарий не идёт. Это не проверки реквизитов подписания и не проверка файлов «На подпись» — только «этот вид документа сюда не пускаем».

**На что смотреть** — зашитые названия видов «Должностная инструкция» / «Служебная записка» и ФИО подписанта в `ЭтоСЗ()`; если вид — служебная записка, но подписант другой, этот отказ не срабатывает.

**Почему важно** — поменять список запрещённых видов или особый случай с подписантом можно только правкой кода (или выносом в настройки).
```

(Текст отказа пользователю — процитировать из фрагмента кода, например: «Документ „Должностная инструкция“ не подписывается…».)
