# Entry-бриф (SSOT) — `/opsx:explain`

Уровень **B-explain**. Индекс в `.cursor/docs/templates/brief-card.md`. Бюджет: ≤6 заполненных слотов; скан ~30 сек.

**Бриф** = рамка сценария (какие операции / что понять).  
**Карта точек** = второй гейт *внутри* утверждённой рамки — не замена брифа.

---

## Слоты

| Слот | Обяз. | Смысл |
|------|-------|--------|
| **Сценарий** | да | Что делал пользователь / что в замере. Несколько операций — нумерованный список (≤3). |
| **Вопрос** | да | Что хотим понять; якорь прохода (не чеклист протокола skill). |
| **Варианты** *или* **Охват** | да | **XOR:** 2–3 взаимоисключающие рамки **или** уже ясный охват одним абзацем. |
| **Контекст** | опц. | Пути трассы / отчёта / change — маркированный список. |
| **Подтвердить?** | да | номер варианта / «да» (= вариант 1 при Вариантах) / уточнение. |

Пустые слоты не выводить. Пути — только в **Контекст**.

---

## HALT (не в чат-бриф)

| Запрещено | Почему |
|-----------|--------|
| **Цель**, **Источник**, **Решено, когда** | Устаревшие слоты; путают с процессом skill |
| Чеклист «карта → карточки → журнал» | Протокол агента, не цель заказчика |
| «Сейчас соберу карту…» в **Подтвердить?** | Достаточно «номер или да» |
| Сырой inventory / коды точек (`pav…`, M01…) **как замена Сценарию** | В карту точек / карточки; не вместо сценария |
| Полный список `path` в слоте **Охват** | Path (+ опц. процедуры) — только в **Контекст**; в **Охват** — UX-абзац |
| **Варианты** и **Охват** одновременно | XOR |
| Имена агентов, жаргон движка | как в `brief-card.md` |

**Разрешено (post-review / apply):** компактный UX-охват в **Охват** + маркированный список path в **Контекст** из `## Explain scope` (эталон C).

---

## Эталон A — замер с двумя операциями (рамка неочевидна)

```markdown
Бриф: направление на подписание (замер)

**Сценарий** — в одном замере две операции:
1. открыли задачу Исполнения (появилась кнопка «Направить на подписание»);
2. нажали кнопку — стартовал подпроцесс Исполнения по шаблону подписания.

**Вопрос** — как в коде устроены эти два шага: что зашито, что уже из данных/шаблона, что имеет смысл выносить в доп. настройки.

**Варианты**
1. Обе операции целиком — от открытия до старта и UX после старта.
2. Только открытие — шаблон и появление кнопки.
3. Только клик и старт — проверки, членство в рабочей группе, файлы, создание бизнес-процесса.

**Контекст**
- `temp/Замеры/Направление на подписание_TRACE_FULL.txt`

Подтвердить? — номер варианта (1–3) или уточните (например, «1, без типового заполнения шаблона»).
```

## Эталон B — рамка уже ясна из команды

```markdown
Бриф: направление на подписание — клик и старт

**Сценарий** — нажали «Направить на подписание» в задаче Исполнения; стартовал подпроцесс.

**Вопрос** — какие проверки и откуда берётся шаблон перед `Старт()`.

**Охват** — только операция клика: от клиентской команды до создания бизнес-процесса и сообщения/открытия формы; без разбора появления кнопки при открытии задачи.

**Контекст**
- `temp/Замеры/Направление на подписание_TRACE_FULL.txt`

Подтвердить? — «да» или уточните.
```

---

## Эталон C — после ревью / apply (prefill из `## Explain scope`)

```markdown
Бриф: разбор кода после ревью модуля проведения

**Сценарий** — завершили `/review` по diff модуля проведения и связанных процедур; замечания закрыты или выбран «только отчёт».

**Вопрос** — как устроены затронутые места: откуда берутся данные и где проходит основная ветка.

**Охват** — обработанный в ревью код проведения документа (несколько процедур в одном модуле и связанный общий модуль); без соседних непросмотренных подсистем.

**Контекст**
- `openspec/changes/my-change/reports/review-provedenie-2026-08-09.md`
- `src/.../Document.МойДокумент/Ext/ObjectModule.bsl`
- `src/.../CommonModules/МойОбщийМодуль/Ext/Module.bsl`

Подтвердить? — «да» или уточните (например, «только ObjectModule»).
```

Для огромного `/release-review` — вместо **Охват** слот **Варианты** (например: 1 — файлы с замечаниями; 2 — Tier1 change; 3 — весь scope расширения).

---

## Разбор ответа

| Слоты | Принимается |
|-------|-------------|
| с **Варианты** | номер (`1`…); «да» = вариант **1**; уточнение текстом |
| с **Охват** | «да» / уточнение |

После подтверждения — карта точек **только в утверждённой рамке** (`templates/inventory-card.md`).
