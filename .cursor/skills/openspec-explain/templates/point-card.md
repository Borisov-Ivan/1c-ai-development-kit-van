# Карточка точки (SSOT) — `/opsx:explain`

Один ход = одна точка. Бюджет чата: **15–35 строк**. Эталон голоса: `fixtures/voice-good-point.md`.

## Форма

```markdown
**Точка N/M: <имя>** · <решение | наблюдение | типовое>

**Зачем смотрим** — <1–2 предложения: роль в сценарии. Если похоже на другую точку — чем отличается.>

**Что берётся** — <какие данные/ссылки/признаки.>

**Как берётся** — <литерал / запрос / API / реквизит формы / настройка — одним-двумя предложениями.>

**Где в коде**

<один цитатный блок 8–25 строк в формате start:end:path>

**Указатель** — <какая строка / литерал / ветка несёт смысл; без метафор, которые нельзя найти в фрагменте.>

**Значимость** — <что будет при ошибке здесь; или почему оставляем as-is.>

<хвост по классу>
```

## Хвост по классу

### решение

```markdown
**Что решить**

- **A.** …
- **B.** …
- **C.** …   <!-- опционально -->

**Следующий шаг:** A, B или C (или уточните).
```

### наблюдение

```markdown
**Дальше:** «понял» / «дальше» — следующая точка; или уточните, если нужно углубить.
```

### типовое (только если показали полную карточку)

```markdown
Типовой механизм — вариантов постановки нет. **Дальше:** «понял» / «дальше».
```

## Правила сборки

1. **Зачем смотрим** обязателен; при двух РГ / двух похожих гейтах — явно «это не то же самое, что точка K».
2. Без фрагмента и без «Что/Как» карточку не отправлять.
3. **Указатель** не дублирует весь код: одна фраза, привязанная к видимой конструкции.
4. Второй цитатный блок — только вызов↔определение.
5. Не добавлять таблицы «всех настроек» и не пересказывать следующие точки.
6. После ответа на **решение** — в следующем сообщении первой строкой: `**Зафиксировано:** …`.
