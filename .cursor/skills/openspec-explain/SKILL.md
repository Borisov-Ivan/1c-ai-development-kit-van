# `/opsx:explain` — пошаговый разбор кода

**Ценность:** заказчик проходит значимый код **как глазами**, но внимание ведёт агент по логическим точкам — не построчный листинг и не свалка таблиц.

**Не делает:** правки BSL, правки `openspec/changes/` (без явной `/opsx:new` / `/opsx:extend`), обзор 3+ модулей «из интереса» (это explore + explorer).

## Уроки → HALT (обязательно)

| Симптом от пользователя | Правило |
|-------------------------|---------|
| «вывалил кучу» | До конца прохода **запрещены** сводные таблицы всех точек/настроек/вариативностей. Карта — отдельный короткий шаг без кода. |
| «не вижу кода / что берётся / как» | Карточка без пары «что/как» и без фрагмента кода — **не слать**. |
| «не вижу где …» | Обязателен блок **На что смотреть**: какая строка, зашитое значение или ветка несёт смысл (не метафора вроде «префикс», если это аргумент `СтрНачинаетсяС`). |
| «это же типовой механизм» | Agent-класс **типовое** — не спрашивать A/B. Полная карточка — только если пользователь явно попросил **или** точка критична для понимания соседних решений (тогда agent-класс **наблюдение**, без A/B). В карте — пометка `(можно не разбирать)`, без служебных абзацев про протокол. |
| «зачем ещё одна …» | До вариантов — блок **Зачем смотрим** и отличие от соседней похожей точки (назвать соседнюю по делу). |
| «класс пункта лишний» / «зачем решение·наблюдение» | Классы **не в чат** (ни в карте, ни в заголовке карточки). Только agent-only для выбора хвоста. |
| «жаргон / каша / непонятно про сообщение» | См. **HALT голоса** ниже. |

### HALT голоса (чат)

В карте и карточке **запрещены**:

- слова: `гейт`, `литерал` / `литералы`, `as-is`;
- голые аббревиатуры `ДИ` / `СЗ` / `РГ` / `БП` **без** расшифровки при первом упоминании в сообщении;
- «правка конфигурации» вместо «правка кода» (если речь о правке модуля);
- служебные оговорки протокола skill («полной карточкой не разбираем…», «сменить класс пункта»);
- «не путать с…» без имени соседней точки **по делу** (эффект / шаг сценария);
- слово «сообщение» / «отсекается сообщением» без **цитаты или пересказа** текста, который видит пользователь.

Идентификаторы 1С — в backticks с пояснением. Эталон плохого голоса — [`fixtures/voice-bad-jargon.md`](fixtures/voice-bad-jargon.md).

## Entry Protocol

До подтверждения брифа **запрещено:** `Task`, TodoWrite прохода, массовый Read `.bsl`.

**Допустимо:** Read этого SKILL и шаблонов; `Glob`/`Read` уже указанных пользователем отчётов/артефактов (≤3 файла) для брифа; `openspec list --json` если упомянут change.

### 1. Бриф (END TURN)

Уровень **B-explain**. SSOT формы и эталоны — [`templates/entry-brief.md`](templates/entry-brief.md); индекс — `.cursor/docs/templates/brief-card.md`.

| Слот | Обяз. |
|------|-------|
| **Сценарий** | да — действия пользователя / операции замера (нумерованный список при 2+) |
| **Вопрос** | да — что хотим понять (якорь прохода) |
| **Варианты** *или* **Охват** | да — XOR: выбор рамки **или** уже ясный охват |
| **Контекст** | опц. — пути трассы/отчёта |
| **Подтвердить?** | да |

**Бриф** согласовывает рамку сценария. **Карта точек** — второй шаг *внутри* рамки (после «да»).

**HALT в брифе:** слоты Цель / Источник / Решено когда; чеклист протокола skill; модули `pav…` / Mxx; «соберу карту» в хвосте.

Критерий конца прохода (журнал, решения) — внутренний, в §4 Выход; **не** слот брифа.

### 2. После подтверждения брифа — карта точек

1. Собрать упорядоченный список значимых точек **только в утверждённой рамке**:
   - из отчёта explore/trace (предпочтительно);
   - или 1× `Task` explorer/trace с узкой целью **только inventory** (якоря + agent-класс внутри, **без** классов и решений в чат).
2. Показать карту по [`templates/inventory-card.md`](templates/inventory-card.md) — **без кода, без A/B, без классов в строках**.
3. END TURN — пользователь подтверждает список (убрать / добавить пункты). Agent-класс при правке списка пересчитывается внутри.

**Классы точек (agent-only, не в чат):**

| Класс | Смысл | Хвост карточки |
|-------|--------|----------------|
| **решение** | влияет на постановку / новую ветку | A/B/(C) |
| **наблюдение** | важно понять; обычно оставляют как есть | «понял — дальше» |
| **типовое** | штатный ДО/платформа | в карте `(можно не разбирать)`; полная карточка — см. HALT выше |

Лимит карты в чате: ≤12 строк (см. `chat-output-budget.mdc`).

### 3. Проход (walk loop)

Один ход пользователя → **ровно одна** точка по [`templates/point-card.md`](templates/point-card.md).

Порядок — как в утверждённой карте. После ответа:

- решение → строка «**Зафиксировано:** …» → следующая точка;
- «понял» / «дальше» → следующая;
- «откати» / уточнение → правка журнала; при влиянии на ещё не пройденные — скорректировать карту вслух одной строкой;
- «хватит» / «собери итог» → выход.

**Бюджет карточки:** 15–35 строк чата (исключение из лимита decision ≤12). Цель — понимание, не ультрасжатие.

**Код в карточке:**

- один основной цитатный блок, ориентир **8–25 строк**;
- второй блок — только связка вызов→определение;
- длинный запрос — суть в прозе + 3–8 ключевых строк;
- не цитировать UI-шум и пустые ветки.

**Read оркестратора на карточке:** точечный `Read` известных `file:line` (± контекст) — **разрешён**. Самостоятельный обход 3+ модулей — **запрещён** → `Task` explorer (лимит ≤3 `Task` на тему, как в explore).

### 4. Выход

В чат — **журнал** пройденных решений/наблюдений (маркированный список; без таксономии «класс:» в подписях).

Затем **одно** из:

- «достаточно»;
- `/opsx:extend <change>` / `/opsx:new <name>` — если цель была пересборка постановки (при наличии решений — блок `## Постановка ЗНИ` по [`openspec-explore/templates/handoff-block.md`](../openspec-explore/templates/handoff-block.md));
- вернуться в `/opsx:explore` с обогащённым контекстом (если explain вызывали из середины исследования).

Handoff-файл — только по словесной просьбе («сохрани», «зафиксируй в файл») → `temp/explain-handoff-YYYY-MM-DD-<slug>.md`.

## Guardrails

- BSL write guard, XML write guard, APPLY GATE — без исключений.
- Не править `proposal`/`design`/`tasks` из explain — только предложить new/extend.
- Persistence: каждый ход сессии `/opsx:explain` проверяется по этому skill.
- Chat Surface: русский, без жаргона движка; идентификаторы 1С в backticks с пояснением; HALT голоса выше.

## Self-check перед карточкой точки

1. Одна точка `N/M`? Заголовок без суффикса класса?
2. Agent-класс выбран внутри; в чат не выведен?
3. Есть **Зачем смотрим** (и отличие от соседа, если похожи)?
4. Есть **Что / Как**?
5. Есть фрагмент + **На что смотреть** на несущую конструкцию?
6. Нет свалки других точек/таблицы всех настроек?
7. Хвост соответствует agent-классу (A/B только для **решение**)?
8. Бюджет 15–35 строк; код не «весь модуль»?
9. Нет запретов из **HALT голоса**? Отказ пользователю — с текстом, не «сообщением» в вакууме?

## Self-check брифа (перед END TURN)

1. Форма по `templates/entry-brief.md` (B-explain)?
2. Есть **Сценарий**, **Вопрос**, **Варианты** XOR **Охват**, **Подтвердить?**?
3. Нет Цель / Источник / Решено когда / чеклиста skill / модулей Mxx?
4. Эталон голоса — `fixtures/voice-good-brief.md`?

## Self-check карты

1. Без кода и без A/B?
2. ≤12 строк?
3. Нет классов `решение` / `наблюдение` / `типовое` в строках чата? (типовое — только `(можно не разбирать)`)
4. Нет служебных абзацев про протокол skill?
5. Рамка = утверждённый бриф?
6. END TURN до прохода?
