# Техпроект по файлу задания

Команда `/opsx:techproject`. На вход — файл частного задания. Чат не заменяет файлы и не является источником ответов. Подтверждения в чате до записи согласования нет.

Папка `template/Техпроект` не читается и этой командой не удаляется. Единственный справочник часов — `labor_standards.md` в этой папке навыка. Файлы `.cursor/skills/openspec-overview/**` не менять и не ждать «да» в чате перед записью текста.

## Entry Protocol

1. Прочитать этот `SKILL.md`.
2. Взять путь к файлу задания из сообщения. Нет пути — один вопрос, какой файл, и остановиться.
3. Имя выхода: имя файла задания без расширения. Рядом с заданием четыре пути:
   - `<имя>-вопросы.md`
   - `<имя>-согласование.md`
   - `<имя>-техпроект.md`
   - `<имя>-постановка.md`
4. Прочитать входящий файл. Не заменять его и не переписывать.
5. Если `<имя>-вопросы.md` уже есть — прочитать ответы и строку подтверждения из него. Чат не источник ответов.
6. Дыры и связь с уже сделанными изменениями взять протоколом исследования из раздела «Дыры и прошлые изменения». Отдельный чеклист дыр не использовать.
7. Первая запись, если строка подтверждения пустая: записать `<имя>-вопросы.md` и `<имя>-согласование.md`. Файлы техпроекта и постановки не создавать. Чат не ждёт подтверждения до записи согласования.
8. Строка подтверждения заполнена, когда после подписи «Подтверждение согласования:» есть непустая пометка. Пробелы и пустая строка — не пометка. Пустая строка второй вывод не открывает.
9. Если пометка есть и команду запустили снова — обновить те же `<имя>-вопросы.md` и `<имя>-согласование.md` и записать `<имя>-техпроект.md` и `<имя>-постановка.md`.
10. Повторный запуск читает тот же лист и обновляет те же пути. Копии с суффиксом версии не создавать.
11. Уже вписанный ответ сохраняется у вопроса с той же формулировкой и не затирается пустым местом. Уже заполненные во входящем файле строки часов не затираются.
12. Каталог задачи на разработку не создавать. Модули конфигурации не править.

## Запрет выдумывать

Не добавлять сведения, которых нет во входящем файле:

- технические имена объектов, полей и параметров;
- толкование неясной фразы;
- «логичные» детали и алгоритмы, которых в тексте нет;
- правила заполнения реквизитов;
- реквизиты и проводки для имени, которого в конфигурации нет.

Нет имени или шага — дыра в листе, не факт в согласовании и не строка в техпроекте. Имя из задания переносить как написано, если исследование нашло объект однозначно.

## Фильтр замечаний

Замечание попадает в лист, только если без него нельзя описать решение: неоднозначный алгоритм, нет источника данных, нет граничного случая, противоречие, объект не опознать.

Не попадают в лист: паспорт, срочность, приоритет, нумерация, стиль, дубль того, что уже ясно из текста.

## Дыры и прошлые изменения

Отдельного чеклиста дыр нет. Чеклист из `template/Техпроект` источником дыр не является. Отдельной сверки имён с каталогом выгрузки нет: путь вроде `src/…/cf/` вторым источником не используется.

Дыры и связь с уже сделанными изменениями ищутся тем же протоколом, что перед созданием задачи на разработку: `.cursor/skills/openspec-explore/SKILL.md`. Смотреть код и уже сделанные изменения. Результат класть в лист и в файл постановки.

Не копировать из исследования: вопросы по одному в чат, бриф с ожиданием «да» до записи файлов, создание каталога задачи.

Имя объекта или счёта, которого исследование не нашло в конфигурации, остаётся дырой в листе. Реквизит и проводка не выдумываются. Из-за одной такой дыры команда не останавливается: остальной текст задания описывается как есть.

## Лист вопросов

Файл `<имя>-вопросы.md`.

Если критичных пробелов нет, лист состоит из фразы и строки подтверждения:

```text
вопросов нет

Подтверждение согласования:
```

Иначе каждый пункт:

```markdown
### <формулировка вопроса>

- Вариант 1. …
- Вариант 2. …

Ответ:
```

Вариантов не меньше двух. Место для ответа обязательно. В конце такого листа та же строка:

```text
Подтверждение согласования:
```

Пометки пробелов внутри согласования лист не заменяют и не задают эти вопросы по одному в чат.

Пустая строка подтверждения означает, что файлы техпроекта и постановки не пишутся. Пользователь вписывает пометку сам и запускает команду снова.

## Каркас согласования

Файл `<имя>-согласование.md`. Голос как у обзора задачи: связная проза для людей, без обучения читателя и без приложения объектов. Разделов «архитектура», «алгоритм», «интеграции» нет.

Порядок:

1. Как сейчас.
2. Зачем.
3. Этапы ситуацией для людей.
4. Что появляется.
5. Как работает.
6. Что сознательно не делаем.
7. Как это закрывает задание.
8. Что согласовать.
9. Строки часов: работа, часы, обоснование вида работы словами.
10. Строка: подтверждение согласования переносится в лист вопросов.

Таблицы нормативов, диапазона, коэффициента, формулы и ссылки на справочник в этот файл, в лист, в техпроект, в постановку и в чат не попадают.

## Часы

Справочник только `labor_standards.md` рядом с этим навыком. Середина диапазона не берётся. Полная формула раздела 8 справочника не применяется. В лист, согласование, техпроект, постановку и чат не попадают таблица справочника, диапазон, коэффициент и формула.

Если во входящем файле уже есть строки часов — перенести их как есть, не пересчитывать и не затирать.

Если строк нет, собрать их по описанным работам:

- под описание подходят две строки справочника — вопрос в листе, более тяжёлую строку молча не выбирать, часы по этой работе не ставить;
- не подходит ни одна строка — вопрос в листе, часы по этой работе не выдумывать и не ставить, пока нет ответа;
- подходит одна строка: часы = (нижняя граница строки × коэффициент из шапки справочника) + сумма нижних границ всех факторов надбавки, названных в задании;
- надбавка равна нулю, если ни один фактор не назван;
- нижняя граница фактора — нижний процент этого фактора от нижней границы строки; на коэффициент эта доля не умножается;
- если в результате есть дробная часть, часы поднимаются до следующего целого; целое не меняется.

Если подтверждение в листе уже заполнено, а вопрос о часах по работе без строки справочника ещё без ответа: эта работа попадает в техпроект без часов, вопрос остаётся в листе, часы не выдумываются.

В документ попадают работа, часы (или пусто, пока нет ответа) и обоснование словами.

## Карта входящего файла

Читать входящий файл по его заголовкам, не подменяя файл бланком. Обычно это общие сведения, функциональные требования, описание процесса, отражение в учёте, отчёты и печатные формы, изменения объектов, карта проводок. Паспорт, срок и приоритет сами по себе дырой не являются. Раздел «технический проект» входящего файла не задаёт каркас согласования.

## Техпроект

Файл `<имя>-техпроект.md` пишется только при заполненном подтверждении в листе и повторном запуске, вместе с постановкой. Входящее задание не заменяется.

Таблицы, без текста процедур:

- объект, реквизит или табличная часть, тип, назначение;
- проводка (дебет, кредит, содержание) — только если она есть в задании;
- внедрение;
- откат;
- работа, часы, обоснование.

Выдуманного реквизита и проводки нет. Работа без ответа по строке справочника пишется без часов.

## Постановка

Файл `<имя>-постановка.md` пишется вместе с техпроектом, когда в листе есть непустая пометка подтверждения. Техпроект он не заменяет. Входящее задание не заменяет. Каталог задачи на разработку не создаётся, модули не правятся.

Каркас — блок для создания задачи на разработку:

```markdown
## Постановка ЗНИ

**Симптом:**

**Корневая причина:**

**Что менять:**

**Файлы:**

**Приёмка:**

**Связь с уже сделанными изменениями:**
```

Связь с уже сделанными изменениями берётся из того же протокола исследования, не из отдельного чеклиста. Если к этому моменту вопрос о часах по работе без строки справочника ещё без ответа, в техпроекте у этой работы часов нет, вопрос в листе сохраняется.
