| --------------------------------------------------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Простой документ без проводок                           | 12-16                   | Документ с базовой логикой заполнения, без формирования движений в регистрах                     |

- Наличие нескольких табличных частей (3+)

- Множественные проверки и контроли при проведении

## 6. МНОЖИТЕЛИ СЛОЖНОСТИ

Применяются к базовой оценке:

| Фактор сложности     | Множитель | Когда применять                                                                      |
| ----------------------------------- | ------------------ | -------------------------------------------------------------------------------------------------- |
| Простая задача         | 0.8-1.0            | Типовая задача без особенностей                                        |
| Средняя задача         | 1.0-1.3            | Задача с некоторыми сложностями                                        |
| Сложная задача         | 1.3-1.6            | Задача с множественными сложностями                                |
| Критическая задача | 1.6-2.0            | Задача с высокими рисками, нестандартная архитектура |

**Критерии сложности:**

- **Простая:** Стандартная задача, типовые объекты, без интеграций
- **Средняя:** Требуется интеграция с 2-3 объектами, есть нестандартная логика
- **Сложная:** Интеграция с 5+ объектами, нестандартные алгоритмы, высокая связность
- **Критическая:** Изменение архитектуры, риски регрессии, миграция данных

## 7. КОЭФФИЦИЕНТ ЗАМЕДЛЕНИЯ

**КРИТИЧНО:** Все базовые оценки из разделов 1-5 умножаются на коэффициент 

**Обоснование:** Фактически работа выполняется медленнее базовых нормативов из-за:

- Переключение контекста между задачами
- Непредвиденные сложности
- Согласования и коммуникация
- Отвлечения и текущие задачи
- Изучение существующего кода

---

## 8. ИТОГОВАЯ ФОРМУЛА РАСЧЕТА

```
Итого = ((Проектирование) + (Разработка × Множитель_сложности) + (Тестирование)) × коэффициент
```

**Где:**

- Проектирование = 10-20% от (Разработка + Тестирование)
- Разработка = сумма часов по всем объектам из нормативов
- Множитель_сложности = 0.8-2.0 (см. раздел 6)
- Тестирование = 30-40% от Разработки
- коэффициент = коэффициент замедления

## 9. ПРИМЕРЫ РАСЧЕТА

### Пример 1: Простой документ без проводок

**Задача:** Создать документ "Заявка на командировку" без формирования движений

**Расчет:**

- Базовая оценка документа: 12-16 часов → возьмем 14 часов
- Множитель сложности: 1.0 (простая задача)
- Разработка: 14 × 1.0 = 14 часов
- Тестирование: 14 × 0.3 = 4.2 ≈ 4 часа
- Проектирование: (14 + 4) × 0.15 = 2.7 ≈ 3 часа
- Согласование: 6 часов
- **Итого без коэффициента:** 14 + 4 + 3 + 6 = 27 часов
- **Итого с коэффициентом 1.5:** 27 × 1.5 = **40.5 ≈ 40 часов**

### Пример 2: Сложная доработка с интеграцией

**Задача:**

- Новый документ с проводками
- Доработка 3 существующих документов
- Механизм выгрузки XML

**Расчет:**

- Новый документ с проводками: 20 часов
- Доработка документа 1 (средняя): 6 часов
- Доработка документа 2 (средняя): 6 часов
- Доработка документа 3 (простая): 3 часа
- Механизм выгрузки XML: 5 часов
- **Итого разработка:** 40 часов
- Множитель сложности: 1.3 (интеграция с 3 объектами)
- Разработка с множителем: 40 × 1.3 = 52 часа
- Тестирование: 52 × 0.35 = 18.2 ≈ 18 часов
- Проектирование: (52 + 18) × 0.15 = 10.5 ≈ 10 часов
- Согласование: 8 часов
- **Итого без коэффициента:** 52 + 18 + 10 + 8 = 88 часов
- **Итого с коэффициентом 1.5:** 88 × 1.5 = **132 часа**

## 10. ПРАВИЛА ПРИМЕНЕНИЯ НОРМАТИВОВ

1. **Всегда начинайте с базовых оценок** из разделов 1-3
2. **Применяйте множитель сложности** если задача нестандартная
3. **Рассчитывайте проектирование и тестирование** как процент от разработки
4. **ОБЯЗАТЕЛЬНО умножайте на коэффициент** - это критично!
5. **Округляйте** итоговые значения до целых часов
6. **Документируйте обоснование** - какие нормативы использовались и почему
