# Шаблон: описание для согласования (customer overview)

Целевой тон — письмо функциональному архитектору / аналитику: связная проза, нумерованные списки. Не карточка OpenSpec, не выжимка `design.md`.

**Эталоны:**
- структура / тема ЭДО: `fixtures/golden-88781-overview.md`
- голос этапа (ситуация, не механизм): `fixtures/voice-good-stage.md`
- стиль HALT: `templates/style-checklist.md`

## Правила наполнения

| Секция | Откуда брать | Не брать |
|--------|--------------|----------|
| Как сейчас / Зачем | `proposal` Why; опц. исходное ТЗ | tasks, verification |
| Заголовок этапа | бриф → сценарий среза **пересказанный ситуацией** (не механизм, не `S1`, не имя change) | «Автомат…», «Алгоритм…», kebab change |
| Вводный абзац | тон как у «Как это работает» | «сервер проходит», «вызов при записи» |
| Что появляется | наблюдаемый эффект для админа/пользователя; зона («в расширении Павлик») — ремарка внутри пункта | инвентарь: «единый серверный алгоритм», «ядро», «перехват» как пункт №1 |
| Как это работает | Behavior / What Changes → прозой по смыслу ТЗ | таблицы Intercept Map, Decisions D* |
| В итоге | одна бытовая фраза | «Итого этап N:» |
| Не усложняем | Non-Goals, опц. срезы | «вне scope» жаргоном |
| Стык с ТЗ | исходный текст ТЗ vs выбранная этапность | пересказ ADR |
| Согласовать | Open questions + ключевые решения на языке эффекта | список задач `12.9` |

**Объём:** ориентир 60–120 строк на одну тему; мульти-ЗНИ — одна история, не сумма двух design.
