# Процесс подписания на основе согласования — технический проект

**ТЗ:** [ID#88781]  
**Зона:** расширение ДемоРасширение

---

Подписание (проверка юристами, подписание, регистрация) сейчас — шаблон **Исполнения**, старт кнопкой «Направить на подписание» в задаче Исполнения. Шаблоны для внутренних и исходящих зашиты в коде.

У Исполнения есть ограничения (отказ, условия по ходу, повтор, отзыв). Есть новый процесс на шаблоне **Согласования**. Нужен постепенный переход и настроечная модель: разные шаблоны, условия и аудитории — без правки конфигурации под каждый случай.

Два этапа.

---

## Этап 1. Система настроек

### Что появляется

1. **Регистр сведений правил кнопок процессов** — одна строка = одно правило (кнопка и условия применения).
2. **Вкладка «Кнопки процессов»** в доп. функциях Демо — ведение строк регистра. Не через доп. настройки «имя → значение».
3. **Выключатель** (доп. функция «Настраиваемые кнопки процессов»). Пока выключен — правила готовят на вкладке, на форму задачи не влияют. При выключенных доп. функциях целиком вкладка только на просмотр.

### Что хранится в строке правила

1. **Имя и представление кнопки** — технический идентификатор и заголовок; опционально цвет текста.
2. **Шаблон процесса** — Исполнение или Согласование; по типу шаблона стартует соответствующий БП.
3. **Условие по предмету** — ссылка на **Условия маршрутизации**. Пусто — фильтр не используется.
4. **Условие по задаче** — ссылка на **Условия задач**. Пусто — фильтр выключен. Оба заполнены — должны выполниться оба.
5. **Рабочая группа** — наименование РГ (`ПолучитьСоздатьРГПоНаименованию`). Пусто — без ограничения по РГ.
6. **Признаки** — активно; порядок на форме; показывать на форме задачи; задел «показывать в Задачи мне» (список в первой поставке не трогаем).

---

## Этап 2. Кнопки и применение настроек

### Показ кнопок

На форме задачи Исполнения после открытия:

1. Доп. функция выключена — кнопок из регистра нет.
2. Включена — для каждого активного правила с признаком «на форме задачи»: пользователь в РГ (если задана); условие предмета пусто или истинно; условие задачи пусто или истинно; шаблон заполнен; на форме ещё нет команды с таким именем.
3. Подходящие правила — кнопки в группе «Направить на подписание». Порядок — из настройки.

### Нажатие кнопки

Как у текущей «Направить на подписание», шаблон — из правила:

1. Проверки (ДИ/СЗ, файлы, блокировки) — по смыслу текущей кнопки.
2. Не стартуем повторно, если по предмету уже есть незавершённый процесс **по тому же шаблону** из правила.
3. Старт синхронно: Исполнение или Согласование по типу шаблона; заполнение — `ЗаполнитьПоШаблонуИПредмету`.
4. Для пользователя: первая задача «ответственный / подготовить к подписанию» — открываем её; иначе — дерево процессов; текущую задачу закрываем.

Кнопку «Направить на подписание» можно оставить (старые шаблоны Исполнения). Правило с тем же техническим именем команды на форму не дублируем. Перенос зашитой логики в регистр — отдельным шагом.

### Что не усложняем в первой поставке этапа 2

1. Показ в «Задачи мне» — поле в настройках можно заложить, код списка — позже.
2. Шаблоны кроме Исполнения и Согласования — вне первой поставки.
3. Правка только в расширении Демо.

---

## Как это закрывает исходное направление

В ТЗ: шаблон, РГ эксперимента, при условиях стартовать Согласование иначе старую логику; затем настроечная таблица.

Порядок поставки:

1. Сначала регистр и форма настройки — модель «разные шаблоны для разных случаев».
2. Затем кнопки и применение — в том числе эксперимент ЭДО: строка с шаблоном Согласования, условием маршрутизации и РГ.

Условие «внутренний / договорная документация / акт» — данные элемента Условия маршрутизации, не ветки в модуле кнопки. Выключатель доп. функции — откат к прежнему поведению без кнопок из регистра.

---

## Что требуется согласовать

1. Сначала РС + вкладка, затем показ кнопок и старт по правилам.
2. Условия предмета и задачи — через справочники условий ДО, без видов документов в коде.
3. РГ по наименованию (не через Полномочия).
4. Несколько правил / кнопок — норма; зашитая кнопка подписания может жить параллельно до переноса в таблицу.
5. «Задачи мне» — не обязательный объём первой поставки кнопок.
