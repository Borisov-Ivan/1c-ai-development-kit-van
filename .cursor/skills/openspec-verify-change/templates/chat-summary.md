# Шаблон чата `/opsx:verify` — бинарный вердикт

Использовать **один** из двух вариантов ниже. Не смешивать. Не добавлять блоки «Решение N», «Как ответить», «1a / 2b».

Главный вопрос разработчика: «**могу ли я безопасно запустить `/opsx:apply`?**» Ответ — бинарный (GO / NO-GO), формулировка вердикта — `templates/verdict-card.md`.

---

## Тихий вариант — `silent_ok` (фильтр новизны прошёл, новый файл отчёта не создаётся)

```
ЗНИ: <change-name> — Готово к apply.

С прошлой проверки от <дата из последнего reports/verification-*.md> ничего не изменилось по снимку (<accepted_tasks: ровно те же; design / tasks / spec / proposal не правились; challenge актуален>).

По плану — <одна следующая команда: `/opsx:apply <name>` или статус активного среза>.

Подробности в прошлом отчёте: `openspec/changes/<name>/reports/verification-<...>.md`.
```

Запреты для тихого варианта:

- Не дописывать блоки «Что нашли», «Сама поправила», «Что обсудим» — для тихого пути они пусты.
- Не создавать новый файл `verification-YYYY-MM-DD.md` для тихого пути.
- Не упоминать «фильтр новизны» / «snapshot» / «last_challenge_at» как термины движка в чате — переформулировать своими словами («ничего не изменилось», «постановка та же»).

---

## Информативный вариант — есть находки, автоправки или развилка

```
ЗНИ: <change-name> — <Готово к apply | На обсуждение>: <одна фраза сути>.

Что нашли:
- <одна строка на новую находку: «что случилось / почему важно для apply»>
- <…>
(пропустить блок, если новых находок нет)

Сама поправила:
- <что сделано автоматически + кратко где>
- <…>
(пропустить блок, если автоправок не было)

Что обсудим:
<один разговорный блок развилки по `templates/card-decision.md` — параграфы, без кодов выбора>
(только при NO-GO; при GO с замечаниями к сведению — использовать секцию «По плану» или «Подробности»)

По плану (известные открытые вопросы с owner-задачей в постановке, не блокирующие):
- <одна строка: тема → закроется в S<N>.<M> или в задаче из tasks.md>
(пропустить блок, если таких нет)

Подробности: `openspec/changes/<name>/reports/verification-YYYY-MM-DD.md`
```

Запреты для информативного варианта:

- Первая строка — **только** одна из двух фраз (`Готово к apply` / `На обсуждение`) с короткой сутью. Никаких «PASS», «verdict: GO», номеров severity или режима verify.
- Один блок «Что обсудим» = одна развилка. При двух и более развилках после `templates/card-decision.md` — два разговорных блока подряд, без объединения «или».
- Не выводить «N CRITICAL, M WARNING» в чат — это YAML отчёта.
- Не упоминать «Layer 1/2/3/4/5», «design-challenge», «task-readiness» как пользовательскую лексику. В чат — суть («согласованность плана», «независимый аудит», «реализуемость»), а имена слоёв — в файл отчёта.

При открытых темах после «Что обсудим» — последняя строка может быть формулировкой вроде «Напишите своими словами, какой путь ближе, или предложите свой». Без меню.

---

## Анти-пример

Требовать «ответьте `1a` или `2b`», отправлять за развилкой только в файл («подробности в отчёте»), показывать имя режима verify пользователю — **запрещено**.
