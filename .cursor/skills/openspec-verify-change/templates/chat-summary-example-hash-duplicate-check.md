# Пример тонкого чата verify (эталон)

ЗНИ: `hash-duplicate-check-before-kontur-api`. Полный отчёт и карточки — в `openspec/changes/hash-duplicate-check-before-kontur-api/reports/verification-legacy-mixed-2026-05-13.md`. Ниже — как должен выглядеть **чат** по `chat-summary.md` (фактуальное содержание на дату отчёта).

---

**ЗНИ:** `hash-duplicate-check-before-kontur-api`

**Готовность: Не готово** — целевой контроль дайджеста перед отправкой в облачный сервис по новой спецификации ещё не реализован в коде; часть отметок в задачах относится к старому контракту.

**Что не так:**
1. В коде ветки режима хешей всё ещё два подряд одинаковых расчёта там, где по постановке нужна одна цепочка «расчёт для запроса + отдельная проверка утилитой» до первого обращения к сервису.
2. Закрытые пункты плана про «два одинаковых расчёта» не подтверждают новую спецификацию; ключевая доработка по новому контракту в задачах ещё открыта.
3. В постановке и фактическом устройстве платформенной обёртки расчёта нужно явно согласовать, что считается «независимой проверкой», чтобы исполнитель не ошибся в глубине защиты.

**Решение 1 — Честная картина прогресса в задачах и спецификации:**
- `1a` — `/opsx:extend hash-duplicate-check-before-kontur-api --from-verify openspec/changes/hash-duplicate-check-before-kontur-api/reports/verification-legacy-mixed-2026-05-13.md`: привести отметки задач и текст постановки в соответствие со спекой (убрать ложную «готовность» по старому контракту, явно привязать приёмку к новым задачам и проверкам) → меняются только артефакты ЗНИ до правки кода.
- `1b` — Принять как есть → высокий риск ошибочной приёмки и споров при ревью постановки.

**Решение 2 — Что считать «независимой проверкой» перед реализацией ключевой задачи по коду:**
- `2a` — Тот же `/opsx:extend … --from-verify …`, зафиксировать в постановке **вариант A**: два последовательных прохода утилиты на тех же байтах считаются допустимой независимой проверкой; выровнять формулировки целей и обоснование → проще согласовать текст и код.
- `2b` — Тот же `/opsx:extend … --from-verify …`, зафиксировать **вариант B**: нужен второй алгоритмический канал помимо текущей обёртки → тяжелее реализация и проверка совпадения дайджеста с ожиданиями сервиса.
- `2c` — Отложить выбор → реализация по задаче переписывания логики останется заблокированной до решения.

**Решение 3 — Формулировка задачи 5.3 в плане (только текст):**
- `3a` — Вручную уточнить текст задачи **5.3** в `tasks.md` на самодостаточную формулировку (паритет с типовой выгрузкой после выполнения переписывания лога), затем `/opsx:verify hash-duplicate-check-before-kontur-api` → не меняет код и поведение до реализации.
- `3c` — Отложить → раздел «План» остаётся менее ясным для ревью.

**От вас нужно:**
1. Выберите по каждому решению вариант `Na` / `Nb` / `Nc` и напишите в чат одну строку (например `1a, 2a, 3a`).

**Как ответить:** одна строка в чате, например `1a, 2a, 3a` или `1a, 2b, 3c` — номера должны совпадать с блоками **Решение 1–3** выше.
