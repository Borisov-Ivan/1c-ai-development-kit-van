# Шаблон бинарного вердикта `/opsx:verify`

Используется в `## Executive Summary` файла отчёта `reports/verification-YYYY-MM-DD.md` (первый абзац) **и** в чате (первая строка ответа пользователю).

Главный вопрос разработчика: «**могу ли я безопасно запустить `/opsx:apply`?**» Ответ обязан быть бинарным.

---

## Вариант 1 — GO (можно apply)

```
ЗНИ: <change-name> — Готово к apply.
```

Опционально, если на пути произошли автоправки или есть нюанс к сведению (одна строка):

```
ЗНИ: <change-name> — Готово к apply. <Что важно знать одной фразой>.
```

Запреты:

- Не использовать формулировки «PASS», «verdict: GO», «slice-pre / pre-apply» в чате — это в YAML отчёта.
- Не указывать счётчики «N CRITICAL / M WARNING» в строке вердикта.

---

## Вариант 2 — NO-GO (на обсуждение)

```
ЗНИ: <change-name> — На обсуждение. <Что мешает запустить apply одной фразой>.
```

«Что мешает» — суть, не имя слоя/шага. Примеры:

- «На обсуждение. Замечание: предложенный путь не покрывает один из сценариев из постановки.»
- «На обсуждение. Замечание: альтернативный путь даёт ту же цель меньшим объёмом изменений — стоит сравнить.»
- «На обсуждение. Замечание: задача S2.1 не однозначна, реализатор будет угадывать.»

Запреты:

- Не использовать «REJECT», «CHALLENGE», «верный путь», «нужен пересмотр» — это лексика движка.
- Не дублировать в первой строке весь блок «Что обсудим» — он идёт ниже.

---

## Связь с дальнейшим сообщением

После строки вердикта — короткие блоки по `templates/chat-summary.md`:

- **GO** + автоправки → блок «Сама поправила» (1–3 строки) и одна строка пути к отчёту.
- **GO** без автоправок → одна строка с путём к отчёту и одна строка «По плану» (если есть).
- **NO-GO** → один разговорный блок развилки по `templates/card-decision.md` + одна строка пути к отчёту.

В файле отчёта первый абзац `## Executive Summary` начинается с одной из двух фраз («Готово к apply.» / «На обсуждение.») и далее раскрывает причину в 1–3 предложениях.
