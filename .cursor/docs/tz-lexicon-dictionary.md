# Словарь лексики ТЗ

ТЗ — документ для согласования с функциональным заказчиком. Язык — строгий технический русский: только нормативная терминология и формулировки, понятные заказчику без погружения в проект. Англицизмы, жаргон и несуществующие слова недопустимы.

Пополняется из `/opsx:doc-tz` (ревью архитектора обнаруживает → оркестратор предлагает добавить → пользователь подтверждает).

## Терминология объектов метаданных 1С

Типовые ошибки в ТЗ: калька с англ. *catalog* или разговорное «каталог» вместо официального названия вида объекта конфигурации. Образец нормативной лексики — `.cursor/docs/standard/std-01-metadata.md` (не требуется читать целиком при каждой генерации ТЗ).

| Некорректно / разговорно | Правильно | Примечание |
|--------------------------|-----------|------------|
| каталог (в значении объекта метаданных типа **Catalog**) | справочник | Например: «расширение каталога», «объект каталога» → **справочник**. Не путать с «каталогом» как **папкой** в ФС или в структуре репозитория; в тексте ТЗ для заказчика пути к файлам проекта не используются. |

## Grep-паттерны

Готовые regex для механической проверки в `/opsx:verify` (шаг 7.8, Lexicon check).
При добавлении слова в таблицу — обновить паттерн.

Для терминологии 1С **не** добавлять голое слово «каталог» — возможны ложные срабатывания. Используются только **контекстные** фрагменты типичной ошибки (см. таблицу выше). Фрагмент `каталог\w*\s*[«"]` ловит падежные формы перед именем объекта в кавычках (например «каталог «…»», «каталога «…»»).

```
диспатчер|чекбокс|checkbox|скоуп|\bscope\b|фича|\bfeature\b|\bflow\b|флоу|деплой|\bdeploy\b|\bUI\b|\bimpact\b|\bMVP\b|per-action|prerequisite|\badopt\b|endpoint|хэндлер|\bhandler\b|коллбэк|\bcallback\b|респонс|\bresponse\b|реквест|\brequest\b|расширени[ея]\s+каталога|каталог\w*\s*[«"]|step-by-step|степ-бай-степ|\bTier\b|когерентн\w*|low[- ]confidence|\bcapability\b|checkpoint
```

**Примечание про Standard / Lite / Full.** В таблице эти метки указаны как запрещённые «как метки объёма verify», но в regex **не добавлены** — слишком общие, дают ложные срабатывания (имя продукта, обычное слово в ТЗ). Ловятся ревью архитектора по смыслу.

Механическая проверка **не заменяет** смысловое ревью; остальные нарушения терминологии 1С — по таблице «Терминология объектов метаданных 1С» и ревью архитектора при `/opsx:doc-tz`.
