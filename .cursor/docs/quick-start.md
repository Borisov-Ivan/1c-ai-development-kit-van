# Quick start — kit-van

Минимальный маршрут после копирования `.cursor/` + `AGENTS.md` в проект 1С. Здесь же — таблицы сценариев и команд (в проект они едут вместе с `.cursor/`).

Как устроен репозиторий kit, ветки и обновление поставки — корневой [`README.md`](../../README.md) (в рабочий проект 1С не копируется). Поставка: [kit-template-workflow.md](./kit-template-workflow.md). Вопросы: [faq-kit.md](./faq-kit.md).

## 1. Поставка

Скопируйте в корень проекта:

- каталог `.cursor/`
- файл `AGENTS.md`

Reload Window в Cursor. Папку `openspec/` из репозитория kit **не** копируйте: в проекте 1С её создаёт `/init-project`.

## 2. Как идём

Не каждая правка требует полной ЗНИ. Сначала выбирают маршрут:

| Маршрут | Когда | Что делать |
|---------|--------|------------|
| Правка документации | Опечатка или уточнение в docs / rules / skills, без кода в `src/` | Править напрямую, без ЗНИ |
| Малый фикс кода | **Один** файл `.bsl`, очевидная правка, без новой архитектуры | Короткий путь без полной ЗНИ — только с вашего явного согласия |
| Полный цикл | Новая возможность, форма или макет, несколько модулей, неочевидный дефект | Разобрать → завести ЗНИ → проверить постановку → сделать в коде → закрыть |

С малого фикса уходят в полный цикл, если появляются: форма или макет, новый общий API модулей, блокировки или права, неочевидная причина бага.

Полный цикл в двух словах:

```text
разобрать → завести ЗНИ → проверить постановку → сделать в коде (по срезам) → закрыть
```

**Срез** — кусок работы с понятной приёмкой: сделали → вы проверили в базе → приняли → идём дальше.

**Единый вход разбора** — `/opsx:explore`: вопрос, дефект, сырой текст или скрины заказчика, идея. Отдельных команд «нормализовать запрос» или «отладка в ЗНИ» нет — всё через explore (при уже открытой ЗНИ разбор причины пишется в артефакты change).

Подробные правила выбора маршрута — в `.cursor/rules/task-triage.mdc`.

## 3. Типовые сценарии

| Ситуация | Команды |
|----------|---------|
| Вопрос «как устроено», без доработки | `/opsx:explore` → ответ в чате, ЗНИ не нужна |
| Дефект или новая возможность | `/opsx:explore` → `/opsx:new` → `/opsx:verify` → `/opsx:apply` (срезы) → снова проверить при необходимости → `/opsx:archive` |
| Сырой текст или скрины от заказчика | `/opsx:explore` → затем new при необходимости |
| Ошибка внутри уже открытой ЗНИ | `/opsx:explore` → дописать постановку (`/opsx:extend`) → verify → apply |
| Управляемая форма | Как полный цикл; на `/opsx:new` вопрос режима формы **не всегда**: только модуль и разметку не трогают — вопроса нет, в карточке сразу программно; разметка или неясность — вручную (по умолчанию), со скриптом или только кодом модуля. Макет (печатная форма) на new **не** спрашивается — политика макета на `/opsx:apply` |
| Малый фикс `.bsl` | Без ЗНИ, только если вы согласились на короткий путь; иначе — полный цикл |
| Сохранить сессию и уйти | `/session-save` → новый чат → `/session-restore` (реализацию запускаете сами командой apply) |
| Краткая ретроспектива сессии | `/session-retro` (заметки в `temp/`; без apply) |

Разбор замеров в базе и гипотез — через explore и доработку постановки, а не серией полных `/opsx:verify`.

## 4. Команды

| Зачем | Команда |
|-------|---------|
| Разобрать вопрос, дефект, сырой запрос или идею | `/opsx:explore` |
| Пошаговый разбор значимого кода | `/opsx:explain` |
| Описание проекта для согласования с ФА/заказчиком | `/opsx:overview` |
| Завести или дозавершить ЗНИ | `/opsx:new <имя>` |
| Посмотреть, где сейчас ЗНИ | `/opsx:status <имя>` |
| Проверить, можно ли идти в код | `/opsx:verify <имя>` |
| Дописать требования в ЗНИ | `/opsx:extend <имя>` |
| Реализовать задачи в коде | `/opsx:apply <имя>` |
| Закрыть и сохранить итоги ЗНИ | `/opsx:archive <имя>` |
| Точечное ревью кода | `/review` |
| Предрелизное ревью | `/release-review` |
| Сохранить / восстановить / ретро заметки сессии | `/session-save`, `/session-restore`, `/session-retro` |
| Первичная настройка проекта | `/init-project` |
| База знаний вне ЗНИ | `/opsx:knowledge-add`, `/opsx:knowledge-init`, `/opsx:knowledge-audit` |
| Перенести требования в общие specs без закрытия ЗНИ | `/opsx:sync` |
| Закрыть несколько ЗНИ пакетом | `/opsx:bulk-archive` |

Индекс якорей — в корневом `AGENTS.md`.

## 5. Формы и макеты

На ЗНИ с **управляемой формой** `/opsx:new` спрашивает режим не всегда. Если правят только модуль и разметку не трогают — выбора из трёх нет, в карточке сразу программно. Если есть разметка или способ неясен — вопрос по-русски: **вручную** / **автоматически** (правки Form.xml в репозитории) / **программно**. Пустой ответ на заданный вопрос → вручную (`form_mode: manual`). Макет на new **не** спрашивается. Подробнее: `.cursor/rules/forms-mxl-mode-gate.mdc`. FAQ: [faq-kit.md](./faq-kit.md).
