# FAQ — kit-van

Кратко по частым вопросам. Детали — в `AGENTS.md` и связанных docs.

## explore vs new

- **`/opsx:explore`** — разобрать симптом, вопрос, идею; для дефекта в конце — блок «Постановка ЗНИ» в чате.
- **`/opsx:new`** — создать артефакты ЗНИ (proposal / design / tasks / specs). Если уже есть постановка из explore — передать её в new.

Не создавайте ЗНИ «на всякий случай» из explore без подтверждения маршрута.

## Mode Gate (формы / макеты)

На `/opsx:new` с формой или макетом — отдельный вопрос **по-русски** (канон в `forms-mxl-mode-gate.mdc`):

| В чате | Смысл | В proposal (`artifact_mode`) |
|--------|--------|------------------------------|
| **вручную** (по умолчанию) | Правки в Конфигураторе + выгрузка; агент не пишет XML | `manual` |
| **автоматически** (через skill) | XML только через skill (`1c-mxl` / `1c-forms` compile·edit) | `assisted` |
| **программно** | UX через модуль формы / код заполнения; Form.xml/Template.xml не на compile | `bsl-only` |

Пустой ответ / «да» → вручную → `manual`. «Заимствовать объект в расширение» — всегда блокер человеку.

## Поставка шаблона

Копируются `.cursor` + `AGENTS.md`. ЗНИ эволюции kit ведутся на ветке шаблонного репо; папку `openspec/changes/` в main потребителей не мержат. См. [kit-template-workflow.md](./kit-template-workflow.md).

## session-restore и apply

`/session-restore` только показывает заметки и **предлагает** команду. Сам apply / writer **не** запускает.

## «Замер → вывод» vs verify

Цикл гипотез по замерам ИБ / опровержению рычага — через `/opsx:explore` + при необходимости `/opsx:extend`, **не** серией полных `/opsx:verify`. Verify проверяет исполнимость **зафиксированного** плана. Малый фикс vs полный цикл — `.cursor/rules/task-triage.mdc`.

## Кейсбуки vs вендорские стандарты

- Кейсбуки: `.cursor/docs/casebooks/`
- Вендор `std-*`: `.cursor/docs/standard/`

Это разные полки (D2).
