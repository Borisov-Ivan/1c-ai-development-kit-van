# FAQ — kit-van

Кратко по частым вопросам. Детали — в `AGENTS.md` и связанных docs.

## explore vs new

- **`/opsx:explore`** — разобрать симптом, вопрос, идею; для дефекта в конце — блок «Постановка ЗНИ» в чате.
- **`/opsx:new`** — создать артефакты ЗНИ (proposal / design / tasks / specs). Если уже есть постановка из explore — передать её в new.

Не создавайте ЗНИ «на всякий случай» из explore без подтверждения маршрута.

## Режим без API (`-noapi`)

Чтобы следующие дорогие вызовы шли на модели чата, напишите в любом сообщении `-noapi` или `--noapi`. Выключить — `-api` или `--api`. Новый чат снова начинается «с API».

Это **не** пропуск архитектора: `-noapi` не заменяет `--skip-architect` и не создаёт `.gate-override.yaml`. Разбор постановки остаётся, только на модели чата.

Ключ в чате пишет **человек**. После лимита платных моделей режим «без API» включается сам по памяти сессии — ключ в чат при этом не появляется.

Поэтому после лимита оркестратор **не** печатает `-noapi`: токен — слово пользователя, а не сигнал сбоя. Что дальше работа идёт на модели чата, говорит каноническая строка «дорогие модели недоступны — дальше на модели чата».

## Режим формы (на `/opsx:new`)

Вопрос поставки формы задаётся **не всегда**. Если в ЗНИ правят только модуль формы и разметку не трогают — выбора из трёх нет, в карточке сразу программно. Если есть разметка или способ неясен — вопрос **по-русски** (канон в `forms-mxl-mode-gate.mdc`); пустой ответ на **заданный** вопрос — вручную. Макет (Template/MXL) на new **не** спрашивается (политика макета — на apply).

| В чате | Смысл | В proposal (`form_mode`) |
|--------|--------|------------------------------|
| **вручную** (по умолчанию) | Правки в Конфигураторе + выгрузка в src | `manual` |
| **автоматически** | Правки Form.xml в репозитории | `assisted` |
| **программно** | UX в модуле формы; Form.xml не правим | `bsl-only` |

Пустой ответ / «да» на **заданный** вопрос → вручную → `manual`. «Заимствовать объект в расширение» — всегда блокер человеку.

## Поставка шаблона

Копируются `.cursor` + `AGENTS.md`. Specs, ADR и ЗНИ эволюции kit живут на `develop`; на `main` — только шаблон. См. [kit-template-workflow.md](./kit-template-workflow.md).

## session-save / restore / retro

- **`/session-save`** — заметки в `temp/session-notes.md` для продолжения в другом чате.
- **`/session-restore`** — только читает заметки и **предлагает** команду. Сам apply / writer **не** запускает.
- **`/session-retro`** — краткая ретроспектива в `temp/session-retro-*.md`; без apply.

## «Замер → вывод» vs verify

Цикл гипотез по замерам ИБ / опровержению рычага — через `/opsx:explore` + при необходимости `/opsx:extend`, **не** серией полных `/opsx:verify`. Verify проверяет исполнимость **зафиксированного** плана. Малый фикс vs полный цикл — `.cursor/rules/task-triage.mdc`.

## Кейсбуки vs вендорские стандарты

- Кейсбуки: `.cursor/docs/casebooks/`
- Вендор `std-*`: `.cursor/docs/standard/`

Это разные полки (D2).
