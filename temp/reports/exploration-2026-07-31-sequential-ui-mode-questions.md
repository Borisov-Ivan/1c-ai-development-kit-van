# Exploration: UX двойного вопроса (маркер + форма/макет)

**Дата:** 2026-07-31  
**Профиль:** explore-question (kit UX)  
**user-goal:** Вопросы только по одному; форма и макет — раздельно и предметно на этапе дизайна.

## Для заказчика

1. Два вопроса в одном экране — не задумано как норма: Metadata Gate уже требует STOP и «не подмешивать другие решения», Mode Gate — «отдельный» и «не смешивать с Metadata». В скрине оркестратор всё равно выдал два `AskQuestion` в одном ходе — инвариант «один вопрос → ответ → следующий» не закреплён жёстко (нет END TURN между 1.5 и 1.55).
2. Склейка «форма/макет» — задумана: один `artifact_mode` на Form.xml и Template.xml, один текст вопроса. Apply уже различает пути Form vs Template и маркеры `[mxl:…]`, но proposal хранит один режим — смешанный кейс (макет вручную, форма программно) выразить нельзя.
3. Frontload (шаг 1.56) тянет Mode Gate рано, рядом с маркером; заказчик хочет предметные вопросы, когда на дизайне ясно, что именно трогаем (форма / макет / оба).

## Свод (доказательства)

| Утверждение | Где |
|-------------|-----|
| Metadata: один AskQuestion только про описание; STOP до ответа; запрет подмешивать другие решения | `openspec-new-change` §1.5 |
| Mode Gate: «отдельный вопрос», «Не смешивать с Metadata Gate» | `forms-mxl-mode-gate.mdc` §Триггеры |
| Формулировка вопроса: «форму/макет» одним блоком | `forms-mxl-mode-gate.mdc` §Формулировка |
| Один `artifact_mode` в proposal | `forms-mxl-mode-gate.mdc` §Запись; new §1.55 |

| Apply различает Form vs Template; `[mxl:assisted\|manual]` | `openspec-apply-change` Task Dispatch; `1c-mxl/SKILL.md` |

## Рекомендуемое решение (для ЗНИ kit)

1. **Инвариант одного вопроса:** после любого `AskQuestion` / текстового выбора — END TURN; следующий гейт только после ответа. Запрет ≥2 `AskQuestion` в одном сообщении (new + brief-card Metadata).
2. **Разделить режимы:** вместо одного `artifact_mode` — `form_mode` и `layout_mode` (`manual` | `assisted` | `bsl-only` | `n/a`); вопрос задавать только если артефакт в scope.
3. **Когда спрашивать:** не вместе с Metadata; при формировании design (когда ясно Form / Template / оба) — по одному вопросу. Frontload 1.56 — «собрать до apply», не «в одном ходе с маркером».
4. **Совместимость:** legacy `artifact_mode` читать как fallback (оба канала одинаковы) на resume/verify/apply; новые proposal — раздельные поля.

## Открытые развилки (не блокируют ответ UX)

- Имена полей: `form_mode`/`layout_mode` vs `form_artifact_mode`/`mxl_artifact_mode`.
- Нужен ли `[form:…]` маркер в tasks симметрично `[mxl:…]`.
