# Частые ошибки XML (метаданные и формы)

## 1. Табличные части — не добавлять `LineNumber` вручную

Платформа добавляет стандартный реквизит номера строки сама. Явный `<standardAttributes>` с `LineNumber` в табличной части → ошибка загрузки или дубль.

## 2. Группа страниц — тип extInfo `PagesGroupExtInfo`

Правильно: `form:PagesGroupExtInfo` (с буквой **s**). Опечатка `PageGroupExtInfo` ломает группу страниц в Конфигураторе без явной ошибки.

## 3. Элемент `Page` — нужен `<enabled>true</enabled>`

Без флага Конфигуратор может считать страницу отключённой или не пройти валидацию.

## 4. UID / UUID — глобально уникальны

Новые объекты, реквизиты, ТЧ — каждый UUID отдельно (`[guid]::NewGuid()` в PowerShell). Не копировать UUID. Placeholder/последовательные UUID запрещены.

Создание **новых** объектов метаданных в kit-van — блокер человеку (`1c-no-metadata-creation.mdc`), не скрипт оркестратора.

## 5. Проверка после ручной правки / выгрузки

1. Режим формы/макета: **вручную** (`manual`) → инструкция Конфигуратор + WAIT до выгрузки; **автоматически** через skill (`assisted`) → только skill (`1c-forms` / `1c-mxl`), не сырой Write.
2. После выгрузки: `1c-forms/validate` или `1c-mxl/validate` по типу артефакта.
3. Не полагаться на MCP / внешние XSD-сервисы как обязательный путь поставки.
