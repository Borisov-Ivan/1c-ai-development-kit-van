# pause-wait — каркас файла `reports/handoff-pause-S<N>-YYYY-MM-DD.md`

Чат — [pause-wait-chat.md](pause-wait-chat.md). Этот файл — **рецепт** для Конфигуратора и возврата агента, не замена чата.

Порядок секций **фиксирован**: человек, открывший файл по ссылке из чата, сразу видит «Что создать». Дамп выгрузки — в конце.

```markdown
## Сессия приостановлена: <change-name>

Срез S<N>: «<название из tasks.md>» — ждём выгрузку из Конфигуратора.

## Что создать в Конфигураторе

**Расширение:** `<имя>`
**Тип:** Own | Adopted (пояснить одним предложением)

### Действия

1. <Объект и зачем>
   - Имя, тип, значения / FillValue / флаги модуля — здесь, не только в чате.
2. …
3. …

### Ловушки записи

- …

### После выгрузки — ожидаемые файлы

- `src/…/Enums/….xml`
- …

Не создавать: <анти-список>.

## Что проверить СЕЙЧАС

Сценарий на ИБ не гонять. Сначала объекты в Конфигураторе и выгрузка в репозиторий.

## Как вернуться

`/opsx:apply <change-name>` — после выгрузки; либо напишите в чат, что объекты на месте. Если имена в живой ИБ другие — напишите фактические.

## Следующие задачи

| Задача | Действие | Тип | Исполнитель | Зависит от | Статус |
|--------|----------|-----|-------------|------------|--------|
| `S<N>.<M>` | … | Конфигуратор | пользователь | — | `[ ]` |

Таблица только в файле.

## Приложение: чего нет в выгрузке сейчас

Идентификаторы и пути, которых агент не нашёл в `src/` — для сверки после выгрузки, не копировать в чат как тело сообщения.
```

**«Что реализовано»** при pause-wait: одна фраза «код ещё не писали». Не открывать файл списком отсутствующих символов.
