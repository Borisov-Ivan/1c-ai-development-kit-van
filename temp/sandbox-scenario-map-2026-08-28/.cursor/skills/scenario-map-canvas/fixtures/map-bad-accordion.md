# Эталон «плохо»: список без связей

Так **не** публиковать. Это аккордеон шагов, не карта сценария.

```yaml
header:
  question: "Что происходит при отправке на согласование"
  insight: "Четыре шага подряд"
  sources:
    - "пройденные точки прохода"
  view_primary: "list"

nodes:
  - step: 1
    name: "Проверка прав на документ"
    effect: "Система проверяет, может ли текущий пользователь отправить документ."
    evidence: "142:158:src/Example/cf/Documents/Согласование/Ext/ObjectModule.bsl"
  - step: 2
    name: "Формирование маршрута"
    effect: "По условиям маршрутизации выбирается цепочка согласующих."
    evidence: "201:224:src/Example/cf/Documents/Согласование/Ext/ObjectModule.bsl"
  - step: 3
    name: "Запись статуса"
    effect: "Документу присваивается статус, блокирующий редактирование."
    evidence: "openspec/changes/example/reports/explain-sample.md"
  - step: 4
    name: "Уведомление согласующих"
    effect: "Формируются задачи и рассылаются уведомления первому звену."
    evidence: "88:102:src/Example/cf/CommonModules/УведомленияСогласования/Ext/Module.bsl"

edges: []
```

## Почему не публиковать

- Нет `edges`: узлы не инцидентны связям.
- Главный вид — нумерованный список / аккордеон без рёбер.
- Порог «четыре шага рассказа» выполнен, порог **публикуемых сущностей после отсева без связи** — нет (после отсева набор пуст).
- Подписи на стрелках взять неоткуда; дорисовывать ветки запрещено.

**Правильно:** либо построить цепочку с `relation: follows`, `label` и `evidence_ref` из порядка прохода (прямая просьба), либо не публиковать и одной строкой сказать, каких связей не хватает. Порядок прохода не выдавать за причинность.
