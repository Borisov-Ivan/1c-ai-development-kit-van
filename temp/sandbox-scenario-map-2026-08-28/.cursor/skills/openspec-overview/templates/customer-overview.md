## Правила наполнения

| Секция | Откуда брать | Не брать |
|--------|--------------|----------|
| Как сейчас / Зачем | `proposal` Why; опц. исходное ТЗ | tasks, verification; уговоры («удобно потому что») |
| Заголовок этапа | бриф → сценарий среза **пересказанный ситуацией** (не механизм, не `S1`, не имя change) | «Автомат…», «Алгоритм…», kebab change |
| Вводный абзац | 0–2 предложения факта | «идея простая», «сервер проходит», «вызов при записи», педагогика |
| Что появляется | наблюдаемый эффект; зона («в расширении Павлик») — ремарка внутри пункта | инвентарь модулей; CRUD-разжёвывание; оправдания выбора |
| Как это работает | Behavior / What Changes → прозой по смыслу ТЗ | Intercept Map, D*; мета «так достигается цель ТЗ»; «не A, а B» |
| В итоге | опционально: одна фраза с **новым** смыслом | «Итого этап N:»; повтор заголовка/списка |
| Не усложняем | Non-Goals, опц. срезы | «вне scope» жаргоном |
| Стык с ТЗ | исходный текст ТЗ vs этапность | пересказ ADR; советы стенда; дубли мета из этапов |
| Согласовать | Open questions + ключевые решения на языке эффекта | список задач `12.9` |

**Объём:** ориентир 60–120 строк на одну тему; мульти-ЗНИ — одна история, не сумма двух design. Плотность важнее «разговорной мягкости».
